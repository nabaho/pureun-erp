# 2026-09-08 · 「🚪 퇴사한 담당 — 이어받기」 문

- 대표 지시: 「이어받기」 (같은 날 「퇴사자는 모두 제외시켜라」의 다음 걸음)

## 왜 필요했나

담당 **고르개**에서 퇴사자를 뺐다(`nonRetiredPicks`). 그런데 그 사람이 **아직 담당인
곳**이 남아 있으면, 이름이 사라진 것만으로는 그 곳들을 어떻게 할지 알 길이 없었다.

> **빼기만 하고 갈 곳을 안 만들면 자료를 잃은 것과 같다.**

## 갈 곳은 «이미 있었다»

메일함의 **「③ 퇴사자 이어받기」**(`openWhoPage` · `whoTab('succ')`).
한 줄만 정하면 그 사람이 맡던 것 **전부**가 새 담당자에게 간다.
없던 것은 **기업정보함에서 그 자리로 가는 길**뿐이었다.

## 만든 것

```
명함 목록 위 조건 띠:   🚪 퇴사한 담당 2명 — 이어받기 ›
```

- 세는 일은 **한 번**이다 — 담당 고르개를 만들 때 같은 목록을 갈라 쓴다(`_mgrGone`).
  따로 세면 6,315장을 두 벌씩 훑는다.
- **0명이면 띠가 아예 없다.** 늘 켜진 등은 아무것도 못 알린다.
- 누구인지는 **말풍선**에 셋까지(그 뒤는 「외 N명」). 띠에 다 늘어놓으면 줄이 길어진다.
- 누르면 **메일 앱 창**이 `?view=mail&mail=succ` 로 열린다.

## ⚠ 남긴 함정

| | |
|---|---|
| **창 이름이 포털의 메일 창과 같다** (`pureun-mail`) | 다르면 메일 창이 둘이 되어 어느 쪽이 진짜인지 모른다. `enter.html` 의 `portalAppWindowName('mail')` 과 «같아야» 한다 — 검사가 저쪽 파일까지 되짚어 본다 |
| **메일 «쓰기» 창과는 따로다** (`puMailWrite`) | 같으면 이어받기를 열 때 **쓰다 만 편지가 사라진다** |
| **`?mail=co` 는 «사업장 갈래»가 먼저 받는다** | `MAIL_WHO_TABS` 에 `'co'` 를 넣으면 「이 사업장과 오간 것」이 주인 가리기 화면으로 샌다. 그래서 **일부러 뺐다** |
| **아는 갈래만 받는다** | 모르는 글자를 `state.whoTab` 에 그대로 넣으면 아무 갈래에도 안 걸려 **빈 화면**이 열린다 |
| **갈래를 안 주면 예전 그대로** | 마지막에 보던 갈래(없으면 `addr`). 늘 덮으면 보던 자리를 잃는다 |
| **팝업이 막히면 알린다** | 아무 일도 안 하면 눌러도 반응 없는 띠가 된다 |
| **색은 팔레트(amber)에서만** | `#fffbeb` · `#fde68a` · `#854d0e`. 처음에 팔레트 밖 색을 써서 `color-palette-apps` 가 잡았다 |

## 함께 고친 옛 검사 둘

`restoreLastScreen` 을 vm 에 떠서 돌리는 검사들이 새로 생긴 `mailWhoFromUrl` 을
몰라 죽었다 — `cards-last-screen.test.js`(다른 방 것)와 내 것에 대역을 넣었다.
⚠ **최상위 `const` 는 컨텍스트 값이 되지 않는다** — `MAIL_WHO_TABS` 를 `var` 로 바꿔 싣는다.

## 검사

`tests/cards-succ-handoff-door.test.js` 13건 — 띠와 창과 주소 받기를 **통째로 떠서
돌린다**. 고장 21개를 넣어 모두 잡았다.

★ **가장 센 검사** — 「이어받기 **화면**이 그 갈래에 실제로 있다」.
길만 잇고 방이 없으면 빈 화면이 열린다. `mbSuccPending`·`mbSuccSet` 이 살아 있는지 본다.

⚠ 고장넣기에서 배운 것: 표식에 `${NL}` 을 쓴 뒤 다시 `split('\n').join(NL)` 하면
CRLF 파일에서 `\r\r\n` 이 되어 **표식이 안 맞는다**. 셋이 조용히 건너뛰어졌다 —
「건너뜀」을 실패로 세지 않으면 못 봤을 것이다.
