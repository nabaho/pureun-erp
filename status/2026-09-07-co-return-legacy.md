# 2026-09-07 · 업체관리 「↩ 계약관리로 복귀」가 옛 이관에도 보이게

- PR: [#1109](https://github.com/nabaho/pureunall/pull/1109) (앞선 것: [#1094](https://github.com/nabaho/pureunall/pull/1094))
- 대표 지시: 「뒤로 버튼 만들어서 계약관리로 다시 보내고 싶다. **다른관리 처럼**」

## 왜 안 보였나

#1094 로 넣은 되돌리기는 `xferUndo`(되돌릴 자리)가 있을 때만 보였다.
그것은 **그 배포부터** 남으므로 **이미 이관된 곳에는 하나도 없다.**
대표 화면의 ⋯ 에는 「수정 / 종료 처리」 둘뿐이었다 — 사건·컨설팅에는
「↩ 계약관리로 복귀」가 늘 보이는데 업체관리만 없었다.

**새 기능을 «앞으로 생길 자료»에만 걸면, 쓰는 사람은 그 기능이 없는 것과 같다.**
이미 있는 자료로 할 수 있는 일이 무엇인지를 먼저 봤어야 했다.

## 고친 것

출처 계약(`sourceContractNo` · `sourceContractId` · `sourceKind==='contract'`)만
있어도 보인다 — **사건·컨설팅이 쓰는 것과 같은 기준**이다.
실측 373곳 중 **9곳**(자문 4 · 급여 4 · 기금 1), 나머지 364곳에는 안 보인다.

이름도 사건·컨설팅과 **같게** 맞췄다(「↩ 계약관리로 복귀」). 하는 일은 여전히 다르다 —
업체를 안 지우고 계약을 새로 안 만든다. 그래도 **화면에서 찾는 사람에게는 같은 말**이어야 한다.

## 옛 이관은 «할 수 있는 것만»

무엇이 채워졌는지 기록이 없다(`mode:'legacy'`).

| | |
|---|---|
| ✓ | 계약을 칸반으로 (`status:'signed'`) |
| ✓ | 업체의 이관 자국(출처 계약·딱지)을 끊는다 |
| ✗ | 칸 값은 **그대로 둔다** — 기록 없이 비우면 사람이 넣은 것까지 지운다 |
| ✗ | 업체를 **지우지 않는다** — 새로 만든 것인지 알 길이 없다 |

⚠ 확인 창에 「비웁니다」라고 **쓰지 않는다.** 왜 못 비우는지 적는다 —
못 하는 일을 한 척하면 사람이 그것을 믿고 확인을 건너뛴다.
