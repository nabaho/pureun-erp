## 왜 저장소에 통째로 넣었나
「나중에 설치하세요」로 남기면 계정·PC 가 바뀔 때마다 없는 채로 시작한다.
푸른은 여러 로그인·여러 PC 에서 이어서 개발한다 — 그래서 도구도 저장소에 붙여 둔다.
`.github/workflows/deploy-pages.yml` 이 `.claude/` 를 배포본에서 지우므로,
9MB 가 인터넷에 올라가지는 않는다(`tests/dev-tools-not-published.test.js` 가 지킨다).

## 푸른이 실제로 쓰는 것
| 파일 | 쓰는 곳 |
|---|---|
| `scripts/convert_hwp.py` | 사업장·공단 서식이 대부분 **.hwp** 다 → .hwpx 로 바꾼다 |
| `scripts/clone_form.py` | 원본 서식을 복제해 «푸른 서식 원본» 을 만든다 |
| `scripts/fill_hwpx.py` | 표 칸 주소로 값을 넣는다(토큰이 없는 서식) |
| `scripts/secure_fill.py` | 개인정보를 **화면에 찍지 않고** 채운다 — 주민번호 서식용 |
| `scripts/validate.py` | 만든 .hwpx 가 한글이 여는 모양인지 본다 |
| `scripts/text_extract.py` | 서식에 어떤 칸이 있는지 읽는다 |

브라우저에서 도는 채우기는 `js/pu-form-fill.js` 다(서버·파이썬 없이 폰에서도 된다).
이 스킬은 **서식을 만들어 두는 쪽**, `pu-form-fill.js` 는 **매일 채우는 쪽**이다.

## 미리 깔아야 하는 것
```bash
python3 -m pip install python-hwpx lxml --break-system-packages
```
(2026-08-30 확인: python-hwpx 6.3.0, 한글 없이 리눅스에서 .hwp → .hwpx 1.2초)

## 안 지운 것
`scripts/vendor/rhwp/rhwp_bg.wasm` (4.4MB) 는 저장소의 `vendor/rhwp-core/rhwp_bg.wasm`
(6.9MB) 와 **다른 판** 이다(md5 `8f1623b6…` vs `4fb79f46…`). 합칠 수 없어 둘 다 둔다 —
하나는 브라우저용, 하나는 이 스킬(node)용이다.

## 고칠 일이 생기면
원본을 고치지 말고 **위에 새로 받아 덮는다**. 푸른이 손댄 곳은 이 메모뿐이다.
