# 푸른 하나문자 연결

권형하 휴대폰의 삼성 메시지 또는 Google 메시지에 도착하는 하나은행·하나카드 거래 알림을 푸른ERP 거래내역 대기함으로 전달하는 내부용 Android 앱입니다.

## 최초 연결

1. 푸른ERP → 재무관리 → 거래내역에서 `휴대폰 연결`을 누릅니다.
2. 휴대폰 앱에 PC 화면의 8자리 연결번호를 입력합니다.
3. `알림 접근 허용`을 누르고 `푸른 하나문자 연결`만 허용합니다.
4. 하나 거래문자가 도착한 뒤 ERP에서 `문자 가져오기`를 누릅니다.

## 보안 원칙

- `READ_SMS` 권한은 **「지난 문자 가져오기」를 누를 때만** 묻고, 그때만 씁니다
  (2026-08-29). 최근 30일치에서 **하나 거래문자만** 골라 보내고 원문은 앱에 남기지 않습니다.
  누르지 않으면 권한을 아예 묻지 않습니다.
- 삼성 메시지와 Google 메시지 알림만 확인합니다.
- 하나은행·하나카드 거래 형식이 아니면 휴대폰에서 버립니다.
- 인증번호·OTP·비밀번호가 포함된 알림은 휴대폰과 서버에서 이중 차단합니다.
- 연결키는 Android Keystore로 암호화합니다.
- 서버는 문자 원문을 저장하지 않고 거래일시·금액·입출금·가맹점만 보관합니다.

## 빌드

GitHub Actions의 `권형하 휴대폰 하나문자 앱 만들기` 작업에서 APK를 내려받습니다.
내부 배포용 debug APK이므로 설치할 때 Android의 `이 출처 허용`을 한 번 켜야 합니다.
사이트에 올려 둔 `hana-bridge.apk`는 **손으로** 갱신합니다
(`tests/hana-apk-shipped.test.js`가 소스와 어긋나면 막습니다).

## 서명키 (한 번만 하면 됩니다)

안드로이드는 **같은 도장으로 서명된 앱**만 덮어쓰기를 허락합니다.
도장이 없으면 빌드마다 임시 도장이 만들어져, 판을 올릴 때마다 앱을
**지웠다 다시 깔아야** 하고 그때마다 **연결이 지워져 8자리 번호를 다시** 넣어야 합니다.

키는 저장소에 두지 않습니다(대표 결정 2026-08-29 「안전하게」). GitHub 금고에 넣습니다.

**1) 도장 만들기** — PC 에서 한 번만. 비밀번호는 아무 것이나 정하고 적어 두세요.

```bash
keytool -genkeypair -v -keystore hana-release.jks -alias hana \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Pureun Labor, O=Pureun, C=KR"
```

**2) 금고에 넣기** — 파일을 글자로 바꿔서 넣습니다.

```bash
base64 -w0 hana-release.jks > hana-release.b64
```

GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret,
아래 넷을 만듭니다.

| 이름 | 값 |
|---|---|
| `HANA_KEYSTORE_B64` | `hana-release.b64` 파일 안의 글자 전부 |
| `HANA_KEYSTORE_PASSWORD` | 1) 에서 정한 비밀번호 |
| `HANA_KEY_ALIAS` | `hana` |
| `HANA_KEY_PASSWORD` | 1) 에서 정한 비밀번호 (같게 물으면 같은 것) |

**3) 도장 파일은 안전한 곳에 보관** — 잃어버리면 다시 만들어야 하고,
도장이 바뀌면 그때 또 한 번 **지웠다 다시 깔아야** 합니다.
저장소에는 넣지 마세요 — `tests/hana-apk-signing.test.js`가 막습니다.

> ⚠ 이 도장을 넣은 **뒤에 만든 첫 APK**를 깔 때는 마지막으로 한 번
> 지웠다 다시 깔아야 합니다(지금 폰에 있는 것은 옛 임시 도장입니다).
> 그다음부터는 덮어쓰기로 깔리고 **연결이 그대로 유지**됩니다.
