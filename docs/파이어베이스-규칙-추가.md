# 파이어베이스 규칙에 칸 세 개 넣기 — 대표님 콘솔 작업

2026-08-21 · 대상: 정부사업일정(`gov-consulting.html`)

> ⚠ **저장소의 규칙 파일을 통째로 붙여넣지 마십시오.**
> 콘솔에 있는 것이 진짜입니다. 저장소 파일은 뒤처져 있을 수 있고, 통째로 덮으면
> 사진첩·성과확인처럼 다른 앱이 막힙니다. **아래 세 덩이만 끼워 넣으세요.**

---

## 왜 필요한가

정부사업일정은 칸(노드)마다 규칙이 하나씩 적혀 있습니다. 새 칸을 만들면
규칙에 없어서 **쓰기가 거부**됩니다. 지금 세 칸이 그렇습니다.

| 칸 | 무엇에 쓰나 | 지금 상태 |
|---|---|---|
| `scal_erpConsHold` | 푸른ERP 새 컨설팅 중 **「안 가져옴」으로 보류한 건** | 규칙 없음 → 이 기기에만 남고 **관리자와 공유가 안 됨** |
| `scal_serverBackups` | **클라우드 자동백업** 본문 (하루 2회·약 10일치) | 규칙 없음 → 저장 안 됨 |
| `scal_serverBackupsIndex` | 그 백업의 목록(날짜·요약) | 규칙 없음 → 목록이 안 보임 |

넣기 전까지는 앱이 조용히 실패하지 않고 **화면에 "칸이 아직 열려 있지 않습니다"** 라고
알립니다. 기기 안 스냅샷과 수동 내보내기는 그대로 됩니다.

---

## 어디에 넣나

콘솔 → **Realtime Database → 규칙**.
이미 `"scal_cos"`, `"scal_scheds"` 같은 줄이 보일 겁니다. **그 옆에** 아래 세 덩이를
붙여 넣고 게시하면 됩니다. 기존 줄은 하나도 건드리지 마세요.

```json
    "scal_erpConsHold": {
      ".read": "auth != null && auth.token.firebase.sign_in_provider === 'password'",
      ".write": "auth != null && auth.token.firebase.sign_in_provider === 'password'"
    },
    "scal_serverBackups": {
      ".read": "auth != null && auth.token.firebase.sign_in_provider === 'password'",
      ".write": "auth != null && auth.token.firebase.sign_in_provider === 'password'"
    },
    "scal_serverBackupsIndex": {
      ".read": "auth != null && auth.token.firebase.sign_in_provider === 'password'",
      ".write": "auth != null && auth.token.firebase.sign_in_provider === 'password'"
    },
```

**기존 `scal_*` 칸들과 똑같은 조건입니다** — 이메일로 로그인한 직원만 읽고 씁니다.
새로운 권한을 여는 것이 아닙니다.

### 붙여넣을 때 흔한 실수

- **쉼표**: 앞 덩이 끝에 `,` 가 있어야 합니다. 마지막 덩이라면 뒤의 `,` 를 빼세요.
- 콘솔이 빨간 줄로 문법 오류를 알려 줍니다. 게시가 안 되면 대부분 쉼표입니다.

---

## 넣은 뒤 확인

1. 정부사업일정을 새로고침
2. **환경설정 → 백업 / 복원** → 「☁ 클라우드 자동백업」 칸
3. 빨간 안내가 사라지고, **[지금 백업]** 을 누르면 목록에 한 줄이 생기면 성공입니다

보류 기능은 「푸른ERP 연결」 탭 아래 「가져오지 않기로 한 건」에서 확인합니다.

---

## 용량 걱정은 안 하셔도 됩니다

정부사업일정 자료는 작습니다. 백업 한 벌이 수십~수백 KB라, 20벌을 쌓아도
무료 한도(1GB)의 아주 일부입니다. 20벌이 넘으면 **옛것부터 자동으로 지웁니다.**
