# 파이어베이스 콘솔에 넣을 규칙 세 칸

마지막 확인: 2026-08-25 (대표가 붙여 주신 콘솔 전문과 대조함 — **세 칸 모두 없음**)

---

## 왜 필요한가

정부사업일정에 새로 만든 기능 둘이 **아직 클라우드에 저장되지 않고 있습니다.**

| 안 되는 것 | 쓰는 칸 |
|---|---|
| ERP 신규 컨설팅에서 「안 가져옴」 표시 | `scal_erpConsHold` |
| 로그인할 때 서버 자동 백업 · 「지금 백업」 | `scal_serverBackups` · `scal_serverBackupsIndex` |

콘솔에 이 칸이 없으면 파이어베이스가 **쓰기를 거절**합니다.
화면에는 「인터넷 연결을 확인하세요」로 나와서 원인이 잘 안 보입니다.

> `serverBackups` · `serverBackupsIndex` 는 이미 있지만 **다른 앱 것**입니다.
> 이름 앞에 `scal_` 이 붙어야 정부사업일정 것입니다. 섞어 쓰면 안 됩니다.

---

## 넣는 방법 (한 번만 하면 됩니다)

1. 파이어베이스 콘솔 → **Realtime Database** → **규칙(Rules)** 탭
2. 글 안에서 아래 줄을 찾습니다 (Ctrl+F 로 `scal_erpTypeMap` 검색)

```
    "scal_erpTypeMap": {
```

3. **바로 그 줄 «위»에** 아래를 통째로 붙여넣습니다
4. **게시(Publish)**

아래 토막은 끝이 쉼표로 끝나 있어서, 뒤에 오는 `"scal_erpTypeMap"` 줄은
**손대지 않아도 됩니다.**

```json
    "scal_erpConsHold": {
      ".read": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)",
      ".write": "(auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)) && (newData.exists() || root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true)",
      "$k": {
        ".write": "(auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)) && (newData.exists() || root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true)",
        "$k2": {
          ".write": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)"
        }
      }
    },
    "scal_serverBackups": {
      ".read": "root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
      ".write": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)"
    },
    "scal_serverBackupsIndex": {
      ".read": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)",
      ".write": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)"
    },
```

---

## 각 칸이 무엇을 허용하나

**`scal_erpConsHold`** — 다른 `scal_*` 칸(사업장·일정·직원)과 **똑같은 규칙**입니다.
비밀번호로 로그인한 직원은 읽고 쓸 수 있고, **지우는 것은 총괄관리자만** 할 수 있습니다.
(누가 실수로 남의 「안 가져옴」 표시를 지우면 그 컨설팅이 매일 다시 물어보게 됩니다.)

**`scal_serverBackups`** — 백업 «내용»입니다.
쓰기는 직원 누구나(로그인할 때 저절로 저장됩니다), **읽기는 총괄관리자만.**
백업 안에는 사업장·일정이 통째로 들어 있어서 아무나 꺼내 볼 일이 아닙니다.
앱에서도 복원 단추는 총괄관리자에게만 동작합니다.

**`scal_serverBackupsIndex`** — 「언제 · 몇 건」만 적힌 **목록**입니다.
직원도 백업이 돌고 있는지는 볼 수 있어야 해서 읽기·쓰기를 열어 둡니다.
내용은 없으므로 새어 나갈 것이 없습니다.

---

## 넣은 뒤 확인

1. 정부사업일정 → **설정 → 백업** → 「지금 백업」
   → 「저장했습니다」가 뜨고 아래 목록에 한 줄이 생기면 성공입니다.
2. ERP에 새 컨설팅이 있을 때 로그인 → 물어보는 창에서 「안 가져옴」
   → **다음 날 다시 안 물어보면** 성공입니다.
   (지금은 저장이 안 돼서 매번 다시 물어봅니다.)

둘 다 안 되면 규칙이 **게시(Publish)** 되지 않은 것입니다 — 저장만 하면 안 됩니다.
