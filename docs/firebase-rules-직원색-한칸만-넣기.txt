파이어베이스 규칙 — 직원 색표 칸 한 개만 넣기 (2026-08-30)
════════════════════════════════════════════════════════════════

■ 왜 넣나
  직원 색(사번 → 색)을 **푸른이알피 법인대시보드 한 곳**에서 정하고,
  컨설팅일정이 그것을 읽어 쓰기로 했습니다(대표 지시
  「푸른이알피 법인대시보드의 본인 색으로 전체 시스템을 일치시켜라」).
  예전에는 대표가 손수 고른 색이 **그 PC 브라우저 안에만** 남아,
  다른 PC 에서 열면 순번 색으로 돌아가고 컨설팅일정은 아예 못 봤습니다.

⚠ **지금도 잘 돕니다.** 이 칸이 없어도 data 아래 이름 없는 자리 규칙($other)으로
  이미 읽고 쓰입니다. 이 붙여넣기는 **여는 일이 아니라 조이는 일**입니다 —
  넣지 않으면 **직원 누구나 남의 색을 바꿀 수 있는** 상태로 남습니다.

■ 어디에
  파이어베이스 콘솔 → Realtime Database → 규칙
  → "data" 안, 이미 있는  "sg_resolved_uid": { … }  **바로 아래**
    (= "$other": { … } 바로 위)에 붙여넣고 [게시]

■ 그 밖에 바뀌는 것
  없습니다. 대표님이 주신 콘솔 원문과 대조했습니다 —
  새로 생기는 칸 1개, 내용이 달라지는 칸 0개, 사라지는 칸 0개.
  (최상위 52칸·data 아래 28칸이 글자 하나까지 같은 것을 확인했습니다)

⚠ 전체를 갈아끼우지 마세요.
  예전에 저장소 파일로 통째 배포했다가 사진첩·성과확인이 막힌 적이 있습니다.
  한 칸만 끼워 넣는 것이 안전합니다.

────────────────────────────────────────────────────────────────
"staff_colors": {
  ".read": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)",
  ".write": "auth != null && (root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true || root.child('uid_roles').child(auth.uid).child('isSubAdmin').val() == true)"
},
────────────────────────────────────────────────────────────────

■ 뜻
  · 읽기 — 로그인한 직원 누구나
    (어느 앱·어느 PC 에서나 같은 색이어야 하므로 모두가 읽어야 합니다)
  · 쓰기 — **총괄관리자·위임관리인만**
    (색은 법인대시보드 한 곳에서만 정합니다. 두 곳에서 정하면 언젠가 어긋나고,
     그때 어느 쪽이 맞는지 아무도 모릅니다)

■ 넣은 뒤 확인
  ① 푸른이알피 → 법인 대시보드를 한 번 엽니다
     (그때 지금 색표가 공용 자리에 올라갑니다)
  ② 컨설팅일정을 새로고침합니다
  ③ 달력 칩과 옆줄 이름표 색이 법인대시보드와 같아지면 된 것입니다

  ⚠ 색이 안 바뀌면 «사번이 안 이어져 있는» 사람입니다 —
    컨설팅일정 → 환경설정 → 직원 관리에서 그 사람의 사번을 이어 주세요.

■ 넣지 않으면
  화면은 그대로 돌아가지만, 직원 누구나 남의 색을 바꿀 수 있습니다.
  (색이 업무를 막지는 않으므로 급한 일은 아닙니다)
