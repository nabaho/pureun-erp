# 파이어베이스 이번 달 사용액 — 켜는 절차

대표 지시 2026-08-15: "결제한 금액 잔여량이 얼마인지 실시간으로 확인 가능한지, 화면에 넣을 수 있는지."
결정: **안 A(관리자 화면) · 대표+관리자 · 첫 달은 눈금 없이 금액만.**

코드는 이미 올라가 있다. 아래 셋을 켜야 화면에 숫자가 뜬다.
**켜기 전에는 아무것도 안 보인다**(빈 칸도 안 만든다 — 준비 중인지 고장인지 헷갈리는 자리를 남기지 않는다).

---

## 먼저 알아 둘 것

- **「남은 금액」은 만들 수 없다.** Blaze 는 미리 넣고 까먹는 방식이 아니라 쓴 만큼 다음 달에
  청구되는 후불이라, 남은 돈이라는 숫자가 구글 쪽에 **없다.** 이번 달 지금까지 쓴 금액만 나온다.
- **완전한 실시간이 아니다.** 구글은 금액이 움직일 때 쏘고, 주기는 20~30분쯤이다.
- **어림수다.** 확정 청구액은 월말에 정산된다.
- **구글 「예산」 금액은 화면 눈금이 아니다.** 예산은 「이 금액을 넘으면 알려 달라」는
  알림 방아쇠일 뿐이라 넉넉히 잡아 둔다. 화면 눈금은 `billing/limit` 하나뿐이고,
  대표님이 정하시기 전까지는 막대를 안 그린다.

## 1단계 — 알림이 지나갈 통로 만들기

[Cloud Shell](https://console.cloud.google.com/?cloudshell=true) 을 열고(오른쪽 위 `>_` 아이콘),
프로젝트가 **PUREUN-ERP** 인지 확인한 뒤 한 줄씩 붙여넣는다.

```bash
gcloud pubsub topics create billing-alerts --project=pureun-erp
```

`Created topic [...]` 가 나오면 된 것이다. 이미 있다면 `ALREADY_EXISTS` 가 나오는데 그냥 두면 된다.

## 2단계 — 전체 예산 하나 걸기 (이것만으로 화면이 돈다)

먼저 결제 계정 번호를 확인한다. **`accounts list` 가 아니라 이것을 쓴다.**

```bash
gcloud billing projects describe pureun-erp
```

`billingAccountName: billingAccounts/XXXXXX-XXXXXX-XXXXXX` 의 번호가 답이다.
`billingEnabled: true` 인지도 같이 보인다.

> ⚠ **여기서 크게 헤맸다 (2026-08-15).** 처음엔
> `gcloud billing accounts list ... | head -1` 로 **목록의 첫 번째**를 집게 만들었는데,
> 이 회사에는 결제 계정이 **둘**이었고 첫 번째가 **이미 닫힌 옛 평가판**이었다.
> 그래서 예산 만들기가 계속 `INVALID_ARGUMENT` 로 거절당했다 —
> 깃발 이름 문제인 줄 알고 세 번을 헛짚었다. 진짜 이유는 콘솔 화면의
> 회색 단추 위 말풍선에 있었다: **「폐쇄된 계정에는 예산을 만들 수 없습니다」**.
>
> **교훈 둘.**
> ① `head -1` 로 계정을 고르지 말 것 — **프로젝트가 실제로 쓰는 계정**을 물어야 한다.
> ② 콘솔에 「무료 평가판이 종료됐다 · 9월 1일까지 업그레이드」 배너가 떠도
> **닫힌 옛 계정 이야기일 수 있다.** `billingEnabled: true` 면 지금 쓰는 결제는 살아 있다.
> (실제로 그 배너가 뜬 상태에서도 Cloud Functions 배포가 성공했다 —
> 결제가 죽었으면 그건 안 된다. 배너보다 이쪽이 확실한 증거다.)

```bash
gcloud billing budgets create --billing-account=여기에번호 --display-name=pu-total --budget-amount=1000000 --filter-projects=projects/pureun-erp --notifications-rule-pubsub-topic=projects/pureun-erp/topics/billing-alerts
```

> 금액 뒤에 `KRW` 를 붙이지 않는다 — 안 붙이면 결제 계정 통화를 그대로 쓴다.

> ⚠ **깃발 이름이 gcloud 판마다 다르다 — 2026-08-15 실제로 여기서 걸렸다.**
> 예전 이름은 `--all-updates-rule-pubsub-topic`, 지금 정식 이름은
> `--notifications-rule-pubsub-topic` 이다. `unrecognized arguments` 로 막히면
> 아래 예비 명령을 쓴다(`||` 로 이어 붙이면 한 번에 붙여넣어도 된다).
>
> ```bash
> gcloud beta billing budgets create --billing-account=여기에번호 --display-name=pu-total --budget-amount=1000000KRW --filter-projects=projects/pureun-erp --all-updates-rule-pubsub-topic=projects/pureun-erp/topics/billing-alerts --all-updates-rule-schema-version=1.0
> ```

> ⚠ **「통로는 이미 있습니다」가 나와도 정상이다.** `recordBillingAlert` 함수를
> 배포하는 순간 통로(Pub/Sub 토픽)가 같이 만들어지기 때문이다.

> **이름 `pu-total` 은 글자 그대로 써야 한다.** 서버가 이 이름으로 어느 칸에 담을지 정한다.
> 다르게 쓰면 쪽지가 조용히 버려진다(모르는 예산은 안 담는 것이 안전 장치다).
>
> **100만원은 눈금이 아니라 알림 방아쇠다.** 넉넉히 잡아 두는 값이고 화면에 안 나온다.

## 3단계 — 화면이 금액을 읽을 수 있게 규칙 넣기

파이어베이스 콘솔 → Realtime Database → **규칙**. 최상단 `{` 바로 아래에 넣는다.

> ⚠ **규칙은 콘솔이 진짜다.** 저장소 파일로 배포하지 말 것 —
> 사진첩·성과확인이 막힌 적이 있다.

```json
"billing": {
  ".read": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
  ".write": false
}
```

- **읽기는 관리자만.** 회사 지출액이라 전 직원에게 열지 않는다.
- **쓰기는 아무도 못 한다.** 금액은 서버(Admin SDK)만 적는다.
  Admin SDK 는 규칙을 통과하므로 `false` 여도 서버는 쓴다.
- ⚠ 화면은 `관리자대행(admin-delegate)`에게도 이 칸을 보여 주려 하지만,
  규칙은 `uid_roles` 의 `isAdmin` 만 본다. 대행에게도 보이게 하시려면
  그 사람의 `uid_roles/{uid}/isAdmin` 을 `true` 로 두어야 한다.
  아니면 **조용히 안 보인다**(오류는 안 난다).

## 4단계 (나중에 해도 된다) — 쪼개 보기

2단계까지만 하면 **총액 하나**가 뜬다. 「사진 창고에 얼마, 실시간DB 에 얼마」를 보시려면
서비스별로 예산을 따로 걸어야 한다 — 구글이 쏘는 쪽지에는 총액뿐이라 다른 방법이 없다.

서비스 번호부터 찾는다.

```bash
curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" "https://cloudbilling.googleapis.com/v1/services?pageSize=5000" | python3 -c "import sys,json;w={'Cloud Storage':'pu-storage','Firebase Realtime Database':'pu-database','Cloud Functions':'pu-functions'};[print(w[s['displayName']], s['serviceId']) for s in json.load(sys.stdin).get('services',[]) if s['displayName'] in w]"
```

나온 번호로 셋을 만든다(`pu-storage` 예시 — 나머지도 이름과 번호만 바꿔 똑같이).

```bash
gcloud billing budgets create --billing-account=여기에번호 --display-name=pu-storage --budget-amount=1000000KRW --filter-projects=projects/pureun-erp --filter-services=services/여기에서비스번호 --notifications-rule-pubsub-topic=projects/pureun-erp/topics/billing-alerts
```

> 여기도 2단계와 같은 깃발 이름 문제가 난다 — 막히면 `gcloud beta` + `--all-updates-rule-*` 로.

> ⚠ **서비스 이름은 짚지 말고 반드시 위 명령으로 뽑을 것.**
> 2026-08-15 에 `Cloud Functions` 로 짚었다가 틀렸다 — 지금 이름은 **`Cloud Run Functions`** 다.
> 그날 확인한 번호: 창고 `95FF-2EF5-5EA1` · 실시간DB `1C58-CF90-9614` · 함수 `29E7-DA93-CA13`.
> (이 번호도 언젠가 바뀔 수 있으니 **뽑아 쓰는 습관**이 맞다.)

쓸 이름은 **다섯뿐**이고 글자 그대로여야 한다 —
`pu-total` `pu-storage` `pu-database` `pu-functions` **`pu-ai`**.

> 쪼갠 것을 더해도 총액과 안 맞는다(예산을 안 건 서비스가 남는다).
> 모자란 몫은 화면에 **「그 밖」**으로 따로 나온다 — 감추면 더해 보시고 안 맞는 걸 발견하시게 된다.

### ⭐ `pu-ai` — AI(제미나이) 요금 (2026-08-29 추가)

서버는 제미나이를 **두 군데**서 부른다 — 서류 판독(`gemini-2.5-flash`)과
사진 지우개(`gemini-2.5-flash-image`). 지우개는 **그림을 만드는** 부르기라
판독보다 훨씬 비싸고, 2026-08-29 에 막 켰다.

> ⚠ **예산이 없는 동안 이 몫은 「그 밖」에 통째로 섞인다.**
> 2026-08 기준 「그 밖」이 11,424원(전체의 11%)이었는데 대부분 이것으로 보인다.
> 예산을 걸어야 **얼마나 쓰는지 보인다** — 안 보이면 늘어도 모른다.

서비스 이름은 **`Generative Language API`** 다. 번호를 뽑는다.

```bash
curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" "https://cloudbilling.googleapis.com/v1/services?pageSize=5000" | python3 -c "import sys,json;[print(s['displayName'], s['serviceId']) for s in json.load(sys.stdin).get('services',[]) if 'Generative Language' in s['displayName']]"
```

나온 번호로 만든다.

```bash
gcloud billing budgets create --billing-account=여기에번호 --display-name=pu-ai --budget-amount=1000000KRW --filter-projects=projects/pureun-erp --filter-services=services/여기에서비스번호 --notifications-rule-pubsub-topic=projects/pureun-erp/topics/billing-alerts
```

> 만드시면 **다음 쪽지부터**(20~30분) 화면에 「AI 판독·지우개」 줄이 생긴다.
> 코드 쪽은 이미 이 이름을 알아듣게 해 두었다(`functions/billing-alert.js`).

## 4-3단계 — 하루 폭주 알림 (2026-08-29 대표 지시)

**대표님이 켜실 것은 없다. 배포하면 돈다.** 다만 왜 만들었는지는 알아 두셔야 한다.

2026-08-16 에 백업이 폭주해 **하루에 86,042원**이 나갔는데 **아무 알림도 없었다.**
4-1 의 메일 알림은 「총액이 얼마를 넘으면」이라, 그 금액에 닿을 때쯤이면 **이미 다 나간 뒤**다.

그래서 서버가 쪽지를 받을 때마다 **「오늘 늘어난 금액이 최근 이레 하루 평균의 몇 배인가」**를
재 둔다(`billing/spike`). **5배가 넘고 그날 3,000원 이상**이면 포털 사용액 창 맨 위에
빨간 줄이 뜨고, 딱지도 빨갛게 바뀐다.

- 비교할 「평소」가 이틀 어치도 없으면 **판정하지 않는다** — 없는 평소로 「몇 배」라고 하면 거짓말이다.
- 작은 금액은 배수가 쉽게 커져서(20원→100원도 5배) **금액 바닥**을 함께 둔다.
- 날짜는 **한국 시간**으로 자른다 — UTC 로 자르면 아침 아홉 시 전에 쓴 돈이 전날에 붙는다.
- ⚠ **막는 장치가 아니라 알리는 장치다.** Blaze 에는 자동 상한이 없어 아무것도 안 멈춘다.

## 4-1단계 — 넘치기 전에 메일로 알림 (대표 지시 2026-08-16)

⚠ **Blaze 에는 자동 상한이 없다.** 예산은 알림 방아쇠일 뿐 **아무것도 멈추지 않는다.**
그래서 「빨리 알아채는 것」이 유일한 방어다. 대표님께도 이렇게 말씀드렸다.

알림 받을 메일 자리를 만들고, **알림 전용 예산**을 따로 판다.

```bash
ACC=여기에번호
CH=$(gcloud beta monitoring channels create --display-name="푸른 결제알림" --type=email --channel-labels=email_address=받을주소@example.com --project=pureun-erp --format="value(name)")
gcloud billing budgets create --billing-account=$ACC --display-name=pu-alert --budget-amount=100000 --filter-projects=projects/pureun-erp --threshold-rule=percent=0.75 --threshold-rule=percent=1.0 --threshold-rule=percent=1.5 --notifications-rule-monitoring-notification-channels=$CH
```

> **왜 `pu-total` 에 붙이지 않고 예산을 따로 파나** — 붙이려다 실패했기 때문이다.
> `update` 는 `create` 와 깃발 이름이 달라(`--threshold-rule` → **`--add-threshold-rule`**)
> 한 번에 안 됐다. 알림 전용으로 따로 파면 `pu-total`(앱에 값을 보내는 예산)을 안 건드려
> 더 안전하기도 하다. **`pu-alert` 는 pubsub 을 안 쓰므로 앱 값에 섞이지 않는다**
> (설령 보내도 서버가 「모르는 예산 이름」으로 버린다 — `functions/billing-alert.js`).

- 메일은 **위에서 등록한 주소 + 결제 관리자 주소** 양쪽으로 간다
  (`disableDefaultIamRecipients` 를 안 켰으므로 관리자는 자동 포함).
- 임계값은 예산액 대비 비율이다 — 위 예시는 10만원 기준 **7.5만 / 10만 / 15만**.
- ⚠ 이미 그 금액을 넘긴 달이면 **켜자마자 메일이 온다.** 고장이 아니다.

## 4-2단계 — 매달 오는 청구서를 한 곳 더 받기 (화면에서, 명령 아님)

4-1 은 **「넘칠 것 같다」는 경고**고, 이건 **매달 오는 청구서·영수증**이다. 다른 것이다.

1. 결제 → **결제 설정** (왼쪽 메뉴 아래쪽. 주소로 바로 가려 하면 `URL을 찾을 수 없음` 이 뜬다 —
   **메뉴로 들어갈 것.**)
2. 아래로 내려 **「결제 서비스 사용자」** → **「결제 서비스 사용자 관리」**
3. **「+ 새 사용자 추가」** → 이름·전화·이메일
4. **「이메일 환경설정」을 펼쳐 결제 메일을 켠다** — 여기를 비워 두면
   **초대만 가고 정작 메일은 안 온다.**
5. **「기본 연락처」 체크는 끈다** — 기본 연락처는 한 명뿐이라, 켜면 원래 담당자가 밀려난다.
   **「대신」이 아니라 「한 명 더」**가 목적이다.
6. **「권한」은 비워 둔다** — 메일만 받으면 되는데 관리자 권한을 주면
   그 주소로 **결제 수단·카드까지 바꿀 수 있게 된다.**
7. **초대** → 받는 쪽 메일함에서 **수락**해야 「초대됨」이 풀린다(스팸함도 볼 것).

> ✅ 2026-08-16 에 `370-6@hanmail.net` 로 실제로 해 봤다. **구글 계정이 아니어도 된다** —
> 수락하면 `email-only user` 로 붙는다(설정은 못 바꾸고 메일만 받는다). 걱정했던 것과 달랐다.

## 5단계 (한 달 뒤) — 눈금 정하기

한 달 지켜보고 실제 사용액을 아신 뒤, 실시간DB `billing/limit` 에 숫자 하나를 넣으면
그때부터 막대가 그려진다(8할에서 노랑, 다 차면 빨강).

```
billing/limit = 50000
```

넣기 전에는 막대가 없고 금액만 보인다. **넘어도 서비스가 끊기지는 않는다** — 눈금일 뿐이다.

## 잘 되는지 확인

1. 실시간DB 에 `billing/current/total` 이 생겼는지 (첫 쪽지는 몇 십 분 걸린다)
2. 관리자로 푸른ERP 를 열면 왼쪽 메뉴 위에 **💳 이번 달 ₩○○○** 줄이 보이는지
3. 그 줄을 누르면 쪼갠 값과 월말 예상액이 펼쳐지는지

안 보이면 순서대로 본다 — ①규칙(3단계) ②예산 이름 철자 ③함수 로그
(`gcloud functions logs read recordBillingAlert --region=asia-northeast3`).
