# 푸른통합 온톨로지 — 3단계 확정 관계망 규격

작성: 2026-09-02

## 결론

통합 진단 결과에서 신뢰도 1.0인 명시적 ID 관계만 `ontology/v1` 관계망 파일로 만든다.
업체명 등 글자로 추정한 신뢰도 0.85 관계는 제외하며, 원본의 `companyId`·`sid`가
확정된 뒤에만 다음 관계망에 들어온다.

## 네 가지 권한 칸

- `internal`: 업체·계약·사건·사업·업무·일정
- `source`: 문서·사진 메타·메일 메타·규정·제출 메타
- `personal`: 사람·재직관계
- `financial`: 입출금·세금계산서·임금기록

관계의 양끝 중 더 민감한 권한을 관계에도 적용한다. 예를 들어 임금기록과 업체의
관계는 `financial`, 문서와 사람의 관계는 `personal`에 둔다.

## 관계망에 넣지 않는 것

- 사람·업체 이름과 화면 표시용 제목
- 문서·메일·뉴스레터 본문
- 사진·미리보기·OCR 글자
- 연락처·주민번호·계좌번호
- 임금 및 입출금 금액
- 신뢰도 1.0 미만의 추정 관계
- 양끝 개체가 모두 존재하지 않는 끊어진 관계

## 안전장치

1. 모든 개체 열쇠는 프로그램 영역을 포함하고 Firebase 금지문자를 인코딩한다.
2. `generationId`와 fingerprint로 같은 입력 관계망을 식별한다.
3. `sourceMutation:'never'`를 필수로 기록한다.
4. 검증기가 금지 열쇠와 `label`, `payload`, `content` 필드를 거부한다.
5. 현재 단계에서는 서버에 쓰지 않고 사용자가 내려받는 JSON만 만든다.

## 화면

푸른ERP → 환경설정 → 데이터·로그 → 온톨로지에서 관계 전수진단 후
`확정 관계망 파일`을 누른다. 화면은 확정 관계 건수와 제외한 추정 후보 건수를 알린다.

## 다음 단계

서버 저장을 열기 전 Firebase 규칙에 네 권한 칸을 각각 정의하고 Rules Emulator에서
일반·재무·관리자·비로그인 계정을 교차 검증한다. 그 검증이 통과하기 전에는
`ontology/v1` 서버 쓰기 버튼을 만들지 않는다.
