반출 기록(exportLog) 규칙 두 칸만 넣기 — 대표님용
════════════════════════════════════════════════════════════════════

전문을 다시 붙여넣지 않아도 됩니다. 아래 «두 칸»만 지금 규칙 맨 앞에 끼워 넣으면 됩니다.

── 왜 넣어야 하나 ──
넣기 «전»에는 기업정보함이 기록을 아예 못 남깁니다. 그러면 내려받기가 되지 않습니다
(기록이 안 남는 내려받기는 만들지 않도록 해 두었습니다). 넣고 나서야 정상으로 돕니다.

── 어디로 가나 ──
1) 파이어베이스 콘솔 → Realtime Database → 위쪽 「규칙」 탭
2) 편집칸 맨 위가 이렇게 생겼습니다:

   {
     "rules": {
       "billing": {
       ...

3) "rules": { 바로 «다음 줄»에 아래를 붙여넣습니다.

── 붙여넣을 것 ──

    "exportLog": {
      ".read": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
      "$id": {
        ".write": "auth != null && !data.exists() && newData.exists()",
        ".validate": "newData.hasChildren(['at','by','uid','kind','what','n']) && newData.child('uid').val() === auth.uid && newData.child('at').val() === now && newData.child('n').isNumber()"
      }
    },
    "exportSeen": {
      "$uid": {
        ".read": "auth != null && auth.uid === $uid",
        ".write": "auth != null && auth.uid === $uid && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true"
      }
    },

4) 오른쪽 위 [게시] 를 누릅니다.

── 무슨 뜻인가 ──

  .read  = 총괄관리자로 로그인한 사람만 반출 기록을 «본다».
           누가 무엇을 가져갔는지는 직원끼리 들여다볼 일이 아닙니다.

  !data.exists()  = ★ 가장 중요한 줄입니다. «새로 만드는 것만» 되고
                    이미 있는 기록을 고치거나 지우는 것은 «아무도» 못 합니다.
                    자기 기록을 지울 수 있으면 기록은 아무 뜻이 없습니다.

  uid === auth.uid = 남의 이름으로 기록을 적을 수 없습니다.

  at === now       = 날짜를 속일 수 없습니다. 앱이 «서버 시각»으로 적어야만 통과합니다.

  exportSeen       = 대표님이 「확인」을 누른 시각만 담습니다(알림 배지를 끄는 데만 씁니다).
                     기록 자체에 「봤음」을 적으면 «기록을 고치는» 것이 되어,
                     고칠 수 있는 문을 열어 주게 됩니다. 그래서 딴 칸에 둡니다.

── 왜 pucards 안이 아니라 «맨 위»인가 ──
파이어베이스 규칙은 위에서 아래로 흐르고, **부모가 준 읽기 권한을 자식이 뺏을 수 없습니다.**
pucards 아래에 두면 「관리자만」이라고 적어도 직원이 그대로 읽습니다.
그래서 반드시 맨 위 칸(rules 바로 아래)에 두어야 합니다. 자리를 옮기지 마세요.

── 넣은 뒤 확인 ──
기업정보함 → 환경설정 → 계정·AI → 「🧾 반출 기록」 을 누르면 목록이 뜹니다.
안 뜨고 「기록을 읽지 못했습니다」가 나오면 규칙이 아직 안 들어간 것입니다.

── 보관 기간 ──
2년이 지난 기록은 정리하기로 정했습니다(대표 결정 2026-08-29).
다만 «지우는 장치는 아직 만들지 않았습니다» — 오늘 만든 첫 기록이 지워질 때는 2028년 8월이고,
지울 수 있는 장치가 있다는 것 자체가 약점이기 때문입니다.
때가 되면 서버가 지웁니다. 앱에는 지우는 단추를 두지 않습니다.
