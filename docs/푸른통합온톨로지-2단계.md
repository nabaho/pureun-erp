# 푸른통합 온톨로지 — 2단계 안전한 프로그램 어댑터

작성: 2026-09-02

## 목표

푸른ERP의 정본뿐 아니라 포털에 등록된 모든 프로그램을 공통 관계망에서 다룬다.
단, 관계를 찾는다는 이유로 개인정보 본문이나 대용량 파일을 한 화면에 모으지 않는다.

## 통합 화면에서 읽는 경량 자료

- 푸른ERP 업체·사람·계약·사건·사업·일정·재무 정본
- 정부사업일정과 기금관리의 ERP 공유 정본
- 업무관리 `work_erp/items`
- 경력관리의 본인 자료 건수 `kcareer/{uid}/counts`
- 기업정보함 경량 검색색인 `pucards/idx`
- 사진첩의 본인 사진 메타 `puphotos/u/{uid}/items`
- 급여관리의 직원표 없는 목록 `payroll_os/payroll/index`
- 급여데이터함의 본인 자료 메타 `paydata/u/{uid}/items`
- 홈페이지 구성원 및 쪽 목록

## 통합 화면에서 읽지 않는 자료

- 사진 원본·미리보기·OCR 글자
- 급여 직원별 금액표와 급여데이터 값 본문
- 메일함·메일 본문·받는 사람 명단
- 전자서명 제출·암호키·서명 그림
- 취업규칙과 뉴스레터의 전체 본문

이 자료들은 각 프로그램의 기존 권한 경계 안에서 `strategy:'in_app'` 방식으로 진단한다.
읽지 못한 경로는 비어 있다고 추정하지 않고 `확인 필요`로 표시한다.

## 생성하는 관계

- 업무 → 주담당 `assignedTo`
- 업무 → 부담당 `assists`
- 업무·문서·사진·임금기록 → 업체 `forOrganization`
- 사진 → 소유자 `ownedBy`

업체명이 유일하게 일치할 때만 신뢰도 0.85의 후보 관계를 만들고, `companyId`가
일치하면 신뢰도 1.0으로 만든다. 원본에는 어떤 값도 다시 쓰지 않는다.

## 다음 단계

3단계에서는 확정된 관계만 별도의 `ontology/v1` 파생 색인으로 저장한다. 저장 전에는
관계마다 원본 프로그램·원본 ID·생성시각·권한등급·스키마 버전을 포함하고, 원본이
삭제돼도 온톨로지가 원본 삭제를 전파하지 않도록 단방향 재생성 구조를 사용한다.
