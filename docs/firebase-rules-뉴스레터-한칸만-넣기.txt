파이어베이스 규칙 — 뉴스레터 칸 한 개만 넣기 (2026-09-02)
════════════════════════════════════════════════════════════════

■ 왜 넣나
  내외관리에 「뉴스레터 관리」를 넣었습니다(대표 지시 2026-09-02
  「푸른내외관리에 뉴스레터관리를 넣고 매주 관리하고 싶다」).
  이 앱이 자리 세 곳을 씁니다 — 모두 newsletter 아래에 있습니다.
    · newsletter/config      뉴스레터 설정(명단 범위·회신주소·배너)
    · newsletter/issues      회차마다의 초안 (실을 기사·법령·우리 글)
    · newsletter/recipients  받는 명단 (거래처 담당자 이름·이메일)

⚠ **지금도 잘 돕니다.** 이 칸이 없어도 이름 없는 자리 규칙($other)으로
  이미 읽고 쓰입니다. 이 붙여넣기는 **여는 일이 아니라 조이는 일**입니다 —
  넣지 않으면 이 셋이 **직원 누구나 읽고 고칠 수 있는** 상태로 남습니다.

  그것이 왜 문제인가:
    · recipients — 거래처 담당자 이름·이메일이 든 명단입니다.
    · issues     — 법인 이름으로 나갈 편지의 초안입니다. 남이 고치면 그대로 나갑니다.
    · config     — 여기의 「범위」가 제목의 (광고) 표기를 켜고 끕니다. 곧 법 판단입니다.

■ 어디에
  파이어베이스 콘솔 → Realtime Database → 규칙
  → **최상위**(data 안이 아닙니다), 이미 있는  "homepage": { … }  **바로 아래**에
    붙여넣고 [게시]

  ⚠ data 안에 넣지 마세요. 앱은 root 의 newsletter 를 봅니다 —
    data 안에 넣으면 규칙은 게시되는데 화면은 여전히 아무 보호도 못 받습니다.

⚠ 전체를 갈아끼우지 마세요.
  예전에 저장소 파일로 통째 배포했다가 사진첩·성과확인이 막힌 적이 있습니다.
  한 칸만 끼워 넣는 것이 안전합니다.

────────────────────────────────────────────────────────────────
"newsletter": {
  ".read": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
  ".write": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true"
},
────────────────────────────────────────────────────────────────

■ 뜻
  · 읽기·쓰기 모두 **총괄관리자만** — 바로 위 "homepage" 와 «같은 잣대»입니다.
  · 왜 직원에게 안 여나 — 화면이 자동으로 담을 밑감이 homepage/newsBrief 에 있고,
    그 자리도 총괄관리자만 읽습니다. 직원에게 열려면 홈페이지 관리의 문을
    함께 열어야 합니다. 여는 것이 옳다고 보시면 «두 곳을 같이» 보고 정하시면 됩니다.

■ 보내기가 막히지 않나
  안 막힙니다. 실제 발송은 서버 함수(sendBulkMail)가 하고,
  서버는 관리자 SDK 로 돌아 이 규칙을 지나지 않습니다.

■ 넣은 뒤 확인
  ① 포털 → 내외관리 → 「뉴스레터 관리」를 엽니다
  ② 「받는 명단」 칸이 열리고, 담은 것이 그대로 보이면 된 것입니다
  ③ 관리자가 아닌 직원 계정으로 열면 「총괄관리자만 쓸 수 있습니다」가 떠야 합니다
     (넣기 전에도 화면은 막지만, 자료 자체는 그때 비로소 막힙니다)

■ 넣지 않으면
  화면은 그대로 돌아갑니다. 다만 거래처 명단과 편지 초안이
  로그인한 직원 누구에게나 열려 있는 채로 남습니다.
