## 0. 프로젝트 한 줄

푸른노무법인(권형하 대표, 공인노무사)의 **약 110개 사업장(목표 500) 급여·노동법 사무 아웃소싱 자동화 시스템**.
사업장은 하던 대로 자료를 보내고(엑셀·HWP·사진·카톡), 시스템이 읽고·계산하고, 담당자 5명은 확인 클릭만.
급여에서 4대보험 신고·연차·퇴직금·지원금·서식까지 자동으로 딸려 나오는 구조.

## 1. 절대 규칙 (반드시 지킬 것)

1. **코딩 보류**: 설계는 완료 단계. 실제 코딩은 "자료 준비 + 하네스 지시문 투입"으로 시작하며, Claude Code에서 진행 예정. 이 채팅에서는 설계·문서·목업만.
2. **설계·구조 설명 시 반드시 플로우차트(다이어그램) 포함** (사용자 지정 규칙).
3. 가정 금지 — 가정은 명시, 갈리면 질문. 최소·단순 우선. 단계 계획 제시 → 승인 후 진행.
4. UI는 폰·PC 모두 **항상 단순하게**: 한 화면 주행동 1개, 버튼 위치 고정(우하단), 3색 신호(초록/주황/빨강), 전문용어 금지, 되돌리기 가능, "3초 안에 다음 행동을 안다".
5. 자동화 한계: **자동화는 "가져와 알려주기"까지, 반영·확정은 사람 승인** (급여는 법적 책임 행위).

## 2. 아키텍처 (확정)

- **하나의 앱, 하나의 창고(DB)**: 사업장 110개 = 설정 카드 110장(데이터). 앱·DB를 사업장별로 쪼개지 않음. DB 안에서 사업장별 사물함(칸막이)+보안규칙 자물쇠.
- **모듈 먼저**: 공통 부품(수당 블록·규칙 블록·계산 코어)을 먼저 만들고, 사업장은 설정 카드에 값만 채움. 비슷한 곳은 카드 복제(와이앤케이 10지점=1장).
- **흐름**: 수신함(자동태깅·D-7 미도착 독촉) → 추출(엑셀 직접/HWP/사진 AI 2단) → 입력 어댑터(양식 패밀리 6종→표준) → **표준 엔진 1개** → 검토(오버라이드 기록) → 확정(담당자 종결 기본+사업장별 승인 노무사 지정형) → 출력 어댑터(사업장 기존 양식 재생성+엑셀 사본) → 사업주 전달(회신기한 D-N) → 명세서(사업주 경유 배포, 화이트라벨, 교부대장).
- **파생 자동**: 엔진이 입사/퇴사/휴직/경계초과 감지 → 4대보험 신고(서식 자동, 서명만 사람)·연차(촉진 통보서)·퇴직정산(퇴직소득세·IRP 이연·중도정산까지)·지원금 스캐너·휴직 처리 자동 개시. **[v1.6] 일용직 매월 신고 2종 편입**: 일용직 급여 확정 시 근로내용확인신고(고용보험·매월) + 일용근로소득 지급명세서(매월) 서식 데이터 자동 생성 — 다른 신고와 동일하게 서식 자동·제출(서명)만 사람. 마감 캘린더에 제출 기한 알림 포함(누락=과태료·가산세).
- **기술**: 단일 HTML + Preact(CDN, 빌드 없음 — pu-erp 방식 그대로) + Firebase(Functions·Storage). GitHub Pages 배포. 정식 React 프로젝트는 하지 않기로 확정(필요 신호가 오면 그때 이전 — Preact라 이전 쉬움). 백엔드는 Firebase 기본, 3단계 전 Supabase 재검토(급여만 분리 옵션, 마스터 단방향 동기화). 장기: 급여로 검증 후 pu-erp 등 순차 이전 검토.
- **브랜드**: 네이비 #2E3A8C + 바이올렛 #7C6CE0.

## 3. 실측으로 확인된 사실 (설계의 뼈)

- **국민연금·건강보험 = 매월 계산이 아니라 공단 고지액 반영** (천안상용 3·4·5월 역산: 급여 출렁여도 연금 3개월 고정, 건보는 4월 정산 때만 일괄 변동). → 엔진은 "고지액 모드"(이월 기본+변동달만 갱신).
- **고지액 확보 = 토탈서비스/EDI 조회** (파일 수신 안 함 — 사용자 확인). 이월 + 변동달(7월 연금·4월 건보·입퇴사)만 조회·수기 입력. 고지서 파싱 불필요. 장기: Claude in Chrome 자동 조회.
- **사업장들은 급여 프로그램이 아니라 수기 엑셀로 계산** (사용자 확인). → 고용보험 단수처리가 절사/올림/반올림 어느 것도 전원 불일치(실측: 33명 중 절사22·올림19·반올림28). 요율도 0.9%/0.899%/면제 혼재.
- → **하네스 채점 기준 = "0원 차이" 아님**: 큰 항목(기본급·수당·과세총액) 정확 일치 + 원 단위 허용오차 + 차이 기록. 사업장 엑셀은 정답이 아니라 참고(골든 오류 실재 가능). 불일치는 엔진오류/골든오류/정책차이 3분류로 노무사 판정.
- 지방소득세 = 소득세×10% 절사 (31명 전원 일치 — 이 규칙은 확실).
- MVP 계산 치명 오류 8건 확인(10원 올림, 비과세 초과분 증발, 세액표 근사 등) — pu-erp 코어가 더 성숙(비과세 한도·통상/평균임금·일할 정확).

- **최저임금 위반 처리 확정(v1.6)**: 최저임금 미달 감지 시 **기본 = 확정 차단**(경고만으로 통과 불가 — 노무법인 책임 직결). **단 법정 예외는 사유·근거 등록 시 해제**: 수습 감액(최저임금 90%, 1년 이상 계약·단순노무 아닌 경우) / 장애인 적용제외 인가 / 감시·단속적 근로 승인 등 — 사유 + 근거(인가번호·계약서 등) 기록 + 노무사 승인. 예외 없이 미달이면 "최저임금 미달 — 재확인 필요" 표시하고 확정 불가. 이 판정은 **상식 범위 하드 가드레일(2차 그물 ②)의 한 규칙(시급 < 최저임금)으로 편입**.

- 퇴직: 평균임금 자동(직전 3개월+상여·연차 3/12, 체불계산기 모듈 이식 예정)→통상임금 비교→퇴직금. 퇴직소득세 전자동(근속공제→환산→세율→재환산), IRP 과세이연/현금 원천징수영수증. DC는 적립 확인 모드. 홈택스 모의계산 대조 검증.
- **중도퇴사자 근로소득 중도정산 확정(v1.6) = 약식 정산 자동(안2)**: 퇴직 시 근로소득 중도정산은 원천징수의무자의 법정 의무 — "연말정산 안 함"·"세무사 협업 없음"과의 공백 해소. **실무 표준인 약식 정산**: 급여 데이터만으로 계산 가능한 범위(총급여→근로소득공제→기본공제→산출세액→기납부세액 비교→환급/추징)를 퇴직월 급여에 자동 반영. 공제자료 수집 불요 → "연말정산 안 함" 방침과 양립(연말 계속근로자 정산은 계속 안 함). **원천징수영수증 자동 발급 + "추가 공제는 이듬해 5월 종합소득세 신고" 안내문 자동 첨부**(근로자 민원 예방). 퇴직 자동화 파이프라인에 편입. ※ 세부 산식(공제 구간·표준세액공제 범위)은 웹검색 재확인 체크리스트에 추가, 약식 범위 최종 확정은 노무사(대표).
- 소급 정정: **자주 발생 → 일상 기능으로 설계**(마감 후 수정은 오직 '소급 정정 절차'로만). **반영 방식 확정(v1.6) = ③ 혼용(사유 기반)**: (1) 관리자만 정정 절차 개시, (2) 정정 사유 입력(수당누락/오분류/소급인상 등), (3) 시스템이 과세소득·4대보험 변동 여부를 계산해 **방식 자동 제안** — 세금·보험 영향 없는 소액은 '다음달 합산' 제안, 과세·보험 변동 시 '재발행(해당 월 재계산 + 정정 명세서 + 원천세·보험 정정신고 안내)' 제안, (4) 담당자/노무사가 제안 수정 가능·**사람 승인 후 확정**, 사유·근거·감사로그 기록, **원본 월 데이터는 절대 보존**. "확정은 사람" 원칙 준수.
  - **엔진 데이터 모델 함의(확정)**: 급여 레코드는 월별 **불변(immutable) + 버전 체인** 구조 — 마감 시 스냅샷 잠금, 정정은 원본을 덮어쓰지 않고 correction 레코드(원본월 참조 + 방식 + 사유 + 차액 + 승인자)를 별도 생성. 월 마감·잠금(D4)은 이 스냅샷 위에 성립. 신고 데이터(원천세 집계표·4대보험)는 correction 방식이 '재발행'일 때만 해당 월 재집계 대상으로 표시.
- **4대보험 고지액 타이밍 갭 처리 확정(v1.6)**: 국민연금·건보는 공단 고지액 반영인데, 입퇴사 많은 달엔 고지가 급여 마감보다 늦게 나옴(취득/상실→공단 반영→고지 시차). 급여는 못 늦춤. → **새 규칙 불필요, 기존 두 모델 조합으로 해결**: (1) 마감 시점에 고지 없으면 **추정 가마감**(연금은 월 고정이라 대부분 전월 고지액 그대로 맞음, 신규 입사자만 첫 달 계산 모드 — 이미 세후역산 항목에 규칙 존재) + '추정' 플래그, (2) 고지 확정 후 차이나면 **소급 정정(③혼용)으로 정산**. 즉 미수신 처리 + 소급 정정과 한 데이터 모델.
  - **[v1.6] 소급 허용 기간 상한**: 무한 소급 방지 — 원천세 경정청구·4대보험 소멸시효(통상 3년)와 맞춰 소급 정정 허용 기간 상한 설정. 상한 초과 건은 자동 처리 불가·노무사 수동 판단 표시.
- 오버라이드: 모든 직접 수정 기록(누가·언제·원값→새값·사유)+셀 표시+근태 불일치 플래그+하네스 분리 채점.
- **급여 이체 확정(v1.6)**: 둘 다 지원. **기본 = 은행 업로드용 이체 파일 생성**(계좌·금액 확정 후 은행 대량이체 포맷 산출, 사람이 은행에서 실행). **옵션 = 원하는 사업장만 펌뱅킹/오픈뱅킹 연동으로 이체 실행**. ⚠️ 이체는 되돌릴 수 없는 확정 행위 — "확정은 사람" 원칙과 유일하게 부딪히는 지점이므로: (1) 연동 사업장이라도 **이체 실행 직전 사람의 최종 승인 + 2차 인증 강제**, (2) **MVP 범위는 파일 생성만 구현**, 실행 연동은 **로드맵 후순위로 분리**(은행별 계약·보안 심사·전용 인증서 필요 → 초기 개발에 넣으면 출시 지연).

**수집·OCR**
- **자료 미수신·지연·오류 실패 경로 확정(v1.6)** — 설계 전제를 "자료가 온다"에서 **"안 와도 급여는 나간다"(법정 지급일 존재)**로 전환. 마감일 도달 시 자료 상태 4분기: (1) 정상→정규 처리, (2) 지연→다채널 독촉 강화 후 재판정, (3) 일부/오류→검증 실패 반려·사유 명시 재요청, (4) 끝내 미수신→담당자 강제 개입.
  - **미수신 시 기본 처리 = 사업장별 기본값 설정**: 설정 카드에 "자료 미수신 시 기본 처리" 필드(전월값 가마감 / 담당자 수기 입력). 초기 구축 시 과거 대장 변동성 보고 **기본값 자동 초안**(변동 적으면 전월값 추천). **'지급 보류'는 기본값 아님** — 임금체불 위험 때문에 담당자 수동 선택 옵션(체불 경고 표시).
  - **공통 원칙**: 가마감·추정값은 반드시 **'추정' 플래그** + 자료 도착 시 **소급 정정 절차(③혼용)로 자동 연결**(원본월 보존). 즉 미수신 처리와 소급 정정이 한 데이터 모델로 연결됨.
- 수신 메일 = 법인 도메인 신설(예: 자료@fairrunlabor.com, 서버 웹훅). 다음메일은 자동전달 유입구로 존속(사업장 재안내 불필요). 발신은 기존 payroll@fairrunlabor.com(Resend 인증 완료).
- 카톡·문자: 자동 수집 불가/금지 → 직원 "공유하기→앱" 1탭 업로드(지금) + 카톡 채널·문자 가상번호(중기 유도, 강제 없음).
- OCR = LLM 비전: Gemini Flash 1차(장당 1~5원) + Claude 재판독(저확신만). 텍스트 PDF는 직접 추출. 3중 방어(행합계 검산→2모델→사람). 예산 월 3만 + 백필 일회성 10만. 사진 주민번호는 전송 전 자동 마스킹.
- **2차 그물 = '조용한 오염' 방어 확정(v1.6)** — 기존 3중 방어는 "숫자가 서로 맞나"(파싱 실패)를 잡고, 2차 그물은 "이 값이 애초에 말이 되나"(그럴듯한 오독)를 잡음. 성격이 달라 둘 다 필요. **엔진 핵심 안전장치로 처음부터 탑재**:
  - **① 전월 대비 급변 감지**: 직원별 항목값이 전월 대비 ±X% 초과 시 사람 확인 플래그. 정당한 급변(신규입사·상여달·소급인상)은 사유 달면 통과. 임계값은 튜닝 가능(초기 넉넉히→파일럿 오탐률 보고 조정).
  - **② 상식 범위 체크(하드 가드레일)**: 물리적 불가능·법정 한도 초과 차단 — 월 연장근로 한도 초과, 근무일수 > 그 달 일수, 시급 < 최저임금, 공제액 > 지급액 등. 절대 규칙이라 오탐 적음 → 강하게 적용.
  - **③ 교차 검증**: 서류 간 대조 — 근태 근무일수 ↔ 대장 지급일수, 4대보험 대상인데 공제 0 등.
  - 세 그물 모두 "차단"이 아니라 **사람 앞으로 끌어올리기**("확정은 사람" 준수). 오탐 피로 방지를 위해 급변 임계값은 파일럿에서 조정 전제.

**운영 (2차 검토 8영역 결론)**
- 초기 구축: 과거 대장에서 **설정 카드 자동 초안**→확인 10~20분/곳→복제, 물결식(파일럿→패밀리 대표→확장), 신·구 병행 계산 일치 시 전환. 총 ≈16시간(5명 분산).
- 실패 대응: 원본 절대 보존·정정본 재발행·확정본 엑셀 사본 상시(시스템 죽어도 급여 나감)·D-2~3 여유 확정·휴지통 30일·확정 취소. **[v1.6 추가] 복구 리허설**: "확정본 엑셀 사본만으로 급여 나감"은 훈련 안 하면 위기 때 안 돌아감 → 파일럿 중 1회 "시스템 없다 치고 엑셀 사본만으로 급여 지급" 훈련 필수(파일럿 계획에 편입).
- 법·제도(노무사 확정 영역): 명세서 법정항목 체크리스트 내장, 전자교부 요건, **연차촉진 서면 요건**(전자+열람기록/서면 병행 — 조합은 대표 확정), 위수탁 계약서·처리방침, 신고 위임.
- 사업·운영: 파일럿=단순·협조 2~3곳(제스트·피앤피·공주 등 근태↔대장 짝 맞는 곳 후보). 변화관리=병행+챔피언 1명+대표 주도. 기간은 하네스 후 추정(하네스 수일~2주/엔진 2~4주/서버 3~6주 감).
- **숙련자 이탈 방지 전략 확정(v1.6)** — 최대 실패 원인(사람 문제). 악순환 구조: 초기엔 시스템이 암묵지를 몰라 숙련자가 더 정확 → "내가 하는 게 빠름" → 시스템 안 씀 → 데이터·피드백 안 쌓임 → 영영 못 따라잡음. **끊는 3개입 + 강제**:
  - **① 병행 기간 시스템 우선 확인 의무(강제)**: 손값 입력 전 시스템 결과를 먼저 확인. 단 프레이밍은 "믿어라"가 아니라 **"감독하라"**(숙련자=검수자, 결과 보고 틀리면 고침=학습 데이터). **종료 조건 명시**: 그 사업장 신·구 값 N개월 연속 일치 시 강제 해제(끝이 보이게).
  - **② 암묵지 선주입**: 직원 스터디(16영역 자료 완료) + 암묵지 관리(설정 카드 승격/사업장 노트)를 **도입 전** 시스템 초기 설정에 미리 반영.
  - **③ 불일치=학습 기회**: 병행 중 손값≠시스템값이면 오버라이드 기록 + 승격 루프(반복→규칙 제안, 분기별 대표 리뷰)로 암묵지를 시스템 규칙으로 승격. 병행 기간 = 격차 해소의 시간.
- 테스트: 계산=하네스(배포 관문), 안전 로직 5개만 자동 테스트(권한격리·마스킹·오버라이드 기록·확정잠금·발송대상), 화면=파일럿 실사용, 회귀=하네스 전수 재채점.
- 기준값: 연도별 이력 구조(값은 코드에 안 박음). 갱신 캘린더 내장(1월 최저임금·7월 연금·4월 건보·세액표). **자동 수급**(공공데이터 API: 최저임금·요율·공휴일 / 파일 파싱: 간이세액표 / 공고 감지+AI: 지원금) → 변경 알림 → **노무사 승인 게이트** → 반영. 법 해석 필요한 것(퇴직세·휴가휴직)은 사람 확인. 완전 무인 반영 금지.
