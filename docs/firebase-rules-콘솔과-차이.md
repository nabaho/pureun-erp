# Firebase 규칙 — 콘솔과 저장소 파일의 차이 (2026-08-09 실측)

**규칙은 코드 배포로 적용되지 않는다.** Firebase 콘솔 [규칙] 탭에 직접 붙여넣어야 한다.
그래서 `docs/firebase-rules-현재적용본.json` 은 「이렇게 되어야 한다」는 기록일 뿐,
**실제로 돌아가는 것은 콘솔**이다. 둘은 어긋날 수 있고, 실제로 어긋나 있었다.

이 문서는 **콘솔 원문을 받아 한 칸씩 맞춰 본 결과**다. 짐작이 아니다.

---

## 최상위 39칸 중 38칸은 같았다

`docs/firebase-rules-현재적용본.json` 과 콘솔이 글자까지 같았다. 아래 두 가지만 달랐다.

## ① `pucards_private` — 콘솔에 **없었다** (2026-08-09 발견)

명함첩 「🔒 개인 폴더 열기」가 이 오류로 막혔다.

```
permission_denied at /pucards_private/<uid>/lock
```

최상위에는 catch-all(`$other`)이 없다 — 규칙에 적히지 않은 칸은 그대로 막힌다.
개인 창고를 만든 커밋(e3de693)이 저장소 파일만 고치고 콘솔 게시를 안 한 것이다.

넣어야 할 것:

```json
"pucards_private": {
  "$uid": {
    ".read": "auth != null && auth.uid === $uid",
    ".write": "auth != null && auth.uid === $uid"
  }
}
```

## ② `puphotos` 사진 공유 — 콘솔에 없었다 (대표 지시로 ①과 함께 넣음)

저장소 파일에는 있고 콘솔에는 없던 칸:

- `puphotos/sharedTo` (와 그 아래 `$uid`, `$pid`)
- `puphotos/u/$uid/items/$year/$id/.read` (shareWith 조건)
- `puphotos/u/$uid/blobs/$year/$id/.read`
- `puphotos/u/$uid/thumbs/$year/$id/.read`

사진첩 「같이 볼 사람 고르기」를 **받는 쪽이 실제로 읽게** 해 주는 규칙이다.
없으면 공유해도 받는 사람 화면에서 사진이 안 열린다.

허용 범위는 **사진 한 장씩**이다. 남의 사진첩이 통째로 열리는 것이 아니라,
그 사진에 `shareWith/{내 uid}` 가 적혀 있을 때만 그 한 장을 읽는다.
앱이 쓰는 이름과 맞는 것도 확인했다 —
`items/{해}/{id}/shareWith/{받는사람}` · `sharedTo/{받는사람}/{id}` = {owner, year, at}.

---

## 게시하면 콘솔 = 저장소 파일

①②를 넣으면 `docs/firebase-rules-현재적용본.json` 과 **글자까지 같아진다**(확인함).
어긋나 있던 것은 이 둘뿐이었다.

---

## ③ `puphotos/sharedTo` — 총괄관리자가 «남의» 사진을 열어 줄 수 없었다 (2026-08-29)

대표 보고: 「권형하가 공유했는데 전혀 공유가 안되었다」.

공유는 **두 자리에 한 묶음으로** 적힌다.

| 자리 | 무슨 뜻 | 관리자가 쓸 수 있었나 |
|---|---|---|
| `puphotos/u/{주인}/items/{해}/{id}/shareWith/{받는사람}` | 규칙이 그 한 장을 열어 준다 | **된다** (`u/$uid` 쓰기에 isAdmin 이 있다) |
| `puphotos/sharedTo/{받는사람}/{id}` | 받는 사람이 목록을 훑을 길 | **안 됐다** (「사진 주인만」) |

실시간DB 의 묶음 쓰기는 **하나라도 막히면 통째로 취소**된다. 그래서 총괄관리자가
남이 올린 사진을 열어 주면 **아무것도 안 써지고**, 화면에는
「내가 올린 사진에만 권한을 줄 수 있습니다」가 떴다 — 관리자에게는 틀린 말이다.

이 때문에 2026-08-28 에 만든 **「업무 담당자에게 저절로 열어 주기」가 남이 올린
계약서·서류 사진에서는 한 번도 동작한 적이 없다.** 계약서 사진은 대개 남이 올린다.

고친 것 — 사진 자리와 **같은 사람**에게 열어 준다:

```
"sharedTo": { "$uid": { "$pid": { ".write":
  "… && (root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true
        || (newData.exists() && newData.child('owner').val() === auth.uid)
        || (!newData.exists() && (data.child('owner').val() === auth.uid || auth.uid === $uid)))" } } }
```

⚠ 이 자리는 **목록(색인)일 뿐 권한이 아니다.** 읽기를 여는 것은 사진 옆 `shareWith`
하나이고 그것은 그대로다. 그래서 여기에 잘못 적혀도 남의 사진이 열리지는 않는다 —
안 열리는 줄 하나가 놓일 뿐이다.

**붙여넣을 파일**: `docs/firebase-rules-현재적용본+분류이름표(붙여넣기용).json`
(전체 규칙이다. 콘솔 → Realtime Database → 규칙 에 통째로 붙여넣고 게시한다.)

## ④ 직원끼리도 공유 (대표 지시 2026-08-29)

「직원끼리도 공유하게 해라」.

받는 것은 처음부터 됐다. **보내는 것이 막혀 있었다** — 사람 명단 `puphotos/owners` 를
총괄관리자만 읽어서, 직원 화면에는 고를 사람이 아무도 안 떴다. 「👥 공유」를 눌러도
「고를 사람이 없습니다」뿐 — 단추는 있는데 아무 일도 안 일어나는 자리였다.

```
"owners": { ".read": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)" }
```

**연 것은 이름표뿐이다.** 이 칸에 담긴 것은 `{name, lastAt}` — 이름과 마지막 올린 때다.
사진은 여기 없다(그것이 이 칸을 사진과 갈라 둔 까닭이다).

**안 연 것 — 이쪽이 더 중요하다.** 남의 사진은 그대로 잠겨 있다.
`puphotos/u/{주인}` 은 주인과 총괄관리자만 읽고, 직원 고르개에는 사람 줄이 없으며,
「전체 근로자」로 훑는 셋(`listYearAll`·`listYearsAll`·`migrateToStorage`)은 저마다
제 `isAdmin` 을 그대로 들고 있다. `tests/photos-staff-share.test.js` 가 그 경계를 못박는다.

## ⑤ ★ 저장소 파일을 그대로 붙여넣었으면 «네 칸이 지워질» 뻔했다 (2026-08-29)

대표께 콘솔 원문을 받아 대조해 보니, 저장소의 붙여넣기용 파일에는
**콘솔에 있는 네 칸이 없었다.**

| 빠져 있던 칸 | 지워졌으면 |
|---|---|
| `rules_mgmt/index` | 취업규칙 이력 **색인이 안 읽힌다**(이력을 이 색인으로 읽는다) |
| `scal_erpConsHold` | 일정관리 — 이알피 상담 보류 |
| `scal_serverBackups` | 일정관리 서버 백업 |
| `scal_serverBackupsIndex` | 일정관리 서버 백업 색인 |

실시간DB 규칙은 **통째로 갈아 끼우는 것**이라, 파일에 없는 칸은 «사라진다».
「저장소 파일을 통째로 붙여넣지 말 것」이라고 이 문서 아래에 이미 적혀 있었는데,
③ 를 쓰면서 내가 그 파일을 그대로 붙여넣으시라고 안내했다 — **틀린 안내였다.**

그래서 지금부터 붙여넣기용 파일은 **콘솔 원문에서 만든다**:

1. 콘솔 [규칙] 탭 내용을 받아 `docs/firebase-rules-콘솔원문-YYYY-MM-DD.json` 으로 저장
2. 거기서 **필요한 덩어리만** 고쳐 붙여넣기용 파일을 만든다
3. `tests/photos-staff-share.test.js` 가 자동으로 본다 —
   **콘솔에 있던 칸이 하나라도 빠지면** 거기서 큰 소리가 나고,
   **일부러 고친 곳 말고 다른 데가 바뀌어도** 걸린다

---

## 다음에 규칙을 만질 때

1. **저장소 파일을 통째로 붙여넣지 말 것.** 콘솔이 더 최신인 칸이 있을 수 있다.
2. 먼저 콘솔 [규칙] 탭 내용을 받아, 한 칸씩 맞춰 보고 **필요한 덩어리만** 더한다.
3. 규칙 안에는 주석을 쓸 수 없다 — 설명 한 줄이 게시를 막은 적이 있다(4ceb241).
