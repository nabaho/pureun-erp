파이어베이스 규칙 — 사진 변경 이력 칸 한 개만 넣기 (2026-08-29)
════════════════════════════════════════════════════════════════

■ 왜 넣나
  사진 변경 이력(누가 언제 무슨 사진을 지웠나)을 이 PC 안이 아니라
  **모두가 보는 공용 자리**(scal_photoLog)에 쌓기로 했습니다(대표 결정).
  그런데 규칙에 그 칸이 없으면 서버가 거절해 **조용히 안 쌓입니다.**
  (앱은 그때 이 PC 에 대신 쌓아 두니 잃지는 않지만, 다른 사람에게는 안 보입니다.)

■ 어디에
  파이어베이스 콘솔 → Realtime Database → 규칙
  → 이미 있는  "scal_roundlog": { … }  **바로 아래**에 붙여넣고 [게시]

■ 그 밖에 바뀌는 것
  없습니다. 콘솔 원문(docs/firebase-rules-콘솔원문-2026-08-29.json)과
  대조했습니다 — 새로 생기는 칸 1개, 내용이 달라지는 칸 0개, 사라지는 칸 0개.

⚠ 전체를 갈아끼우지 마세요.
  예전에 저장소 파일로 통째 배포했다가 사진첩·성과확인이 막힌 적이 있습니다.
  한 칸만 끼워 넣는 것이 안전합니다.

────────────────────────────────────────────────────────────────
"scal_photoLog": {
  ".read": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)",
  ".write": "(auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)) && (newData.exists() || root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true)",
  "$k": {
    ".write": "(auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)) && (newData.exists() || root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true)",
    "$k2": {
      ".write": "auth != null && (auth.token.firebase.sign_in_provider === 'password' || auth.token.passkey === true)"
    }
  }
},
────────────────────────────────────────────────────────────────

■ 뜻
  · 읽기 — 로그인한 직원 누구나 (이력은 함께 봐야 뜻이 있습니다)
  · 쓰기 — 로그인한 직원은 **남길 수** 있고, **지우기는 총괄관리자만**
    (회차 변경 이력 scal_roundlog 과 똑같은 규칙입니다)

■ 넣은 뒤 확인
  1. 사진을 하나 지우거나 바꿔 봅니다
  2. 머리줄 ⋯ → 🕘 사진 변경 이력 에 그 줄이 뜨는지
  3. **다른 PC 에서도** 같은 줄이 보이는지 (이것이 이번에 고친 핵심입니다)

  안 보이면 콘솔 규칙 화면에서 scal_photoLog 철자를 확인해 주세요.
