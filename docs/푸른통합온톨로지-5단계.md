# 푸른통합 온톨로지 5단계 — 검증센터

## 목적

통합 관계 진단에서 발견한 문제를 담당자가 한 건씩 안전하게 검토할 수 있게 한다.
온톨로지는 원본을 수정하지 않으며, 검토가 필요한 위치와 권장 확인 절차만 안내한다.

## 분류

- 식별자·중복: ID 없음, 중복 ID, 동일 업체명, 중복 사업자번호
- 업체 연결: 끊어진 업체, 업체 ID 미입력, 미확정 업체, 이름 기반 추정 관계
- 담당자 연결: 존재하지 않는 담당자 사번
- 원본·권한: 끊어진 원본, 읽기 제한, 시작·도착 개체가 없는 관계

각 항목에는 위험도, 원본 프로그램, 레코드 ID, 후보 ID, 권장 확인 절차가 표시된다.

## 검토 절차

1. 푸른ERP의 `환경설정 → 데이터·로그 → 온톨로지`에서 관계 전수진단을 실행한다.
2. 검증센터에서 유형·위험도·상태 또는 검색어로 항목을 좁힌다.
3. `원본 프로그램 열기`로 정본을 확인한다.
4. 원본 프로그램의 권한과 동시편집 보호 아래에서 필요한 내용을 한 건씩 수정한다.
5. 화면의 `검토 완료` 또는 `보류`로 현재 세션의 진행상태를 표시한다.
6. 원본 수정 후 관계 전수진단을 다시 실행하여 문제가 실제로 사라졌는지 확인한다.

## 안전 원칙

- 검증센터는 Firebase 쓰기·수정·삭제 명령을 호출하지 않는다.
- `검토 완료`와 `보류`는 현재 화면 메모이며 서버에 저장되지 않는다.
- 후보 업체 ID와 이름 기반 관계를 자동 확정하지 않는다.
- 중복 레코드를 자동 병합하거나 삭제하지 않는다.
- 검토목록 파일은 진단과 현재 검토상태를 내려받는 용도이며 원본으로 역반영되지 않는다.
- 민감 원문, 사진 본체, 메일 본문, 급여 직원표는 통합 진단에서 읽지 않는다.

## 완료 기준

- 진단 오류와 추정·끊어진 관계가 네 범주로 분류된다.
- 검색, 유형, 위험도, 검토상태 필터가 동작한다.
- 항목별 원본 프로그램 이동, 검토 완료, 보류가 가능하다.
- 검증목록을 JSON으로 내려받을 수 있다.
- 모든 동작이 `readOnly:true`, `sourceMutation:'never'` 원칙을 지킨다.
