# 검사는 「모양」이 아니라 「지키려는 것」을 적는다

2026-08-17 전수 점검. 검사 386개·4,349건을 훑고 정리했다.

## 왜 이 문서가 있나

한 주 사이에 **검사 8건이 «옳은 고침»을 막았다.** 코드는 제대로 고쳐졌는데,
검사가 옛 코드의 *생김새*를 붙잡고 있어서 깨진 것이다.

- 「부르는 자리가 세 곳」이라고 **개수**를 적어 둔 검사 — 네 번째를 제대로 붙여도 막는다
- 「`$('viewerInfo').textContent = it …`」라고 **표현식 통째**를 붙잡은 검사 — 그 줄을 함수로 옮기면 깨진다
- 「ESC 를 듣는 곳은 하나」라며 **처리기 개수**를 센 검사 — ESC 를 아예 안 건드리는 처리기까지 막는다

검사가 이렇게 되면 두 가지를 잃는다. **하나**, 고칠 때마다 검사부터 손봐야 해서
사람이 검사를 「걸리적거리는 것」으로 여기게 된다. **둘**, 그러다 보면 뜻을 안 보고
숫자만 맞춰 통과시키게 되어, 정작 진짜 사고를 놓친다.

## 규칙

### ① 개수를 적지 말고 «성질»을 적는다

```js
// ✗ 못 박기 — 네 번째를 제대로 붙여도 막는다
assert.equal((app.match(/fetchT\(getNasBase\(\)/g) || []).length, 5, 'NAS 다섯 곳');

// ✓ 뜻 — 감싸지 않은 부름이 하나라도 남으면 걸린다
left.forEach(t => assert.match(t, /return fetch\(url, (?:opts|o)\)/));
```

개수는 «더 나쁜» 쪽으로도 샌다. 창구가 셋이 되고 그중 하나가 규칙을 빠뜨려도,
**다른 곳이 두 번 나오면 통과한다.** 「둘이다」가 아니라 「자리마다 빠짐없이」를 적는다.

```js
// ✗ 두 곳이라고만 셌다
t('본인 확인을 거친다', (SRV.match(/requireUserVerification: true/g) || []).length, 2);

// ✓ 서명을 따지는 자리를 모두 찾아, 하나하나 본다
const 자리 = 서명자리들();
t('본인 확인을 거친다', 자리.every(s => /requireUserVerification: true/.test(s)), true);
```

**개수가 뜻인 경우도 있다.** 「쓰는 곳이 딱 하나」(단일 창구)나 「둘을 넘지 않는다」
(권한창이 두 번 뜨면 안 된다)는 진짜 규칙이다. 그때는 `=== 1` · `<= 2` 로 **그 뜻 그대로** 적는다.

### ② 자리가 아니라 «이름»으로 찾는다

```js
// ✗ 그 줄을 함수로 옮기면 깨진다
const i = app.indexOf("$('viewerInfo').textContent");

// ✓ 함수를 이름으로 찾는다
const fn = cutFn(app, 'function renderViewerTitle(');
```

### ③ 함수는 «통째로» 뽑는다 — `tests/cut-fn.js`

두 가지 뽑기가 조용히 어긋난다.

| 방식 | 어긋나는 때 | 어떻게 어긋나나 |
|---|---|---|
| `function X\([\s\S]*?\n\}` | 함수 안에 **열 0 짜리 `}`** 가 생기면 | 뒤를 통째로 못 본다. 「없어야 한다」는 **조용히 통과** |
| `src.slice(at, at + 900)` | 함수가 길어지면 | 창이 못 닿는다. 창 숫자를 키우며 쫓아가게 된다 |

```js
const { cutFn } = require('./cut-fn');
const fn = cutFn(src, 'function openViewer(');
```

⚠ **파수꾼이 있다** — `tests/test-cut-truncation.test.js` 가 「지금 실제로 잘리고 있는가」를
본다. 방식을 금지하지 않는다(그것도 못 박기다). **못 닿는 순간에만** 운다.
2026-08-17 기준 302곳 중 잘리는 것 0건.

### ④ 글자를 찾지 말고 «돌려» 본다

가장 튼튼하다. 조건을 죽여도 낱말은 그대로 남아 글자 찾기로는 안 잡힌다.

```js
// ✗ 조건만 죽여도(`m.__ownerName ?` → `false ?`) 낱말이 남아 통과한다
assert.match(code, /__ownerName/);

// ✓ 뽑아서 실제로 돌리고, 결과에 찍히는지 본다
const out = whenBoxOf(src)({ meta: { __ownerName: '권형하' } });
assert.match(out, /권형하/);
```

실제로 이 저장소에서 **주석에 적힌 낱말**·**죽은 문자열**·**딴 구역의 같은 낱말**에
검사가 네 번 속았다.

## 검사를 고칠 때 반드시 할 것

검사를 느슨하게 고치면 **진짜 사고까지 놓칠 수 있다.** 그래서 고친 뒤에는
일부러 고장 내어 **여전히 잡는지** 확인한다.

```
① 검사를 뜻 중심으로 고친다
② 원본에 진짜 사고를 심는다 (감싸지 않은 부름 · 규칙 빠뜨린 창구 · 안 지우는 갈래)
③ 검사가 우는지 본다  ← 안 울면 ①이 너무 느슨해진 것이다
④ 원본을 되돌린다
```

## 되풀이되는 함정 (겪은 것들)

- 검사가 **주석**을 읽고 통과했다 — 주석을 걷어내고 봐야 한다
- 검사가 **거짓 갈래의 죽은 문자열**을 읽고 통과했다 — 돌려 봐야 한다
- `.replace()` 는 **첫 하나만** 바꾼다 — 고장을 심을 때 「다 바꿨겠지」로 읽으면 뮤테이션이 헛돈다
- CRLF 파일에서 `\n` 무늬가 안 맞는다 — 심기 전에 줄바꿈을 맞춘다
- 팔레트 밖 색은 `color-palette.test.js` 가 배포를 막는다 (승인 27색 안에서 고를 것) — 이건 **옳은 못 박기**다
