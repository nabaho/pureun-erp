 창고(Storage) 규칙 — 「메일에 붙일 내 PC 파일」 한 칸만 더 넣기
 2026-08-31 · 대표 물음 「용량이 너무 작은 것 아닌가」

 ▶ 넣는 곳: 콘솔 → Storage → 창고 이름 옆 ▾ → pureun-erp-photos → 규칙 → 게시
   (명함첩이 쓰는 창고입니다. 다른 창고에는 넣지 않으셔도 됩니다.)

 ▶ 무엇이 바뀌나
   지금은 편지에 붙일 파일을 «글자로 바꿔» 서버로 실어 보냅니다. 그런데 보내는
   함수가 요청 하나에 10MB 까지만 받고, 글자로 바꾸면 크기가 1.33배로 붑니다 —
   그래서 8MB 가 한도였습니다(사실 그 8MB 도 실려 갈 때 10.7MB 라 아슬아슬했습니다).
   이 칸을 넣으시면 파일이 «창고를 거쳐» 가므로 그 한도와 무관해지고,
   다음메일이 주는 18MB 를 다 쓸 수 있습니다.

 ▶ 안 넣으셔도 지금과 같습니다
   앱이 «예전 길»로 되돌아갑니다 — 6MB 이하는 그대로 붙고, 큰 파일만
   「창고 규칙 한 칸이 올라가야 합니다」라고 알려 줍니다. 아무것도 안 깨집니다.

 ⚠ 아래는 «한 칸»입니다. 지금 쓰시는 규칙에서 무엇도 지우지 마시고,
   다른 match 블록들 사이에 그대로 끼워 넣으신 뒤 [게시]를 누르시면 됩니다.
   (signedIn() 은 이미 아래쪽에 있는 그 함수를 그대로 씁니다.)
═══════════════════════════════════════════════════════════════════

    // ── 메일에 붙일 「💻 내 PC 파일」 임시 자리 (2026-08-31) ──
    //    브라우저가 여기에 올리고, 서버가 꺼내 붙인 뒤 «지웁니다».
    //    ⚠ 사람마다 제 자리만 — 서버도 「보낸 사람 제 자리인가」를 한 번 더 봅니다
    //      (mail-deliver.js 의 mailOutPathOk). 두 곳이 함께 막습니다.
    //    ⚠ 사진만 받는 검사(okImage)를 걸지 않습니다 — PPT·한글·PDF 를 붙입니다.
    //      엉뚱한 종류는 앱이 올리기 전에 막습니다.
    //    ⚠ 20MB 는 앱의 18MB 보다 조금 넉넉하게 둔 것입니다.
    match /pucards/mailout/{uid}/{file} {
      allow read:   if signedIn() && request.auth.uid == uid;
      allow write:  if signedIn() && request.auth.uid == uid
                    && request.resource != null
                    && request.resource.size < 20 * 1024 * 1024;
      allow delete: if signedIn() && request.auth.uid == uid;
    }
