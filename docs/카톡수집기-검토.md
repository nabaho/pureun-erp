# 카톡 대화 수집기(kakao-auto) 검토 — 심어도 되나 · 필요한가

대표 지시 2026-09-03 「검토 및 시스템에 심어도 되는지 확인, 필요한지 확인」
검토 대상: `kakaoautomain.zip` = AidanKR/kakao-auto (Apache-2.0, 파이썬 4,031줄 + 배치 14개)

---

## 한 줄 결론

**푸른ERP에는 «심을 수 없다»** — 심을 자리가 아예 없다.
**대표 PC에 깔아 쓰는 것도 지금은 권하지 않는다** — 코드가 나빠서가 아니라, 지는 위험이
얻는 것보다 크다. 얻는 것 대부분은 사진첩·업무관리에 «이미 있다».

---

## ① 코드 자체는 악성이 아니다 (이건 분명히 해 둔다)

훑어보고 확인한 것:

| 본 것 | 결과 |
|---|---|
| 몰래 밖으로 보내는 곳 | **없다.** 나가는 길은 둘뿐이고 둘 다 설정이 비면 안 나간다 |
| ㉠ `alert_webhook_url` | 기본값 `""`. 켜도 나가는 것은 «상태 한 줄»뿐(대화 내용 아님) |
| ㉡ `ai_provider` | 기본값 `""`(규칙기반만). 켜면 대화 원문이 OpenAI/Anthropic 으로 나간다 |
| 배치·설치 파일의 몰래 내려받기 | **없다** (파이썬 공식 내려받기 페이지 여는 것 하나뿐) |
| `eval`·`exec`·난독화 | **없다** |
| 암호화(`cryptobox.py`) | **진짜다** — PBKDF2-HMAC-SHA256 200,000회 + 16바이트 난수 소금 + Fernet(AES) |
| 라이선스 | Apache-2.0, NOTICE 있음. 만든 이가 위험을 README 에 먼저 적어 두었다 |

⚠ 다만 **`kakao.db` 본체는 평문 SQLite** 다. 암호화는 «백업 파일»에만 걸린다.

## ② 「심는다」가 불가능한 까닭 — 종류가 다른 물건이다

| | 푸른ERP | 이 도구 |
|---|---|---|
| 무엇 | 브라우저에서 도는 정적 화면 + 파이어베이스 | **윈도우 데스크톱 프로그램** |
| 어디서 | GitHub Pages (서버 실행 없음) | 대표 PC 안에서 카톡 창을 «키보드로 조종» |
| 언어 | HTML·JS | 파이썬 + .bat + .exe |

배포 게이트(`deploy-pages.yml`)의 남길 목록은 `js css vendor *.html manifest.json …` 이다 —
`.py`·`.bat`·`.exe` 는 올려도 **그 자리에서 걷힌다.** 억지로 넣을 자리를 만드는 것은
저장소를 「배포되는 화면」과 「배포 안 되는 도구」로 갈라 둔 규칙을 무너뜨리는 일이다.

이을 수 있는 길은 하나뿐이다 — **대표 PC 에서 돌리고, 나온 CSV 를 ERP 가 읽는 것.**
그것은 「심는다」가 아니라 「자료를 받는다」이고, 아래 ③ 이 먼저 정리돼야 한다.

## ③ 진짜 걸리는 것 셋 — 코드가 아니라 «법과 업무»다

### ㉮ 카카오 이용약관 위반 (만든 이가 먼저 적어 두었다)
> "Automating or scraping the KakaoTalk client **violates KakaoTalk's Terms of Service**.
>  Your account **may be restricted, suspended, or terminated**."

**업무 카톡 계정이 정지되면 노무법인 업무가 멈춘다.** 의뢰인 연락이 그 계정으로 온다.
대화 기록을 지키자고 대화 통로를 잃는 것이라, 이 하나만으로도 셈이 안 맞는다.

### ㉯ 개인정보보호법 — ★ 이것이 가장 무겁다
푸른노무법인은 **이미 개인정보처리자**다. 이 도구가 쌓는 것은:

- 근로자·의뢰인의 대화 **원문 전체**(임금·징계·질병·가정사가 섞여 있다)
- **사진·파일 전부** (`media_backup.py`) — 카톡으로 오간 **신분증·통장 사본이 그대로 복사된다**
  (20KB 미만만 걸러 내므로 신분증 사진은 «전부 통과»한다)
- 무기한. 보유기간도 파기 절차도 도구에 없다

그런데 이 저장소는 정반대 방향으로 여러 겹을 쌓아 왔다 —
사진첩의 **판독 울타리**(`read-fence-apps`), **주민번호 지우개**(`rrnScrub`),
**민감 갈래**(`SENSITIVE_KINDS`), **보유기준 알림**(`retNote`), 온톨로지의
**「민감 본문을 안 읽는다」** 규칙. 카톡 방 전체를 밤마다 긁어 평문 SQLite 에 쌓는 것은
그 노력과 **정면으로 어긋난다.** 한쪽 문을 잠그고 옆에 큰 문을 여는 셈이다.

### ㉰ 매일 밤 «모든 방이 읽음» 처리된다
`collector.py` 머리말: 「⚠ 방을 열면 '읽음' 처리됨」.
**「아직 답 안 한 의뢰인」 신호를 매일 잃는다.** 도구가 대시보드로 대신하려 하지만,
그것은 카톡 앞에서 잃은 것을 다른 화면에서 되찾으라는 말이다.

부수로: 도는 동안 **그 PC 를 만지면 안 된다**(마우스·키보드를 뺏는다) → **전용 PC 가 필요하다.**

## ④ 필요한가 — 얻는 것 넷 중 셋은 이미 있다

| 이 도구가 주는 것 | 푸른ERP 에 있는가 |
|---|---|
| 카톡 사진이 **만료되기 전에 보관** | **있다** — 사진첩. 게다가 판독·주민번호 가리기·보유기준까지 붙어 있다 |
| 누구에게 **답을 안 했는지** | **있다** — 업무관리(담당자별 진행업무) |
| 방별 활동·조용해진 곳 | 부분적으로 있다 — 기업정보함·업무관리 |
| **대화 원문 전체를 검색** | **없다** ← 이것 하나가 진짜 새것이다 |

**즉 판단할 것은 하나다** — 「대화 원문을 통째로 검색하는 것」 하나를 위해
㉮약관·㉯개인정보·㉰읽음처리 셋을 감수할 것인가.

검토자 의견: **아니다.** 노무 상담 대화는 성격상 ㉯의 위험이 가장 큰 자료다.
찾아야 할 대화가 있으면 카톡 안에서 찾는 것이 느리지만 위험이 없고,
남겨야 할 것은 «그때 사진첩·업무관리에 올리는 것»이 이미 되는 길이다.

## ⑤ 그래도 쓰겠다면 — 최소 조건

대표께서 필요하다고 판단하시면, 아래를 **모두** 갖춘 뒤에만.

1. **전용 PC** — 업무 PC 와 분리(도는 동안 조작 불가)
2. **`ai_provider` 는 비워 두거나 `ollama`** — openai/anthropic 을 켜면 상담 원문이 밖으로 나간다
3. **`nightly_media: false`** — 신분증·통장 사본이 딸려 온다
4. **`backup_passphrase` 설정 + `copy_db: false`** — 공유폴더에 평문 DB 를 두지 않는다
5. **`share_dir` 은 클라우드가 아닌 사내 잠긴 폴더**
6. **보유기간·파기 절차를 문서로 정하고 개인정보 처리방침에 반영** — 위탁이 아니라 «직접 처리»다
7. 나온 CSV 를 ERP 로 옮길 때는 **주민번호·계좌 걸러개를 반드시 거친다**(이미 있는 `rrnScrub` 계열)

⚠ 1~7 을 다 해도 ㉮(약관)은 남는다. 그것은 기술로 못 없앤다.
