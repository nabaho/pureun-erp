# 매달 성과급 확인 기능 — 계획

작성 2026-08-01 · 상태 **계획 확정, 구현 전**

매달 초 각자 자기 성과급 내역을 직접 확인하고, 누가 언제 확인했는지 기록으로 남긴다.
폰에서도 된다.

---

## 왜 '발행' 단계가 필요한가

성과급 원본은 `finance_income` 에 있고, 각 입금 건 안에
`perfShares[] = {sid, name, role, pct, amount}` 로 분배가 박혀 있다.

이 노드의 규칙은 **재무 권한자만 읽기/쓰기**다.

```
"finance_income": {
  ".read":  "root.child('uid_roles').child(auth.uid).child('fin').val() == true",
  ".write": "root.child('uid_roles').child(auth.uid).child('fin').val() == true"
}
```

→ **직원 본인은 자기 성과급을 못 읽는다.** 규칙을 풀면 남의 것까지 다 보이므로 풀면 안 된다.

그래서 재무 권한자가 그 달치를 **사람별로 추려 확인용 사본을 발행**하고,
직원은 사본만 읽는다. 원본은 안 건드린다.
덤으로 "확인 대상이 확정된 시점"이 분명해진다.

---

## 정해진 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 안내 강도 | 하루 첫 로그인 팝업 1회 + 상단 빨간 띠 상시 | 매번 막으면 월초에 일을 못 한다 |
| 확인 화면 | **업무관리(work.html) 안에 '성과급' 메뉴 추가** | 아래 "확인 화면을 어디에 둘까" 참고 |
| 대상 월 기준 | **입금 확정된 달** | 지금 성과관리가 쓰는 기준과 같다. 급여 지급월 기준이면 한 달 늦게 확인하게 된다 |

발행·현황판은 pu-erp 성과관리 안에 둔다(대표가 PC 에서 하는 일).

### 확인 화면을 어디에 둘까 — 한 번 바뀐 결정

처음에는 별도 파일 `pu-perf.html` 로 잡았다. 이유는 **pu-erp 가 3.6MB** 라 폰에서
체크 몇 개 하려고 받을 수 없다는 것이었다.

그런데 확인 화면을 **업무관리 안에** 두면 그 이유가 사라진다.

- work.html 은 **358KB** 이고, 직원이 **어차피 매일 여는 화면**이다 → 추가 부담 0
- 안내와 실제 확인이 같은 화면에 있다 → "다른 프로그램으로 가라"는 단계가 없어진다.
  가라는 안내는 항상 사람을 잃는다
- 성과급이 붙은 원천(사건·컨설팅·기금)이 곧 업무관리의 업무다. 맥락이 맞다
- 새 파일을 안 만든다 → 만들 것이 4개에서 3개로 줄어든다
- 폰 앱은 work.html 에 manifest 를 붙이면 된다(명함첩과 같은 방식).
  업무관리를 홈화면에 두는 건 어차피 쓸모가 있다

**`pu-perf.html` 은 만들지 않는다.**

#### 업무관리에 둘 때 반드시 지킬 것

1. **본인 고정** — work.html 에는 `setView(sid,name)` 으로 *다른 사람 업무를 열람*하는
   기능이 있다(`S.vsid`). 성과급 화면은 **반드시 로그인 본인 `S.me.sid`** 에 묶고,
   열람 대상 `S.vsid` 를 절대 따라가면 안 된다.
   규칙(`uid` 대조)이 한 번 더 막으므로 코드가 틀려도 남의 것은 안 열린다 — 이중 잠금.
2. **금액 가림** — 업무관리는 하루 종일 켜 두는 화면이라 어깨너머로 보인다.
   금액은 처음에 `●●●` 로 두고 누르면 보이게 한다.
3. 팀 전체·업무량 화면에는 성과급이 **절대 섞이지 않게** 한다.

## 데이터 자리

**`data/perf_confirm`** — `data/finance_income` 과 나란히.
(최상위가 아니라 `data` 아래다. 규칙 안의 경로도 `root.child('data').child('perf_confirm')`)

```
data/perf_confirm/
  2026-08/                         대상 월 (입금 확정월)
    p/
      <sid>/
        uid                        ← 발행 때 심는다. 규칙이 이걸로 본인을 가린다
        name  total  itemCount
        openedAt  openedBy
        items/
          <fiId>/                  finance_income 레코드 id — 추적용
            date source coName role pct amount
            ok  okAt  okBy
        done  doneAt  doneBy  deviceHint
        objection/  text  at
        reopen/     at by reason   ← 대표가 완료를 푼 기록
```

**월 단위 `meta` 는 두지 않는다.** 거기에 전사 합계를 넣으면 전원이 읽게 된다.
업무관리는 자기 칸이 있는지만 보면 되므로 meta 가 필요 없다.

### 권한 규칙 — **게시 완료본이 `docs/firebase-rules-현재적용본.json` 에 들어 있다**

`data` 아래 `finance_income` 바로 앞에 47줄이 들어갔다. 기존 규칙은 한 줄도 안 지웠다.

핵심 세 가지:

- **읽기** — `$sid` 칸은 `data.child('uid').val() === auth.uid` 인 사람과 재무권한자만.
  `p` 묶음과 `$ym` 묶음에는 읽기 권한을 주지 않았다 → **남의 것을 훑을 수 없다**
- **쓰기** — `$sid` 칸에 통짜 `.write` 를 주지 않았다.
  본인이 쓸 수 있는 건 `items/$fid/ok·okAt·okBy` · `done` · `doneAt` · `doneBy` ·
  `deviceHint` · `objection` **뿐**. `amount` · `total` · `name` 에는 규칙이 없으므로
  **금액은 못 고친다**
- **되돌리기** — `done` 은 재무권한자도 쓸 수 있다(대표가 완료를 풀어 준다).
  `ok` 와 `objection` 은 본인만

`.validate` 로 `ok`·`done` 은 참/거짓만, 시각 문자열은 40자, 이의 사유는 500자로 제한했다.

uid 는 발행할 때 `data/user_accounts` 의 매핑을 보고 심는다.
uid 가 비어 있으면(계정 미연결) 그 사람 것은 **아무도 못 읽으므로**,
발행 미리보기에서 **uid 없는 사람을 먼저 경고**해야 한다.

점검 스크립트: `rules-perf-check.js` (20가지 — 남의 것 못 훑는지, 금액 쓰기 규칙이
없는지, 기존 항목이 안 빠졌는지)

## 화면 셋

### 1. 발행 (pu-erp 성과관리 `hr/perf` — `PerfManagement`)
- `[이달 확인 발행]` — 그 달 확정 입금의 `perfShares` 를 sid 로 묶는다
- 미리보기: 사람 / 건수 / 합계, uid 없는 사람 경고, 이미 발행됐으면 차이만 표시
- 재발행은 덮어쓰지 않고 **새 항목만 추가**한다 (이미 체크한 걸 날리면 안 된다)
- `perfExclude` · `isPersonalIncome` 건은 제외 (지금 성과관리와 같은 기준)

### 2. 본인 확인 — 업무관리 안 '성과급' 메뉴 (work.html)
work.html 은 vanilla JS 다. React 아님.

- 메뉴 추가 지점: `route()` 의 `['my','team','stats','kb','ho','archive']` 배열과
  `crumbs` 객체에 `perf` 를 넣고 `renderPerf()` 를 붙인다. 좌측 nav 에 `nav-perf` 항목 추가
- 읽는 곳: `fbDb.ref('data/perf_confirm/'+ym+'/p/'+S.me.sid)` — **`S.vsid` 아님, `S.me.sid`**
- 항목마다 체크, 전부 체크해야 `확인 완료` 활성
- 금액은 처음에 `●●●`, 누르면 보임
- `다른 것 같습니다` → 사유 남기면 대표에게 표시
- 완료하면 본인은 못 푼다. 대표만 풀 수 있고 푼 것도 기록
- 폰: `viewport` 는 이미 있다. `@media` 가 3개뿐이라 이 화면만 세로로 쌓이게 만든다

### 3. 안내 (같은 work.html)
- `data/perf_confirm/<이번달>/p/<내sid>` 가 있는데 `done` 이 아니면
- 하루 첫 로그인 팝업 1회(`localStorage` 로 날짜 기억) + 상단 빨간 띠 상시
- 누르면 **같은 화면 안** '성과급' 메뉴로 이동 (`go('perf')`). 다른 프로그램으로 안 보낸다
- 팝업은 `showModal(html)` / `closeM()` 을 그대로 쓴다

### 4. 현황판 (pu-erp 성과관리)
- 발행 대비 완료 인원, 미확인자 목록, 이의 신청 목록
- 미확인자에게 알림 보내기(추후)

## 순서

| 단계 | 무엇 | 위험 |
|---|---|---|
| 1 | 데이터 자리 + 권한 규칙 + 발행 화면 (pu-erp) | 직원 화면 안 건드림. **없음** |
| 2 | work.html 에 '성과급' 메뉴 + 확인 화면 | 새 화면이라 기존 화면 무영향 |
| 3 | work.html 안내 (팝업 + 띠) | 전 직원이 매일 보는 자리 — **여기가 유일한 고비** |
| 4 | 현황판 + work.html manifest(홈화면 앱) | 낮음 |

1단계 끝나면 대표 혼자 8월분으로 시험해 볼 수 있다.

### 대표가 직접 해야 하는 것
- **1단계 전** — `docs/firebase-rules-현재적용본.json` 을 열어 전체 선택 →
  Firebase 콘솔 Realtime Database → 규칙 → 전체 선택 후 붙여넣기 → 게시.
  붙여넣기 전에 콘솔에 있는 내용을 훑어보고 **낯선 항목이 있으면 멈출 것**
  (다른 세션에서 규칙이 또 바뀌었을 수 있다)
- 4단계 후 폰에서 업무관리 홈화면 추가
