# 급여 아웃소싱 자동화 — 하네스 1차 구축 지시문 (v2.2)

> **투입 방법**: 이 파일을 Claude Code 세션에 올리고 "이 지시문대로 하네스 1차 시작"이라고 요청.
> **v2.2 변경점 (실제 자료 6,764개 대조 검토 반영)**:
> - **파일 자동 분류 전처리(목표 0) 신설** — 폴더에 급여대장·근태·계약서·퇴직금·공단신고 등이 섞여 있음.
> - **연간누적형 = 한 파일 안 월탭 여러 개 분해 명시** (표본 18%, 최대 14탭 실측).
> - **폴더 구조 가정 현실화** — 담당자 3인 체계가 제각각, 사업장별 다중 하위폴더.
> - **`2.급여관리` 폴더 = 과거 아카이브 → 1차 대상 제외**.
> - **.xls 구형 실측 450개**(문서 추정 142개보다 큼) → 모수·비중 리포트 강화.
> - (v2.1 유지) D1(산정기간)·D2(동명이인) 조사, 패밀리별 채점 분리, 근태↔대장 매칭 키 실태 조사.

## 배경
나는 노무법인 대표다. 약 110개 사업장의 급여 아웃소싱 자동화 시스템의 첫 단계로,
"골든(완성 급여대장) 파서 + 채점 기반"인 하네스를 만든다.
**이번 세션 목표는 하네스 1차뿐. 그 이상 만들지 마라.** (엔진·어댑터·서버·계산교정은 다음 세션.)

## 폴더 (실제 구조 — v2.2 갱신)
- 최상위 = 담당자별 폴더 3개: `주민정/`, `박은비/`, `김보람/`. **세 사람의 하위 폴더 체계가 서로 완전히 다르다**(예: 주민정 `1.급여/{사업장}/2.급여대장/…`, 박은비 `급여/{번호.사업장}/3.급여대장/…`, 김보람 `{번호.사업장}/1.급여대장/…`). 경로 깊이·이름을 고정 가정하지 말고 **내용으로 판별**하라.
- **`2.급여관리/` = 과거 아카이브(2015~2016년 위주, .xls 다수). 1차 하네스 대상에서 제외**한다(리포트에 "아카이브 제외: N개"만 명시).
- 각 사업장 폴더 안에는 급여대장 외에 **근태·근로계약서·취득상실·퇴직금·연말정산·공단신고·피부양자·육아휴직** 등이 섞여 있다. → 목표 0의 자동 분류로 급여대장만 골라내라.
- ※ 원본 zip을 리눅스에서 풀 경우 한글 파일명 CP949 주의(`unzip -O cp949` 또는 파이썬 cp437→cp949 재해석). 폴더 구조 없는 낱개 급여대장(담당자/사업장 루트에 존재)도 정상 입력으로 취급.
- ※ 실측: `.xls` 구형이 (아카이브 포함) 총 450개. 아카이브 제외 후에도 담당자 3인 폴더에 상당수 존재 — 1차는 규칙대로 건너뛰되 리포트에서 비중 확인, 크면 2차에서 .xls 판독(xlrd) 추가 결정.
- `./payroll_mvp.html`, `./puerp/` = 참고(수정 금지)
- 결과 → `./harness/`

## 반드시 알아야 할 사실 (실측 확인)
1. 사업장은 급여 프로그램이 아니라 **수기 엑셀** — 고용보험 단수처리(절사/올림/반올림)가 뒤섞여 단일 규칙으로 전원 안 맞는다. 요율도 0.9%/0.899%/면제 혼재.
2. **국민연금·건강보험은 공단 고지액 그대로**(연금 월 고정, 건보 4월 변동) — 계산 재현 시도 금지.
3. **골든 자체에 오류 있을 수 있음** — 맹신 금지. 골든은 정답이 아니라 참고.
4. 지방소득세 = 소득세×10% 절사 (이 규칙만 확실).
5. **[v2.2] 한 파일이 여러 월을 담는다** — 급여대장 xlsx의 약 18%가 `25년1월·2월·…` 식 월별 시트를 한 파일에 누적(연간누적형). 파일 하나 = 1개월이 아니다.
6. **[v2.2] 급여대장 xlsx에 주민번호가 실재**(표본 52%). 그래도 **추출 금지·마스킹**. 전량 로컬 처리.

## 목표 (이것만)

### 0) [신규·선행] 파일 자동 분류
전처리로 각 파일을 **급여대장 / 근태 / 근로계약서 / 퇴직금산정 / 공단신고 / 기타** 로 분류하라.
- 판별 = 폴더명 키워드(급여대장·근태·근로계약서·퇴직금·취득상실 등) + **내용 검증**(헤더에 기본급·과세·공제 등 급여 항목이 있으면 급여대장으로 확정).
- 폴더명과 내용이 어긋나면 **내용 우선**, 어긋난 사실을 기록.
- 급여대장으로 분류된 파일만 목표 1의 파서로 넘긴다. 나머지(근태 등)는 목표 5의 조사에만 쓴다.
- 분류 근거를 파일별로 리포트에 남긴다(오분류 추적용).

### 1) 골든 파서: 급여대장 엑셀 → 직원별 JSON
필드: `{성명, 입퇴사일, 유형추정, 기본급, 수당들, 과세총액, 소득세, 지방세, 연금, 건보, 장기, 고용, 공제총액, 실수령, 귀속월}`
- **[v2.2] 월탭 분해**: 한 파일에 월별 시트가 여러 개면 **각 월 시트를 개별 급여대장으로 분해**해 각각 JSON 산출. 시트명(`25년1월`, `1월`, `2501` 등)에서 귀속월 파싱, 실패 시 시트 내용 날짜로 역산.
- 2단·3단 병합 헤더 평탄화 / 급여대장 시트와 부속 시트(소득세표·간이세율표·Base·Data 등) 자동 구분.
- **파일명 불신** — 내용으로 귀속월 판별(5월 폴더에 6월 파일 실재).
- 양식 패밀리 6종 태깅: 표준형 / 단순형 / ★DB형 / 직군분리형 / 근태기반형 / **연간누적형**(월탭 다수).
- `.xls` 구형·손상·PDF는 건너뛰고 **사유 기록**.
- **주민등록번호 추출 금지(성명만). 외부 API 전송 금지 — 전부 로컬.**

### 2) 단수처리 자동 판정
사업장별 고용보험 절사/올림/반올림 중 **최다 일치 방식** 리포트 (+요율 0.9%/0.899%/면제 편차 감지).

### 3) 산정 기간 자동 감지 (D1)
각 사업장 대장의 날짜 범위를 역산 → "1일~말일 / 26일~25일" 등 판별. 감지 실패 시 사유 기록.

### 4) 동명이인 실태 조사 (D2)
사업장 내 동일·유사 이름 목록화. 유사 판정은 이름 정규화(공백·한자·오타) 후 비교.

### 5) 근태↔대장 매칭 키 실태 조사
근태표엔 이름만 있고 주민번호 추출은 금지 → 이름만으로는 동명이인·투잡에서 매칭 필연 실패.
- **[v2.2] 근태 파일은 목표 0의 분류 결과에서 가져온다**(사업장 폴더 안에 대장과 섞여 있음, 별도 `raw/` 폴더 아님).
- ※ 근태 확보 현황: 주민정·박은비·김보람 3명분 있음 / 신욱임 근태 미제출 — 신욱임 담당 사업장은 "근태 미제출"로 기록하고 조사에서 제외, 추후 도착 시 증분 조사.
- **대장·근태 양쪽에 어떤 매칭 키 후보가 실재하는지 조사**: 사번, 부서, 입사일, 직급, 연락처 뒷자리 등.
- 각 사업장별로 "이름 단독 매칭 가능 / 보조키 필요 / 매칭 불가" 3분류.
- 근태·대장 이름 대조 시 한쪽에만 있는 이름(unmatched) 목록.

### 6) 급여일 분포 조사
사업장별 급여 지급일(대장·파일명·내용에서 추정) 분포표 — 10일·25일·말일 집중도 파악(담당자 5명 처리 캘린더 설계용). 추정 불가 시 사유 기록.

### 7) 커버리지 리포트 (HTML 1장)
- 사업장 × 월 성공/부분/실패 표
- 사업장별 실수령 합계(눈대조용)
- 실패 사유
- **[v2.2] 파일 분류 결과 표**(급여대장/근태/기타 개수 + 오분류 의심)
- 단수 판정 / 산정기간 / 동명이인 / 매칭 키 실태 / 급여일 분포

## 성공 기준 (v2.2 — 패밀리별 분리)
파싱 가능 엑셀(구형·손상·PDF·아카이브 제외 = 모수 산출) 중 **전체 92%+**에서 직원별 실수령 추출.
**단, 전체 92%만 보지 말고 패밀리 6종 각각의 성공률을 별도 표기**한다.
- 특정 패밀리(특히 DB형·연간누적형)에 실패가 몰리면 전체 92%를 넘겨도 "그 패밀리는 실사용 불가"로 판정 → 리포트에 경고.
- 패밀리별 모수가 너무 작아(예: 3건 이하) 통계가 무의미하면 그렇게 명시.
- **[v2.2] 연간누적형은 "파일 단위"가 아니라 "분해된 월 단위"로 성공률 집계**(한 파일 14탭 중 1탭만 성공을 100%로 착시 금지).
- **모수 산출 근거를 리포트에 명시**: 전체 파일 N개 중 제외 M개(아카이브/구형/손상/PDF 각각 몇 개), 파싱 대상 모수 = N−M.
