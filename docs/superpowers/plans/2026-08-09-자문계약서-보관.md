## 1. 어디에 두나 — 업체관리의 그 업체에 붙인다

계약서에 적힌 내용은 **이미 업체관리에 들어가 있다.** 업체 하나마다
월 자문료(`monthlyAdvisoryFee`)·계약 시작일·종료일·세금계산서 발행일·부가세 유형·
담당자가 다 있다. 스캔본은 그 값들의 **증빙**이다.

값과 증빙이 떨어져 있으면 "이 자문료가 맞나" 할 때 종이를 따로 찾아야 한다.
같은 자리에 있으면 업체 화면에서 바로 열어 확인한다.

### 사진첩에 그냥 두지 않는 이유

| | 사진첩 | 계약서에 필요한 것 |
|---|---|---|
| 자리 | **사람별**(`puphotos/u/{uid}`) | 회사 자산 — 담당자가 바뀌어도 남아야 한다 |
| 보유 | 기본 1년 | **5년**(대표 결정) — 계약이 끝난 뒤에도 남아야 한다 |
| 찾는 길 | 날짜·올린 사람 | "○○업체 계약서" |

사진첩에 두면 담당자가 퇴사할 때 그 사람 자리에 갇힌다.

### 자료함·명함첩이 아닌 이유

- **자료함**(`pucards/materials`)은 **내보내는** 자료다 — 제안서·홍보물 틀. 성격이 반대다.
- **명함첩**에 두면 계약 값은 업체관리에, 종이는 명함첩에 갈린다. 나중에 어느 쪽이 맞는지 헷갈린다.

## 2. ⚠ 계약서 본문은 **파일 창고가 아니라 실시간DB**에 둔다

사진은 창고(Storage)로 옮기는 중인데 계약서는 반대로 간다. 이유가 있다.

**창고 규칙은 실시간DB를 읽지 못한다.** 그래서 "이 업체의 담당자인가"를 물어볼 수 없고,
대표님이 정하신 **「담당자와 관리자만」을 창고에서는 만들 수 없다.**
(사진첩 창고 규칙에 관리자 예외를 못 넣은 것과 같은 한계다)

실시간DB 규칙은 다른 자리를 읽을 수 있다. `uid_roles/{uid}/sid` 에 사번이 들어 있고
업체의 `managerMain` 도 사번이라 **둘을 맞대면 진짜로 잠긴다.**

### 전임 담당자도 계속 본다 (대표 결정)

지금 담당자만 보게 하면 담당이 바뀌는 순간 전임자가 끊긴다. 인수인계 중이거나
과거 경위를 확인할 때 곤란하다. 그래서 **거쳐 간 사람 명단(`seenBy`)을 계약서마다
따로 들고 간다 — 더하기만 하고 빼지 않는다.**

규칙은 셋 중 하나면 열어 준다:

```
".read": "root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true
       || root.child('uid_roles').child(auth.uid).child('sid').val()
          === root.child('companies').child($coId).child('managerMain').val()
       || data.child('seenBy')
             .child(root.child('uid_roles').child(auth.uid).child('sid').val())
             .val() == true"
```

**지금 담당자를 규칙이 바로 보게 한 것이 요점이다.** 담당이 바뀌어도 새 담당자는
`seenBy` 에 아무것도 안 넣어도 곧바로 열린다 — 담당자가 바뀔 때마다 계약서를
훑어 고치는 일이 없다.

`seenBy` 에 넣는 때는 두 곳뿐이다.
- 계약서를 처음 담을 때 — 그때의 주담당·부담당
- 업체의 담당자를 **바꾸기 직전** — 물러나는 담당자를 넣는다

⚠ 이 방식은 시간이 갈수록 볼 수 있는 사람이 **늘기만 한다**(대표님이 정하신 대로다).
줄이는 길이 필요해지면 `seenBy` 에서 빼는 화면을 따로 만들어야 한다.

⚠ **부담당(`managerSubs`)은 배열이라 규칙이 안을 못 뒤진다.** 그래서 부담당은
「지금 담당자」쪽이 아니라 `seenBy` 로 처리한다 — 계약서를 담을 때와 담당자가
바뀔 때 부담당 사번도 함께 넣는다. 안 넣으면 부담당이 자기 업체 계약서를 못 본다.

### 용량은 감당된다 — 다만 사진을 먼저 옮긴 뒤에

| | 지금 | 사진 옮긴 뒤 |
|---|---|---|
| 실시간DB | **1.7GB — 한도(1GB) 초과** | 약 0.3GB |
| 여유 | 없음 | 약 0.7GB |
| 계약서 예상 | — | 연 50건 × 3~5장 ≈ **100MB/년** |

⛔ **사진을 창고로 옮기기 전에는 시작하지 않는다.** 지금 넣으면 터진 것을 더 터뜨린다.

## 3. 들어오는 길은 새로 만들지 않는다

**사업자등록증이 이미 이 길로 업체관리에 자동으로 간다.** 계약서는 종류를 하나 얹는 일이다.

```
사진첩 카메라로 찍기 → 판독 → 「자문계약서」로 인식
   → 업체관리 그 업체에 붙임 (본문 + 뽑아낸 값)
   → 사진첩에는 사본만 남고, 보관 원본은 업체관리 쪽
```

### 판독으로 뽑을 값

| 값 | 쓰임 |
|---|---|
| 상대 업체명 · **사업자등록번호** | 어느 업체인지 잇는 열쇠(체크섬 통과분만) |
| 계약 시작일 · 종료일 · 자동연장 여부 | `contractStartDate` · `contractEndDate` |
| 월 자문료 · 부가세 별도 여부 | `monthlyAdvisoryFee` · `vatType` |
| 세금계산서 발행일 | `taxInvoiceIssueDay` |

⚠ **빈 칸만 채운다.** 사람이 넣어둔 값을 AI가 덮어쓰지 않는다 —
사업자등록증이 이미 그 규칙으로 돌고 있고(2026-08-03 대표 결정), 바꾸지 않는다.
⚠ 사업자번호 체크섬을 통과한 것만 자동으로 붙인다. 한 자리 잘못 읽으면 엉뚱한 업체에 간다.

---

## 4. 여러 쪽을 한 건으로 묶는다

지금 사진첩은 PDF 여러 쪽을 **쪽마다 한 건**으로 쪼갠다. 계약서는 3~5장이 한 건이어야 한다.
명함 앞뒤 묶기(2026-08-09, `meta.cardBack`)와 같은 얼개를 쓴다 —
둘째 쪽부터 첫 쪽 고리를 달고, 등록할 때 한 건으로 합친다.

## 5. 단계

| 단계 | 무엇 | 없어도 되나 |
|---|---|---|
| **0** | **사진 1.7GB 를 창고로 옮긴다(Blaze)** | 아니오 — 전제조건 |
| **1** | 업체관리에 계약서 자리 + 규칙(담당자·전임담당자·관리자) · 담당자 바꿀 때 `seenBy` 고리 | 아니오 |
| **2** | 판독에 「자문계약서」 종류 추가 · 값 뽑기 | 아니오 |
| **3** | 여러 쪽 한 건으로 묶기 | 아니오 |
| 4 | 업체 화면에서 계약서 열어보기·바꾸기 | 예(먼저 쌓고 나중에) |

## 6. 조심할 것

- **부담당(`managerSubs`)은 배열이다.** 실시간DB 규칙은 배열 안을 뒤지지 못한다.
  그래서 부담당은 `seenBy` 로 처리한다(2장 참고). 안 하면 부담당이 자기 업체
  계약서를 못 본다.
- **담당자를 바꾸는 자리에 고리를 하나 건다.** 바꾸기 **직전**에 물러나는 담당자를
  `seenBy` 에 넣어야 한다. 바꾼 뒤에 넣으려 하면 누가 담당이었는지 이미 지워져 있다.
- **보유기간 5년**(대표 결정). 사진첩 기본 1년과 따로 잡는다.
  ⚠ 계약 **종료일부터** 5년인지 **담은 날부터** 5년인지 헷갈리지 않게 한 곳에 적어 둔다.
  계약이 자동연장되면 종료일이 계속 밀리므로, 세는 기준을 코드에 박지 말고 값으로 둔다.
- 계약서에는 대표자 정보·계좌가 들어 있을 수 있다. 그래서 전 직원 공유인
  업체관리 **본체와 다른 자리**에 두고 규칙을 따로 건다.

## 7. 안 만드는 것

| | 왜 |
|---|---|
| 기존 계약서 소급 스캔 | 대표 결정 — 앞으로 것만 |
| 계약서 본문 전체 글자 검색 | 여러 쪽 긴 글이라 값이 커진다. 뽑아낸 값으로 찾으면 충분하다 |
| 계약 종료일 자동 알림 | 중소기업확인서 만료 알림을 이미 「필요 없다」고 정하셨다(2026-08-05) |
| 계약서로 자문료를 자동 수정 | 빈 칸만 채운다. 이미 있는 금액을 종이로 덮으면 거래내역 매칭이 흔들린다 |
