# 사진첩 보안 3건 실행 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사진첩 전체 점검(2026-08-17)에서 나온 보안 구멍 셋을 막는다 —
①판독 열쇠가 전 직원에게 읽히는 것 ②사진 주소가 사실상 공개 링크인 것 ③주민번호가 그대로 담기는 것.

**Architecture:** ①②는 **열쇠·주소를 브라우저에서 없애는** 방향이다. 판독은 서버 함수(`functions/`)로 옮기고, 민감 서류(계약서·근태표)의 사진 주소는 **만료되는 서명 주소**를 서버가 그때그때 발급한다. ③은 이미 있는 `js/pu-rrn-mask.js` 계획을 사진첩에도 붙인다.

**Tech Stack:** 빌드 없는 단일 파일 HTML + `js/*.js` 전역 모듈 · Firebase Functions(v1, `asia-northeast3`) · 검사는 `node --test` + `node:vm`(가짜 DB·가짜 fetch)

## 배경 — 무엇이 문제였나 (2026-08-17 점검)

이 세 가지는 **실제 자료로 확인한 것**이다. 짐작이 아니다.

### ① 판독 열쇠가 전 직원에게 읽힌다

```
pucards/config/geminiKey  →  55자 열쇠가 평문
규칙: "pucards": { ".read": "auth != null && auth.token.email != null" }   ← 로그인한 모든 직원
```

`js/pu-doc-read.js` 의 `keysFrom(db).getKey()` 가 이 자리를 읽는다.
**직원 누구나 꺼내 개인 용도로 쓸 수 있고 요금은 회사에 붙는다.**

⚠ **「잠긴 자리로 옮기기」로는 못 푼다** (2026-08-17 에 이 처방을 냈다가 정정했다):
- `data/app_config` 도 규칙의 `"$other"` 에 걸려 **전 직원 읽기**다.
- 더 근본적으로, **판독은 직원 브라우저에서 돈다.** 관리자만 읽게 잠그면 직원이 판독을 못 한다.
- 열쇠가 브라우저에 닿는 한 반드시 새어 나온다. **서버로 옮기는 것만이 답이다.**

> 임시 방어는 이미 걸어 두었을 수 있다 — 구글 콘솔에서 API 키에 **웹사이트 제한**
> (`https://nabaho.github.io/*`)과 **API 제한**(Generative Language API)을 채우는 것.
> 훔쳐도 밖에서 못 쓴다. **이 계획은 그 위에 얹는 근본 수리다.**

### ② 사진 주소가 사실상 공개 링크

사진 정보에 토큰 주소가 그대로 들어 있다(실제 확인):

```
puphotos/u/{uid}/items/{해}/{id}
  fullUrl : https://firebasestorage.../...?alt=media&token=...
  thumbUrl: (같은 형태)
```

| | |
|---|---|
| 만료 | **없다** |
| 로그인 | **필요 없다** |
| 공유를 풀면 | **그래도 열린다** — 주소를 이미 받았다 |

⚠ **이건 의도된 맞바꿈이었다.** 창고(Storage) 규칙은 실시간DB(`uid_roles`)를 읽을 수 없어
관리자·공유자가 403 으로 막혔고(2026-08-17 「남의 회의사진 46장 회색 칸, 403 832건」),
그것을 푸는 방법으로 토큰 주소를 택했다(`tests/photos-url-tokens.test.js`).
**그러니 이 계획은 그 결정을 뒤집는 것이 아니라, 민감한 것만 골라내는 것이다.**

### ③ 주민번호가 그대로 담긴다

사진첩에 계약서 18장·근태표 10장이 있고 근로계약서에는 주민번호가 있다.
가림 기능은 급여데이터함용으로 **계획만** 있고 사진첩에는 없다
(`docs/superpowers/plans/2026-08-15-주민번호-가림.md`).
게다가 판독을 누르면 **구글 AI로 원본이 그대로 전송**된다.

## Global Constraints

- **빌드 과정이 없다.** 새 파일은 `<script src="js/...">` 로 바로 실린다. `import`/번들러 금지.
- **주석은 한국어.** 「무엇을」이 아니라 **「왜」**를 적는다.
- **검사 판정은 종료코드로 한다:** `node --test tests/*.test.js` 가 `0` 이어야 한다. 출력을 골라 읽지 말 것.
- **커밋은 경로를 지정한다:** `git add <파일들>`. 이 작업트리는 다른 세션과 함께 쓴다.
  `git add -A` 와 `git reset --soft origin/main` 은 **쓰지 말 것** — 남의 작업을 지우는 커밋이 만들어진다.
- **`js/*.js` 를 고치면 부르는 html 의 `?v=` 를 올린다.** 커밋 훅이 막지만, 막히기 전에 올릴 것.
- **실시간DB 규칙은 콘솔이 진짜다.** 저장소 파일로 배포하지 말 것(사진첩·성과확인이 막힌 적 있다).
  규칙이 필요하면 **대표님께 붙여넣을 조각을 드린다.**
- **함수 배포는 이름을 찍어서:** `firebase deploy --only functions:이름`. 전체 배포는 막힌다.
- **검사는 「글자가 있나」로 못 박지 말 것.** 2026-08-16~17 에 주석·죽은 문자열·딴 구역의
  같은 낱말에 **네 번** 속았다. 값이 걸린 것은 **함수를 실제로 돌려** 확인한다.

## 1단계 — 판독을 서버로 (열쇠를 브라우저에서 없앤다)

### Task 1: 서버 판독 함수

**Files:**
- Create: `functions/doc-read.js`, `tests/doc-read-server.test.js`
- Modify: `functions/index.js`

**Interfaces:**
- Produces: `POST /readDoc` — 몸통 `{ imageBase64, mimeType }`, 응답 `{ kind, fields, error }`

- [ ] **Step 1: 실패하는 검사를 쓴다** — `tests/doc-read-server.test.js`

가짜 `fetch` 를 넣고 **실제로 돌려서** 확인한다:
- 로그인하지 않은 요청은 **401** 로 막힌다(`requireStaff` 재사용 — `functions/index.js` 에 이미 있다)
- Gemini 를 부를 때 열쇠가 **환경변수**에서 온다(`process.env.GEMINI_KEY`)
- 응답에 **열쇠가 섞여 나가지 않는다**(오류 본문을 그대로 돌려주다 열쇠가 새는 사고가 흔하다)
- 사진이 너무 크면(> 4MB) 받지 않는다

- [ ] **Step 2: `functions/doc-read.js` 를 만든다**

`js/pu-doc-read.js` 의 **판정 로직(`autoOk`·`KINDS`·필드 뽑기)은 옮기지 않는다** — 그건 화면과
급여데이터함이 함께 쓰는 순수 계산이다. 서버는 **Gemini 를 부르는 부분만** 맡는다.

⚠ 모델 이름은 `js/pu-doc-read.js` 의 `MODELS` 와 **한 곳에서** 온다. 두 벌이 되면
2026-06-01 의 `gemini-2.0-flash` 종료 같은 일이 또 한쪽만 고쳐진다.

- [ ] **Step 3: 열쇠를 서버 비밀로 옮긴다**

```bash
firebase functions:secrets:set GEMINI_KEY
firebase deploy --only functions:readDoc
```

- [ ] **Step 4: 브라우저에서 열쇠 읽기를 걷어낸다**

`js/pu-doc-read.js` 의 `keysFrom(db).getKey()` 를 지우고 `readDoc` 호출로 바꾼다.
⚠ **localStorage 개인 열쇠(`pucards_gemini_key`)도 같이 걷어낸다** — 남겨 두면
「내 열쇠를 넣으면 옛 길로 돈다」가 되어 구멍이 그대로 남는다.

- [ ] **Step 5: 실시간DB 의 열쇠를 지운다 (대표님 확인 뒤)**

`pucards/config/geminiKey` · `data/app_config/geminiKey`.
⚠ **명함첩(pu-cards.html)도 같은 열쇠를 쓰는지 먼저 확인할 것.** 쓰고 있으면
명함첩도 함께 옮긴 뒤에 지운다 — 안 그러면 명함첩 판독이 죽는다.

회의사진·명함·사업자등록증은 **그대로 토큰 주소**를 쓴다 — 지금 잘 돌고 있고,

### Task 3: 서명 주소 발급 함수

**Files:** Create `functions/photo-url.js`, `tests/photo-url-signed.test.js`

- [ ] **Step 1: 검사부터** — 가짜 창고·가짜 DB로 실제로 돌린다
  - 남의 사진을 달라고 하면 **거부**된다(주인·관리자·`shareWith` 에 있는 사람만)
  - 발급된 주소에 **만료 시각이 있다**(2시간)
  - 민감하지 않은 서류를 물으면 **그냥 적힌 토큰 주소**를 돌려준다(불필요한 서명 안 함)

- [ ] **Step 2: 함수를 만들고 배포한다** — `firebase deploy --only functions:photoUrl`

### Task 4: 저장·읽기 배선

- [ ] **Step 1:** `savePhoto` — 민감 서류면 `fullUrl`·`thumbUrl` 을 **안 적는다**
- [ ] **Step 2:** `loadFull`·`loadThumb` — 적힌 주소가 없으면 `photoUrl` 을 불러 받아 온다
- [ ] **Step 3:** 이미 적혀 있는 옛 민감 서류의 주소를 지우는 서버 도구
  ⚠ **지우기 전에 몇 장인지 세어 대표님께 보고할 것.** 지우면 그 사진들은

⚠ **토큰을 무효로 만들지는 못한다.** 이미 새어 나간 주소는 창고에서 토큰을 **새로 발급**해야
죽는다(콘솔 작업, 대표님). 이 계획은 **앞으로 새는 것**을 막는다.
