# 업무관리 「내 업무」 화면 구현 계획

> **작업자에게:** 이 계획은 `superpowers:subagent-driven-development` 또는 `superpowers:executing-plans` 로 한 과제씩 실행한다. 각 단계는 체크박스(`- [ ]`)로 표시한다.

**Goal:** 「내 업무」 표를 구분별로 묶고, 안 쓰는 열을 접고, 요일 칸에서 앞으로 할 일을 걸어 체크 한 번으로 실적이 되게 한다.

**Architecture:** `work.html` 한 파일 안의 인라인 `<script>` 를 고친다. 새 저장 자료를 만들지 않는다 — 할 일은 이미 있는 `work_erp/steps/{업무ID}` 를 그대로 쓰고, 화면 설정(접힌 열·접힌 묶음)은 `localStorage` 에만 둔다. 검사는 저장소 관례대로 HTML에서 함수 원문을 뽑아 `eval` 로 태운다.

**Tech Stack:** 무빌드 바닐라 JS (ES5 문법), Firebase Realtime Database compat SDK, Node 기본 실행 검사(`node tests/*.test.js`)

## Global Constraints

- 설계 근거: `docs/superpowers/specs/2026-08-07-업무관리-내업무화면-design.md`
- **ES5 문법만.** 화살표 함수·`let`/`const`·템플릿 문자열·`class` 를 `work.html` 안에 쓰지 않는다. 주변 코드가 전부 `var` + `function` 이다. (검사 파일은 Node에서만 도니 최신 문법을 써도 된다.)
- **푸른이알피(`data/*`)에 절대 쓰지 않는다.** 이 화면은 읽기만 한다.
- **`project_progress`·`my_todos`·`my_schedules`·`my_work_items` 를 건드리지 않는다.** 푸른이알피가 배열 통째로 저장하는 노드라, 한 칸만 써도 다음 전체 저장에 사라지거나 남의 자료를 덮는다.
- 파일은 **CRLF** 줄바꿈이다. 편집 도구가 LF로 바꾸지 않게 한다 (바꾸면 전체 파일 diff가 되어 다른 세션과 충돌한다).
- 작업 폴더 `C:\Users\fair0\Documents\pureunall` 는 여러 세션이 함께 쓴다. **`git add` 는 내가 만진 파일만 이름으로 지정**하고, 커밋 전 `git diff --stat` 로 크기를 확인한다.
- 새 저장 필드를 만들 때는 **옛 자료에 그 필드가 없는 경우**를 항상 먼저 처리한다.
- 검사 이름과 주석은 한국어로 쓴다. 저장소 전체가 그렇다.

## 과제 순서

각 과제는 그 자체로 쓸 만한 상태를 만든다. 앞 과제가 끝나야 뒤 과제가 성립한다.

1. `wkMarks` 결함 수정 — 요일 칸에 단계 기한이 보이기 시작한다
2. 열 접기 — 화면이 즉시 넓어진다
3. 구분별 묶어 보기 — 2의 "구분 열 자동 접기"가 여기서 이어진다
4. 상태 드롭다운 — 독립적
5. 요일 칸의 할 일 — 1 위에 올라간다. 가장 크다
6. Enter 머무르기 — 5와 짝이다

**Interfaces:**

  - `colTD(k, inner, attr)` → `string` — 접혀 있으면 띠 `<td>`, 아니면 보통 `<td>`

### 왜

```js
/* ── 열 접기 ────────────────────────────────────────────────────────
   안 쓰는 열을 없애지 않고 접는다 — 기록이 쌓이면 「최근 기록」이 다시
   필요해진다. 접힌 열은 사라지지 않고 폭 14px 띠로 남아 그 자리에서 편다.
   메뉴 안에 숨기면 접었다는 사실 자체를 잊는다.
   이 브라우저에만 저장한다 — 남의 화면에 영향이 없고, 남의 업무를
   열람할 때도 내 설정이 유지된다. */
var COLS_KEY='work_my_cols';
var MYCOLS=[['cat','구분'],['pt','업무'],['st','상태'],['last','최근 기록'],['due','다음 할 일']];
var COLS_DEFAULT='pt,last';        // 처음 여는 사람이 보는 상태
function colPref(){
  if(S.cols===undefined){
    var v=null; try{ v=localStorage.getItem(COLS_KEY); }catch(e){}
    if(v===null) v=COLS_DEFAULT;                 // 저장된 적 없음 = 기본값
    S.cols={};                                   // 빈 문자열이면 전부 펴진 상태다
    String(v).split(',').forEach(function(k){ if(k) S.cols[k]=1; });
  }
  return S.cols;
}
function colHidden(k){
  if(!MYCOLS.some(function(c){ return c[0]===k; })) return false;   // 접을 수 없는 열
  return !!colPref()[k];
}
function colToggle(k){
  if(!MYCOLS.some(function(c){ return c[0]===k; })) return;
  var p=colPref();
  if(p[k]) delete p[k]; else p[k]=1;
  try{ localStorage.setItem(COLS_KEY,Object.keys(p).join(',')); }catch(e){}
  renderMy();
}
```

- [ ] **2-7. 띠와 칩을 그리는 함수를 더한다**

`colToggle` 함수 바로 뒤(`work.html`)에 넣는다.

```js
// 접힌 열은 <th>/<td> 를 폭 14px 띠로 바꾼다. 띠 자체가 펴는 단추다.
function colTH(k,inner,style){
  var c=MYCOLS.filter(function(x){ return x[0]===k; })[0];
  if(!c||!colHidden(k)) return '<th style="'+(style||'')+'">'+inner+'</th>';
  var dot=fHas('my',k)?'<span class="cbd"></span>':'';    // 조건이 걸린 채 접힌 열
  return '<th class="cband" onclick="colToggle(\''+k+'\')" '
    +'title="'+esc(c[1])+' — 눌러서 폅니다'+(dot?' (걸러 보기 조건이 걸려 있습니다)':'')+'">'
    +'<span class="cbl">'+esc(c[1])+'</span>'+dot+'</th>';
}
function colTD(k,inner,attr){
  if(colHidden(k)) return '<td class="cband"></td>';
  return '<td'+(attr?' '+attr:'')+'>'+inner+'</td>';
}
// 표 위 칩 — 띠를 못 찾아도 여기서 한 번에 켜고 끈다
function colChips(){
  return MYCOLS.map(function(c){
    var off=colHidden(c[0]);
    return '<span class="chipbtn'+(off?'':' on')+'" onclick="colToggle(\''+c[0]+'\')" '
      +'title="'+esc(c[1])+' 열을 '+(off?'폅니다':'접습니다')+'">'
      +(off?'':'✓ ')+esc(c[1])+'</span>';
  }).join('');
}
```

**Files:**
- Modify: `work.html` — `wkDays`(2525), `wkCellHTML`(2557), `wkKey`(2474), `stepToggle`(3619) 옆에 새 함수
- Test: `tests/work-my.test.js`, `tests/work-week.test.js`

**Interfaces:**
- Consumes: `stepsOf(id)`, `addLog(itemId,text,dateStr,kind)` → `Promise<boolean>`, `_delLog(itemId,lid)`, `stepsOf` 가 읽는 `steps` 전역, `rid(prefix)` → `string`, `todayStr()`, `wkLogsOf(itemId,wk)`
- Produces:
  - `isPlanDay(d)` → `boolean` — 그 날짜가 오늘보다 뒤인가
  - `wkSave(id,text,d)` → `Promise<boolean>` — 날짜에 따라 할 일 또는 기록으로 저장
  - `planAdd(id,text,d)` → `Promise<boolean>`
  - `planCheck(id,sid)` → `void` — 체크: `done` + 그 날 기록
  - `planUncheck(id,sid)` → `void` — 체크 풀기: `done:0` + 그 기록 삭제
  - `planToLog(id,sid)` — 할 일을 기록으로 (잘못 들어갔을 때)
  - `logToPlan(id,lid)` — 기록을 할 일로
  - `planDel(id,sid)` — 할 일 지우기
  - `planRowHTML(it,s)` → `string`

### 왜

요일 칸에 적을 수 있는 것이 **이미 한 일**뿐이라, 앞으로 할 일을 적을 자리가 표에 없다. 앞을 보는 화면이어야 하는데 뒤만 보여 준다.

새 저장 자료를 만들지 않고 **이미 있는 「진행 단계」** 를 쓴다. 따로 만들면 할 일을 적는 곳이 세 군데(다음 할 일·진행 단계·주간 할 일)로 나뉘어 어디에 적을지 헷갈린다.

```js
   적은 것이 할 일이 되느냐 기록이 되느냐는 그 칸의 날짜 하나로 정한다.

   할 일은 새 자료를 만들지 않고 이미 있는 「진행 단계」에 담는다. 따로
   만들면 할 일을 적는 곳이 세 군데로 나뉘어 어디에 적을지 헷갈린다. */
var PLAN_GROUP='주간';
function isPlanDay(d){ return !!d&&String(d)>todayStr(); }
function wkSave(id,text,d){
  return isPlanDay(d)?planAdd(id,text,d):addLog(id,text,d);
}
function planAdd(id,text,d){
  text=String(text||'').trim();
  if(!text){ toast('내용을 입력하세요','warn'); return Promise.resolve(false); }
  var all=stepsOf(id), last=all.length?all[all.length-1].o:0;
  var rec={t:text,g:PLAN_GROUP,o:(last||0)+1,done:0,d:d,
           by:(S.me&&S.me.sid)||'',byName:(S.me&&S.me.name)||''};
  return fbDb.ref(NS+'/steps/'+id+'/'+rid('S')).set(rec)
    .then(function(){ toast('할 일 저장됨'); return true; })
    .catch(function(e){ toast('저장 실패: '+e.message,'err'); return false; });
}
/* 체크 = 실적. 단계를 done 처리하고 그 날 기록도 만든다.
   기록을 안 만들면 팀 전체의 「✍ 미기록」·「최근 기록」·전체 검색이 그 일을
   못 본다. 그렇다고 두 줄로 그리면 같은 일이 두 번 적힌 것처럼 보이므로,
   기록에 sid 를 달아 두고 칸에서는 그 기록을 다시 그리지 않는다. */
function planCheck(id,sid){
  var s=(steps[id]||{})[sid]; if(!s||s.done) return;
  addLog(id,s.t,s.d||todayStr(),'step').then(function(ok){
    if(!ok) return;
    var lid=_lastLogId;                       // addLog 가 방금 만든 기록

    up[NS+'/steps/'+id+'/'+sid+'/done']=1;
    up[NS+'/steps/'+id+'/'+sid+'/by']=(S.me&&S.me.name)||'';
    up[NS+'/steps/'+id+'/'+sid+'/at']=todayStr();
    up[NS+'/steps/'+id+'/'+sid+'/lid']=lid||null;   // 체크를 풀 때 이 기록을 지운다
    fbDb.ref().update(up).catch(function(e){ toast('실패: '+e.message,'err'); });
  });
}
function planUncheck(id,sid){
  var s=(steps[id]||{})[sid]; if(!s||!s.done) return;
  var up={};
  up[NS+'/steps/'+id+'/'+sid+'/done']=0;
  up[NS+'/steps/'+id+'/'+sid+'/by']=null;
  up[NS+'/steps/'+id+'/'+sid+'/at']=null;
  up[NS+'/steps/'+id+'/'+sid+'/lid']=null;
  fbDb.ref().update(up).then(function(){
    if(s.lid) _delLog(id,s.lid);              // 체크가 만든 기록은 체크가 거둔다
  }).catch(function(e){ toast('실패: '+e.message,'err'); });
}
```

- [ ] **5-11. 잘못 들어간 것을 서로 바꿀 수 있게 한다**

설계의 "잘못 들어갔으면 그 줄을 눌러 서로 바꾼다"가 이것이다. 날짜 규칙이 거의 다 맞히지만, 어제 한 일을 오늘 아침에 내일 칸에 잘못 적는 일은 생긴다. 되돌릴 길이 없으면 지우고 다시 적어야 한다.

```js
// 잘못 들어간 것을 옮긴다 — 지우고 다시 적지 않아도 되게.
// 할 일 → 기록: 그 날 기록을 만들고 할 일을 없앤다(체크와 달리 흔적을 남기지 않는다).
function planToLog(id,sid){
  var s=(steps[id]||{})[sid]; if(!s) return;
  addLog(id,s.t,s.d||todayStr()).then(function(ok){
    if(!ok) return;
    fbDb.ref(NS+'/steps/'+id+'/'+sid).remove()
      .then(function(){ toast('기록으로 옮겼습니다'); })
      .catch(function(e){ toast('실패: '+e.message,'err'); });
  });
}
// 기록 → 할 일: 그 날짜로 할 일을 걸고 기록을 지운다.
function logToPlan(id,lid){
  var l=(itemLogsCache[id]||{})[lid];
  if(!l){ loadItemLogs(id).then(function(){ logToPlan(id,lid); }); return; }
  if(!canLog(l)){ toast('본인이 쓴 기록만 옮길 수 있습니다','warn'); return; }
  planAdd(id,l.t,l.d).then(function(ok){ if(ok) _delLog(id,lid); });
}
```
