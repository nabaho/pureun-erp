# 푸른카메라 — 리멤버식 독립 카메라 계획서

**2026-08-08** · 대표 지시: "스마트폰에서 리멤버처럼 독립적인 카메라 기능 만들어 줄 수 있나"

---

## 1. 먼저 확인한 것 — 카메라가 이미 둘이다

| | 어디 | 무엇을 하나 | 어디에 담기나 |
|---|---|---|---|
| **푸른카메라** | `pu-camera.html` (독립 앱, 525줄) | 명함 한 장 찍기 → AI 판독 → 확인 → 저장 | **명함첩** |
| **사진첩 카메라** | `pu-photos.html` 안 | 연속촬영 · 명함틀 · 손전등 · 탭 초점 · 골라 올리기 | **사진첩** (그 뒤 자동 분류) |

**이것이 지금 가장 큰 문제입니다.** 명함을 찍으려는데 **어느 카메라를 열어야 하는지** 알 수 없습니다. 두 앱을 다 설치하면 홈 화면에 카메라 아이콘이 둘입니다.

> 기능을 더하기 전에 **이 둘을 어떻게 할지** 먼저 정해야 합니다. → 6장

---

## 2. 리멤버와 지금의 차이

리멤버를 실제로 뜯어보면 빠른 이유는 **찍는 동작이 하나**이기 때문입니다.

| 리멤버 | 지금 | 차이 |
|---|---|---|
| 앱을 열면 **곧바로 카메라** | 홈 화면 → 「명함 찍기」 를 눌러야 | 터치 1번 더 |
| 명함 **테두리를 스스로 찾아** 잘라냄 | 정해진 틀에 사람이 맞춤 | 비뚤면 글자가 안 읽힘 |
| 틀에 들어오면 **저절로 찍힘** | 셔터를 눌러야 | 누르는 순간 흔들림 |
| 찍으면 **바로 다음 장 준비** | 푸른카메라는 한 장씩 | 여러 장이면 반복 |
| 흔들리면 **안 찍고 기다림** | 흔들려도 찍힘 | 다시 찍어야 |

**사진첩 카메라는 연속촬영이 이미 됩니다.** 없는 것은 ①곧바로 카메라 ②테두리 자동 인식 ③자동 촬영 ④흔들림 감지 넷입니다.

---

## 3. 만들 것 — 네 단계

### 1단계 · 열면 곧바로 카메라 〔쉬움 · 반나절〕

푸른카메라를 열면 홈 화면 없이 **바로 카메라**가 켜집니다.

- 사진첩에서 고르기·설정은 카메라 화면 안 작은 단추로
- 권한을 아직 안 준 기기에서는 한 번은 물어봐야 하므로, **그때만** 안내 화면
- 뒤로 가기를 누르면 카메라가 꺼지고 앱이 닫힙니다(홈 화면으로 안 돌아감)

**확인 방법**: 앱 아이콘을 눌러 **카메라가 뜨기까지 몇 번 터치하는지** 센다. 목표 **0번**.

### 2단계 · 흔들림·초점 감지 후 자동 촬영 〔보통 · 하루〕

셔터를 누르지 않아도 됩니다. 화면이 멎고 초점이 맞으면 스스로 찍습니다.

- 미리보기 프레임을 **작게 줄여 앞 프레임과 비교** — 차이가 작으면 「멎었다」
- 멎은 상태가 연속 3프레임(약 0.4초)이면 촬영
- 찍기 직전 **화면이 한 번 반짝** — 찍혔다는 것을 몸으로 알게
- **셔터 단추는 그대로 둡니다.** 자동이 안 잡히는 상황(어두운 곳)에서 사람이 누를 길을 없애면 안 됩니다
- 「자동으로 찍기」 껐다 켤 수 있게

⚠ 자동 촬영은 **연속으로 마구 찍힐 위험**이 있습니다. 찍은 뒤 1.2초는 다시 안 찍고, 화면이 크게 바뀌어야(다음 명함을 올려놓아야) 다음 장을 받습니다.

**확인 방법**: 명함 5장을 이어서 스캔하며 **손이 셔터에 안 가는지**, 헛촬영이 몇 장인지 센다.

### 3단계 · 명함 테두리 찾아 잘라내기 〔어려움 · 2~3일〕

이 단계가 리멤버와 가장 크게 갈리는 곳이자 **가장 위험한 곳**입니다.

**방법** — 바깥 라이브러리를 들이지 않고 만듭니다(OpenCV.js 는 8MB라 폰에서 켜는 데만 몇 초 걸립니다).

1. 미리보기를 320px로 줄여 흑백으로
2. 밝기 차이(경계)를 구해 **긴 직선 네 개**를 찾는다
3. 네 직선이 사각형을 이루고, 그 넓이가 화면의 25% 이상이면 「명함을 찾았다」
4. 찾은 네 꼭짓점을 **원본 좌표로 되돌려** 그 부분만 잘라내고 기울기를 편다

**안전장치 — 이것이 이 단계의 핵심입니다.**
- 못 찾으면 **지금처럼 틀 전체를 그대로 씁니다.** 잘못 잘라 글자를 날리느니 안 자르는 게 낫습니다
- 잘라낸 넓이가 원본의 30% 미만이면 **버리고 원본을 씁니다**(잘못 찾은 것)
- **원본을 덮어쓰지 않습니다** — 자른 것과 원본을 둘 다 두고, 판독이 실패하면 원본으로 다시 시도

⚠ **못 만들 수도 있습니다.** 조명이 나쁘거나 배경이 명함과 비슷한 색이면 테두리를 못 찾습니다. 그때는 2단계까지만 쓰고 이 단계는 접는 것이 낫습니다 — 판단은 실제 명함 20장으로 시험한 뒤 대표님께 숫자로 보고하겠습니다.

### 4단계 · 찍자마자 결과 보여주고 바로 고치기 〔보통 · 하루〕

- 찍으면 판독을 **뒤에서 돌리고** 카메라는 계속 켜 둡니다(기다리지 않음)
- 아래에 작은 줄로 「3장 · 읽는 중 1」
- 다 찍고 「끝」을 누르면 **읽은 결과 목록** — 틀린 곳만 고쳐 저장
- 사업자등록번호가 검증에 걸린 것은 **빨갛게** 표시

## 4. 안 만드는 것 (그리고 왜)

| | 왜 |
|---|---|
| **명함 뒷면 자동 인식** | 앞뒤를 이어 붙이는 규칙이 애매합니다. 지금처럼 두 장을 따로 찍고 합치는 편이 확실합니다 |
| **오프라인 촬영 후 나중에 올리기** | 이미 됩니다 — 사진은 기기에 먼저 담고 올라간 뒤에만 지웁니다 |
| **명함 이외 서류 자동 인식** | 사업자등록증·확인서는 A4라 테두리 찾기 방식이 다릅니다. 명함이 확실해진 뒤에 봅니다 |
| **QR·바코드 읽기** | 명함에서 쓸 일이 드뭅니다 |

## 5. 위험한 곳

1. **자동 촬영이 헛찍는 것** — 손이 지나가거나 책상 무늬를 명함으로 볼 수 있습니다. 그래서 「크게 바뀌어야 다음 장」 규칙을 둡니다.
2. **테두리를 잘못 찾아 글자를 자르는 것** — 되돌릴 수 없습니다. 그래서 **원본을 함께 남깁니다.**
3. **폰이 뜨거워지는 것** — 매 프레임 계산하면 발열이 큽니다. **5프레임에 한 번만** 봅니다.
4. **기기마다 카메라가 다른 것** — 초점·손전등을 못 쓰는 기기가 있습니다. 지금도 그런 기기에서는 단추를 숨깁니다. 자동 촬영도 같게 합니다.

## 6. 정해 주실 것 — 카메라 둘을 어떻게 할까요

이것을 정해야 1단계를 시작할 수 있습니다.

### 안 A · 푸른카메라를 「명함 전용 스캐너」로 (권장)

- 푸른카메라 = 명함만. 열면 바로 카메라. 찍으면 명함첩으로
- 사진첩 카메라 = 현장·회의 사진. 지금 그대로
- **좋은 점**: 각자 하는 일이 뚜렷합니다. 리멤버와 가장 비슷합니다
- **나쁜 점**: 폰에 앱 아이콘이 둘입니다

### 안 B · 사진첩 카메라로 합치고 푸른카메라를 없앰

- 카메라는 하나. 찍은 뒤 「명함첩으로 보내기」를 누름
- **좋은 점**: 아이콘 하나. 관리할 코드도 하나
- **나쁜 점**: 명함을 찍는 데 단계가 하나 늘어납니다. 리멤버의 빠름을 잃습니다

### 안 C · 푸른카메라를 없애고 사진첩 안에서 「명함 모드」

- 사진첩 카메라에 「명함 모드」 스위치. 켜면 명함첩 직행
- **좋은 점**: 아이콘 하나이면서 빠름도 지킵니다
- **나쁜 점**: 폰 홈 화면에서 바로 카메라를 못 엽니다(사진첩을 먼저 열어야)

## 8. 어떻게 확인할까

말이 아니라 **숫자로** 보고드리겠습니다.

- **터치 수** — 앱 아이콘을 누르고 명함 5장을 담기까지 몇 번 만지는가 (지금 몇 번인지 먼저 재고 시작)
- **헛촬영** — 자동 촬영에서 버려야 할 사진이 몇 장인가
- **판독 성공률** — 명함 20장 중 회사명·이름·번호가 다 맞는 것이 몇 장인가 (자르기 전후 비교)
- **뜨거움** — 연속 20장 찍은 뒤 폰이 뜨거워지는가

3단계는 이 숫자가 **자르기 전보다 나아지지 않으면 접습니다.**
