# 기업정보함 반출 기록 — 구현 계획

> **일하는 사람에게:** 설계서는 `docs/superpowers/specs/2026-08-29-기업정보함-반출기록-design.md` 다.
> 왜 이렇게 하는지는 거기 있다. 여기는 «무엇을 어느 자리에» 만 적는다.

**목표:** 기업정보함에서 자료가 나가는 모든 길이 «문지기 하나»를 지나고, 지울 수 없는 기록을 남긴다.

**얼개:** 문지기 `puExport()` 가 ① 대량이면 사유를 묻고 ② 기록을 남기고 ③ 그 뒤에야
`true` 를 돌려준다. 부르는 쪽은 `true` 일 때만 파일을 만든다. 기록은 `pucards` **밖**의
맨 위 칸 `exportLog` 에 쌓이고, 읽기는 관리자만·고치기와 지우기는 규칙이 막는다.

**손대는 파일:** `pu-cards.html`(문지기·문·기록 화면) · `enter.html`(포털 배지) ·
`docs/firebase-rules-반출기록-한칸만-넣기.txt`(대표가 콘솔에 붙여넣을 글) · `tests/`

## 전체에 걸리는 것

- 대량 기준 **200건**. 수는 `EXPORT_BIG` 한 곳에만 둔다.
- 기록 자리 **`exportLog`** — `pucards` 안에 두지 말 것(부모가 준 읽기를 자식이 못 뺏는다).
- 기록에 남기는 칸은 **일곱뿐**: `at·by·uid·kind·what·n·why`. **내용(이름·전화·이메일)은 절대 안 남긴다.**
- `at` 은 반드시 `firebase.database.ServerValue.TIMESTAMP` — 규칙의 `at === now` 와 짝이다.
- 기록 쓰기가 실패하면 **파일을 만들지 않는다.**
- 복사(📋)만 순서를 뒤집는다 — 먼저 복사, 그다음 기록(브라우저가 「누른 순간」에만 복사를 허용한다).

### Task 1 — 문지기와 기록

**파일:** `pu-cards.html` (수정) · `tests/cards-export-log.test.js` (새로)

**내놓는 것(뒤 Task 들이 쓴다):**
- `EXPORT_BIG = 200`
- `async puExport(kind, n, what) → boolean` — `true` 면 진행
- `exportLogRec(o) → {at,by,uid,kind,what,n,why}` — 순수 로직(검사 대상)

- [ ] **1-1 깨지는 검사부터** — `exportLogRec` 가 일곱 칸만 담는다 · 200건이면 사유를 묻는다 ·
      기록이 실패하면 `false` 를 돌려준다
- [ ] **1-2 돌려서 깨지는 것 확인**
- [ ] **1-3 구현** — `exportLogRec` · `writeExportLog` · `askExportWhy`(창) · `puExport`
- [ ] **1-4 통과 확인 + 구문검사**
- [ ] **1-5 도로 막아 걸리는지 확인** (칸 하나 더 담기 · 사유 안 묻기 · 실패인데 true)

### Task 2 — 엑셀 셋 (한 자리)

**파일:** `pu-cards.html:runExport` (수정)

엑셀 셋은 이미 `openExportPick` 한 자리에 모여 있다. `runExport(kind)` 안에서 한 번만 지나면 된다.

- [ ] **2-1 검사** — `runExport` 가 `puExport` 를 «먼저» 부르고, `false` 면 파일을 안 만든다
- [ ] **2-2 구현** — `runExport` 를 async 로, `exportScope` 로 건수를 얻어 `puExport` 에 넘긴다
- [ ] **2-3 통과 확인 · 커밋**

### Task 3 — 파일로 나가는 나머지 문 넷

**파일:** `pu-cards.html` — `downloadCsvFile` · `downloadVcf` · `downloadPhoto` ·
`downloadMaterial` · `downloadMaterialOriginal`

- [ ] **3-1 검사** — 다섯 함수가 모두 `puExport` 를 지난다(글자가 아니라 «먼저 부르는지»)
- [ ] **3-2 구현** — 각 함수를 async 로 바꾸고 맨 앞에 문지기를 둔다.
      `downloadCsvFile` 은 부르는 두 곳(`coMailCsv`·태그별)도 `await` 로 고친다.
- [ ] **3-3 통과 확인 · 커밋**

### Task 4 — 복사 (순서를 뒤집는다)

**파일:** `pu-cards.html` — `copyCardInfo` · `copySelInfo` · `selMailCopy`

- [ ] **4-1 검사** — 복사 함수에서는 `clipboard.writeText` 가 `puExport` «앞»에 온다.
      이 예외를 검사에 적어 둔다(모르고 「통일」하면 복사가 죽는다).
- [ ] **4-2 구현** — 복사한 뒤 기록만 남긴다(사유 창은 200건 이상일 때만).
- [ ] **4-3 통과 확인 · 커밋**

### Task 5 — 반출 기록 화면 (환경설정 · 관리자만)

- [ ] **5-3 통과 확인 · 커밋**

### Task 6 — 포털 타일 배지 (대표만)

**파일:** `enter.html`

- [ ] **6-1 검사** — 0건이면 배지를 아예 안 만든다 · 관리자가 아니면 조회조차 안 한다
