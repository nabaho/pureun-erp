# 서류 판독 층 구현 계획 — `js/pu-doc-read.js`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사진 한 장을 넣으면 그것이 명함인지 사업자등록증인지 중소기업확인서인지 가리고, 필요한 항목을 읽어 내고, **사업자등록번호가 맞는지 기계로 검증하고**, 각 앱의 필드 이름으로 바꿔 주는 공용 조각을 만든다. 저장은 하지 않는다.

**Architecture:** 판독을 아는 유일한 파일을 하나 둔다 — `js/pu-photo-store.js`가 "저장을 아는 유일한 파일"인 것과 같은 원리다. 사진첩·명함첩·푸른이알피가 모두 이 파일을 쓴다. 판독 방식(AI 모델·프롬프트)이 바뀌어도 앱은 손대지 않는다. Gemini 호출·프롬프트·체크섬은 저장소에 이미 있는 것을 옮겨와 한 곳으로 모은다(새로 발명하지 않는다).

**Tech Stack:** Gemini 2.0 Flash (`generativelanguage.googleapis.com`) · 국세청 사업자상태조회(odcloud.kr) · 빌드 없음 · `node --test`

## Global Constraints

- **판독 결과를 저장하지 않는다.** 이 층은 읽고 검증하고 변환만 한다. 저장은 부르는 쪽 책임(다음 단계).
- **`fetch`·키 읽기를 주입받는다.** 노드에서 가짜로 갈아끼워 검사할 수 있어야 한다 — **실제 Gemini·국세청에 절대 붙지 않는다.**
- **기존 것을 옮겨 온다, 새로 쓰지 않는다:**
  - 명함 프롬프트 = `pu-cards.html:1715` 문장 그대로
  - 사업자등록증 프롬프트 = `pu-cards.html:1716` 문장 그대로
  - 사업자번호 체크섬 = `pu-erp.html:52292-52298` `_validBizNo` 그대로
  - 국세청 조회 = `pu-erp.html:1047-1056` `lookupBizNoFromNTS` 형태 그대로
  - AI 키 3단 폴백 = `pu-camera.html:226-236` (로컬 → `pucards/config/geminiKey` → `data/app_config/geminiKey`)
- **AI가 읽은 사업자번호는 검증을 통과해야 '확정'이다.** 체크섬 실패 = 확정 아님. 국세청 조회는 키가 없으면 건너뛰되 **건너뛴 사실을 결과에 남긴다**(조회한 것처럼 보이면 안 된다).
- **필드 이름이 앱마다 다르다** — `bizno`(명함첩) / `bizNo`(푸른이알피) / `biz_no`(기금관리). 매핑표를 이 파일 한 곳에 둔다. 앱이 각자 바꾸면 조용히 안 붙는다.
- 한국어 주석 · ES5 스타일(`var`/`function`, 화살표 함수 금지 — `pu-photo-store.js`와 통일).
- `git add .` 금지, 커밋은 경로 지정, 커밋 직후 `git show --stat HEAD` 확인.
- 브랜치는 사진첩 B단계 브랜치가 아니라 **새 브랜치** `feat/pu-doc-read`. main 직접 push 금지.

## 서류 세 종류와 읽을 항목

| 종류 | `kind` | 읽을 항목 | 갈 곳 |
|---|---|---|---|
| 명함 | `card` | name, company, dept, title, mobile, tel, fax, email, companyTel, companyFax, companyAddr, website, address, memo | 명함첩 |
| 사업자등록증 | `bizreg` | company, ceo, bizno, corpno, openDate, bizType, bizItem, companyTel, companyFax, address, memo | 명함첩(`kind:'biz'`) → 사업장 정보 |
| 중소기업확인서 | `sme` | company, bizno, ceo, smeType(기업규모), issueNo(발급번호), issueDate(발급일), expiry(유효기간 만료일), industry(주업종) | 사업장 정보 + 만료 알림 |

`sme`의 `expiry`는 `kcareer.html:4568`의 `id_doc` 프롬프트가 `expiry`를 쓰는 선례를 따른다.

```js
/* 푸른통합시스템 — 서류 판독 층
   사진 한 장이 명함인지 사업자등록증인지 중소기업확인서인지 가리고,
   항목을 읽어 내고, 사업자등록번호가 맞는지 기계로 검증하는 유일한 파일이다.
   사진첩·명함첩·푸른이알피가 모두 이 파일을 쓴다 — 판독 방식이 바뀌어도 앱은 안 고친다. */
(function (global) {
  'use strict';

  function bizNoDigits(v) { return String(v == null ? '' : v).replace(/\D/g, ''); }

  /* 국세청 사업자등록번호 체크섬. AI가 한 자리 잘못 읽으면 여기서 걸린다 —
     '검증 통과하면 자동 입력'의 근거가 이 함수다. (pu-erp.html 의 _validBizNo 와 같은 식) */
  function bizNoValid(v) {
    var d = bizNoDigits(v);
    if (!/^\d{10}$/.test(d)) return false;
    var w = [1, 3, 7, 1, 3, 7, 1, 3, 5], s = 0;
    for (var i = 0; i < 9; i++) s += parseInt(d[i], 10) * w[i];
    s += Math.floor(parseInt(d[8], 10) * 5 / 10);
    return (10 - (s % 10)) % 10 === parseInt(d[9], 10);
  }

  function fmtBizNo(v) {
    var d = bizNoDigits(v);
    return d.length === 10 ? d.slice(0, 3) + '-' + d.slice(3, 5) + '-' + d.slice(5) : d;
  }

  global.PuDocRead = {
    bizNoDigits: bizNoDigits,
    bizNoValid: bizNoValid,
    fmtBizNo: fmtBizNo
  };
})(typeof window !== 'undefined' ? window : globalThis);
```

## Task 3: 종류 판정 + 항목 판독 (Gemini)

**Files:**

- Test: `tests/pu-doc-read.test.js`

**Interfaces:**
- Consumes: `init({ fetch, getKey })` — `getKey(): Promise<string>` (앱이 3단 폴백을 넣어 준다)
- Produces:
  - `PROMPTS: { card, bizreg, sme }` — 프롬프트 문장(검사에서 내용 확인용)
  - `read(dataUrl): Promise<Result>` — 종류 판정과 항목 판독을 **한 번의 호출로** 한다
  - `Result` = `{ kind:'card'|'bizreg'|'sme'|'other', fields:Object, bizNoOk:boolean|null, ntsChecked:boolean, ntsState:string|null, error:string|null }`

한 번의 호출로 하는 이유: 종류 판정과 항목 판독을 따로 부르면 사진을 두 번 올려 시간·비용이 두 배가 되고, 판정과 판독이 서로 다른 판단을 할 수 있다.

// Gemini 흉내 — 실제 서버에 붙지 않는다.
function fakeFetch(reply, opts) {
  const calls = [];
  const fn = function (url, init) {
    calls.push({ url: url, body: JSON.parse(init.body) });
    if (opts && opts.httpFail) return Promise.resolve({ ok: false, status: 429, json: () => Promise.resolve({}) });
    if (opts && opts.network) return Promise.reject(new Error('네트워크 없음'));
    return Promise.resolve({
      ok: true, status: 200,
      json: () => Promise.resolve({ candidates: [{ content: { parts: [{ text: reply }] } }] })
    });
  };
  fn.calls = calls;
  return fn;
}
