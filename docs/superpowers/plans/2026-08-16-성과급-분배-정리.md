# 입금확정 성과급 분배 정리 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 입금확정 창에서 성과급이 조용히 0원이 되는 일을 없애고, 주담당·부담당이 있을 때 누가 얼마 받는지 한눈에 보이게 한다.

**Architecture:** 「기본값을 정하는 층」(`erpDefaultSplit`) 하나를 새로 두고, 입금확정 창과 자동확정이 **둘 다** 그 함수를 쓴다. 나누는 셈(`calcPerfShares`)은 건드리지 않는다 — 거기서 재분배하면 화면의 %와 저장 금액이 달라진다. 화면은 요율 칸을 잠그고 분할 칸 하나만 남기며, 총 성과급이 0원이면 확정을 막는다.

**Tech Stack:** 단일 파일 `pu-erp.html` (빌드 없음, **ES5만** — `var`/`function`, 화살표·`const`/`let`·템플릿리터럴 금지), React 없이 `h()` 헬퍼, Firebase RTDB, 검사는 `node --test tests/*.test.js`.

**설계서:** `docs/superpowers/specs/2026-08-16-성과급-분배-정리-design.md`

`pu-erp.html` 의 `getRateAt` 함수가 끝나는 `}` 다음 줄, `// 푸른노무법인 직인` 주석 **앞**에 넣는다:

```js
/* ── 분할 %의 «기본값» 을 정하는 한 곳 (2026-08-16 대표 지시) ─────────────────
   대표 지시: "요율 0%인 사람은 분할에서 자동으로 빠진다 · 둘 다 대상자면 기본 주 50 / 부 50."

   ★ 왜 필요했나 — 대표님 직책 요율은 0%(성과급 대상 아님)인데 분할 기본값이 「주담당 100%」였다.
     요율 0%인 사람에게 분할을 주면 그 몫은 «누구에게도 안 가고 사라진다».
     대표님이 주담당인 건이 많아, 실무 노무사가 성과급을 통째로 못 받고 있었다.
     그런데 합계는 100 이라 화면은 초록 ✓ 를 띄웠다.

   ★ 여기는 «기본값을 정하는» 층이다. 나누는 셈(calcPerfShares)은 건드리지 않는다 —
     거기서 몰래 재분배하면 화면에 보이는 %와 저장되는 금액이 달라진다.

   ★ 입금확정 창과 자동확정이 «둘 다» 이 함수를 쓴다. 규칙이 두 군데로 갈라지면 언젠가 어긋난다. */
function erpPerfMainPct(){
  var p = dbGet('policy_perf', null) || {};
  var v = (typeof p.confirmMainPct === 'number') ? p.confirmMainPct : 50;
  if(isNaN(v)) v = 50;
  return Math.max(0, Math.min(100, v));
}
/* 누가 이번 건에서 성과급을 받을 수 있나.
   ★ 수습·퇴사·요율 판정을 여기서 «다시 하지 않는다» — 베껴 오면 언젠가 calcPerfShares 와
     조용히 어긋난다. 돈을 계산하는 그 함수에 어림수를 넣어 「0원보다 큰가」만 본다.
     (어림수는 결과에 남지 않는다. 크게 잡아야 요율이 낮은 사람도 반올림으로 0이 되지 않는다.) */
function erpPerfEligibleSet(mainSid, subSids, paidDate){
  var subs = (subSids || []).filter(function(s){ return s; });
  var PROBE = 100000000;
  var okMain = false, okSubs = [];
  try {
    if(mainSid){
      var byMain = calcPerfShares(PROBE, mainSid, subs, 'case', 100, { paidDate:paidDate }) || [];
      byMain.forEach(function(s){
        if(s.role === '주담당' && (s.amount || 0) > 0) okMain = true;
      });
    }
    if(subs.length){
      var bySub = calcPerfShares(PROBE, mainSid, subs, 'case', 0, { paidDate:paidDate }) || [];
      bySub.forEach(function(s){
        if(s.role === '부담당' && (s.amount || 0) > 0 && okSubs.indexOf(s.sid) < 0) okSubs.push(s.sid);
      });
    }
  } catch(e){ if(window._erpErrLog) window._erpErrLog(e); }
  return { main:okMain, subs:okSubs };
}
function erpDefaultSplit(mainSid, subSids, paidDate){
  var subs = (subSids || []).filter(function(s){ return s; });
  var ok = erpPerfEligibleSet(mainSid, subs, paidDate);
  var map = {}; subs.forEach(function(s){ map[s] = 0; });
  var excluded = [];
  if(mainSid && !ok.main) excluded.push(mainSid);
  subs.forEach(function(s){ if(ok.subs.indexOf(s) < 0) excluded.push(s); });

  function round1(v){ return Math.round((v || 0) * 10) / 10; }
  /* 나머지를 여럿이 나눌 때 나누어떨어지지 않는 몫은 «마지막 사람» 이 받는다.
     그래야 합계가 정확히 100 이 되어 「100%가 되어야 함」으로 확정이 막히지 않는다. */
  function spread(list, total){
    var each = round1(total / list.length), used = 0;
    list.forEach(function(s, i){
      var v = (i === list.length - 1) ? round1(total - used) : each;
      if(v < 0) v = 0;
      map[s] = v; used = round1(used + v);
    });
  }
  var mainPct = 0;
  if(ok.main && ok.subs.length){
    mainPct = erpPerfMainPct();
    spread(ok.subs, round1(100 - mainPct));
  } else if(ok.main){
    mainPct = 100;
  } else if(ok.subs.length){
    spread(ok.subs, 100);
  }
  return { mainPct:mainPct, subPctMap:map, excluded:excluded,
           eligible:(ok.main ? 1 : 0) + ok.subs.length };
}
```
