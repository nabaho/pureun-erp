# 서류 자동 등록 구현 계획 — 판독 결과를 각 앱에 넣기

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 판독이 끝난 서류를 각 프로그램에 넣는다. 기계 검증을 통과한 것은 자동으로, 걸린 것만 사람이 확인한다.

**Architecture:** 사진첩은 판독 결과를 갖고 있고, 어디에 어떻게 넣을지는 **등록 층 `js/pu-doc-file.js`(신규)** 가 안다. 판독 층(`pu-doc-read.js`)이 "읽기"를 아는 유일한 파일인 것과 짝을 이룬다. 화면은 등록 층 함수 하나를 부르고 결과 문구만 띄운다.

**Tech Stack:** Firebase RTDB compat · 빌드 없음 · `node --test`

## 착수 전 관문 (아직 안 열림)

- [ ] **업체관리의 `🔗 업체 연결`·`🌐 바깥 앱 연결 고정` 실행 완료.** 업체에 `co_id`가 안 붙어 있으면 "각자의 프로그램"이 같은 회사를 못 알아본다.

## Global Constraints

- **설계서** `docs/superpowers/specs/2026-08-02-푸른사진첩-design.md` 6-0장이 우선.
- **다중 경로 `update` 한 번만.** 상위 노드 `set` 금지 (2026-07 실데이터 사고).
- **명함첩에 쓸 때 검색 인덱스 `pucards/idx/{id}` 를 반드시 함께 쓴다.** 안 쓰면 다른 앱이 그 명함을 못 찾는다(명함첩의 `idxRecord` 형태를 그대로 따른다: `n c m t e ti d ct ad bz ceo k`).
- **사업자등록번호 없이 업체를 새로 만들지 않는다.** 그게 지금 업체 중복 126쌍이 생긴 경로다.
- **잠긴 폴더(개인잠금) 명함은 idx에 넣지 않는다** — 명함첩의 기존 규칙과 같게.
- 한국어 주석 · ES5 스타일 · 브라우저 시험에서는 **저장 함수를 반드시 가짜로 갈아끼운다**.
- 커밋은 경로 지정. 여러 세션이 같은 작업트리를 공유한다.

## 핵심 설계 결정 — 기존 업체를 만나면 "빈 칸만" 채운다

사업자등록증을 읽었을 때 갈 곳이 두 가지다.

| 상황 | 무엇을 하나 | 왜 |
|---|---|---|
| **사업자번호로 기존 업체를 찾았다** | 그 업체의 **빈 칸만** 채운다 (대표자·업태·종목·개업일·주소 중 비어 있는 것) | 기존 값을 절대 덮지 않으므로 사고가 없다. 그리고 **사업자번호가 없던 업체 63개를 메우는 것이 이 기능의 실제 값**이다 |
| **찾지 못했다** | 명함첩에 `kind:'biz'` 레코드로 남긴다. **사업장 신규 생성은 하지 않는다** | 새 업체를 만드는 일은 계약·청구가 걸린 결정이다. 사진 한 장으로 자동 생성하면 유령 업체가 쌓인다 |

명함은 더 단순하다 — 휴대폰 번호로 중복을 걸러 명함첩에 넣는다(위험이 낮고 명함첩이 이미 그렇게 한다).

중소기업확인서는 기존 업체를 찾았을 때 **기업규모와 유효기간만** 채운다.

test('빈 칸만 채운다 — 기존 값은 절대 덮지 않는다', () => {
  const F = loadFile();
  const out = F.fillGaps(
    { name: '가나상사', ceo: '김대표', bizNo: '', bizType: '' },
    { name: '가나상사(주)', ceo: '홍길동', bizNo: '220-81-62517', bizType: '제조업' });
  assert.deepEqual({ ...out }, { bizNo: '220-81-62517', bizType: '제조업' });
  assert.ok(!('ceo' in out), '기존 대표자를 덮으려 합니다');
