# 푸른사진첩 A단계 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사진 저장 층과 앱 껍데기를 만들고, 파일 창고를 실제로 점검해 저장 방식을 확정한다.

**Architecture:** 사진 저장을 `js/pu-photo-store.js` 한 파일에 가둔다. 파일 창고(Firebase Storage)와 실시간DB 두 방식을 이 파일이 모두 알고, 어느 쪽을 쓸지는 한 곳에서 정한다. 화면 코드는 저장 방식을 모른다 — 점검 결과에 따라 방식이 바뀌어도 화면은 손대지 않는다. 앱은 저장소 관례대로 빌드 없는 단일 HTML(`pu-photos.html`)이다.

**Tech Stack:** Firebase compat SDK 10.12.0 (app / database / storage / auth / app-check) · 빌드 없음 · `node --test`

## Global Constraints

- **설계서:** `docs/superpowers/specs/2026-08-02-푸른사진첩-design.md`. 이 계획과 어긋나면 설계서가 우선이다.
- **Firebase compat SDK 버전은 `10.12.0`** — `pu-camera.html`·`pu-cards.html`과 동일하게 맞춘다.
- **실시간DB 루트는 `puphotos`** — 기존 앱의 루트(`pucards`, `data`, `p_cos`, `p_scheds`)를 절대 건드리지 않는다.
- **파일 창고 루트는 `pu_photos`** — `fund_erp`(기금 서류)를 건드리지 않는다.
- **한국어 주석**을 쓴다. 노무 도메인 용어를 지킨다(급여→임금, 직원→근로자).
- **테스트:** `node --test tests/` 로 실행한다. 빌드가 없으므로 정적 검사(인라인 스크립트 문법 파싱 + 소스 문자열 단정)와 `js/` 단위 검사가 검증 수단이다.
- **`git add .` 금지, `git stash pop` 금지.** 여러 AI 세션이 같은 작업트리를 공유한다. 건드린 파일만 지정해서 add한다.
- **커밋은 반드시 경로를 지정해서 한다** — `git commit -m "..." -- <파일들>`. 다른 세션이 이미 index에 올려둔 파일(현재 `work.html`이 그 상태다)이 내 커밋에 섞여 들어가는 것을 막는다. 새 파일은 `git add` 를 먼저 해야 경로 지정이 먹는다.
- **커밋 직후 `git show --stat HEAD` 로 내가 지정한 파일만 들어갔는지 확인한다.** 남의 파일이 섞였으면 보고한다.
- **화면을 만들기 전에 목업을 먼저 보여주고 승인받는다** (Task 3 Step 1).
- **`Get-Content -Raw` 로 HTML을 읽지 않는다** — 한글이 깨진다. `[System.IO.File]::ReadAllText(path, [System.Text.Encoding]::UTF8)` 를 쓴다.
- **localhost에서 데이터가 안 읽히는 것은 정상이다.** 2026-07-30 규칙 개편으로 익명 로그인이 차단됐다. 고장이 아니다.
- **기존 앱의 클라우드 저장 함수를 브라우저에서 호출하지 않는다.** 2026-07에 브라우저 테스트가 실제 사업장 26곳·일정 53건을 덮어썼다. A단계는 새 파일만 만들고 `enter.html`에 한 줄만 더하므로 그 위험이 없지만, 컨설팅·명함첩 앱을 열어 시험하지 않는다.

### 대표님이 하셔야 하는 선행 조건 (개발자가 대신 못 함)

Task 2의 창고 점검이 통과하려면 파이어베이스 콘솔에서 **파일 창고 접근 규칙**에 `pu_photos` 경로를 추가해야 한다. 기존 실시간DB 규칙과 같은 기준 — 이메일 로그인 계정만 읽고 쓴다.

**규칙이 없어도 점검은 돌아간다.** 막히면 "막힘"으로 보고하고, 그때 실시간DB로 진행한다. 계획이 멈추지 않는다.

`js/pu-photo-store.js` 를 새로 만든다.

```js
/* 푸른사진첩 — 사진 저장 층
   사진을 어디에 어떤 경로로 담을지 정하는 유일한 파일이다.
   '파일 창고(Firebase Storage)'와 '실시간DB' 두 방식을 모두 알고 있고,
   어느 쪽을 쓸지는 이 파일 안에서 정한다. 화면 코드는 방식을 모른다.
   → 1단계 창고 점검 결과로 방식이 바뀌어도 화면은 손대지 않는다.

   나중에 당겨오기 창(컨설팅·급여·기금에서 사진을 가져가는 창)도 이 파일을 쓴다.
   그래서 앱 안이 아니라 js/ 공용 파일로 둔다. */
(function (global) {
  'use strict';

  var DB_ROOT = 'puphotos';       // 실시간DB 루트 — 기존 앱 루트와 겹치지 않게 새로 판다
  var BUCKET_ROOT = 'pu_photos';  // 파일 창고 루트 — 기금 서류(fund_erp)와 분리

  /* 촬영 시각(ms) → 보관 연도.
     연도별로 나눠 담아야 평소에 올해 것만 불러온다(해마다 느려지는 것 방지).
     카톡으로 받은 사진은 촬영 시각이 지워져 있다 — 버리지 않고 'unknown'에 모은다. */
  function yearOf(ts) {
    var n = Number(ts);
    if (!Number.isFinite(n) || n <= 0) return 'unknown';
    return String(new Date(n).getFullYear());
  }

  /* 사진 한 장의 정보(올린 사람·회사·설명 등)가 들어가는 실시간DB 경로 */
  function metaPath(year, id) { return DB_ROOT + '/items/' + year + '/' + id; }

  /* 실시간DB 방식에서 사진 본문(base64)이 들어가는 경로.
     정보와 반드시 갈라 둔다 — 목록만 읽을 때 사진까지 내려받으면 앱이 느려진다. */
  function blobPath(year, id) { return DB_ROOT + '/blobs/' + year + '/' + id; }

  /* 파일 창고 방식의 파일 경로.
     kind: 'full' = 긴 변 1600px 축소본 / 'thumb' = 격자용 작은 미리보기 */
  function filePath(year, id, kind) {
    return BUCKET_ROOT + '/' + year + '/' + id + (kind === 'thumb' ? '_t' : '') + '.jpg';
  }

  global.PuPhotoStore = {
    DB_ROOT: DB_ROOT,
    BUCKET_ROOT: BUCKET_ROOT,
    yearOf: yearOf,
    metaPath: metaPath,
    blobPath: blobPath,
    filePath: filePath
  };
})(typeof window !== 'undefined' ? window : globalThis);
```

## Task 2: 저장 방식 선택과 창고 점검

파일 창고를 실제로 써보는 기능. 작은 파일을 올리고 주소를 받아본 뒤 지운다. **실데이터 경로에 쓰지 않고 전용 점검 경로만 쓴다.**

**Files:**
- Modify: `js/pu-photo-store.js` (Task 1에서 만든 파일에 추가)
- Test: `tests/pu-photo-store.test.js` (Task 1 테스트에 추가)

**Interfaces:**
- Consumes: Task 1의 `BUCKET_ROOT`, `filePath`
- Produces: `window.PuPhotoStore` 에 추가로 노출한다
  - `init(opts: {db?: object, storage?: object, mode?: 'storage'|'rtdb'}): string` — 파이어베이스 객체를 넣고 현재 방식을 돌려준다
  - `getMode(): 'storage'|'rtdb'` — 기본값은 `'rtdb'`
  - `setMode(m: 'storage'|'rtdb'): string` — 다른 값이면 예외를 던진다
  - `probePath(stamp: string): string` — 점검용 경로
  - `probe(stamp: string): Promise<{ok: boolean, step: string, url?: string, message?: string}>` — `step`은 `'init'|'ref'|'upload'|'url'|'delete'|'done'`

> **구현 중 정정(2026-08-02):** 아래 Step 3의 코드는 `getDownloadURL()` 이 거부될 때 그 실패를 맨 끝 `.catch` 로 흘려보내 `step:'upload'` 로 잘못 보고하고, 점검 파일을 창고에 남긴다. 검토에서 잡혔고 커밋 `689bcf0` 에서 고쳤다 — 주소받기 실패를 그 자리에서 갈라 잡아 `step:'url'` 로 돌려주고, 돌려주기 전에 점검 파일을 지우려 시도한다. **현재 `js/pu-photo-store.js` 가 정본이다.**

`stamp`를 밖에서 넣는다. 안에서 현재 시각을 읽으면 테스트가 매번 달라진다.

```js
// 파일 창고 흉내. putString·getDownloadURL·delete 를 마음대로 성공/실패시킨다.
function fakeStorage(behavior) {
  const calls = [];
  return {
    calls,
    ref(p) {
      calls.push(['ref', p]);
      return {
        putString(s) {
          calls.push(['putString', p, s]);
          return behavior.upload === 'fail'
            ? Promise.reject(new Error('권한이 없습니다'))
            : Promise.resolve({});
        },
        getDownloadURL() {
          calls.push(['getDownloadURL', p]);
          return behavior.url === 'fail'
            ? Promise.reject(new Error('주소를 못 받았습니다'))
            : Promise.resolve('https://example.test/' + p);
        },
        delete() {
          calls.push(['delete', p]);
          return behavior.del === 'fail'
            ? Promise.reject(new Error('지울 권한이 없습니다'))
            : Promise.resolve();
        }
      };
    }
  };
}

test('점검 경로는 실사진 경로와 겹치지 않는다', () => {
```

- [ ] **Step 3: 저장 방식 선택과 점검을 구현한다**

`js/pu-photo-store.js` 의 `filePath` 함수 **다음에** 붙이고, 맨 아래 `global.PuPhotoStore = {...}` 를 교체한다.

```js
  /* ── 저장 방식 ──
     기본은 'rtdb'(실시간DB). 이미 명함첩·푸른카메라가 쓰고 있는 검증된 길이다.
     창고 점검을 통과한 뒤에만 'storage'(파일 창고)로 올린다. */
  var mode = 'rtdb';
  var deps = { db: null, storage: null };

  function init(o) {
    o = o || {};
    deps.db = o.db || null;
    deps.storage = o.storage || null;
    if (o.mode) setMode(o.mode);
    return mode;
  }

  function getMode() { return mode; }

  function setMode(m) {
    if (m !== 'storage' && m !== 'rtdb') {
      throw new Error('저장 방식은 storage 또는 rtdb만 가능합니다: ' + m);
    }
    mode = m;
    return mode;
  }

  /* ── 창고 점검 ──
     파일 창고를 이 저장소에서 실제로 써본 적이 없다. 그래서 사진을 담기 전에
     작은 파일 하나로 올리기·주소받기·지우기를 확인한다.
     실사진 경로가 아니라 전용 점검 경로만 쓴다 — 실데이터를 덮어쓰지 않는다. */
  function probePath(stamp) { return BUCKET_ROOT + '/_probe/' + stamp + '.txt'; }

  function probe(stamp) {
    if (!deps.storage) {
      return Promise.resolve({ ok: false, step: 'init', message: '파일 창고가 연결되지 않았습니다' });
    }
    var ref;
    try {
      ref = deps.storage.ref(probePath(stamp));
    } catch (e) {
      return Promise.resolve({ ok: false, step: 'ref', message: (e && e.message) || String(e) });
    }
    return ref.putString('pu-photos probe')
      .then(function () { return ref.getDownloadURL(); })
      .then(function (url) {
        // 지우기가 막혀도 사진은 담을 수 있다. 통과로 보되 규칙을 손보라고 알린다.
        return ref.delete()
          .then(function () { return { ok: true, step: 'done', url: url }; })
          .catch(function (e) {
            return {
              ok: true, step: 'delete', url: url,
              message: '올리기는 됐지만 지우기가 막혔습니다 — ' + ((e && e.message) || e)
            };
          });
      })
      .catch(function (e) {
        return { ok: false, step: 'upload', message: (e && e.message) || String(e) };
      });
  }

  global.PuPhotoStore = {
    DB_ROOT: DB_ROOT,
    BUCKET_ROOT: BUCKET_ROOT,
    yearOf: yearOf,
    metaPath: metaPath,
    blobPath: blobPath,
    filePath: filePath,
    init: init,
    getMode: getMode,
    setMode: setMode,
    probePath: probePath,
    probe: probe
  };
```

```html
    if (r.ok && r.step === 'done') {
      out.textContent = '통과 — 파일 창고를 쓸 수 있습니다.\n올리기 · 주소 받기 · 지우기 모두 됩니다.';
    } else if (r.ok) {
      out.textContent = '일부 통과 — ' + r.message + '\n사진은 담을 수 있습니다. 창고 규칙에서 지우기 권한을 확인하세요.';
    } else {
      out.textContent = '막혔습니다 (' + r.step + ')\n' + (r.message || '') +
        '\n\n창고 규칙이 아직 없을 수 있습니다. 실시간DB로 진행해도 됩니다.';
    }
  });
}
</script>
</body>
</html>
```

배포된 주소에서 포털로 로그인한 뒤 푸른사진첩을 열고, 설정 → 「파일 창고 점검」을 누른다.

`localhost` 에서는 안 된다 — 익명 로그인이 차단돼 있다. 반드시 배포 주소에서 한다.

| 결과 | 다음 |
|---|---|
| 통과 | `pu-photos.html` 의 `PuPhotoStore.init({ db: db, storage: store })` 를 `PuPhotoStore.init({ db: db, storage: store, mode: 'storage' })` 로 바꾸고 커밋한다 |
| 일부 통과 (지우기 막힘) | 대표님께 창고 규칙에서 삭제 권한을 알린다. 그동안은 `mode: 'storage'` 로 진행한다 |

| 규칙을 넣어도 막힘 | 실시간DB로 확정한다. `mode`를 그대로 `'rtdb'` 로 둔다. **B단계는 이 결정과 무관하게 진행된다** |
