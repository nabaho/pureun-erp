# 폴더·탭 드래그 정렬 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기업정보함(`pu-cards.html`)의 네 목록(명함·사업자 폴더 / 기업 상세 폴더 / 메인 탭 / 폴더 안 ＃탭)을 마우스로 끌어 순서를 바꾸고, 그 순서를 전 직원이 함께 보게 저장한다. 끌 수 있는 사람은 대표뿐이다.

**Architecture:** 순서 계산은 순수 함수 `reorderList` 하나에 모으고, 저장은 `saveOrder` 하나가 **한 번의 multi-path `update()`** 로 `order` 칸만 보낸다. 네 목록은 `ordSiblings(kind,id,scope)` 로 「그 항목의 형제 목록」과 「저장 경로」만 다르게 알려 주고, 드래그 손놀림(`onOrdDragStart`/`Over`/`Leave`/`Drop`)은 네 곳이 똑같은 것을 쓴다. 이미 있는 ⋮ 메뉴의 「⬆위로 ⬇아래로」와 명함을 폴더로 끌어 넣는 기존 기능은 그대로 둔다.

**Tech Stack:** 순수 JS(빌드 없음), HTML5 드래그 앤 드롭(`draggable`/`ondragstart`/`ondrop`), Firebase Realtime Database multi-path `update()`, `node:test`+`node:vm` 검사.

## Global Constraints

- 설계서: `docs/superpowers/specs/2026-08-16-드래그-정렬-design.md` — 모든 과제는 이 설계서를 벗어나지 않는다.
- **레코드를 통째로 `set` 하지 않는다.** 반드시 `order` 칸만 보낸다 — 통째 쓰기는 그 사이 남이 고친 이름을 되돌린다(2026-08-11 실제 사고와 같은 종류).
- **바뀐 것을 한 번의 `update()` 로 묶어 보낸다** — 하나씩 보내다 끊기면 순서가 반쯤 섞인다.
- **끌 수 있는 사람은 대표(`state.isAdmin`)뿐이다.** 화면(`draggable` 안 붙이기)과 처리 함수 둘 다에서 막는다. ⚠ 이것은 실수 방지이지 보안 잠금이 아니다(서버 규칙은 직원도 쓸 수 있게 열려 있다) — 규칙은 이번 범위 밖이다.
- **기존 것을 안 건드린다**: ⋮ 메뉴의 `moveFolderOrder`, 명함을 폴더로 끌어 넣는 `onFolderOrCardDrop` 의 `dragId` 갈래, 표의 열 드래그(`onColDragStart`~`onColDrop`).
- **폰(터치)에서는 안 켠다** — HTML5 드래그가 터치에서 동작하지 않는다. 폰에는 ⋮ 메뉴가 이미 있다.
- **개인 창고 폴더(`state.priv.groups`)는 끌 수 없다** — 공용 자리(`state.groups`)가 아니라 순서 개념이 다르다. `openFolderMenu` 가 이미 같은 이유로 되돌아간다.
- 클라우드에 연결돼 있지 않으면(`Store.mode!=='firebase'`) 안내만 하고 아무 것도 안 쓴다.
- 파일 수정은 Edit/Write 도구만 쓴다 — PowerShell `Get-Content`/`Set-Content` 왕복은 UTF-8 한글을 깨뜨린 전례가 있다.
- 커밋 전 `node --test tests/*.test.js` 전체 실행(0 실패), 뮤테이션으로 새 검사가 실제로 잡는지 확인.

- [ ] **Step 3: `reorderList` 구현**

`pu-cards.html` 에서 `function onFolderOrCardDrop(...)` 함수가 끝나는 `}` 다음 줄(현재 약 6035행)에 아래를 넣는다:

```javascript

/* ══════ 끌어서 순서 바꾸기 (대표 지시 2026-08-16) ══════
   네 목록이 같은 계산·같은 저장을 쓴다 — 명함·사업자 폴더, 기업 상세 폴더,
   메인 탭, 폴더 안 ＃탭. 같은 일을 네 곳에 베끼면 한 곳만 고쳐져 어긋난다.
   ⚠ 이미 있는 ⋮ 메뉴의 「⬆위로 ⬇아래로」(moveFolderOrder)는 그대로 둔다 —
     드래그가 안 되는 자리(폰·터치)의 길이자, 이 기능이 고장 나도 쓸 수 있는 길이다. */

/* 끈 것을 놓은 자리 «앞»에 끼워 넣고 1..n 으로 번호를 다시 매긴다.
   돌려주는 것은 **값이 실제로 달라진 것만** — 안 바뀐 것까지 저장하면
   서버에 쓸데없는 쓰기가 나가고, 남이 그 사이 고친 것과 부딪힐 일만 는다. */
function reorderList(list, dragId, dropId){
  const arr = (list||[]).slice();
  if(dragId === dropId) return [];
  const from = arr.findIndex(x=>x && x.id===dragId);
  const to   = arr.findIndex(x=>x && x.id===dropId);
  if(from < 0 || to < 0) return [];
  const moved = arr.splice(from, 1)[0];
  const at = arr.findIndex(x=>x && x.id===dropId);
  arr.splice(at, 0, moved);
  const out = [];
  arr.forEach((x,i)=>{ const n = i+1; if((x.order||0) !== n) out.push({ id:x.id, order:n }); });
  return out;
}
```

**Interfaces:**
- Consumes: `reorderList(list, dragId, dropId)` (Task 1)
- Produces:
  - `ordSiblings(kind, id, scope)` → `{ list, pathOf, applyLocal }`. `kind` 는 `'group'|'cofolder'|'view'|'coftab'`. `scope` 는 `coftab` 일 때 부모 폴더 id, 아니면 `''`. `list` 는 그 항목의 **형제 목록**(정렬됨), `pathOf(id)` 는 `DB_ROOT` 아래 상대 경로(예: `'groups/g1/order'`), `applyLocal(id, order)` 는 화면이 곧바로 새 순서로 그려지게 메모리 값을 바꾼다. 못 다루는 kind 면 `null`.
  - `saveOrder(kind, dragId, dropId, scope)` → `Promise`. 대표가 아니거나 클라우드가 아니면 아무 것도 안 쓰고 되돌아간다.
  - `onOrdDragStart(e, kind, id, scope)` / `onOrdDragOver(e)` / `onOrdDragLeave(e)` / `onOrdDrop(e, kind, id, scope)` — Task 3~6 이 화면에 붙인다.
  - `_dragOrd` — 지금 끌고 있는 것 `{kind, id, scope}` 또는 `null`.

/* ── 저장 층 ── 네 목록이 같은 저장을 쓴다.
   ⚠ 여기서 지키는 두 가지가 이 기능의 안전선이다.
     ① order 칸만 보낸다 — 레코드를 통째로 set 하면 그 사이 남이 고친 이름이 되돌아간다
     ② 한 번의 update() 로 묶는다 — 하나씩 보내다 끊기면 순서가 반쯤 섞인다 */
function loadSave(opts){
  opts = opts || {};
  const at = source.indexOf('function reorderList(');
  const end = source.indexOf('\nfunction onOrdDragStart', at);
  assert.ok(at > 0 && end > at, 'reorderList~onOrdDragStart 사이를 찾지 못했습니다');
  const updates = [], toasts = [];
  const ctx = {
    DB_ROOT: 'pucards',
    state: {
      isAdmin: opts.isAdmin !== false,
      groups: opts.groups || {},
      views:  opts.views  || {},
      priv:   { groups:{} },
      tab: 'card', group: 'all'
    },
    _coFolders: opts.coFolders || {},
    toast: m => toasts.push(m),
    render: () => {},
    Store: {
      mode: opts.mode || 'firebase',
      db: { ref: p => ({ update: v => { updates.push({ path:p, v }); return Promise.resolve(); } }) }
    }
  };
  vm.createContext(ctx);
  vm.runInContext(source.slice(at, end), ctx);
  ctx._updates = updates; ctx._toasts = toasts;
  return ctx;
}

function saveOrder(kind, dragId, dropId, scope){
  if(!state.isAdmin){ return Promise.resolve(); }   /* 화면 게이트를 넘겨도 여기서 막는다 */
  const spec = ordSiblings(kind, dragId, scope||'');
  if(!spec) return Promise.resolve();

  if(!changed.length) return Promise.resolve();     /* 바꿀 것이 없으면 서버를 안 부른다 */
  if(Store.mode!=='firebase'){ toast('클라우드에 연결된 상태에서만 순서를 바꿀 수 있습니다'); return Promise.resolve(); }
  const upd = {};
  changed.forEach(x=>{ upd[spec.pathOf(x.id)] = x.order; });

  changed.forEach(x=>{ spec.applyLocal(x.id, x.order); });

  if(!state.isAdmin) return;
  _dragOrd = { kind:kind, id:id, scope:scope||'' };

function onOrdDragOver(e){
  if(!_dragOrd) return;                 /* 명함을 끄는 중이면 기존 길에 맡긴다 */
  e.preventDefault(); e.stopPropagation();

  e.currentTarget.classList.remove('ord-dragging');

  document.querySelectorAll('.ord-dragover').forEach(n=>n.classList.remove('ord-dragover'));

  e.currentTarget.classList.remove('ord-dragover');
