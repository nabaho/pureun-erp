# 기업정보 폴더와 탭 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기업정보 화면에 명함·사업자 갈래와 같은 「손으로 만드는 폴더」와 「여럿에 겹쳐 붙는 탭」을 더해, 컨설팅 신청이 들어온 사업장을 사업 단위로 모아 관리할 수 있게 한다.

**Architecture:** 새 회사 「갈래」를 만들지 않는다 — 기존 `pucards/coInfo/<회사열쇠>` 레코드에 `folder`(문자열 하나)와 `tags`(이미 있는 필드)를 더 쓴다. 폴더 목록은 `pucards/coFolders/<id>`에 따로 둔다. 화면은 이미 있는 명함 폴더 이동 UI(`#folderDlg`/`#folderDlgBg`, `.movefolder`)를 그대로 재사용한다.

**Tech Stack:** 빌드 없는 단일 HTML(`pu-cards.html`) + Firebase Realtime Database. 검사는 `node:test` + `node:assert/strict`, 순수 함수는 `node:vm`으로 `pu-cards.html`에서 코드 조각을 뽑아 실행한다(`tests/cards-hwp-integration.test.js`의 `loadMgTableHtml` 방식을 그대로 따른다).

## Global Constraints

- 새 `kind`(`'co'` 등)나 `state.tab` 값을 만들지 않는다 — 기업정보는 화면이지 갈래가 아니다(설계서 §"안 하기로 한 것").
- 회사를 가르는 열쇠는 **사업자번호**다(`coKeyOf`). 폴더·탭은 이 열쇠에 붙는다.
- 폴더는 회사 하나에 **하나만**(`coInfo/<key>/folder`, 문자열). 탭은 **여럿**(`coInfo/<key>/tags/<탭이름>`, 불리언 맵) — 이미 있는 구조를 그대로 쓴다.
- 탭 이름에서 `. # $ [ ] /` 를 뺀다 — 실시간DB 열쇠에 못 쓰는 글자다. `js/pu-doc-file.js`의 `sendToCoInfo`가 이미 하는 것과 같은 규칙(`replace(/[.#$/[\]]/g, ' ').replace(/\s+/g, ' ').trim()`)을 화면 쪽에도 둔다.
- 폴더를 지워도 회사는 안 지운다 — `folder` 값만 비운다.
- 탭은 **지우지 않는다** — 숨기기만 둔다(`pucards/coTagHidden/<탭이름>`).
- 회사 열쇠가 이름 열쇠(`n...`)에서 사업자번호 열쇠로 바뀌면, 옛 이름 열쇠에 있던 `folder`·`tags`가 안 보이게 된다. **조용한 배경 쓰기로 옮기지 않는다** — 읽을 때 두 열쇠의 값을 합쳐 보여준다(`coEffectiveExtra`). 사람이 다시 손대면 그때부터 새 열쇠에 남는다.
- Firebase 다중 경로 쓰기는 `Store.db.ref(DB_ROOT).update(upd)` 하나로 모은다 — 회사 하나씩 따로 쓰면 중간에 실패했을 때 절반만 반영된다.
- 파일은 UTF-8. 주석과 화면 글은 한국어, 이 저장소 말투(왜 이렇게 했는지)를 따른다.
- 커밋 메시지는 한국어, `feat(기업정보): …` 또는 `test(기업정보): …` 꼴.
- 모든 과제 끝에 `node --test tests/*.test.js` 가 `fail 0` 이어야 한다.

- [ ] **Step 3: `coEffectiveExtra`를 만든다**

`pu-cards.html`에서 `const coKeyOf = it => { const d=digits(it.bizno||''); return d.length>=10 ? d : ('n'+_norm(it.company||'')); };` 줄 **바로 뒤**에 넣는다.

```javascript

/* 회사 열쇠가 이름 열쇠(n...)에서 사업자번호 열쇠로 바뀌면, 옛 이름 열쇠에 있던
   folder·tags 가 안 보이게 된다 — 사업자등록증이 나중에 들어온 회사가 이 경우다
   (설계서 2026-08-13, "회사 열쇠가 바뀌어 폴더가 끊어짐" 대비).
   ⚠ 조용한 배경 쓰기로 옮기지 않는다. 옮기다 실패하면 대표가 모르는 새 사라진다.
     읽을 때 두 열쇠의 값을 합쳐 보여준다 — 사람이 다시 손대면 그때부터 새 열쇠에 남는다. */
function coEffectiveExtra(key, name, coInfoMap){
  const cur = coInfoMap[key];
  const nameKey = 'n'+_norm(name||'');
  if(nameKey===key) return cur || null;   /* 합칠 상대가 없다 */
  const old = coInfoMap[nameKey];
  if(!old) return cur || null;
  if(!cur) return old;
  /* 폴더는 하나만 있을 수 있다 — 새 열쇠에서 사람이 다시 정한 것을 우선한다.
     탭은 여럿 겹칠 수 있다 — 옛 것도 새 것도 버리지 않는다. */
  return Object.assign({}, old, cur, {
    tags: Object.assign({}, old.tags||{}, cur.tags||{}),
    docs: Object.assign({}, old.docs||{}, cur.docs||{}),
    folder: cur.folder || old.folder || ''
  });
}
```
