# 명함첩 중복 정리 — ⚠중복 배지를 눌러 판단하고 한 번에 치우기

작성일 2026-08-10 · 지시: 대표
> "중복의 경우 중복 단어 클릭하면 중복 삭제 또는 합치기 등 판단할 수 있는 부분을
> 팝업시켜주고 한번에 정리 할 수 있게도 해달라."

## 지금 무엇이 문제인가

명함 표의 `⚠중복` 은 **글자일 뿐 눌리지 않는다.** 누구와 겹쳤는지 알 길이 없다.

그리고 배지와 「🧹 중복 정리」의 **기준이 다르다.**

| | 기준 |
|---|---|
| `⚠중복` 배지 (`isDup`) | 휴대폰·이메일·(이름+회사) 중 **하나라도** 겹치면 붙는다 |
| 🧹 중복 정리 (`findDupGroups`) | 같은 기준으로 묶은 뒤 **이름이 서로 다른 묶음을 버린다** |

이름을 걸러내는 것은 옳다 — 회사 대표이메일(`info@…`)을 여럿이 함께 쓰거나 회사
대표번호를 휴대폰 칸에 적은 명함이 흔해서, 그것만 보고 합치면 김철수와 박영희가
한 장이 되고 한 사람이 휴지통으로 사라진다. 합친 뒤에는 어느 값이 누구 것이었는지
알 수 없어 되돌려도 원래대로 돌아오지 않는다.

**문제는 그 명함이 배지를 영원히 달고 있으면서 정리 목록에는 안 나온다는 것이다.**
사람이 「이건 다른 사람이다」라고 말할 자리가 없다.

또 지금 정리 화면은 이름과 회사만 보여준다. **무엇이 다른지 모르고 「병합」을 눌러야
한다.** 그리고 합치기만 있고 **지우기가 없다.**

## 만들 것

### 1. 배지를 누르면 열리는 팝업

`⚠중복` → `openDupFix(id)` → 그 명함이 든 묶음만 **칸별로 나란히** 본다.

- 열 = 겹친 명함들(등록일 표시), 행 = 칸(이름·회사·직책·핸드폰·회사전화·이메일·주소·폴더)
- 색이 판단을 대신한다
  - **빨강** 이름이 다름 → 다른 사람일 수 있음
  - **노랑** 값이 다름 → 합치면 메모에 `[병합]` 으로 남는다
  - **초록** 한쪽이 비어 있음 → 합치면 채워진다
- 이름이 하나로 모이지 않으면 머리에 **경고 띠**: 「이메일만 같습니다. 회사 대표주소를
  여럿이 함께 쓰는 경우일 수 있습니다」

### 2. 세 가지 선택

| 단추 | 하는 일 |
|---|---|
| 한 장으로 합치기 | 고른 것을 **바탕**으로 삼아 나머지를 얹는다. 빈 칸은 채우고, 값이 다르면 메모에 `[병합]` 으로 남긴다. 사진도 지킨다 |
| 고른 것만 남기고 휴지통 | 나머지를 휴지통으로. **30일 안에 되살릴 수 있다** |
| 중복 아님 | 이 묶음의 짝을 「겹친 것 아님」으로 적어 둔다 → 배지가 사라진다 |

「남길 것」은 라디오로 사람이 고른다. 기본값은 **가장 최근에 고친 것**.

### 3. 「중복 아님」의 저장 자리 — 이 PC만

`localStorage: pucards_dup_ignore`, 짝 서명(`id1~id2`, 정렬) 목록.
유사 항목 검사의 `pucards_sim_ignore` 와 같은 방식이다.

- 이유: 서버를 안 건드려 가볍고, 규칙을 손댈 일이 없다(콘솔이 진짜인 규칙을 만지는
  것은 그 자체가 위험이다)
- 값: **배지 판정(`isDup`)과 묶기(`dupGroupOf`) 양쪽에서 함께 걸러야 한다.**
  한쪽만 걸면 「배지는 없는데 정리 목록엔 있다」가 된다
- 되돌리기: 팝업 아래에 「중복 아님으로 적어 둔 N건 보기」 — 목록에서 지우면 배지가
  돌아온다. 되돌릴 길이 없는 지우기는 만들지 않는다

### 4. 「한 번에 정리」 — 안전한 것만 자동

지금 「⚡ 모든 묶음 자동 병합」은 이름이 다른 묶음을 애초에 안 받으므로, 눌러도 그
묶음들은 그대로 남고 왜 남았는지 말해 주지 않는다.

새 동작:

1. **이름까지 같은 묶음** = 확실한 중복 → 한 번에 모두 합친다
2. **이름이 엇갈리는 묶음** = 사람이 봐야 함 → 목록으로 남기고 **몇 건인지 숫자로** 알린다
3. 목록의 각 줄은 팝업으로 이어진다 — 한 장씩 보고 합치거나 「중복 아님」

끝나면 「확실한 중복 N묶음 합쳤습니다. 사람이 봐야 할 M묶음이 남았습니다」.

## 짜임새

새 함수는 **순수 로직**과 **화면**을 나눈다. 순수 로직만 검사한다(화면은 단일 파일 앱이라
띄울 수 없다).

```
순수 로직 (검사 대상)
  dupIgnoreKey(a,b)      짝 서명 — 정렬해 한 가지 모양으로
  dupLinked(a,b,ignore)  두 명함이 이어지나 (열쇠 겹침 - 「중복 아님」)
  dupGroupsOf(items,ignore)   묶음 전부 (이름 안 걸러냄)
  dupGroupFor(items,id,ignore) 한 명함이 든 묶음
  dupSameName(group)     이름이 하나로 모이나 → 확실한 중복인가
  dupFieldRows(group,fields)   칸별 비교표 (값 + 상태: same|diff|fill|namediff)
  dupPickKeeper(group)   기본으로 남길 것 (가장 최근 고친 것)

화면
  openDupFix(id)         팝업 그리기
  dupFixMerge/Delete/NotDup
  openDedup()            「한 번에 정리」 (고쳐 씀)
```

## 지키는 것

- **지우기는 휴지통으로.** `Store.del` 이 이미 그렇게 한다 — 직접 지우지 않는다
- **합치기 전에 무엇이 다른지 반드시 보인다.** 안 보이면 판단이 아니라 도박이다
- **「중복 아님」은 되돌릴 수 있다.** 목록과 지우기를 함께 만든다
- **개인 폴더(잠금) 명함은 이 팝업에 섞지 않는다.** 공용 목록에서 개인 명함이 옆에 나오면
  숨긴 사실이 드러난다
- 3장 이상 겹치면 열이 늘어난다 — 두 장만 다루지 않는다

## 검사

새 `tests/cards-dup-fix.test.js` — pu-cards.html 에서 순수 로직 덩어리를 잘라 실제로 돌린다.

- 열쇠가 겹치면 묶인다 / 안 겹치면 안 묶인다
- 「중복 아님」한 짝은 묶이지 않고 배지도 안 붙는다
- 이름이 다르면 `dupSameName` 이 거짓 → 자동 합치기에서 빠진다
- 칸별 비교가 same·diff·fill·namediff 를 제대로 가른다
- 3장 묶음도 된다
- 기본 남길 것 = 가장 최근 고친 것
