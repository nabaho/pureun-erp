# 급여데이터함 2중 대시보드 — 설계서

- 날짜: 2026-08-17
- 대표 결정: **안 4 + 안 2**(목업 `docs/mockups/paydata-two-pane.html`), 접기 단추(안 3)도 함께
- 앞선 결정: 유형 「급여」만·계약중단 제외(2026-08-17 병합 완료), 자료 온 곳 먼저, 검색은 사람·업체 둘 다

## 1. 왜 바꾸나

지금 왼쪽 칸은 **사람 트리 하나**다. 사람을 펼치면 그 사람 업체가 트리 안에 딸려 들어온다.

- 한 사람이 20~33곳을 맡는다. 한 명만 펼쳐도 화면 두 배가 되고, 둘 펼치면 못 쓴다.
- 담당자는 **자기 것만** 본다 — 남의 이름이 목록 대부분을 차지한다.
- 관리자는 **전부** 봐야 한다 — 112곳을 트리로 훑을 수는 없다.

원인은 업체 목록이 **남의 칸에 얹혀 있다**는 것이다. 사업장에 전용 칸을 주면
화면 높이를 통째로 써서 메일함처럼 굴러간다 — 33곳이든 112곳이든 같다.

## 2. 무엇을 만드나

```
┌─────────┬──────────────┬────────────────────────┐
│ ① 보기  │ ② 사업장 목록 │ ③ 본문(서랍·값 표·뷰어) │
│ + 담당자 │              │                        │
└─────────┴──────────────┴────────────────────────┘
  132px    ‹  214px                   나머지
```

### ① 첫 칸 — 「보기」가 먼저, 「담당자」가 그 아래

사람이 아니라 **보기**를 맨 위에 둔다. 안 1~3은 담당자에게 첫 칸이 자기 이름
하나뿐이라 무용지물이었다 — 그래서 숨기거나 접어야 했다. 보기로 두면
**담당자도 관리자도 같은 구조**를 쓴다.

**내 일** (모두에게)

| 항목 | 무엇 |
|---|---|
| 내 담당 | 내가 주·부담당인 급여 업체 전부 |
| 아직 안 온 곳 | 그중 이 달 자료가 0장인 곳 |
| 오늘 들어온 것 | 그중 오늘 자료가 들어온 곳 |
| 공유받음 | 남이 나에게 공유한 업체 |

**전체** (관리자만 — `S.amAdmin()`)

| 항목 | 무엇 |
|---|---|
| 전체 사업장 | 급여 112곳 |
| 전체 미도착 | 그중 이 달 0장 |
| 담당 없음 | 업체관리에 주·부담당이 없는 급여 업체 |

**담당자** (관리자만) — 안 2의 진행률

사람 줄마다 `22/33` 과 막대, 그 밑에 「아직 11곳」. 관리자가 **누가 밀렸는지**
첫 칸에서 바로 본다 — 지금은 알 길이 없는 정보다.
한 번도 급여데이터함에 안 들어온 사람은 「아직 안 들어옴」을 단다.

**접기** — 칸 사이 「‹」 하나로 첫 칸을 밀어 넣는다. 왼쪽 두 칸이 346px을
먹어 13인치에서 본문이 빠듯하기 때문이다. **담당자는 접힌 채로 시작한다**
(보기 넷은 접힌 상태에서도 아이콘 줄로 남는 게 아니라, 펼치면 나온다 —
담당자도 「아직 안 온 곳」은 쓰므로 기본 펼침으로 두고 접기는 본인이 고른다).

### ② 둘째 칸 — 사업장 목록

- 머리: 지금 보기 이름 + 곳수
- 찾기: 사업장 이름. **전체 보기에서는 담당자 이름으로도 찾힌다**
  (대표 결정 "사람·업체 둘 다" — 「화담원」을 치면 누가 맡았는지 옆에 뜬다)
- 칩: 전체 / 안 온 곳 / 온 곳
- 줄: ●(도착) 이름 · [담당자 — 남의 것일 때만] · 장수
- **내 담당 보기에서만** 손잡이(⠿ 순서 바꾸기)와 「↗ 공유」가 붙는다
- 남의 업체를 누르면 지금 그대로 **사유를 묻고** 들어간다(대리면 안 묻는다)

### ③ 본문

지금 화면 그대로다. 「전체 사업장」 보기일 때만 본문이 지금의 사업장 표
(고르기·한꺼번에 처리)로 간다 — 기업 명단 전체를 봐야 할 때 쓰는 자리다.

## 3. 담당자 명단을 어디서 뽑나

지금은 `paydata/owners`(**한 번이라도 로그인한 사람**)에서 뽑는다. 그래서
대부분이 안 보인다. 바꾼다:

1. 급여 업체의 `managerMain`·`managerSubs`(사번)를 모은다 — 이것이 곧 배정이다
2. 사번 → 이메일(`sidToEmail`) → 공개 명부 `data/user_dir` 에서 이름을 찾는다
3. `paydata/owners` 에서 같은 이메일을 찾아 uid 를 붙인다
4. uid 를 못 찾으면 **「아직 안 들어옴」** — 이름·업체는 보이되 그 사람 자리는
   못 연다(아직 자료가 없다). 누르면 안내만 뜬다

업체관리에서 담당을 바꾸면 여기도 따라 바뀐다. **따로 배정하는 화면은 만들지 않는다.**

## 4. 안 바꾸는 것

- 순서 바꾸기(myOrder), ↗ 공유와 공유사항 체크, 남의 서랍 열 때 사유 묻기,
  대리 지정, 자리 옮기기 — 모두 그대로
- 업체 명단은 계속 업체관리(`data/companies`)가 진짜다. 급여데이터함은 읽기만 한다
- 콘솔 규칙은 손대지 않는다. `data/user_dir` 은 이미 포털·로그인이 읽는 공개 명부다

## 5. 위험한 곳

- **폭**: 132 + 15 + 214 = 361px. 1280 화면에서 본문 900px — 값 표는 괜찮고
  판독 패널(원본+판독 절반씩)은 빠듯하다. 판독 패널을 열면 첫 칸을 자동으로
  접는다.
- **모바일**: 지금도 760px 아래에서는 왼쪽 칸을 숨긴다. 두 칸 다 숨긴다.
- **다시 그리기**: 둘째 칸 찾기 칸은 글자를 칠 때마다 화면을 다시 그린다 —
  `restoreFocus` 에 이 칸을 반드시 등록해야 한다(안 하면 한 글자 치고 커서가 빠진다,
  이미 네 곳에서 겪은 일).
- **user_dir 를 못 읽을 때**: 이름 없이 사번으로라도 세운다. 명부 하나 못 읽었다고
  담당자가 통째로 사라지면 안 된다.
