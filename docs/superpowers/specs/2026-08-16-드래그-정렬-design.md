# 폴더·탭을 마우스로 끌어 순서 바꾸기

작성 2026-08-16 · 대상 `pu-cards.html`

## 왜 필요한가

대표 지시 2026-08-16 저녁: *"기업정보함 전체 폴더는 마우스로 드래그로 위아래 움직이게
해라, 그리고 메인의 탭도 마우스로 좌우 움직이게 해달라. 이부분은 기업정보함 전체에
저장해달라."*

지금도 순서를 바꿀 수는 있다 — 명함 폴더 ⋮ 메뉴의 「⬆ 위로 / ⬇ 아래로」 하나씩. 폴더가
열 개면 맨 아래 것을 맨 위로 올리는 데 아홉 번을 눌러야 한다. 기업 상세 폴더와 메인 탭에는
그마저도 없다.

## 이미 있는 것 (새로 만들 것이 적다)

조사해 보니 **절반은 이미 있다.**

| 있는 것 | 자리 | 상태 |
|---|---|---|
| `moveFolderOrder(id, ±1)` | `pu-cards.html` | 명함 폴더 순서를 바꾸고 저장까지 한다. ⋮ 메뉴에서 부른다 |
| `onFolderDrag(e, gid)` | 〃 | 폴더를 **끌기 시작**하는 것까지 된다(`dragFolderId` 를 세운다) |
| `onFolderOrCardDrop` | 〃 | **놓았을 때 폴더끼리는 아무 일도 안 한다** — 주석에 "폴더끼리는 계층 없음 — 순서는 ⋮ 메뉴로" |
| 열 순서 드래그 | 〃 (`onColDragStart`~`onColDrop`) | 표의 열을 좌우로 끌어 바꾸는 것이 **이미 잘 돈다**. 좌우 드래그의 본보기 |
| `order` 칸 | 네 목록 모두 | 이미 있고 `sort((a,b)=>(a.order||0)-(b.order||0))` 로 정렬 중 |

즉 **비어 있는 자리를 채우고, 나머지 세 목록으로 넓히는** 일이다.

## 대상 — 네 목록

| # | 목록 | 방향 | 자료 자리 | 저장 |
|---|---|---|---|---|
| ① | 명함·사업자 폴더 | 위아래 | `state.groups` | `Store.putGroup` → `pucards/groups/<id>` |
| ② | 기업 상세 폴더 | 위아래 | `_coFolders` | `putCoFolder` → `coFolders/<id>` |
| ③ | 메인 탭(전체·자문·급여·노조·기금·사무대행) | 좌우 | `state.views` | `Store.putView` → `pucards/views/<id>` |
| ④ | 폴더 안 ＃탭 | 위아래 | 부모 폴더의 `folder.tabs[id]` | `putCoFolder` 한 번(부모째 저장) |

④ 만 모양이 다르다 — 탭이 부모 폴더 **안에** 들어 있어, 한 폴더의 탭 순서를 바꾸면
`putCoFolder` **한 번**으로 끝난다.

## 만들 것

### 1. 순서 계산 — 순수 함수 하나

```
reorderList(list, dragId, dropId) → 새 배열
```

- `list` 는 이미 정렬된 배열(`{id, order, ...}`).
- 끈 것을 빼서 **놓은 자리 앞에** 끼워 넣는다.
- 결과에 `order = 1..n` 을 다시 매긴다.
- 화면도 저장도 안 건드린다 — 그래서 검사로 곧장 돌릴 수 있다.

**되돌아보는 자리**: `dragId === dropId` 이거나 둘 중 하나가 목록에 없으면 **원래 배열을
그대로** 돌려준다(아무 것도 저장하지 않게).

### 2. 저장 — 한 번의 update 로 묶는다

지금 `moveFolderOrder` 는 두 폴더를 `Store.putGroup` 으로 **하나씩** 보낸다. 드래그는
여러 개가 한꺼번에 바뀌므로, 바뀐 것만 모아 **한 번의 `update()`** 로 보낸다.

```
Store.db.ref(DB_ROOT).update({ 'groups/<id>/order': 1, 'groups/<id2>/order': 2, ... })
```

중간에 끊겨 순서가 반쯤 섞이는 것을 막는다(이 저장소가 이미 여러 곳에서 쓰는 방식).
실패하면 `.catch` 로 안내한다 — 이 파일의 30여 곳이 이미 그렇게 한다.

⚠ **`order` 만 보낸다.** 레코드를 통째로 `set` 하면 그 사이 남이 고친 이름이 되돌아간다
(이 저장소가 2026-08-11 에 실제로 겪은 사고와 같은 종류).

### 3. 화면 배선 — 대표만

- 대표(`state.isAdmin`)일 때만 `draggable="true"` 와 「끌 수 있음」 커서를 붙인다.
- **놓았을 때 처리하는 함수에서도 다시 막는다** — 화면만 막으면 개발자도구로 넘길 수 있다.
- 기존 ⋮ 메뉴의 「⬆ 위로 / ⬇ 아래로」는 **그대로 둔다**. 드래그가 안 되는 상황(터치·손떨림)의
  대안이자, 이 기능이 고장 나도 순서를 바꿀 수 있는 길이다.

**⚠ 이것은 보안 잠금이 아니다.** 서버 규칙은 직원도 `pucards/groups` 를 쓸 수 있게 열려
있다. 그래서 「대표만」은 **실수 방지**이지 못 하게 막는 장치가 아니다. 진짜로 막으려면
규칙을 고쳐야 하는데, 규칙은 콘솔에 사람이 직접 붙여넣는 것이라 이번 범위 밖이다
(대표 확인함 2026-08-16).

### 4. 눈에 보이는 것

- 끄는 중인 항목은 흐리게 — 기존 `.col-dragging` 과 같은 결.
- 놓일 자리 표시: 폴더는 **파란 가로줄**, 메인 탭은 **파란 세로줄** — 기존 `.col-dragover` 와
  같은 결.
- 놓으면 곧바로 다시 그리고 「순서를 바꿨습니다」 안내.

### 5. 기존 「명함을 폴더로 끌어 넣기」와 겹치는 것

같은 폴더 줄이 **두 가지 드롭**을 받는다.

```
명함을 끌어 폴더에 놓음  → 그 명함을 그 폴더로 옮긴다 (기존 기능, 그대로)
폴더를 끌어 폴더에 놓음  → 순서를 바꾼다 (이번에 새로)
```

코드는 이미 `dragId`(명함)와 `dragFolderId`(폴더)로 무엇을 끌었는지 구분한다.
`onFolderOrCardDrop` 의 **이미 비어 있는 폴더 갈래**를 채우면 된다 — 기존 명함 갈래는
한 글자도 안 건드린다.

## 안 하기로 한 것

- **폰(터치)에서는 안 켠다.** HTML5 드래그는 터치에서 동작하지 않는다. 폰에는 ⋮ 메뉴가
  이미 있으므로 순서를 바꿀 길이 없어지는 것은 아니다.
- **부드러운 애니메이션(포인터 이벤트 직접 구현)은 안 한다.** 코드가 훨씬 길고, 이 파일의
  기존 드래그와 손놀림이 달라져 두 방식이 공존하게 된다.
- **폴더 계층(폴더 안에 폴더)은 안 만든다.** 이미 폐지된 구조다(`parent` 정리 코드가 있다).
- **서버 규칙은 고치지 않는다.**

## 새로 만든 것이 기존 순서를 망가뜨리지 않는가

지금 폴더는 만들 때 `order: Date.now()`(아주 큰 수)를 받는다. 드래그로 재번호를 매기면
1..n 이 된다. 그 뒤에 새 폴더를 만들면 `Date.now()` 라 **항상 맨 끝**에 붙는다 — 지금과
같은 동작이다. 다음 드래그 때 그것도 1..n 안으로 들어온다.

## 에러 처리

- 클라우드에 연결돼 있지 않으면(`Store.mode!=='firebase'`) 안내만 하고 아무 것도 안 쓴다.
- 저장이 실패하면 `.catch` 로 알리고, 화면은 다시 그려 서버의 실제 순서로 되돌린다
  (성공한 척 남지 않게).
- 목록이 한 개거나 제자리에 놓으면 아무 것도 저장하지 않는다.

## 검사

- `reorderList` 는 순수 함수라 vm 으로 직접 돌린다 — 위→아래, 아래→위, 제자리,
  맨 끝으로, 목록 1개, 없는 id.
- 「대표가 아니면 `draggable` 이 안 붙는다」.
- 「대표가 아니면 놓아도 저장이 안 된다」(화면 게이트를 넘겨도 막히는지).
- 「저장이 **한 번의** `update()` 로 나간다」 — 하나씩 보내면 실패하게.
- 「레코드를 통째로 `set` 하지 않고 `order` 만 보낸다」.
- 「명함을 끌어 폴더에 놓는 기존 동작이 그대로다」.
- 뮤테이션으로 각 검사가 실제로 잡는지 확인한다.
