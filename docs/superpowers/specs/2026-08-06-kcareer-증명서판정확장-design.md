# kcareer 증명서 판정 확장 — 외부기관 발급 실적증명서 등록

- 작성일: 2026-08-06
- 대상 앱: `kcareer.html`, 판정 모듈 `js/kcareer-scan.js`
- 선행 작업: 2026-07-31 서류 일괄등록, 2026-08-01 실적 동기화·증명서 보관

## 1. 목표

외부기관(능률협회·경제진흥원 등)이 발급해준 **실적증명서 67건을 등록**해
외부기관 실적 탭의 기관 묶음에 붙인다. 지금은 0건이다.

## 2. 원인 — 판정 규칙이 증명서에 맞지 않는다

위촉장 작업에서 확립한 규칙은 **"이름 끝이 결과물 낱말이면 승격"**이다.
`위촉장 목록`·`위촉식 시나리오` 같은 오탐을 막기 위한 것이고 위촉장에는 잘 맞았다.

그런데 증명서 파일명은 **`증명서_대상_본인이름`** 꼴이 흔하다.

```
2024 구조혁신지원사업 컨설팅 수행실적 증명서_(주)코시노인터네셔널_권형하.pdf  → 끝이 '권형하'
경력증명서-푸른.pdf                                                    → 끝이 '푸른'
재직증명서-권형하.pdf                                                  → 끝이 '권형하'
실적증명서- 중소벤처기업부 비즈니스지원단.pdf                              → 끝이 '지원단'
```

실측(2026-08-06): 증명서 낱말이 든 원본 확장자 파일 **205건 중 현재 규칙은 15건만** 잡는다.
**190건이 누락**된다. 이것이 "이 기관이 발급한 증명서 0건"의 직접 원인이다.

## 3. 확정 결정 (사용자)

1. **증명서 낱말만 예외적으로 "이름 어느 자리에든" 허용.** 위촉장·표창 등은 "이름 끝" 유지.
2. **외부기관 발급 실적증명 67건을 먼저** 등록. 본인 경력·재직증명서 146건은 나중.
3. 발급기관은 **폴더 경로 추정 + 행의 🔍 OCR 보정**.

## 4. 판정 규칙 — 종류별로 두 갈래

| 종류 | 규칙 | 근거 |
|---|---|---|
| 위촉장·위촉계약서·재위촉·표창·포상·상장·자격증·수료증·이수증·협약서 | **이름 끝** (기존 `RESULT_END`) | `위촉장 목록`·`위촉식 시나리오` 오탐 방지 |
| **증명서·확인서** | **이름 어느 자리에든** (신규 `CERT_ANY`) | `증명서_대상_이름` 꼴이 흔해 끝을 보면 전부 놓친다 |

```js
CERT_ANY = /실적\s*증명|수행실적\s*증명|경력증명|재직증명|참여확인서|수행확인서|용역수행/
```

**부정어(`NEGATIVE`)와 원본 확장자 제한(`ORIG_EXT`)은 그대로 적용한다.**
실측으로 검증했다 — 부정어가 막아낸 3건은 전부 걸러야 할 것이었다:

- `신청서 및 실적증명서.pdf` (신청서 묶음)
- `실적증명서_양식.hwp` (빈 양식)
- `붙임4. 컨설팅 수행실적 증명서 표준양식.hwp` (빈 양식)

⚠ **위촉장 판정 결과는 바뀌지 않는다.** `RESULT_END`(현재 `js/kcareer-scan.js:52`) 목록에서
증명서 낱말(`경력증명서`·`실적증명서`·`참여확인서`·`수행확인서`)을 빼고 `CERT_ANY`로 옮기므로,
위촉장·표창·자격증 계열의 239건 판정은 그대로다. 회귀테스트로 보증한다(§7).

### 인터페이스 변경 — `classify`의 반환값

`classify(name)`가 certdoc으로 판정할 때 **`certKind`를 함께 돌려준다**(§5).

```js
// 전:  { level:'sure', store:'certdoc', type:'', titleHint:'' }
// 후:  { level:'sure', store:'certdoc', type:'', titleHint:'', certKind:'own' }
```

⚠ 기존 테스트 `tests/kcareer-scan.test.js`가 `2.권형하노무사 경력증명서.pdf`에 대해
`deepEqual`로 정확한 객체를 비교하고 있다(현재 67~68행). **`certKind`를 더하면 그 테스트가 깨진다** —
기대값에 `certKind:'own'`을 넣어 함께 고친다. certdoc이 아닌 판정(위촉장·표창·자격증)은
`certKind`를 붙이지 않아 기존 deepEqual이 그대로 통과한다.

`능률협회,공인노무사회경력증명서.zip`은 `.zip`이 원본 확장자가 아니므로 계속 `maybe`다(변화 없음).

## 5. 외부기관 것과 본인 것 갈라 담기

증명서는 성격이 둘로 나뉜다. `certKind` 꼬리표로 구분한다.

| certKind | 판정 | 실측 | 용도 |
|---|---|---|---|
| `ext` | `실적증명·수행실적증명·참여확인서·수행확인서·용역수행` 중 하나 | **67건** | 기관이 내 수행실적을 증명 → **외부기관 실적 탭에 붙는다** |
| `own` | `경력증명·재직증명`만 해당(위 낱말 없음) | **146건** | 푸른이 본인 경력을 증명 → 제출용 |

```js
function certKindOf(core){
  if (/실적\s*증명|수행실적\s*증명|참여확인서|수행확인서|용역수행/.test(core)) return 'ext';
  if (/경력증명|재직증명/.test(core)) return 'own';
  return '';
}
```

- 스캔 미리보기는 **두 숫자를 따로** 보여주고, **`ext`만 체크된 상태로 시작**한다.
  `own` 146건은 사용자가 체크를 켜야 들어온다.
- 이렇게 나누는 이유: 외부기관 실적 탭 기관 묶음에는 `ext`만 붙어야 한다.
  본인 경력증명서 146건이 섞이면 기관 묶음이 못 쓰게 된다.

## 6. 발급기관 채우기

세 단계로 시도하고, 실패하면 비워 둔다.

```
1순위  폴더 경로에서 기관명 찾기   → 26건 / 67건 (실측)
       6. 컨설팅 실적증명/구조혁신(능률협회)/2024/…  →  능률협회
2순위  파일명에서 기관명 찾기      → 공인노무사회·중소벤처기업부 등
3순위  비워둠 → 행의 🔍 OCR 보정   → 사용자가 필요할 때만
```

**기관 후보 목록은 이미 시스템이 아는 이름을 쓴다** — 새 사전을 만들지 않는다:

1. pu-erp 유형 코드표(`biz_*_types`)의 `agency` 값 (능률협회·노사발전재단·상공회의소 등)
2. 기존 실적 레코드의 `agency` 값 (외부기관 실적 탭에 실제로 있는 6개 기관)
3. 기존 `certdoc` 레코드의 `issuer` 값

찾은 기관명은 `issuer`에 넣는다. `issuer`가 채워지면 외부기관 실적 탭이 자동으로 매칭한다
(2026-08-01 작업에서 이미 구현됨).

**26건은 즉시 기관 묶음에 붙고**, 나머지 41건은 목록에 들어와 발급기관만 빈 상태다.
`📎 원본 없는 항목만`과 같은 방식으로 골라 `🔍`로 채우면 된다.

## 7. 안전장치·검증

1. **미리보기 → [등록].** 외부기관 67 / 본인 146을 따로 세어 보여주고 체크한 쪽만 저장.
2. **`scanId` 단위 되돌리기** — 이번 스캔이 만든 것만 삭제, 기존에 붙인 것은 경로만 해제.
3. **중복 방지** — 등록된 `relPath`는 건너뛰고, 원본 없는 기존 증명서에는 경로만 붙인다
   (`_cdFindAttachTarget` 재사용).
4. **`made` 보호** — 직접 만든 증명서는 스캔·OCR이 건드리지 않는다.
5. **위촉장 회귀 보증** (가장 중요):
   - 기존 테스트 `classify 회귀: 상공회의소 위촉장은 절대 걸러지지 않는다`를 그대로 유지
   - 기존 테스트 `classify 제출서류: 위촉장 목록·위촉식 시나리오는 승격하지 않는다` 유지
   - **신규**: `2024 구조혁신지원사업 컨설팅 수행실적 증명서_(주)코시노인터네셔널_권형하.pdf` →
     `{level:'sure', store:'certdoc', certKind:'ext'}`
   - **신규**: `경력증명서-푸른.pdf` → `{level:'sure', store:'certdoc', certKind:'own'}`
   - **신규**: `실적증명서_양식.hwp`·`신청서 및 실적증명서.pdf` → 승격 안 함
   - **신규**: `위촉장 목록.xlsx` → 여전히 승격 안 함(증명서 규칙이 위촉장에 새지 않음)
6. **실자료 재검증**: `tools/kcareer-scan-report.js`를 다시 돌려 판정 수를 확인한다.
   기대: 확실이 239 → 약 306(+67)로 늘고, **위촉장·표창·자격증 계열 건수는 불변**.
