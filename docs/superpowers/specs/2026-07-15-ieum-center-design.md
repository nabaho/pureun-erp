   칩 드래그로 이음센터 근무 등록 (attendance_records 저장 + 구글 캘린더 연동).
2. **법률상담 = 자동 집계**: 변호사의 캘린더 이음센터 일정을 법률상담 횟수로 자동 카운트.

3. **스코프 통합(A안)**: 인원 현황의 KPI 스트립 왼쪽에 기간 조종석

   연간 한도·잔여는 [연] 모드에서만 표시·설정.
4. **비고 열**: 연락처 오른쪽에 개인 요구사항 인라인 입력. 외부=external_staff.note 연동,
   내부=ieum_notes 신규 키.
5. **퇴사·종료 관리**: 기록 보존 원칙. KPI·합계는 항상 포함, 기본 보기 숨김,
   필터 '🚪 퇴사·종료 포함'으로 회색+배지 표시. 캘린더 과거 기록 이름 유지(전체 계정 폴백).
6. **공개 미러 자동 발행**: 이음센터 화면 진입 시 + 근무 등록/수정/삭제 시 3초 디바운스로
   ieum_public 자동 발행. 수동 [지금 발행] 버튼 병행.
7. **Firebase 규칙 적용됨**: ieum_public(익명 읽기/직원 쓰기) + data/$other 익명 차단 강화.
8. 내부 노무사 색상은 법인 대시보드 지정색 규칙(커스텀 우선→STAFF_COLORS)과 동일.
- 목업: 대화 중 승인된 v7 (탭 3개: 근무 캘린더 / 인원 현황 / 외부 공유 뷰)

## 1. 개요

이음센터(외부 협력기관) 관련 근무·상담·강의 데이터를 pu-erp.html 안의 전용 공간에서
한눈에 관리한다. 현재는 법인 대시보드 캘린더에 "○○○ 이음센터" 일정(eum-work)이
다른 일정과 섞여 있어 이음센터만의 현황(근무 횟수, 변호사 상담 한도, 강의 실적)을
파악하기 어렵다.

**구축 위치 결정(A안 확정)**: 별도 페이지가 아닌 pu-erp.html 내부에 통합한다.
이음근무 데이터(`attendance_records`)와 외부 인원 명단(`external_staff`)이 이미
pu-erp에 존재하므로, 데이터 이원화 없이 단일 원본을 유지한다.
단, 외부인 열람용 읽기전용 페이지(ieum-view.html)는 별도 파일로 신설한다(§6).

## 2. 용어

| 용어 | 정의 |
|---|---|
| 이음근무 | 이음센터 당직 근무. `attendance_records`의 `type:'eum-work'` 레코드 |
| 법률상담일 | 변호사가 이음센터에 배정된 날. eum-work 레코드 중 담당자의 role이 변호사인 것 |
| 상담건수 | 실제 처리한 법률상담 실적 건수. **캘린더 일정과 별개로 수기 입력** (분리 확정) |
| 이음강의 | 지식이음 프로그램 교육. 일자·시간·장소·제목·내용·참여인원을 기록 |
| 한도 | 변호사별 연간 상담 한도, 인원별 연간 강의 한도. 잔여 = 한도 − 실적 |

## 3. 화면 구조

### 3.1 사이드바 진입
- 위치: 대시보드 섹션, `법인 대시보드`와 `나의 업무` 사이에 `🤝 이음센터` 메뉴 추가
- 클릭 시 이음센터 화면으로 전환. 상단에 연도·월 선택기 (사업기간 개념은 제거 확정)

### 3.2 탭 1: 📅 근무 캘린더
- **기존 법인 대시보드 캘린더 컴포넌트를 그대로 재사용**하되, 이음센터 일정만 필터
  (eum-work 레코드 + 해당일의 법률상담 표기)
- 월/주/일 보기, 이전·다음 달, 오늘, 일정 검색 등 기존 기능 유지
- 드래그 배정 등 편집 동작도 기존과 동일 (이 화면에서 수정하면 법인 대시보드에도 동일 반영 — 같은 데이터)
- 표기 규칙:
  - 내부 노무사 이음근무: 파랑 칩
  - 외부 노무사 이음근무: 주황 칩
  - 변호사 법률상담일: 해당 인원 고유색 칩 + 셀 상단 주황 띠(⚖)
  - 공휴일 표기 유지

### 3.3 탭 2: 👤 인원 현황 (행×열 테이블)
- 상단: ERP 스타일 소형 KPI 4개 (이음근무(월) / 법률상담(연) / 이음강의(연) / 활동 인원)
- 필터: 드롭다운 (전체 / 노무사(내부) / 노무사(외부) / 변호사)
- 테이블 열: `No. | 인원 | 구분 | 이음근무 | 법률상담(연간) | 잔여 | 이음강의 | 잔여 | 연락처`
  - **정렬: 법인 내부 노무사 최상단 고정** → 외부 노무사 → 변호사
  - 해당 없는 항목은 `—` 표시
  - 잔여는 신호등 배지 (여유=초록 / 중간=주황 / 85% 이상 소진=빨강)
  - 하단 합계 행
- 행 클릭 → 상세 펼침:
  - 노무사: 월별 이음근무 일자 목록(자동 집계) + 이음강의 이력
  - 변호사: 월별 상담건수 + 상담건수 빠른 입력(스테퍼) + 이음강의 이력
  - 한도 설정 입력(상담/강의 연간 한도)
  - 강의 기록 추가 버튼 → 입력 모달 (일자·시간·장소·제목·내용·참여인원·담당)
- **수정 권한: 전 직원 가능** (admin 한정 아님 — 확정)

### 3.4 탭 3: 🔗 외부 공유 뷰 (관리 화면)
- 인원별 고유 링크 목록·복사 버튼
- 기존 "이음센터 근무 문자" 모달(EumNotifyModal)에 개인 링크 자동 첨부

## 4. 데이터 모델

기존 노드는 변경하지 않고, 신규 키를 추가한다. 모두 기존 dbGet/dbSet 계층 사용
(localStorage `pureun_v6_` + Firebase `data/{키}` 동기화).

### 4.1 기존 (그대로 사용)
- `attendance_records`: `{ type:'eum-work', date, sid | externalId, note, ... }` — 이음근무 원본
- `external_staff`: `{ id, name, role(노무사|변호사), org, contact, note, color, active, sortOrder }` — 외부 인원
- `user_accounts`: 내부 직원 (sid, name, ...)

### 4.2 신규 키
- `ieum_members`: 이음센터 참여 내부직원 sid 배열. 인원 현황 테이블에 표시할 내부 노무사 지정
  (전 직원이 자동 노출되는 것 방지)
- `ieum_caps`: 연도별·인원별 한도
  `{ "2026": { "<personKey>": { law: 24, edu: 6 } } }`
  - personKey = 내부직원 `sid` 또는 외부인 `externalId`
- `ieum_consults`: 연도별·월별·변호사별 상담건수 (수기 입력)
  `{ "2026": { "07": { "<personKey>": 3 } } }`
- `ieum_lectures`: 이음강의 기록 배열
  `[{ id, date, time, place, title, content, attendees, personKey }]`

### 4.3 집계 규칙
- 이음근무 횟수 = attendance_records에서 `type==='eum-work'` && 연도 일치 레코드를 personKey별 카운트 (자동)
- 법률상담 사용 = ieum_consults 해당 연도 월별 합산 (수기)
- 이음강의 사용 = ieum_lectures 해당 연도 personKey별 카운트
- 잔여 = ieum_caps − 사용. 한도 미설정 시 잔여 표시 생략(— 처리)

## 5. 상담일 ↔ 상담건수 분리 (확정)

- 캘린더의 법률상담일 = **일정** (언제 누가 상담하러 오는가)
- 인원 현황의 상담건수 = **실적** (그 달에 몇 건 처리했는가, 수기 입력)
- 하루에 여러 건 처리가 가능하므로 두 수치는 원래 다르다. 화면 라벨로 구분을 명시하고
  상호 자동 연동하지 않는다 (이중 집계 문제 원천 차단).

## 6. 외부인용 읽기전용 페이지 — ieum-view.html (신규 파일)

외부 변호사·노무사가 **로그인 없이** 본인 일정을 확인하는 모바일 우선 초경량 페이지.

### 6.1 데이터 공개 방식 (개인정보 보호)
- pu-erp가 eum-work 저장 시, Firebase `ieum_public/` 아래에 파생 미러를 자동 발행:
  - `ieum_public/roster`: `{ "YYYY-MM-DD": [{ n:이름, k:'in'|'ex'|'law' }] }` — **이름·날짜·구분만**. 연락처·메모 등 개인정보 제외
  - `ieum_public/people/<token>`: `{ name }` — 개인 토큰 → 이름 매핑
- 단방향 발행(원본 → 미러)이므로 데이터 이원화 아님. 미러는 읽기전용
- Firebase 규칙: `ieum_public`은 익명 인증 읽기 허용, 쓰기는 로그인 사용자만.
  `people`은 토큰 직접 경로 읽기만 허용(목록 조회 차단)하여 토큰 열거 방지
- 토큰: external_staff 각 인원에 `shareKey`(추측 불가 랜덤 문자열) 필드 추가

### 6.2 페이지 구성
- `ieum-view.html?k=<token>` — Firebase 익명 인증(gov-consulting.html과 동일 방식)
- 상단: "○○○ 노무사님 근무일정" + 다음 근무 D-day 카드
- 본문: 월 달력 — 본인 근무일 강조(진한 파랑), 다른 근무자 근무일은 회색 표시
- 이전/다음 달 이동. 읽기 전용, 실시간 반영
- 토큰 불일치·누락 시: 이름 없이 전체 로스터만 표시하거나 안내 문구

### 6.3 문자 연동
- EumNotifyModal의 문자 본문에 개인 링크 자동 첨부:
  `"...내일 7/16(목) 이음센터 근무 예정입니다. 📅 전체 일정: .../ieum-view.html?k=xxxx"`

## 7. 구현 범위 및 단계

1. **1단계 — 이음센터 메뉴 + 근무 캘린더 탭**: 사이드바 메뉴, 캘린더 필터 재사용
2. **2단계 — 인원 현황 탭**: 테이블·집계·상담건수 입력·강의 기록 모달·한도 설정
3. **3단계 — 공개 미러 + ieum-view.html**: 발행 로직, 토큰, 외부 공유 뷰 탭, 문자 연동

각 단계는 독립적으로 배포 가능하며 순서대로 진행한다.

## 8. 비범위 (하지 않는 것)

- 사업기간(계약 기간) 단위 관리 — 삭제 확정. 연도·월 기준만 사용
- 상담 내용(케이스별 상세) 기록 — 건수만 집계
- 외부인의 일정 수정 — 외부 뷰는 읽기 전용
- enter.html 포털 타일 추가 — pu-erp 내부 통합으로 대체 (필요 시 추후)

## 9. 에러 처리·엣지 케이스

- 한도 미설정 인원: 잔여 배지 대신 `—`. 사용 횟수는 표시
- external_staff에서 삭제(비활성)된 인원: 과거 기록은 집계에 유지, 테이블에는 active만 표시
- 이름 동명이인: personKey(sid/externalId) 기준 집계이므로 문제 없음
- 12월→1월 전환: 연도 선택기로 과거 연도 조회 가능. 한도·상담건수는 연도별 키로 분리 저장
- ieum-view 토큰 분실: ERP 외부 공유 뷰 탭에서 재발급(새 shareKey 생성) 가능

## 10. 테스트 계획

- 이음근무 집계가 법인 대시보드 캘린더 표시와 일치하는지 (동일 데이터 확인)
- 상담건수 입력 → KPI·잔여 즉시 갱신, 새로고침·타 기기 동기화 확인
- 한도 85% 초과 시 빨강 배지 전환 확인
- ieum-view: 토큰별 본인 강조 정확성, 잘못된 토큰 처리, 모바일 렌더링
- 공개 미러에 연락처가 포함되지 않는지 확인 (개인정보)
