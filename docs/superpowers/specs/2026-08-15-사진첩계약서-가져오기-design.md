# 사진첩 계약서 → 이알피 계약추가 가져오기 — 설계

- 날짜: 2026-08-15 (2026-08-15 코드 조사 결과 반영해 수정)
- 상태: 설계 확정 (대표 승인 완료)
- 대상: `pu-erp.html` 계약관리 `ContractModal`, `pu-photos.html`(읽기 전용, 데이터 소스)

> **수정 기록**: 구현 계획을 쓰기 전 실제 코드를 확인해보니 "지금 보고 있는 계약유형 탭"이라는
> 게 화면에 없었다(체크한 유형이 전부 동시에 펼쳐지는 구조, 탭 전환 없음). 대표 확인 결과
> **계약유형을 하나만 체크했을 때만 배지를 보여준다**로 정정. 부가세 체크칸도 실제로는
> 유형별이 아니라 계약 전체에 딱 2~3개뿐(착수금/계약금용 하나, 잔금/성공보수용 하나, 기금
> 전용 하나)임을 확인 — 아래 본문에 반영함.

## 배경

계약추가 창에서 계약금·부가세·계약일·계약기간·업무요약을 손으로 다시 입력하는데, 이미
사진첩에 그 회사 계약서를 스캔해 OCR로 읽어둔 경우가 많다. 같은 값을 두 번 치지 않게
사진첩에서 바로 가져와 채운다.

**CMS 자동이체·개인입금 여부는 대상이 아니다** — 계약서 서식 자체에 없는 항목이라 OCR이
애초에 뽑지 않는다(`js/pu-doc-read.js`의 contract 프롬프트 확인됨). 이 두 칸은 지금처럼
계속 손으로 입력한다.

## 흐름

1. 계약추가 창에서 회사명(`f.company.name`)을 입력하면, **내(로그인한 사람)**가 사진첩에
   올려둔 계약서 중 이름이 비슷한 것이 있는지 조용히 확인한다.
2. **계약유형(`f.kinds`)을 정확히 하나만 체크했을 때만** 회사명 칸 옆에
   `📷 계약서 N건 발견` 배지가 뜬다. 매칭이 없거나, 유형을 0개·2개 이상 체크한 상태면
   배지 자체가 안 뜬다 — 어느 유형 칸에 계약금을 넣을지 애매해지는 것을 막는다.
3. 배지를 누르면 후보 목록(날짜·문서명 한 줄씩)이 뜨고 하나를 고른다. 여러 건이면 목록에서
   고르게 한다 — 자동으로 가장 최근 것을 고르지 않는다.
4. 고르면 미리보기 카드를 보여준다: 체크된 그 하나의 계약유형의 계약금·계약일·계약기간·
   업무요약과, 계약 전체 공용인 부가세 체크(아래 필드 매핑 참고)가 무엇으로 바뀌는지
   한 번에 보여준다. [적용]/[취소].
5. 적용을 누르면 이미 입력돼 있던 값이라도 **덮어쓴다** — 사람이 미리보기를 보고 확인한
   뒤이므로 안전하다.

## 권한·검색 범위

사진첩은 회사별이 아니라 **올린 사람별**로 저장된다
(`puphotos/u/{ownerUid}/items/{year}/{id}`). Firebase 규칙상 본인 것만 읽을 수 있고
(관리자는 전체) — 이번 기능은 **로그인한 사람 본인 것만** 뒤진다. 다른 담당자가 올린
계약서는 안 보인다(권한 규칙을 넓히지 않는다 — 별도 결정 없이는 확대하지 않음).

계약추가 창을 열 때, 내 puphotos 항목(최근 몇 개 연도)을 한 번 읽어 캐시한다(다른 화면의
`_erpCaseCons` 캐시 패턴과 같은 결). 회사명을 입력할 때마다 이 캐시 안에서 느슨한 이름
검색(기존 `searchPucardsPeople`와 같은 방식)으로 후보를 찾는다. **실시간 구독이 아니다** —
사진첩에 새 계약서를 올린 뒤에는 계약추가 창을 새로 열어야 반영된다.

매칭 기준은 **회사명**(느슨한 검색)이다. 사업자번호는 계약서에 없는 경우가 많아 기준으로
쓰지 않는다.

## 필드 매핑

| 이알피 계약추가 칸 | 사진첩 OCR 필드 | 규칙 |
|---|---|---|
| 계약금(`f.amounts[유일하게 체크된 kind]`) | `fields.deposit` 또는 `fields.fee` | 있는 값 그대로 채움 |
| 업무 요약(`f.briefs[유일하게 체크된 kind]`) | `fields.scope` | 그대로 |
| 착수금/계약금 부가세 체크(`f.contractFeeVatIncluded` — 계약 전체 공용 플래그) | `fields.vat` (자유 텍스트) | "포함" 포함 → 체크함 / "별도" 포함 → 체크 안 함 / 그 외(빈칸·애매함) → **건드리지 않음**, 미리보기에 원문을 그대로 보여줘 사람이 판단 |
| 계약일(`f.signDate`) | `fields.signDate` | 그대로 |
| 계약기간(`f.startDate`/`f.endDate`) | `fields.startDate`/`fields.endDate` | 그대로 |
| (덤) 대표자·주소·사업자번호 — 비어 있으면 | `fields.ceo`/`fields.address`/`fields.bizno` | 이미 있는 값은 안 건드림(부가세와 달리 세금 계산에 영향 없어 위험이 낮다) |

부가세 체크칸은 유형별이 아니라 계약 전체에 `f.contractFeeVatIncluded`(착수금/계약금용)·
`f.balanceFeeVatIncluded`(잔금/성공보수용)·`f.fundVatIncluded`(기금 전용) 세 개뿐이다.
이번 기능은 착수금/계약금 쪽(`f.contractFeeVatIncluded`)만 채운다 — 잔금·성공보수는
계약서 한 장만으로는 아직 확정 안 된 경우가 많아 손으로 입력하는 영역으로 남긴다.

부가세 판정을 보수적으로 하는 이유: 잘못 추측해 체크박스를 틀리게 채우면 세금 계산이
바로 틀어진다. 애매하면 아예 안 건드리는 쪽이 잘못 채우는 것보다 안전하다.

## 화면

- 배지: `📷 계약서 N건 발견` — 회사명 입력 칸(`f.company.name`) 바로 옆에 새로 붙인다.
  계약유형을 정확히 하나만 체크했고 매칭도 있을 때만 보인다. 그 외에는 렌더링 자체를 안
  한다(조용).
- 목록 팝업: 기존 `PucardsCompanyPickerModal`과 같은 모양(오버레이 · 560px 폭 · 검색창 ·
  클릭 가능한 카드 목록)을 그대로 본떠 만든다 — 날짜·문서명 한 줄씩.
- 미리보기 카드: "계약금 500,000원 · 부가세 별도 · 계약일 2026-07-01 ·
  기간 2026-07-01~2027-06-30 · 업무: 취업규칙 정비" + [적용] [취소].

## 안 하는 것 (범위 밖)

- CMS 자동이체·개인입금 자동 채움 — 데이터 자체가 없어 불가능.
- 다른 사람이 올린 사진첩 검색 — 권한 규칙 확대 없이는 안 한다.
- 사진첩 쪽 실시간 구독 — 창을 열 때 한 번만 읽는다.
- 사업자번호 기반 매칭 — 계약서에 흔히 없어 회사명 검색으로 충분하다고 판단.

## 검증 계획

- 부가세 문구별 판정(포함/별도/빈칸/애매함 각각) 단위 테스트
- 여러 계약서 후보 중 하나를 고르면 정확히 그 값만 적용되는지
- 계약유형을 0개·2개 이상 체크한 상태에서는 배지가 안 뜨는지
- 이미 입력된 값이 있어도 적용 후 실제로 덮어써지는지(미리보기 확인 흐름 포함)
- 사진첩에 매칭되는 계약서가 없을 때 배지가 안 뜨는지
- 본인이 아닌 다른 사람 사진첩 데이터가 섞이지 않는지(권한 경계)
