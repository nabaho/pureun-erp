# 푸른명함첩 — 분류를 한 번에 하는 설계

작성 2026-08-05 · 대상 `pu-cards.html`

## 배경 — 왜 지금이 힘든가

명함 6,302장 중 폴더에 담긴 것은 약 1,200장뿐이다. 나머지 **약 5,000장이 미분류**로 쌓여 있다.
대표가 직접 말한 어려움은 "폴더에 넣고 그 안에서 다시 탭에 넣으려면 여러 단계를 거친다"는 것이다.

코드를 읽어 확인한 실제 원인은 네 가지다.

| 원인 | 근거 |
|---|---|
| 끌어다 놓기가 **한 장만** 옮긴다 — 20장을 골라도 끌던 한 장만 이동 | `onFolderOrCardDrop` 은 단일 `dragId` 만 본다 |
| 폴더로 옮기면 **선택이 풀린다** → 탭에 담으려면 처음부터 다시 고른다 | `moveSelTo` 가 `state.sel={}` 로 비운다 |
| 탭 칩에 **드롭을 받는 곳이 없다** | `renderMyTabsHtml` 에 드롭 처리 없음 |
| 명함이 **어느 탭에 담겼는지 화면에 안 나온다** → 확인도 빼기도 어렵다 | 행 렌더에 `vtabs` 표시 없음 |
| 우클릭 메뉴에 **탭 항목이 없다** | `openRowMenu` 에 폴더 이동만 있음 |

그래서 지금은 폴더+탭을 둘 다 하려면 **일곱 단계**가 든다.

```
체크 → 폴더이동 → 폴더고르기 → (선택 풀림) → 다시 체크 → 탭에담기 → 탭고르기
```

### 오해 하나를 함께 푼다

메인 상단의 `자문 270` `급여 40` `노조 0` `기금 0` `사무대행 0` 은 **손으로 담는 탭이 아니다.**
ERP 업체관리와 이름이 맞으면 저절로 채워지는 **조건 탭**이다 (`seedErpTabs` 가 `erpFilter` 로 만든다).
노조·기금이 0인 것은 안 넣어서가 아니라 ERP에 그 유형 업체가 없기 때문이다.
지금 화면에서는 조건 탭 🔖 과 담는 탭 🏷 이 한 줄에 섞여 있어 어디에 담을 수 있는지 알 수 없다.

## 목표

1. 명함을 **한 번 끌어서** 폴더와 탭에 동시에 넣는다.
2. 쌓인 5,000장을 **규칙으로 한 번에** 치운다.
3. 폴더 수는 늘리지 않는다. 세부 구분은 **메인 화면의 탭**으로 한다.

## 설계 원칙

- **폴더는 적게, 탭은 자유롭게.** 폴더는 "이 사람이 우리에게 누구인가"라는 큰 갈래만 담는다(6~8개). 그 안의 세부 구분은 탭이 맡는다. 폴더를 늘리면 왼쪽 목록이 길어져 한 화면에 안 들어온다 — 이미 겪은 문제다.
- **손으로 넣은 분류는 절대 자동으로 건드리지 않는다.** 기존 `erpAutoFoldered` 가 쓰는 방식을 따른다.
- **한 번에 되돌릴 수 있어야 한다.** 수천 장을 옮기는 기능은 되돌리기 없이는 쓸 수 없다.
- **잠긴 폴더는 남의 눈에 보이지 않는다.** `canSeeGroup` 을 지나는 것만 화면·규칙 대상에 넣는다.

## 폴더 구성 — 두 개만 늘린다

| 폴더 | 채우는 방식 |
|---|---|
| 업체관리 | ERP 자동 (`autoFolder`) |
| 업체종료및퇴사 | ERP 자동 |
| 노무사 | 규칙 + 손 |
| 전문가 | 규칙 + 손 — 세무·회계·법무·변호사·특허 |
| **기관·공공** *(신규)* | 규칙 — 공단·공사·청·시청·구청·센터·협회 |
| **생활·기타** *(신규)* | 규칙 — 배달·보험·음식점·꽃집 등 업무와 무관한 것 |
| 지인 | 손 |
| 개인폴더 | 잠금 (본인만) |

세무/회계/법무 구분, 지역별, 협업 여부 같은 세부는 **폴더를 더 만들지 않고 탭으로** 만든다.

## 1단계 — 규칙으로 한 번에 치우기

쌓인 5,000장에서 가장 크게 이득이 나는 곳이다. 회사명만으로 거의 판별된다.

### 기본 규칙 (내장, 수정 가능)

| 순서 | 회사명·이름에 이 말이 있으면 | 보낼 폴더 |
|---|---|---|
| 1 | 노무법인 · 노무사사무소 · 노무사무소 | 노무사 |
| 2 | 세무 · 회계 · 법무 · 변호사 · 변리 · 특허 · 감정평가 | 전문가 |
| 3 | 공단 · 공사 · 청 · 시청 · 구청 · 군청 · 센터 · 협회 · 진흥원 · 재단 | 기관·공공 |
| 4 | 배달 · 꽃 · 보험 · 갈비 · 식당 · 마트 · 택배 · 통신 · 렌터카 · 화수목 | 생활·기타 |

### 동작

- **저절로 돌지 않는다.** 대표가 `적용`을 누를 때만 돈다. 로그인·저장·새로고침 때 자동 실행하지 않는다 — 수천 장을 건드리는 기능이라 사람이 누른 순간에만 움직여야 한다. (ERP 자동 분류 `autoFolder` 와 다른 점이다. 그쪽은 ERP 대조라 근거가 확실하고 대상이 좁다.)
- 대상은 **미분류(`(it.group||'')===''`)만**. 이미 폴더에 든 명함은 건드리지 않는다.
- 규칙은 **위에서 아래로, 먼저 맞은 것 하나만** 적용한다.
- `kind`(명함/사업자)를 구분해 각 종류의 폴더로 보낸다.
- 잠긴 폴더로는 보내지 않는다.

### 화면

환경설정 → 🧹 정리 탭 안에 인라인으로 넣는다(`_panelTarget`/`showPanel` 규칙을 따른다. 팝업을 만들지 않는다).

```
🗂 규칙으로 한 번에 분류                     미분류 5,098장

☑ 노무법인 · 노무사사무소 …        → 노무사       412장  [단어 고치기]
☑ 세무 · 회계 · 법무 · 변호사 …     → 전문가       287장  [단어 고치기]
☑ 공단 · 공사 · 청 · 센터 …         → 기관·공공     531장  [단어 고치기]
☑ 배달 · 꽃 · 보험 · 갈비 …         → 생활·기타   1,842장  [단어 고치기]
                                    규칙에 안 걸림  2,026장

              [ 3,072장 미리보기 ]   [ 그대로 적용 ]
```

- **미리보기**를 누르면 규칙별로 걸린 명함 20장씩 샘플을 그 자리에서 펼친다.
- 규칙마다 켜고 끌 수 있고, `단어 고치기`는 쉼표로 구분된 단어 목록을 고치는 한 줄 입력이다.
- 적용 뒤 **되돌리기** 단추가 남는다.

### 저장 구조

규칙은 전 직원이 함께 쓰므로 공유 위치에 둔다.

```
pucards/classifyRules/{id} = {
  id, order, kind:'card'|'biz', enabled:true,
  words:['노무법인','노무사사무소'],      // 회사명·이름에서 찾는다
  toGroupName:'노무사'                   // 폴더는 이름으로 지정 — 없으면 만든다
}
```

1단계 규칙은 **폴더만 바꾼다.** 탭까지 한꺼번에 지정하는 기능은 넣지 않는다 —
규칙이 폴더만 다루면 되돌리기가 "원래 폴더로 되돌린다" 한 가지로 끝나 안전하다.
탭 지정은 2단계의 「보낼 곳」 패널에서 사람이 직접 한다.

폴더를 id가 아니라 **이름**으로 가리키는 이유는, 규칙이 만들어진 뒤 폴더가 지워졌다 다시 생겨도 살아남게 하려는 것이다. `autoFolder` 의 `ensure(nm,k)` 와 같은 방식이다.

### 되돌리기

```
pucards/classifyLog/{batchId} = {
  at, by,                                 // 언제 · 누가
  n,                                      // 옮긴 장수
  from:{ cardId: prevGroupId, ... }       // 되돌릴 때 쓸 원래 폴더
}
```

최근 **10건**만 남기고 오래된 것은 지운다. 되돌리기는 `from` 을 그대로 되돌려 쓴다.

### 성능 — 반드시 한 번에 쓴다

5,000장을 `Store.put` 으로 하나씩 쓰면 5,000번 통신한다. `rebuildIdxAll` 이 이미 쓰는 방식대로
**한 번의 `update()` 다중 경로 쓰기**로 몰아 보낸다. 검색색인(`idx`)도 같은 방식으로 함께 갱신한다
(폴더가 바뀌면 `inLockedGroup` 결과가 달라져 색인 포함 여부가 바뀐다).

## 2단계 — 메인에서 한 번에 조절

일상 도구다. 여기서 "일곱 단계 → 한 번 끌기"가 된다.

### 2-1. 오른쪽 「보낼 곳」 패널 — 항상 켜둔다

```
   왼쪽: 보기               가운데: 명함 표            오른쪽: 보낼 곳
┌────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ 📁 업체관리 │   │ ☑ 노무법인로율    │══▶│ 📦 20장을 놓으세요 │
│ 📁 노무사   │   │ ☑ 동북아노무법인  │   │ ─────────────────│
│ 📁 전문가   │   │ ☑ 세무법인다솔    │   │ 📁 업체관리       │
│ 📁 지인     │   │ ☑ …              │   │ 📁 노무사         │
└────────────┘   └──────────────────┘   │   🏷 지역노무사    │
                                        │   🏷 협업중        │
   왼쪽 = 어디를 볼지                     │ 📁 전문가         │
   오른쪽 = 어디로 보낼지                  │   🏷 세무·회계     │
                                        │ 📁 생활·기타      │
                                        └──────────────────┘
```

- **📁 위에 놓으면** → 그 폴더로 이동
- **🏷 위에 놓으면** → **폴더 이동 + 탭 담기가 한 번에.** `doAddToTab` 이 이미 "탭이 폴더 소속이면 그 폴더로 함께 옮긴다"로 동작하므로 새 규칙이 아니라 이미 있는 동작을 드러내는 것이다.
- 폴더 아래에 그 폴더의 **담는 탭 🏷 만** 접어서 보여준다. 조건 탭 🔖 은 자동으로 채워지므로 넣을 곳이 아니다 — 목록에 넣지 않는다.
- 지금 보고 있는 폴더가 아니어도 **모든 폴더·탭이 보인다.** 전체 명함에서 곧장 「노무사 › 지역노무사」로 보낼 수 있다는 뜻이고, 5,000장 정리에 이게 핵심이다.
- 폭 200px 고정, `◀` 로 접을 수 있고 접힘 상태는 `localStorage` 에 기억한다. 기본값은 **펼침**(대표 요청: 항상 켜두고 쓴다).
- **PC 전용.** 폰에서는 화면이 좁아 지금의 시트 방식을 그대로 둔다.
- 잠긴 폴더는 `canSeeGroup` 을 지나는 것만 넣는다. 본인 것이면 보인다.

### 2-2. 여러 장 끌기 — 지금 못 되는 것을 고친다

`onRowDrag` 가 끌기 시작할 때, 끄는 행이 **선택된 것 중 하나면 선택 전부**를, 아니면 그 한 장만 옮긴다.

```
끄는 행이 선택 안에 있나?
  예  → state.sel 전부 (20장)
  아니오 → 그 한 장만
```

끌고 있는 동안 마우스에 **「20장」 표시**를 붙이고, 놓을 수 있는 곳은 노랗게 빛나게 한다.
지금 드래그가 안 되는 것처럼 느껴진 이유가 바로 이 표시가 없고 한 장만 옮겨졌기 때문이다.

### 2-3. 표에 「탭」 열 — 메인에서 바로 빼기

```
이름            회사            탭
노무법인로율     노무법인로율     🏷지역노무사 ✕   🏷협업중 ✕
```

- `it.vtabs` 를 칩으로 보여준다. `✕` 를 누르면 그 탭에서만 빠지고 명함은 그대로 남는다.
- 지금은 명함이 어느 탭에 담겼는지 **볼 방법이 아예 없다.** 이 열이 "메인에서 조절"의 핵심이다.
- 다른 열과 같이 `state.colW`·열 순서·보이기/숨기기 규칙을 따른다.

### 2-4. 우클릭으로 두 번에 — 끌기가 불편할 때

`openRowMenu` 에 두 줄을 더한다.

```
👁 상세 보기
✏️ 수정
📋 정보 복사
📁 폴더로 보내기 ▸   업체관리 / 노무사 / 전문가 / …
🏷 탭에 담기    ▸   지역노무사 / 협업중 / ＋ 새 탭
☆ 즐겨찾기
🗑 삭제
```

- 하위 목록에서 곧장 고른다. 팝업을 거치지 않는다.
- 선택된 명함이 여럿이면 **선택 전부**에 적용하고, 없으면 우클릭한 그 한 장에 적용한다.

### 2-5. 탭 칩 정리

- 🏷 **담는 탭** — 실선. 드롭을 받는다.
- 🔖 **조건 탭** — 점선 + `자동` 딱지. 드롭하면 넣지 않고 *"자동으로 채워지는 탭이라 손으로 담을 수 없습니다"* 라고 알린다.
- 칩을 좌우로 끌어 **순서를 바꾼다** (`v.order` 저장). 지금은 `⋮` 메뉴를 거쳐야 한다.

### 2-6. 선택이 풀리는 문제

`moveSelTo` 는 옮긴 뒤 선택을 비운다. 폴더와 탭을 잇달아 지정할 수 없는 이유다.
「보낼 곳」 패널과 우클릭은 **폴더+탭을 한 번에** 지정하므로 잇달아 할 일이 없어진다.
다만 표에서 폴더만 옮긴 경우에도 선택을 유지해, 곧바로 탭을 지정할 수 있게 한다.
`선택 해제` 단추가 이미 있으므로 유지가 갇히는 일은 없다.

## 3단계 — 빠른 분류 모드 (남은 것용)

1단계 규칙이 못 맞춘 나머지를 한 장씩 처리한다. 1단계를 적용한 뒤 남는 양을 보고 만든다.

```
        ┌───────────────────────────┐
        │  아름다운정원화수목        │
        │  041-415-0815             │
        │  천안시 동남구 …           │
        └───────────────────────────┘
   [1]업체관리 [2]노무사 [3]전문가 [4]기관 [5]지인 [6]생활기타
        ↑ 추천 6번 (꽃·화훼)
        숫자키를 누르면 배정 + 다음 장 / [←] 이전 / [S] 건너뛰기
```

- 폴더를 숫자키 1~9에 붙인다. 한 장에 한 번만 누른다.
- 회사명 키워드로 추천 폴더를 미리 강조한다 (1단계 규칙을 그대로 쓴다).
- 되돌리기는 `←` 로 직전 한 장.

## 나눠 만드는 순서

세 단계는 **각각 따로 배포해도 바로 쓸 수 있다.** 한 번에 다 만들지 않는다.

| 단계 | 무엇 | 왜 이 순서 |
|---|---|---|
| **1** | 규칙 일괄 분류 + 되돌리기 | 5,000장 중 3,000장 이상이 클릭 몇 번에 정리된다. 이득이 가장 크다 |
| **2** | 보낼 곳 패널 · 여러 장 끌기 · 탭 열 · 우클릭 | 이후 매일 쓰는 도구 |
| **3** | 빠른 분류 모드 | 1단계 적용 후 남는 양을 보고 결정 |

**1단계를 먼저 구현 계획으로 옮긴다.** 2단계는 1단계 배포 뒤 별도 계획으로 만든다.

## 잘못될 수 있는 곳과 대비

| 위험 | 대비 |
|---|---|
| 규칙이 잘못 걸려 수천 장이 엉뚱한 폴더로 | 미리보기 필수 · 되돌리기 10건 보관 · 미분류만 대상 |
| 5,000번 통신으로 앱이 멈춤 | 한 번의 `update()` 다중 경로 쓰기 (`rebuildIdxAll` 방식) |
| 잠긴 개인폴더 명함이 규칙에 휩쓸림 | `canSeeGroup`·`inLockedGroup` 통과분만 대상 |
| 검색색인이 옛 폴더 기준으로 남음 | 같은 `update()` 에 `idx` 갱신을 함께 넣는다 |
| 손으로 정리해 둔 폴더가 규칙에 덮임 | 미분류만 건드린다. `erpAutoFoldered` 와 같은 원칙 |
| 끌기가 행 클릭(상세 보기)과 부딪힘 | 끌기 시작 후에는 클릭을 취소한다 (`dragging` 상태 확인) |
| 폰에서 오른쪽 패널이 화면을 먹음 | PC 전용. 폰은 기존 시트 유지 |

## 확인 방법

`pu-cards.html` 은 빌드 없는 단일 파일이므로 이 파일에서 이미 쓰는 방식을 따른다.

1. **문법 검사** — 인라인 `<script>` 블록을 뽑아 `node --check`.
2. **기능 검사** — 로컬 `http.server` + 브라우저 자동화로 가짜 데이터를 넣고 실제 경로를 실행한다.
   - 규칙: 미분류 4장 + 폴더에 든 2장 → 적용 → **미분류 4장만** 옮겨졌는지, 폴더에 든 2장은 그대로인지
   - 되돌리기: 적용 → 되돌리기 → 원래 폴더로 정확히 복귀하는지
   - 잠긴 폴더: 남의 잠긴 폴더 명함이 규칙 대상에서 빠지는지
   - 여러 장 끌기: 3장 선택 후 그중 하나를 끌면 3장이, 선택 밖 행을 끌면 1장이 옮겨지는지
   - 조건 탭 드롭: 🔖 탭에 놓으면 담기지 않고 안내가 뜨는지
3. **두 번 적용해도 안전한지** — 규칙을 연달아 두 번 적용해도 결과가 같아야 한다.

## 안 하기로 한 것

- **탭을 폴더 밖으로 공유하지 않는다.** 탭은 폴더 소속을 유지한다 (대표가 앞서 못 박은 규칙).
- **정규식 규칙 편집기를 만들지 않는다.** 단어 목록만 고친다.
- **AI 자동 분류를 넣지 않는다.** 키워드로 충분하고, 결과를 사람이 검증할 수 있어야 한다.
- **왼쪽 사이드바에 탭을 겹쳐 넣지 않는다.** 사이드바가 길어지는 문제를 이미 겪었다. 왼쪽은 보기, 오른쪽은 보내기로 나눈다.
