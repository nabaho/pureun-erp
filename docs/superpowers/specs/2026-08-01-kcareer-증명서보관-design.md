# kcareer 증명서 보관 재설계 — 외부기관 발급 실적증명서 관리

- 작성일: 2026-08-01
- 대상 앱: `kcareer.html` (푸른노무법인 경력관리)
- 선행 작업: 2026-07-31 서류 일괄등록(로컬 폴더 참조), 2026-08-01 실적 동기화 — 같은 패턴을 재사용한다

## 1. 목표

외부 컨설팅기관(충남경제진흥원·한국능률협회 등)이 발급해준 **실적증명서·경력증명서 PDF**를
위촉장 관리와 같은 수준으로 다룬다: 폴더 스캔으로 일괄 등록, 끌어다 놓기로 개별 추가,
OCR로 발급기관·발급일·증명기간 자동 추출, 원본은 경로 참조, 표 목록으로 검색·정렬.

발급기관이 정확히 채워지면 **외부기관 실적 탭(6개 기관 63건)의 기관 묶음에 증명서가 자동으로 붙는다** —
이것이 이번 작업의 실질적 이득이다(현재는 `➕ 증명서 연결`로 수동).

## 2. 확정 결정 (사용자)

1. **기존 `경력증명서 보관` 화면을 살린다** — 전용 화면 신설 없음. 발급기관·용도·증명기간 칸과
   제출기록 기능이 이미 있어 가장 빨리 끝난다.
2. **폴더 스캔 + 끌어다 놓기 둘 다** 지원한다.
3. **OCR은 발급기관·발급일·증명기간·종류** 네 가지만 추출한다(상세 내용은 범위 밖).

## 3. 현황 (2026-08-01 실측)

- `경력증명서 보관` 화면(`page-certdoc`)은 `CAREER_CFG`의 표준 목록이 아니라 **`DOMAINS` 구조**를 쓴다
  (`DOMAINS.certdoc`, kcareer.html:2687 부근). 렌더는 `renderDocStore(domain)`, 초기화는
  `initDocStore`·`initDocCreate`. 목록은 연도별 **카드 나열**이고 표가 아니다.
- 이미 있는 것: `받은 증명서 업로드` 버튼(`cdAddExisting`, `.hwp/.hwpx/.pdf/.docx` 1개씩),
  `extra` 칸 3개(`issuer` 발급기관 / `usage` 용도·제출처 / `coverage` 증명 기간),
  기관 필터(`cdOrgFilter`), 검색(`cdSearch`), 제출기록(`openSubmitLog`), 양식 가져오기·양식 보관함.
- **레코드가 "내가 만들어 발급하는 증명서"를 전제로 설계돼 있다**: `genFileId`(만든 파일)와
  `origFileId`(참고 원본). 목록 카드는 `showBig(r.genFileId)`를 무조건 그린다.
  → 2026-07-31 서류 스캔으로 들어온 **14건은 `genFileId`가 없어 `📄 경력증명서` 버튼이 빈 것을 가리킨다.**
- 재사용할 자산: `js/kcareer-scan.js`(판정 규칙 — `실적증명서`·`경력증명서`·`참여확인서`·`수행확인서`로
  끝나면 certdoc으로 승격, 테스트 19개), `openLocalOriginal`·`hasOriginal`·`openOriginal`,
  `fsRoot`(연결된 폴더 핸들), `reOcrForm`(OCR), `_agencyNorm`·`renderPuAgency`(기관 매칭).

## 4. 레코드 모델 — 만든 것 / 받은 것 구분

기존 `certdoc` 스토어를 그대로 쓰고 **출처 구분만 추가**한다.

```js
{
  id, kind, org, date, year, memo, savedAt,        // 기존 그대로
  issuer, usage, coverage,                          // 기존 extra 칸 그대로
  submits: [...],                                   // 제출기록 그대로

  docSrc: 'made' | 'received',                      // ★ 신설
  genFileId, origFileId,                            // made에서만 의미 있음
  src: 'fs', relPath, fileSize, fileMtime,          // received + 폴더 참조
  scanId                                            // 스캔 되돌리기 단위
}
```

### 출처 판정 (기존 레코드 마이그레이션 없이)

```js
function _cdSrc(r){
  if(r && r.docSrc) return r.docSrc;                       // 새로 저장된 것
  if(r && (r.relPath || (!r.genFileId && r.fname))) return 'received';  // 스캔으로 들어온 것
  return 'made';                                            // 그 밖은 기존 방식
}
```

기존 14건은 `relPath`가 있어 `received`로 판정된다. **직접 만들어 쓰던 증명서(`made`)는 변경하지 않는다.**

### 버튼 구성

| 출처 | 원본 보기 | 그 밖 |
|---|---|---|
| `made` | `📄 증명서`(genFileId) · `⬇` · `📎 원본`(origFileId 있으면) | 제출기록 · 삭제 |
| `received` | `📄 원본`(경로 또는 base64 — `openOriginal(r)`) | 제출기록 · 삭제 · `🔍 다시 읽기(OCR)` |

`received`에는 `genFileId` 버튼을 그리지 않는다(현재 빈 버튼 문제의 직접 원인).

## 5. 넣는 두 가지 길

### 5-1. 폴더 스캔 (일괄)

- 위촉장 `⋯ 더보기`의 스캔과 **같은 폴더 핸들**(`fsRoot()`)을 쓴다 — 폴더를 다시 지정하지 않는다.
- 판정은 `js/kcareer-scan.js`의 기존 규칙을 재사용한다. `classify(name)`이
  `{level:'sure', store:'certdoc'}`을 주는 파일만 대상이다(파일명 끝이 증명서 단어).
- 원본은 **복사하지 않고 `relPath`만** 저장한다.
- 미리보기 → `등록`. 이미 등록된 `relPath`는 건너뛴다.
- **원본 없는 기존 레코드에 경로만 붙인다.** 매칭 기준은 위촉장의 `matchByFilename`과 같은
  점수 방식을 쓰되 대상은 `_cdSrc(r)==='received' && !hasOriginal(r)`인 레코드로 한정한다.
  점수는 `issuer`(또는 `org`) 앞 4자 일치 +50, 정규화 부분일치 +50, 연도 일치 +30,
  `kind`의 한글 낱말 일치 +5씩, 이미 원본 있으면 −100 — **50점 이상만** 붙인다.
  붙일 때 채우는 것은 `src`·`relPath`·`fileSize`·`fileMtime`·`attachedScanId`뿐이고
  기관·종류·날짜 등 사람이 고칠 수 있는 칸은 건드리지 않는다.
- `made` 레코드는 스캔 대상에서 제외한다(직접 만든 증명서를 덮어쓰지 않는다).

### 5-2. 끌어다 놓기 (개별)

- `page-certdoc`에 이미 `pageDropFile(event,'certdoc')` 훅이 걸려 있다. 이걸 살려
  PDF·이미지를 놓으면 `received` 레코드로 저장한다.
- 폴더 밖 파일은 경로가 없으므로 **이 경우만 base64로 앱에 저장**한다(`saveFileUnified`).
  메일로 받은 증명서용이다.
- 저장 직후 편집창을 열어 발급기관·발급일을 확인·수정할 수 있게 한다.

## 6. OCR — 네 가지만

| 추출 | 저장 칸 | 쓰임 |
|---|---|---|
| 발급기관 | `issuer` | **외부기관 실적 탭 자동 연결의 열쇠** |
| 발급일 | `date`(→ `year`) | 연도별 묶음·정렬 |
| 증명 기간 | `coverage` | "2019~2021 수행" |
| 종류 | `kind` | 실적증명서 / 경력증명서 / 참여확인 |

- **자동 실행하지 않는다.** 행의 `🔍 다시 읽기(OCR)`를 누를 때만 부른다.
  41개를 자동으로 돌리면 시간·비용이 들고, 파일명만으로도 기관·연도는 대개 나온다.
- 엔진은 기존 것을 그대로 쓴다: Gemini(무료) → 실패 시 Claude (`PAGE_OCR_PROMPT`에 `certdoc` 항목 추가).
- `src:'fs'` 레코드도 OCR할 수 있게 원본 취득을 `openOriginal` 경로에 맞춘다.

## 7. 목록 화면

카드 나열을 **표**로 바꾼다(63건 실적에 증명서 40~50건이 붙으면 카드로는 못 찾는다).

```
증명서 종류 │ 발급기관       │ 발급일     │ 증명기간   │ 원본 │ 제출 │ 관리
실적증명서  │ 충남경제진흥원 │ 2025.03.06 │ 2024       │ 📄   │ 🧾2  │ …
경력증명서  │ 한국능률협회   │ 2023.05.11 │ 2019~2021  │ 📄   │ 🧾   │ …
```

- 검색은 발급기관·종류·용도. 기관 필터(`cdOrgFilter`)는 기존 것을 쓴다.
- **`📎 원본 없는 항목만`** 필터를 단다(위촉장과 동일 — `hasOriginal` 기준).
- **제출기록(`🧾`)은 그대로 유지한다.** 이 화면에서 가장 쓸모 있는 기능이고,
  받은 증명서도 어디에 제출했는지 남겨야 한다.
- 양식 만들기 영역(①양식 가져오기·②양식 보관함)은 **`<details>` 접이식**으로 내리고 기본 접힘으로 둔다.
  마크업을 감싸기만 하므로 `initDocCreate`가 잡는 요소 id(`cdDrop`·`cdFile`·`cdTplLib` 등)는
  그대로 살아 있고 기능은 변하지 않는다.
- 표는 기존 카드 렌더(`renderDocStore`)를 대체하지 않고, `certdoc`에서만 표로 그린다
  (`DOMAINS.certdoc.tableView = true`). 이력서·프로필 도메인은 카드를 유지한다 —
  그쪽은 건수가 적고 이번 요구와 무관하다.

## 8. 외부기관 실적과의 양방향 연결

- 외부기관 실적 탭 → 기관 묶음 아래 그 기관 증명서 자동 표시 (**이미 구현됨**,
  `renderPuAgency`의 certdoc 매칭). `issuer`가 채워지면 매칭 정확도가 올라간다.
  현재 매칭은 `org`·`title`·`fname`을 합쳐 보는데 **`issuer`도 포함**하도록 넓힌다.
- 증명서 표 행 → `🏛 이 기관 실적 N건` 버튼으로 외부기관 실적 탭의 해당 기관으로 이동.
- 수동 연결(`➕ 증명서 연결`, `agencyKey`)은 **남겨둔다** — OCR이 기관명을 애매하게 읽거나
  (`충남경제진흥원` vs `충청남도경제진흥원`) 증명서에 기관명이 없을 때의 구제 수단이다.

## 9. 안전장치

1. **스캔은 미리보기까지만.** `등록`을 눌러야 저장된다.
2. **`scanId` 단위 되돌리기** — 그 스캔이 만든 레코드만 삭제, 경로만 붙인 기존 레코드는 경로만 해제
   (위촉장 `fsUndoScan`과 같은 구분).
3. **중복 방지** — 등록된 `relPath`는 건너뛰고, 원본 없는 기존 레코드에는 경로만 붙인다.
4. **`made` 보호** — 직접 만든 증명서는 스캔·OCR이 건드리지 않는다.
5. **판정 규칙은 `js/kcareer-scan.js` 재사용** — 새 규칙 모듈을 만들지 않아 회귀 위험이 낮다.
6. 테스트: `tests/kcareer-html.test.js`에 정적 검사 추가
   (`_cdSrc` 분기 · received에 genFileId 버튼 없음 · 스캔이 made를 건드리지 않음 ·
   표 컬럼과 원본없음 필터 존재 · 반복문 안 `set()` 금지).

## 10. 범위 밖

- 증명서 상세 내용(사업명·금액·수행건수) 추출
- 증명서 발급 요청·기관 연락처 관리
- 41개 전부 자동 OCR (필요한 건만 `🔍 다시 읽기`)
- `made` 증명서 생성 흐름 변경 (양식 가져오기·채우기·저장은 그대로)
- 카드 화면 완전 제거 (표를 기본으로 두되 기존 기능은 유지)

## 11. 가정

- 서류 폴더는 위촉장 작업에서 이미 연결돼 있다(`fsRoot()`가 핸들을 준다).
  연결돼 있지 않으면 스캔 버튼이 `⋯ 더보기 › 서류 폴더 연결`로 안내한다
  (환경설정으로 보내지 않는다 — 비관리자에게 숨겨지므로).
- 6번 폴더(`6. 컨설팅 실적증명`, 41개)가 증명서의 주 공급원이다. 다른 폴더에 있는 증명서도
  판정 규칙이 같으므로 함께 들어온다.
