# 출금관리 머리 영역 정리 + 거래내역 출금 연동 — 설계

- 날짜: 2026-08-16
- 요청: 대표님 — "출금관리에서 캡쳐1을 좀 더 깔끔하게 정리하고 중복되는 부분 삭제 했으면 좋겠다. 그리고 거래내역에는 입금뿐 아니라 출금도 정리되는데 그때는 출금관리에 자동으로 연동이 되어서 확인할 수 있으면 좋겠다. 캡쳐3 콤팩트하게 정리할 수 있을까"
- 목업: `docs/mockups/expense-toolbar.html`
- 대상 파일: `pu-erp.html` (단일 파일, 빌드 없음, ES5)

---

## 1. 먼저 확인한 것 — 연동은 이미 되고 있다

`FinanceLedger.saveExpense(row, cat)` 가 **`finance_expense` 에 곧바로 쓴다.**
출금관리(`FinanceExpense`)는 그 자료를 읽는다. 즉 **거래내역 → 출금관리 연동은 새로 만들 것이 아니다.**

출금관리의 **「📥 가져오기」는 `ImportLedgerModal`** 이고, 그 안은 `h(FinanceLedger, null)` —
**거래내역을 통째로 띄우는 창**이다.

### 그런데 두 가지가 불편하다

1. **그 창이 「입금」 탭으로 열릴 수 있다.**
   `FinanceLedger` 는 `usePersistedState('ledger_tab','inc')` 로 **마지막에 보던 탭을 기억**한다.
   출금관리에서 눌렀는데 입금이 뜨면 「연동이 안 되나」로 읽힌다.
2. **목록에서 어디서 온 건지 알기 어렵다.**
   `saveExpense` 가 비고에 `[하나은행]`/`[하나카드]` 를 섞어 넣지만 **읽어야 안다.**

---

## 2. 찾은 중복 셋

| 무엇 | 어디 |
|---|---|
| **「🔁 정기」가 두 곳** | 도구줄 단추와 KPI 카드가 **같은 창**(`setShowRecurring(true)`)을 연다 |
| **들여오는 길이 셋** | `📋 일괄`·`💳 카드엑셀`·`📥 가져오기` — 모두 「밖에서 가져오기」인데 흩어져 있다 |
| **지점 줄이 정보를 안 준다** | 서산 0건·공통 0건이라 「전체 25건·6,638만」과 「천안 25건·6,638만」이 **똑같다** |

머리 영역이 **세 줄**(도구줄 / 월네비+KPI / 지점+검색)을 쓴다.

---

## 3. 대표님이 정하신 것

| 물음 | 정하신 것 |
|---|---|
| 자주 쓰는 단추 | **네 묶음 모두** — 출금추가·가져오기 · 기준 토글 · 지난달 · 예산/수수료/CSV |
| 지점 줄 | **자료가 있는 지점만 보이게** |

→ 자주 쓰는 것이 대부분이므로 **감추기가 아니라 「합치기」로 줄인다.**

## 4. 설계

### 4-1. 세 줄 → 두 줄

```
줄1: ◀ 2026년 4월 ▶ 오늘 │ +출금추가  📥가져오기▾  💸기준  📋지난달  📊예산  🏦수수료  ⬇CSV  🔓마감  [🔍 검색]
줄2: [이번 달 지출] [건당 평균] [미납] [정기 ↗]
(지점 줄 — 서산·공통에 자료가 있을 때만)
```

**어떻게**: `MonthKpiHeader` 는 이미 `props.extra` 를 **월 네비 줄 끝에** 그린다. 거기에 도구줄과 검색을 넣는다.
다만 지금은 화면이 넓으면 KPI 를 그 줄에 **끼워 넣는다**(`inlineKpi`) — 도구줄까지 들어가면 글자가 잘린다.
→ **`props.kpiOwnRow`** 를 더해, 그 값이 참이면 KPI 는 **늘 아랫줄**을 쓴다.
→ 도구줄이 길어질 수 있으므로 그 줄에 `flexWrap:'wrap'` 을 준다.

⚠ `MonthKpiHeader` 는 **여러 화면이 함께 쓰는 부품**이다. 새 옵션은 **기본값이 지금과 같아야** 한다
(`kpiOwnRow` 를 안 주면 지금 그대로 동작). 다른 화면을 건드리지 않는다.

### 4-2. 들여오기 셋을 한 입구로

**「📥 가져오기 ▾」** 하나만 두고, 누르면 작은 메뉴가 열린다:

1. **🏦 거래내역에서 가져오기** — `ImportLedgerModal` (**출금 탭**으로 연다)
2. **📋 붙여넣기로 여러 건** — `ExpenseBulkImportModal`
3. **💳 카드 엑셀 파일** — `CardExcelImportModal`

⚠ **창 세 개는 그대로 둔다.** 합치는 것은 위험하고, 지금 문제는 「단추가 흩어져 있다」이다.
바꾸는 것은 **입구뿐**이다.

### 4-3. 「🔁 정기」 단추를 뺀다

KPI 카드 「🔁 정기 18건」이 이미 같은 창을 연다. **눌리는 것임을 알 수 있게** 부제를 「눌러서 관리」로 바꾼다.
⚠ 눌리는 줄 모르면 기능을 잃는 것이다 — 이 저장소에서 「안 보이는 기능은 없는 기능」을 다섯 번 겪었다.

### 4-4. 지점 줄은 자료가 있을 때만

서산·공통에 **이 달 자료가 한 건도 없으면** 줄 자체를 안 그린다(검색은 도구줄로 옮겼으므로 빈자리가 안 생긴다).
한 지점이라도 생기면 지금처럼 네 칸이 다 나온다 — **자료가 있는 지점을 감추지 않는다.**

### 4-5. 거래내역에서 온 것을 표로 알린다

`saveExpense` 가 쓰는 기록에 **`src:'ledger'`** 를 더한다.
읽는 곳은 함수 하나로 모은다:

```js
function erpExpenseFrom(it){
  if(!it) return '';
  if(it.src === 'ledger') return 'ledger';
  // 옛 기록은 표가 없다 — 비고 머리글자로 알아본다
  if(/^\[하나(은행|카드)\]/.test(String(it.note || ''))) return 'ledger';
  return '';
}
```

목록에 **「🏦 거래내역」** 딱지를 붙인다. 손으로 넣은 건에는 안 붙인다(없는 것이 기본).

### 4-6. 「가져오기」를 출금 탭으로 연다

`FinanceLedger` 에 **`initialTab`** 프로퍼티를 더한다.
지금 탭은 `usePersistedState('ledger_tab','inc')` 라 **기억된 값을 덮어쓰면 안 된다** —
거래내역을 직접 열 때까지 바뀌어 버린다.

→ **한 번만 덮어쓰는 지역 상태**를 둔다:

```js
var ovS = useState(props.initialTab || '');
var ldTab = ovS[0] || ldTabS[0];
function setLdTab(v){ ovS[1](''); ldTabS[1](v); }   // 사람이 탭을 누르면 덮어쓰기를 푼다
```

`ImportLedgerModal` 은 `props.initialTab` 을 그대로 넘긴다. 출금관리에서 열 때 `'exp'` 를 준다.

---

## 5. 안 건드리는 것

- **기능은 하나도 안 없앤다** — 자리만 옮긴다
- 모달 세 개(`ExpenseBulkImportModal`·`CardExcelImportModal`·`ImportLedgerModal`)의 **속**
- `finance_expense` 저장 형식(칸 하나를 **더할** 뿐), 금액 셈, 분류
- `MonthKpiHeader` 를 쓰는 **다른 화면들** — 새 옵션은 기본값이 지금과 같다
- 거래내역 화면 자체 — **어느 탭으로 여느냐만** 정한다

## 6. 검사

`tests/expense-header.test.js` 새로 만든다.

**부품을 실제로 돌린다**
- `erpExpenseFrom` — `src:'ledger'` 를 찾는다 / 옛 기록의 `[하나은행]`·`[하나카드]` 도 찾는다 /
  손으로 넣은 건은 빈 값 / 빈 값·`null` 에도 안 터진다
- `saveExpense` 가 `src:'ledger'` 를 적는다

**화면 규칙**
- 머리 영역이 **두 덩어리**다 (월네비+도구줄 / KPI)
- 도구줄에 「🔁 정기」 단추가 **없다**, KPI 「정기」는 **눌린다**
- 들여오기 단추가 **하나**다 (일괄·카드엑셀이 도구줄에 따로 없다)
- 지점 줄이 **조건부**다
- 검색이 도구줄 안에 있다
- 출금관리에서 여는 거래내역이 `initialTab:'exp'` 를 받는다
- `MonthKpiHeader` 의 새 옵션은 **기본값이 지금과 같다**(안 주면 `inlineKpi` 판단이 그대로)

뮤테이션으로 각 규칙을 하나씩 망가뜨려 검사가 실제로 잡는지 확인한다.
⚠ **뮤테이션 전에 기준선이 초록인지 먼저 본다.**
⚠ 검사에 **글자수 거리·코드 모양·색·높이**를 박지 않는다(`CLAUDE.md` 「검사를 쓰는 규칙」).
⚠ 「글자가 있나」로 볼 때는 **주석에 속지 않게 따옴표까지** 본다(오늘만 세 번 겪었다).

---

## 7. 이 설계가 막는 것

| 지금 | 뒤 |
|---|---|
| 머리가 세 줄을 먹는다 | 두 줄 |
| 단추 11개, 들여오기가 셋으로 흩어짐 | 8개, 들여오기 한 입구 |
| 「정기」가 두 곳 | 한 곳(KPI) |
| 지점 줄이 같은 숫자를 두 번 적는다 | 자료가 있을 때만 나온다 |
| 가져오기를 눌러도 입금 탭이 뜬다 | 출금 탭으로 열린다 |
| 어디서 온 출금인지 비고를 읽어야 안다 | 「🏦 거래내역」 딱지 |
