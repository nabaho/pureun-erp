# 홈페이지 관리 — 설계

작성일 2026-08-16 · 목업 `docs/mockups/homepage-manage.html`

## 무엇을 만드나

푸른노무법인 홈페이지(`https://푸른노무법인.kr`)의 **구성원 소개·주요업무·오시는길** 내용을
푸른통합시스템에서 관리한다. 통합시스템이 원본이고 홈페이지는 사본이다.

통합시스템은 **홈페이지에 붙여넣을 완성본을 만들어 줄 뿐, 홈페이지를 직접 바꾸지 않는다.**
마지막 붙여넣기 한 번은 사람이 한다.

## 조사로 확인한 사실

홈페이지는 **라이믹스(Rhymix)** 로 만들어진 PHP 사이트이며, 별도 웹호스팅(openresty)에 있다.
파이어베이스 위에 있는 통합시스템과는 완전히 분리된 서버다.

| 확인한 것 | 결과 | 설계에 미친 영향 |
|---|---|---|
| 관리자 화면 | 로그인 필요(403은 "로그인이 필요합니다" 화면) | 계정만 있으면 접근 가능. IP 차단 아님 |
| 화면 안에 끼워넣기 | `X-Frame-Options: SAMEORIGIN` | 통합시스템 안에 홈페이지 관리자 화면을 띄울 수 없음 |
| 브라우저에서 직접 읽기 | CORS 허용 헤더 없음 | 대조하려면 **서버 중계 부품이 반드시 필요** |
| 외부 쓰기 창구 | 없음(공식 API 부재) | 자동 전송은 화면 흉내 방식뿐 → 채택하지 않음 |

페이지별 구조가 두 갈래로 갈린다. 이게 이 설계의 핵심 제약이다.

| 페이지 | 주소 | 구조 | 붙여넣기 단위 |
|---|---|---|---|
| 주요업무 5쪽 | `/work1` `/work2` `/work3` `/work4` `/work5a` `/work5b` | 페이지에 HTML 직접 작성 | 쪽 통째로 |
| 오시는길 | `/inquiry` | 페이지에 HTML 직접 작성 | 쪽 통째로 |
| 구성원 소개 | `/people` | 갤러리 위젯 `gall_people_sub` — 1명 = 게시판 글 1건 | **사람 하나씩** |
| 자문사현황 | `/partner` | 갤러리 위젯 `gall_logo` — **로고 이미지만, 회사명 텍스트 없음** | 이번 판 제외 |

구성원 9명의 글 번호: 190(권형하) 193(박성수) 195(박한별) 197(김혜민) 203(박재원)
281(임혜미) 304(김동현) 320(장한돌) 322(조현범).

경력관리 앱(`kcareer.html`)에는 **위촉장·자격증·학력·수료증·강의**가 사람별로 쌓여 있고
(항목 필드: `name` `title` `org` `date` `role` `period` `issuer`),
이미 pu-erp에서 실적을 당겨오는 기능(`puSyncNow`, `KcareerPuSync`)이 들어가 있다.
홈페이지 경력사항은 이 자료를 골라 요약한 것이므로, 당겨오기의 원본으로 삼는다.

## 범위

**넣는 것**

- 구성원 9명 — 이름, 직책, 경력사항(줄 목록)
- 주요업무 5쪽 — 본문 글
- 오시는길 1쪽 — 지사 4곳 주소·전화
- 경력관리에서 당겨오기 (체크한 것만)
- 홈페이지와 자동 대조

**빼는 것과 이유**

| 뺀 것 | 이유 |
|---|---|
| 얼굴사진·로고 | 올리고 내려받는 장치가 붙어 일이 두 배가 된다. 홈페이지에서 직접 올린다 |
| 자문사현황 | 홈페이지에 회사명이 글자로 없어 **관리할 글도 대조할 근거도 없다** |
| 자동 전송 | 관리자 비밀번호를 서버에 보관해야 하고, 공식 창구가 없어 홈페이지 업데이트 시 조용히 깨진다 |
| 공지사항 | 성격이 다르다(자주 올리는 글). 자동 전송이 값어치 있는 유일한 대상이라 별도 판에서 다룬다 |

## 구조

**새 앱 `pu-home.html` 하나로 만든다.** 명함첩·사진첩과 같은 단일 파일 앱 관례를 따른다.
통합시스템 본체 `pu-erp.html`은 이미 4.7MB라 여기에 기능을 더하면 무거워지고,
고칠 때 급여·인사 화면을 건드릴 위험이 커진다.

부품은 셋이고 각각 하나의 일만 한다.

1. **화면** (`pu-home.html`) — 목록·편집·복사·안내
2. **홈페이지 읽기 함수** (functions에 1개 추가) — 홈페이지 쪽을 읽어 본문 텍스트를 돌려준다. 읽기만 한다. 쓰기 권한 없음
3. **완성본 만들기** (`js/pu-home-html.js`) — 자료 → 붙여넣을 HTML. 화면과 분리해 검사할 수 있게 둔다

배포는 함수 이름을 찍어서 한다(전체 배포는 막힌다).

## 자료

파이어베이스 RTDB에 둔다.

```
homepage/members/{id}   name, position, careers[], srl, updatedAt, updatedBy
homepage/pages/{mid}    html, updatedAt, updatedBy        (mid: work1…work5b, inquiry)
homepage/check/{key}    lastCheckedAt, liveText, status   (대조 결과)
```

`careers[]`는 줄 목록이며 각 줄은 `{ text, from }`. `from`은 경력관리에서 당겨온 항목의 출처
(수기로 쓴 줄은 비어 있다).

## 대조

「홈페이지 다시 확인」을 누르면 읽기 함수가 해당 쪽을 읽어와 비교한다.

비교 전에 **양쪽 다 같은 방식으로 다듬는다**: HTML 태그 제거, 연속 공백·줄바꿈 정리,
문장부호 통일. 이걸 안 하면 눈에 안 보이는 공백 차이로 "다름"이 쏟아진다.

상태는 넷이다.

| 딱지 | 뜻 |
|---|---|
| 같음 | 홈페이지와 내용이 일치 |
| 안 올라감 | 통합시스템에서 고쳤는데 홈페이지엔 아직 |
| 새로 올릴 것 | 홈페이지에 아직 없는 사람 |
| 내릴 것 (퇴사) | pu-erp에서 퇴사 처리됐는데 홈페이지엔 아직 있음 |
| 홈페이지에만 | 통합시스템에서 지웠는데 홈페이지엔 남아있음 |

## 입·퇴사 연결

pu-erp의 직원 명부(`staff`)는 이미 **노무사와 직원을 구분**하고 **입사일·퇴사일**을 가지고 있다
(급여 매트릭스가 퇴사일 지난 직원을 자동으로 숨기고 있다). 이걸 그대로 근거로 쓴다.

- 노무사가 **입사** → 구성원 목록에 「새로 올릴 것」으로 뜬다
- 노무사가 **퇴사 처리** → 「내릴 것 (퇴사)」으로 뜨고, 통합시스템 첫 화면에 알림이 뜬다

**실제로 내리는 것은 자동으로 하지 않는다.** 두 가지 이유가 있다.

1. 구성원은 게시판 글이라 내리려면 글을 지우거나 숨기는 동작이 필요하다. 붙여넣기로는 안 된다
2. 지우는 것은 되돌리기 어렵다. pu-erp에 퇴사일을 잘못 넣었을 때 기계가 곧바로 홈페이지에서
   사람을 지워버리면 고객이 보는 화면에서 노무사가 사라진다. 확인 한 번은 사람이 한다

안내는 **삭제가 아니라 비공개(숨김)** 를 권한다. 잘못 내렸어도 되살릴 수 있다.

**이름 훑기**: 퇴사자 이름이 구성원 목록에서만 빠지고 인사말이나 업무 소개글 안에 남는 일이 있다.
대조하느라 어차피 모든 쪽을 읽어오므로, 그 이름이 다른 쪽에 남아 있는지 훑어
「○○ 이름이 아직 2곳에 있습니다」라고 알린다. 어디에 있는지 쪽 이름도 함께 보여준다.

동명이인이나 흔한 이름 때문에 엉뚱한 곳이 걸릴 수 있으므로, **경고만 하고 자동으로 고치지 않는다.**

## 경력관리에서 당겨오기

「경력관리에서 당겨오기」를 누르면 그 사람의 위촉장·자격증·학력·수료증이 목록으로 뜬다.
사람은 **이름으로** 맞춘다.

체크한 항목은 문장으로 바뀐다.

- 기간이 안 끝난 것 → `現 충남 노동권익보호관`
- 기간이 끝난 것 → `前 대전질병판정위원회 위원`

기간 정보가 없으면 **끝났다고 단정하지 않고 現으로 두되 표시를 남긴다**(사람이 판단).
만들어진 문장은 손으로 고칠 수 있다. 자동 문장을 그대로 쓸 의무는 없다.

**만료 경고**: 위촉 기간이 지났는데 홈페이지에 아직 `現`으로 올라가 있으면 목록에서 표시한다.
홈페이지에 만료된 직함이 걸려 있는 것은 밖에서 보기에 나쁜 일이다.

## 붙여넣기

「붙여넣을 내용 복사」를 누르면 완성본이 복사되고 4단계 안내가 함께 뜬다.

1. 홈페이지 관리자 로그인 (`푸른노무법인.kr/admin`)
2. 구성원 갤러리에서 해당 사람 글 → 편집 (쪽인 경우 해당 페이지 → 편집)
3. 본문 전체 선택 후 붙여넣기
4. 저장 → 통합시스템에서 「홈페이지 다시 확인」

4번까지 하면 딱지가 「같음」으로 바뀐다. 안 바뀌면 붙여넣기가 안 된 것이다.

## 잘못될 때

| 상황 | 처리 |
|---|---|
| 홈페이지를 못 읽음 | 「확인 실패」로 표시하고 **지난 대조 결과를 그대로 둔다**. 자료는 건드리지 않는다 |
| 홈페이지 구조가 바뀌어 읽어낸 사람 수가 0 | 대조 결과를 반영하지 않는다. 전부 「안 올라감」으로 잘못 뜨는 것을 막는다 |
| 이름이 안 맞아 당겨오기 실패 | 그 사람만 건너뛰고 화면에 알린다. 다른 사람 작업은 계속된다 |
| pu-erp 직원 명부를 못 읽음 | 입·퇴사 딱지만 표시하지 않는다. 나머지 대조는 그대로 돌아간다 |

## 검사

`tests/`에 규칙 검사를 넣는다.

- 문장 변환: 기간 끝남 → `前`, 진행중 → `現`, 기간 없음 → `現` + 표시
- 비교 전 다듬기: 공백·태그 차이가 「다름」으로 새지 않는지
- 홈페이지 읽어내기: 백업 파일로 구성원 9명이 나오는지
- 입·퇴사 판정: 퇴사일이 지난 노무사 → 「내릴 것」, 퇴사일이 없거나 미래 → 「내릴 것」이 되지 않을 것
- 이름 훑기: 퇴사자 이름이 다른 쪽에 있으면 찾아내고, 없으면 조용할 것

검사에서 **화면 모양이나 항목 개수를 못 박지 않는다.** 그렇게 하면 나중에 내용이 바뀔 때
검사 하나가 모든 앱 배포를 막는다.
