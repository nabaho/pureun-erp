# 푸른사진첩 — 설계서

작성일: 2026-08-02 · **이 문서가 최신이다.** `docs/사진첩_세션인수인계_v1.0.md` 와 `docs/푸른사진첩-당겨오기-계획.md`(2026-08-01)의 결정 중 4개 항목을 대표 지시로 갱신했다. 갱신 내역은 2장.

## 1. 왜 만드는가

사진이 세 군데로 흩어져 있고, 그중 가장 중요한 컨설팅 현장사진이 폰 밖으로 나올 길이 없다.

| 사진 종류 | 현재 저장 위치 | PC에서 보이나 | 문제 |
|---|---|---|---|
| 명함 사진 | 실시간DB에 base64 통째로 | 보임 | 사진이 쌓이면 목록 열기가 느려지고 요금이 오른다 |
| 컨설팅 현장사진 | 사진을 찍은 그 브라우저의 IndexedDB | **안 보임** | 기기 밖으로 못 나온다. 브라우저 저장공간이 정리되면 **소실된다** |
| 카톡·문자로 받은 사진 | 어디에도 없음 | — | 갈 곳이 없다 |

"폰에서 PC로 옮기는 게 번잡하다"의 실제 원인은 두 번째 줄이다. 폰으로 찍은 컨설팅 사진을 PC에서 쓰려면 카톡으로 자기에게 보내거나 케이블로 옮겨야 한다.

### 사진첩의 역할은 보관까지다 (대표 지시 2026-08-02)

**사진첩은 사진을 보관하는 것이 목적이다.** 사진을 가져간 뒤의 처리는 각 프로그램의 업무수행자가 스스로 조정해서 입력한다.

- 컨설팅의 **도장 기능에는 관여하지 않는다.** 도장 시각·도장 그리기는 지금 컨설팅이 하는 방식 그대로 둔다
- 사진첩은 사진과 그 사진에 딸린 정보(촬영 시각 등)를 넘겨주기만 한다. 어떻게 쓸지는 받는 쪽이 정한다
- 사진첩이 보관하는 촬영 시각은 **사진첩 안에서 날짜별로 찾고 정리하기 위한 것**이다

| 항목 | 결정 | 이유 |
|---|---|---|

| 각 앱 연결 | `js/` 공용 조각 하나 → 앱마다 한 줄 | 앱 15개가 이미 공용 파일 4개를 함께 씀 |

| 컨설팅 앱 안에 보관함 | 안 함 | 앱이 커지고 다른 앱이 못 씀 |

## 3. 사진의 네 가지 용도

설계는 이 네 개를 모두 만족해야 한다.

1. 컨설팅 기록에 붙이기 (증빙·현장사진)
2. 보고서·문서에 넣기 (PC에서 파일로 내려받아야 함)
3. 그냥 보관 후 나중에 찾아보기 (검색이 되어야 함)
4. 명함 등록

## 4. 저장 방식 — 1단계에서 시험으로 결정

1단계 착수 시 파일 창고에 사진 한 장을 실제로 올려본다. 반나절 이내. 되면 창고, 막히면 실시간DB. **어느 쪽이든 나머지 설계는 그대로 쓴다.**

### 시험하는 이유

8/1 문서는 "이 저장소의 어떤 앱도 파일 창고를 실제로 쓰지 않는다"며 창고를 철회했다. 확인해보니 정확하지 않다 — `fund.html`에 기금 서류 보관용으로 올리기·내려받기 주소·삭제·DB 기록까지 완성된 창고 코드가 있다. 다만 창고가 꺼져 있으면 경고를 띄우고 넘어가는 분기가 있어, 실제 운영에서 켜서 써봤는지는 확실치 않다. 그래서 "검증 안 된 길"이라는 8/1의 걱정 자체는 타당하다.

### 용량 비교

| | 실시간DB | 파일 창고 |
|---|---|---|
| 무료 저장 용량 | 1GB | 5GB |
| 사진 담는 방식 | base64 — **33% 팽창** | 파일 그대로 |
| 꽉 차는 시점 | 3년쯤 | 15년 넘게 |

사진 한 장당 축소본 300KB + 컨설팅 도장본 400KB ≈ 700KB 기준. 8/1 문서 6장 계산에 base64 팽창을 반영한 값이다.

### 창고를 택할 경우 선행 조건

**대표님이 파이어베이스 콘솔에서 창고 접근 규칙을 넣어야 한다.** 개발자가 대신 할 수 없다. 기존 실시간DB 규칙과 같은 기준으로 맞춘다 — 이메일 로그인 계정만 읽고 쓴다.

### 어느 쪽이든 지킬 것

- **연도별로 나눠 보관한다.** 평소에는 올해 것만 불러온다
- 사진은 **볼 때만 한 장씩** 받아온다. 앱 열 때 통째로 받으면 느려진다
- 올릴 때 긴 변 1600px로 축소(약 300KB). **카메라 원본은 클라우드에 올리지 않는다**
- 격자용 작은 미리보기를 따로 만든다. 격자에서는 미리보기만 받는다
- 사진은 **한 장씩 추가만.** 배열·객체를 통째로 덮어쓰지 않는다 (2026-07 데이터 사고 재발 방지 — 8장)

## 5. 사진을 올리는 길

### 길 1 — 갤러리에서 여러 장 골라 올리기 (기본)

푸른사진첩을 열고 「사진 고르기」 → 폰 갤러리에서 여러 장 선택 → 한 번에 업로드. 사업장·일정은 고르지 않는다.

### 길 2 — 공유하기로 바로 보내기

카톡·갤러리에서 사진 선택 → 「공유」 → 목록의 「푸른사진첩」. 앱을 열지 않고 전송. (Web Share Target — 안드로이드에서 동작. 사무실 폰은 대부분 안드로이드로 확인됨.)

### 길 3 — 앱 안에서 즉석 촬영

### 경로별 자동 분류 정확도

| 올린 경로 | 촬영 시각 정보 | 자동 분류 |
|---|---|---|
| 앱에서 갤러리 사진 고르기 | EXIF 있음 | 날짜·시각으로 일정 대조 → 대체로 자동 |
| 앱에서 즉석 촬영 | 현재 시각 | 거의 확실히 자동 |
| 카톡·문자에서 공유 | **카톡이 EXIF를 제거함** | 파일 날짜 → 없으면 후보 제시 → 탭 한 번 |
| 명함 (경로 무관) | 무관 | 글자 판독으로 판정 → 명함첩 |

## 6. 자동 분류 규칙

업로드 직후 자동 실행. **자동으로 정해도 담당자가 언제든 고칠 수 있다.**

1. **명함 여부 판정** — Gemini로 판정. 명함이면 이름·회사·전화를 읽어 명함첩 등록 후보로 올린다. (푸른카메라의 기존 판독 로직 재사용)
2. **명함이 아니면 일정 대조** — 촬영 시각(EXIF → 파일 날짜 → 업로드 시각)과 올린 사람을 기준으로 그날 그 사람의 컨설팅 일정을 조회한다.
   - 일정 1건 → 그 회사에 자동 연결
   - 여러 건 → 후보를 제시하고 탭 한 번 받음 (하루 두 사업장 방문 시)
   - 없음 → 미분류함으로
3. **함께 처리할 사람 자동 지정** — 회사가 정해지면 그 사업장 담당 노무사(주·부)가 자동으로 포함된다. 컨설팅 일정에 이미 사업장별 주/부 담당이 지정되어 있으므로 별도 선택이 필요 없다.

**여기까지는 회사를 붙이는 것뿐이다. 컨설팅 일정의 사진 칸에 넣는 것은 담당자가 당겨오기 창에서 직접 한다**(7장 ③). 자동으로 증빙 칸에 밀어넣지 않는다.

미분류로 남은 사진은 「미분류 N장」 배지로 표시한다. 이것이 할 일 목록 역할을 한다.

## 7. 쓰는 흐름

### ① 현장 — 할 일 없음

평소대로 폰 기본 카메라로 찍는다. 앱을 열지 않는다.

### ② 올리기 — 폰, 터치 세 번

푸른사진첩 → 「사진 고르기」 → 앨범에서 여러 장 선택. 올리는 중 자동으로 축소·촬영 시각 읽기·분류가 돌아간다. 분류 결과가 카드로 뜨고, **맞으면 아무것도 누르지 않고 나간다.**

신호가 약하면 폰에 담아뒀다가 연결되면 자동 재시도한다.

### ③ 컨설팅에 넣기 — PC, 당겨오기 창

일정의 사진 칸 옆 「사진첩에서 가져오기」 버튼.

- 창이 뜨면 날짜를 고른다 → 그날 사진만 격자로 (자동 분류로 회사가 붙어 있으면 그 회사 것이 먼저)
- 사진마다 촬영 시각을 참고용으로 표시
- 쓸 것 체크 → 고른 순서대로 칸에 배정 → 「넣기」
- 사진첩에는 "사용됨" 표시만 남고 사진은 그대로 보관

**넣은 뒤의 처리는 컨설팅 담당자가 지금 하던 대로 한다.** 도장 시각을 비롯한 조정·입력은 컨설팅 쪽 몫이고, 당겨오기 창은 사진을 칸에 놓아주는 것까지만 한다.

이 창은 `js/` 공용 조각으로 만든다. 다른 앱에서도 한 줄 추가로 쓴다. 받는 앱마다 사진을 어떻게 쓰는지가 다르므로, 창은 **사진을 넘겨주는 데까지만** 책임진다.

## 8. 화면

### 폰 화면

버튼 두 개(「사진 고르기」·「카메라」)만 크게. 업로드 후 분류 결과 카드. 명함으로 판정된 사진은 읽어낸 이름·회사·전화와 「명함첩에 등록」 버튼.

### PC 화면

- 왼쪽: 걸러보기 — 회사 / 날짜 / 올린 사람 / 종류(명함·회의·현장·미분류)
- 가운데: 사진 격자 (작은 미리보기)
- 사진 클릭 → 크게 보기 + 정보 패널 (올린 사람, 촬영 시각, 회사, 사용된 일정, 함께 처리하는 사람, 설명)
- 여러 장 선택 → 한꺼번에 회사 지정 / 내려받기 / 설명 달기

보고서 작성 시 "○○기업 6월 사진 전부"를 골라 한 번에 내려받는 흐름을 지원한다.

## 9. 사진에 기록되는 정보

- 올린 사람 (로그인 계정에서 자동)
- 올린 시각 / 촬영 시각 (수정 가능)
- 회사 (자동 분류 또는 수동 지정)
- 사용된 컨설팅 일정·칸 표시 (사진은 컨설팅이 복사해 가짐)
- 종류 (명함 / 회의 / 현장 / 미분류)
- 함께 처리하는 사람 목록
- 설명 (수동 입력)
- 개인잠금 여부

## 10. 권한

| 행위 | 누가 |
|---|---|
| 보기 | 전 직원 |
| 정리 — 회사 변경, 설명 작성, 촬영 시각 수정, 내려받기 | 올린 사람 + 공유받은 사람 + 그 사업장 담당자 |
| 지우기 | 올린 사람 + 관리자 |

**개인잠금을 걸면** 보기·정리 모두 올린 사람과 명시적으로 공유한 사람으로 제한된다. 사업장 담당자 자동 포함도 적용하지 않는다. 관리자도 열람하지 않는다 — 명함첩의 잠금폴더와 같은 취급이다.

**자동 삭제는 하지 않는다.** 사람이 지운 사진만 휴지통에 30일 보관한다(명함첩과 동일).

## 11. 기존 사진 옮기기

### 명함첩 사진 — 자동

이미 클라우드에 있으므로 뒤에서 순차적으로 옮긴다. 사용자 조작 없음. (3단계)

### 컨설팅 사진 — 기기별 수동 1회

클라우드에 없고 사진을 찍은 기기의 브라우저 저장공간에만 있으므로 다른 곳에서 꺼낼 방법이 없다. 컨설팅 일정 앱에 「내 기기 사진 창고로 올리기 (N장)」 버튼을 둔다. 사진 촬영에 사용한 기기마다 한 번씩 눌러야 한다.

**업로드 후에도 기기 안 사진은 지우지 않는다.** 정상 업로드를 확인하기 전에 원본을 삭제하는 것은 위험하다.

## 12. 반드시 지킬 규칙

### 12-1. 실데이터 사고 방지 (제일 중요)

2026-07에 브라우저 테스트가 저장 함수를 실제로 호출해 **사업장 26곳·일정 53건을 테스트 데이터로 덮어썼다.** 백업에서 복구했다.

- 브라우저 테스트 전에 **반드시 클라우드 저장 함수를 스텁으로 갈아끼운다**
  ```js
  window.__origFbPush = fbPush;
  window.fbPush = function(){ (window.__pushed=window.__pushed||[]).push(1); return Promise.resolve(); };
  ```
- 끝나고 `window.__pushed.length === 0` 을 확인해 보고한다
- 테스트 데이터는 `localStorage.setItem` 으로 직접 넣고, 끝나면 지운다

### 12-2. 검증

빌드가 없으므로 스크립트를 뽑아 문법 검사 → 브라우저에서 동작 확인 순서.

```powershell
$h=[System.IO.File]::ReadAllText("gov-consulting.html",[System.Text.Encoding]::UTF8)
$m=[regex]::Matches($h,'(?s)<script(?![^>]*\ssrc=)[^>]*>(.*?)</script>')
$js=($m|ForEach-Object{$_.Groups[1].Value}) -join "`n;`n"
[System.IO.File]::WriteAllText("$env:TEMP\chk.js",$js,(New-Object System.Text.UTF8Encoding($false)))
node --check "$env:TEMP\chk.js"
```

`Get-Content -Raw` 로 읽으면 한글이 깨진다. 반드시 `ReadAllText` + UTF8.

## 13. 만드는 순서

각 단계가 끝나면 그것만으로 쓸 수 있어야 한다. **A~C는 새 파일이라 기존 앱에 영향이 없다. D에서 처음으로 컨설팅 앱을 건드린다.**

| 덩이 | 내용 | 이것까지 하면 |
|---|---|---|
| **A** | 창고 시험(4장) → 앱 껍데기 + 포털 등록 | 앱이 열림. 저장 방식 확정 |
| **B** | 사진 클라우드 저장 (연도별 분리) + 업로드 대기열·재시도 | **폰↔PC 사진 공유됨** |
| **C** | 사진첩 화면 — 올리기·격자·날짜별 보기·촬영 시각 수정·올린 사람 표시 | 앨범에서 몰아 올리기 됨 |
| **D** | 당겨오기 창(공용 조각) + 컨설팅 연결 + 기기별 이전 버튼 | **대표 요구 완성** |
| **E** | 자동 분류(명함 판정·일정 대조) + 함께 처리하는 사람 + 미분류 배지 | 손이 덜 감 |
| **F** | 명함첩 사진 창고로 이전 | 명함첩이 가벼워짐 |
| **G** | 연말 ZIP 백업 | 해마다 안전하게 남음 (12월 전) |

A~D가 급한 부분이다. **컨설팅 사진이 지금 촬영 기기 안에만 있어 소실 위험이 있다.**

## 14. 범위에서 제외한 것

- **아이폰의 「공유하기」 연동** — Safari가 Web Share Target을 지원하지 않는다. 아이폰에서는 앱을 열고 사진을 고르는 길 1·3만 동작한다. 사무실 폰이 대부분 안드로이드이므로 감수한다.
- **카톡으로 받은 사진의 촬영 시각 복원** — 카톡이 EXIF를 제거하므로 불가능하다. 파일 날짜 → 후보 제시로 대체한다.
- **컨설팅 일정의 사진 칸 구조 변경** — 정부지원사업 증빙 요건에 맞춰 이미 정교하게 만들어져 있다(칸 개수가 일정별로 다르고 최대 12칸). 손대지 않는다.
- **컨설팅의 도장 기능 일체** — 대표 지시(8/2). 도장 시각·도장 그리기는 컨설팅이 하던 방식 그대로 둔다. 사진첩이 촬영 시각을 도장에 자동으로 밀어넣지 않는다. 8/1 문서 1장의 "도장 시각: 실제 찍은 시각을 기본값으로" 항목은 **범위에서 빠졌다** — 다시 제안하지 말 것.
- **자동으로 증빙 칸에 넣기** — 회사만 자동으로 붙이고, 칸 배정은 담당자가 한다. 증빙물이므로 사람이 확인한다.
- **기기 안 컨설팅 사진 자동 삭제** — 창고 업로드 후에도 남긴다.
- **카메라 원본 보관** — 1600px 축소본만 올린다.
