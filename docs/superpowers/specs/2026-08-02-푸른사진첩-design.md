# 푸른사진첩 — 설계서

작성일: 2026-08-02

## 1. 왜 만드는가

사진이 세 군데로 흩어져 있고, 그중 가장 중요한 컨설팅 현장사진이 폰 밖으로 나올 길이 없다.

| 사진 종류 | 현재 저장 위치 | PC에서 보이나 | 문제 |
|---|---|---|---|
| 명함 사진 | 실시간DB에 base64 통째로 | 보임 | 사진이 쌓이면 목록 열기가 느려지고 요금이 오른다 |
| 컨설팅 현장사진 | 사진을 찍은 그 브라우저의 IndexedDB | **안 보임** | 기기 밖으로 못 나온다. 브라우저 저장공간이 정리되면 **소실된다** |
| 카톡·문자로 받은 사진 | 어디에도 없음 | — | 갈 곳이 없다 |

사용자가 "폰에서 PC로 옮기는 게 번잡하다"고 한 것의 실제 원인은 두 번째 줄이다. 폰으로 찍은 컨설팅 사진을 PC에서 쓰려면 카톡으로 자기에게 보내거나 케이블로 옮겨야 한다.

부수적으로, 컨설팅 사진에 백업이 없다는 것은 증빙 자료 소실 위험이다.

## 2. 사진의 네 가지 용도

사용자가 밝힌 용도. 설계는 이 네 개를 모두 만족해야 한다.

1. 컨설팅 기록에 붙이기 (증빙·현장사진)
2. 보고서·문서에 넣기 (PC에서 파일로 내려받아야 함)
3. 그냥 보관 후 나중에 찾아보기 (검색이 되어야 함)
4. 명함 등록

## 3. 구조 결정

**사진 창고를 하나 두고, 각 앱은 참조만 한다.**

사진 파일은 파일 창고(Firebase Storage — 기금관리가 이미 사용 중)에 저장한다. 명함첩과 컨설팅 일정은 사진을 복사해 갖지 않고 "이 사진이 붙어 있다"는 연결만 갖는다.

검토했으나 채택하지 않은 안:

- **컨설팅 일정에 첨부 기능만 추가** — 가장 적게 만들지만, 일정에 붙지 않는 사진(보관용·보고서 재료)이 갈 곳이 없다. 위 4가지 용도 중 2, 3을 못 채운다.
- **푸른카메라를 사진첩 겸용으로 확장** — 앱 개수는 안 늘지만, 폰 전용으로 만든 앱에 PC 정리 화면을 얹으면 무거워진다. 명함 특화 구조와 맞지 않는다.

### 앱별 역할

| 앱 | 역할 | 변경 |
|---|---|---|
| **푸른사진첩** (신규) | 사진 창구 + 정리 화면 | 신규 |
| 컨설팅 일정 | 슬롯 구조(입장/활동/추가) 유지 | 사진이 창고로 올라가게 + 이전 버튼 추가 |
| 명함첩 | 명함 관리 | 사진을 창고에서 읽게 + 기존 사진 창고로 이전 |
| 푸른카메라 | 명함 전용 빠른 촬영기 | 변경 없음 |

## 4. 사진을 올리는 길

### 길 1 — 갤러리에서 여러 장 골라 올리기 (기본)

푸른사진첩을 열고 「사진 고르기」 → 폰 갤러리에서 여러 장 선택 → 한 번에 업로드. 지난주 회의 사진을 몰아서 올리는 경우.

### 길 2 — 공유하기로 바로 보내기

카톡·갤러리에서 사진 선택 → 「공유」 → 목록의 「푸른사진첩」. 앱을 열지 않고 전송. (Web Share Target — 안드로이드에서 동작. 사무실 폰은 대부분 안드로이드로 확인됨.)

### 길 3 — 앱 안에서 즉석 촬영

### 경로별 자동 분류 정확도

| 올린 경로 | 촬영 시각 정보 | 자동 분류 |
|---|---|---|
| 앱에서 갤러리 사진 고르기 | EXIF 있음 | 날짜·시각으로 일정 대조 → 대체로 자동 |
| 앱에서 즉석 촬영 | 현재 시각 | 거의 확실히 자동 |
| 카톡·문자에서 공유 | **카톡이 EXIF를 제거함** | 업로드 날짜로 후보 제시 → 탭 한 번 |
| 명함 (경로 무관) | 무관 | 글자 판독으로 판정 → 명함첩 |

## 5. 자동 분류 규칙

업로드 직후 자동 실행.

1. **명함 여부 판정** — Gemini로 판정. 명함이면 이름·회사·전화를 읽어 명함첩 등록 후보로 올린다. (푸른카메라의 기존 판독 로직 재사용)
2. **명함이 아니면 일정 대조** — 촬영 시각(EXIF, 없으면 업로드 시각)과 올린 사람을 기준으로 그날 그 사람의 컨설팅 일정을 조회한다.
   - 일정 1건 → 그 회사·일정에 자동 연결
   - 여러 건 → 후보를 제시하고 탭 한 번 받음
   - 없음 → 미분류함으로
3. **함께 처리할 사람 자동 지정** — 회사가 정해지면 그 사업장 담당 노무사(주·부)가 자동으로 포함된다. 컨설팅 일정에 이미 사업장별 주/부 담당이 지정되어 있으므로 별도 선택이 필요 없다.

미분류로 남은 사진은 「미분류 N장」 배지로 표시한다. 이것이 할 일 목록 역할을 한다.

## 6. 화면

### 폰 화면

버튼 두 개(「사진 고르기」·「카메라」)만 크게 둔다.

업로드하면 분류 결과가 카드로 표시된다. **맞으면 아무것도 누르지 않고 나간다.** 틀렸을 때만 회사를 탭해서 바꾼다. 명함으로 판정된 사진은 읽어낸 이름·회사·전화와 함께 「명함첩에 등록」 버튼이 붙는다.

### PC 화면

- 왼쪽: 걸러보기 — 회사 / 날짜 / 올린 사람 / 종류(명함·회의·현장·미분류)
- 가운데: 사진 격자 (작은 미리보기)
- 사진 클릭 → 크게 보기 + 정보 패널 (올린 사람, 촬영 시각, 회사, 연결된 일정, 함께 처리하는 사람, 설명)
- 여러 장 선택 → 한꺼번에 회사 지정 / 내려받기 / 일정에 붙이기

보고서 작성 시 "○○기업 6월 사진 전부"를 골라 한 번에 내려받는 흐름을 지원한다.

## 7. 저장 방식

사진 파일은 파일 창고에, 목록 정보(회사·설명·올린 사람 등 글자)만 실시간DB에 가볍게 둔다.

사진 한 장을 **작은 미리보기와 원본 두 개로** 저장한다. 격자에서는 미리보기만 내려받고, 원본은 크게 볼 때와 내려받을 때만 가져온다.

현재 명함첩처럼 실시간DB에 base64로 넣으면 목록을 여는 것만으로 전체 사진을 내려받게 되어 사진이 쌓일수록 느려지고 요금이 오른다.

각 사진에 기록되는 정보:

- 올린 사람 (로그인 계정에서 자동)
- 올린 시각 / 촬영 시각
- 회사 (자동 분류 또는 수동 지정)
- 연결된 컨설팅 일정과 슬롯 (있는 경우)
- 종류 (명함 / 회의 / 현장 / 미분류)
- 함께 처리하는 사람 목록
- 설명 (수동 입력)
- 개인잠금 여부

## 8. 권한

세 겹으로 나눈다.

| 행위 | 누가 |
|---|---|
| 보기 | 전 직원 |
| 정리 — 회사·일정 변경, 설명 작성, 내려받기 | 올린 사람 + 공유받은 사람 + 그 사업장 담당자 |
| 지우기 | 올린 사람 + 관리자 |

**개인잠금을 걸면** 보기·정리 모두 올린 사람과 명시적으로 공유한 사람으로 제한된다. 사업장 담당자 자동 포함도 적용하지 않는다. 관리자도 열람하지 않는다 — 명함첩의 잠금폴더와 같은 취급이다.

지운 사진은 **휴지통에 30일** 보관한다. 명함첩이 이미 같은 방식을 쓰고 있으므로 동일하게 맞춘다.

## 9. 기존 사진 옮기기

### 명함첩 사진 — 자동

이미 클라우드에 있으므로 뒤에서 순차적으로 창고로 옮긴다. 사용자 조작 없음.

### 컨설팅 사진 — 기기별 수동 1회

클라우드에 없고 사진을 찍은 기기의 IndexedDB에만 있으므로, 다른 곳에서 꺼낼 방법이 없다. 컨설팅 일정 앱에 「내 기기 사진 창고로 올리기 (N장)」 버튼을 둔다. 사진 촬영에 사용한 기기마다 한 번씩 눌러야 한다.

**업로드 후에도 기기 안 사진은 지우지 않는다.** 창고에 정상 업로드된 것을 확인하기 전에 원본을 삭제하는 것은 위험하다.

## 10. 끊기지 않게 하는 장치

현장에서 신호가 약한 경우가 많다. 업로드 실패 시 폰에 대기열로 남겨두고 신호가 돌아오면 자동 재시도한다. 오프라인에서 찍은 사진도 일단 대기열에 담긴다.

## 11. 만드는 순서

한 번에 다 만들지 않는다. 각 단계가 끝나면 그것만으로 쓸 수 있어야 한다.

**1단계 — 사진이 폰 밖으로 나오게** (가장 급한 것)
파일 창고 연결, 푸른사진첩 기본 화면(올리기·격자·크게 보기), 컨설팅 사진의 기기별 이전 버튼, 컨설팅 사진의 창고 업로드. 이 단계만으로 "폰에 갇힌 사진" 문제와 소실 위험이 해소된다.

**2단계 — 손이 덜 가게**
공유하기 연동, 자동 분류(명함 판정 + 일정 대조), 함께 처리하는 사람 자동 지정, 미분류 배지, 업로드 대기열·재시도.

**3단계 — 명함첩 정리**
명함첩 사진을 창고로 이전하고 명함첩이 창고에서 읽게 바꾼다. 급하지 않으므로 마지막에 둔다.

## 12. 범위에서 제외한 것

- **아이폰의 「공유하기」 연동** — Safari가 Web Share Target을 지원하지 않는다. 아이폰에서는 앱을 열고 사진을 고르는 길 1·3만 동작한다. 사무실 폰이 대부분 안드로이드이므로 감수한다.
- **카톡으로 받은 사진의 촬영 시각 복원** — 카톡이 EXIF를 제거하므로 불가능하다. 후보 제시로 대체한다.
- **컨설팅 일정의 슬롯 구조 변경** — 정부지원사업 증빙 요건에 맞춰 이미 정교하게 만들어져 있다. 손대지 않는다.
- **기기 안 컨설팅 사진 자동 삭제** — 창고 업로드 후에도 남긴다.
