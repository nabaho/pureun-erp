# 파이어베이스 사용액 — 시간별 기록 · 항목별 시간당 사용량 (설계)

- 날짜: 2026-08-17
- 요청: 대표님 — "금액 변화에 대해 기록 남길 수 있나. 몇 시에 체크 시 얼마 그리고 얼마 상승 이렇게 구체적으로 각 시간별 금액을 표시해 두면 좋겠다. 그래야 체크 가능하다. 그리고 각 항목마다 구체적으로 시간당 얼마씩 사용했는지 구분해 달라." + "창고·DB·서버·그 밖 각각 변화도 보여지게 해라."
- 목업: `docs/mockups/billing-history.html`
- 대상: `functions/billing-alert.js` · `functions/index.js` · `js/pu-billing.js` · `enter.html`

## 1. 지금 어떻게 도는가 (확인한 것)

```
구글 예산 4개 → Pub/Sub「billing-alerts」→ recordBillingAlert → RTDB billing/current/{key}
```

- 예산 이름으로 갈라 담는다: `pu-total`→`total` · `pu-storage`→`storage` · `pu-database`→`database` · `pu-functions`→`functions`
- 한 줄: `{ cost, budget, currency, updatedAt }`
- **`billing/current` 은 「이 순간 값」만 덮어쓴다** — 지난 값이 안 남는다. 그래서 「어제보다 늘었나」를 알 길이 없다.
- 화면은 `enter.html` 의 `#billModal` (관리자만), 셈은 `js/pu-billing.js`(그리지 않는다 — 그려야 확인되는 코드는 검사를 못 한다).

### ★ 이 숫자가 오는 방식이 설계를 정한다

- **구글은 「금액이 움직일 때만」 쏜다.** 정해진 시각마다가 아니다(주기 20~30분쯤).
  밤에 아무도 안 쓰면 몇 시간씩 조용한 것이 **정상**이다(그래서 「소식 끊김」 기준이 26시간이다).
- **항목 넷이 각각 따로 온다.** 예산이 넷이므로 쪽지도 넷이고, 시각도 다르다.
  → **한 시점에 넷이 다 있는 스냅샷이 아니다.** 항목별 시계열로 담아야 정직하다.

### 규칙은 안 건드린다 (살아 있는 규칙을 읽어 확인)

```json
"billing": { ".read": "auth != null && …isAdmin…", ".write": false }
```

`.read` 가 `billing` 에 걸려 있어 **하위(`billing/history`)까지 그대로 내려간다.**
서버는 Admin SDK 라 규칙을 우회하므로 쓰기도 된다. **콘솔에서 게시할 것이 없다.**

## 2. 무엇을 만드는가

### 2-1. 기록 자리

알림이 올 때마다 **한 줄**을 더한다. 항목별로 따로 온다.

```
billing/history/{YYYY-MM}/{key}/{ts} = cost          (숫자 하나)
예) billing/history/2026-08/database/1755419280000 = 81225
```

- **값 하나만** 적는다(금액). 한 줄이 40바이트도 안 된다. `budget` 은 `current` 에 이미 있다.
- **달마다 나눠 담는다** — 달이 바뀌면 구글이 0부터 다시 센다. 경계를 넘겨 증가분을 내면 **큰 마이너스**가 나온다.
- 달은 쪽지의 `costIntervalStart`(집계 시작일)에서 뽑는다 — 도착 시각으로 뽑으면 월말 자정 무렵 쪽지가 엉뚱한 달에 담긴다.
- `ts` 는 **도착 시각(ms)**. 같은 `ts` 로 두 번 오면 덮어쓴다(같은 값이라 문제 없다).

⚠ `current` 는 「더 큰 값만」 받는데(늦게 온 옛 쪽지 방어), **`history` 는 그 시각의 값을 그대로 남긴다.**
기록은 「그때 얼마였나」이고, 늦게 온 쪽지도 그 시각의 사실이다.

⚠ **기록 쓰기가 실패해도 `current` 갱신은 살린다.** 지금 값이 더 중요하다 —
기록 때문에 지금 값이 안 올라가면 손해가 크다. `try/catch` 로 감싸고 로그만 남긴다.

### 2-2. 셈 (js/pu-billing.js — 그리지 않는다)

**`hourBuckets(history, opts)`**
항목별 시계열 → **한 시간 칸별 증가분**.

```
{ hour:'2026-08-17T17', total:3640, parts:{ storage:2, database:3600, functions:0, etc:38 },
  known:{ storage:true, database:true, functions:false, etc:true } }
```

- 한 시간 안에 여러 쪽지가 오면 **그 칸의 마지막 값 − 앞 칸의 마지막 값**.
- 그 칸에 그 항목 쪽지가 **아예 없으면** `known[항목] = false` → 화면은 **「—」**.
  ⚠ **0 으로 적지 않는다.** 0 은 「그 시간엔 공짜였다」로 읽힌다.
  이 저장소에서 「없는 값을 0 으로 둔갑시키는」 실수를 여러 번 겪었다(`num()` 이 그것 때문에 있다).
- 첫 칸에는 **앞이 없으니 증가분도 없다** → `known:false`. 0 으로 적지 않는다.
- `etc`(그 밖) = `total − (storage+database+functions)`. **음수면 0 으로 깎는다** —
  낡은 칸 몫이 새어 마이너스로 보이던 일이 있었다(2026-08-16 「그 밖 착시」).

**`hourlyRates(buckets)`**
항목별 **시간당 평균**.

- 나누는 것은 **「알고 있는 칸 수」**다. 「소식 없음」 칸을 0 으로 치고 나누면 **시간당이 실제보다 낮게** 나온다.
- 칸 수가 0 이면 `null` — 「아직 모른다」다.

⚠ **왜 시각 그대로 안 나누나** — 알림 간격이 2분일 때도 4시간일 때도 있다.
간격으로 나누면 2분짜리 기록에서 **시간당이 30배로 부풀어** 보인다.
한 시간 칸으로 묶으면 「17시에 3,640원 늘었다」가 곧 「그 시간에 시간당 3,640원」이라 셈이 필요 없다.

### 2-3. 화면 (enter.html #billModal)

칸 두 개: **「지금」**(지금 그대로) · **「기록」**(새로).

**기록 칸** — 기간 고르기: `오늘 / 어제 / 이번 달`

| 시각 | 전체 | +증가 | 창고 | DB | 서버 | 그 밖 |
|---|---|---|---|---|---|---|

- 칸이 일곱이라 **「기록」 칸에서만 창을 넓힌다**(380px → 660px). 「지금」 칸은 지금 크기 그대로.
- **+빨강** 늘어난 돈 · **회색 0** 안 늘었다 · **—** 소식이 없어 「모른다」
- 이 세 가지 뜻을 **표 아래에 적어 둔다** — 안 적으면 0 과 「—」를 같은 것으로 읽는다.
- 날짜가 바뀌는 줄에 **그날 합계를 항목별로** 적는다.

**항목별 시간당** — 표로.

| 항목 | 이 기간 늘어난 돈 | 시간당 | 이대로 하루면 |
|---|---|---|---|

- 막대는 **비중**만 (숫자는 표가 말한다).
- 창고·서버가 0 이어도 **줄을 남긴다** — 「0 이다」와 「항목이 없다」는 다르고, 언젠가 늘면 그 자리에서 보인다.
- 아래에 「이대로 남은 N일이면 ≈ ₩…」 + **「지금 추세일 뿐」** 이라고 적는다.

**읽기**: 고른 달 하나를 **`once()` 로 한 번만** 읽는다.
⚠ **구독(`on()`)하지 않는다.** 사용액 보려다 사용액이 늘면 웃긴다
(이 저장소가 실시간DB 비용으로 고생했고, `once()` 뒤 같은 자리 `on()` 은 두 번 받는다는 것도 겪었다).

## 3. 안 건드리는 것 / 안 만드는 것

- **`billing/current` 과 「지금」 칸** — 이미 도는 것이다. 기록은 **옆에 새로 쌓기만** 한다.
- **RTDB 규칙** — 손댈 것이 없다(위 1절).
- **그래프** — 표로 충분하다. 숫자를 눈으로 대조하는 것이 목적이다.
- **알림·경고** — 「얼마 넘으면 알려 주기」는 지금도 구글 예산이 한다. 여기서 또 하면 두 곳에서 울린다.
- **분 단위 기록** — 구글이 그 간격으로 안 쏜다. 없는 정밀도를 그리면 거짓이다.
- **오래된 달 정리** — 지금은 안 한다. 한 달 수백 KB라 여러 달을 둬도 괜찮다. 무거워지면 그때.

⚠ **지난 기록은 없다.** 지금까지 「이 순간 값」만 덮어써 왔으므로 **기록은 켜는 날부터 쌓인다.**
오늘 켜면 내일부터 하루치 비교가 된다. 화면이 이 사실을 말해야 한다 —
빈 표를 보고 「고장났나」로 읽으면 안 된다.

## 4. 검사

**서버 (`functions/billing-alert.js` — 네트워크 안 탄다)**
- `historyEntry(parsed)` 가 달을 **`costIntervalStart`** 에서 뽑는다 (도착 시각이 아니다)
- 경로가 `billing/history/{YYYY-MM}/{key}/{ts}` 모양이다
- 값이 **숫자 하나**다
- 못 알아보는 쪽지에는 **아무것도 안 만든다**(반쪽을 담으면 0 원이 뜬다)

**셈 (`js/pu-billing.js`)**
- `hourBuckets` — 한 칸 안에 여러 쪽지면 마지막 값으로 / 첫 칸은 증가분 없음(`known:false`) /
  쪽지 없는 칸은 **0 이 아니라 `known:false`** / 달 경계를 안 넘는다
- `etc` 가 음수면 0 으로 깎는다
- `hourlyRates` — **「아는 칸」으로만 나눈다** / 칸이 없으면 `null`(0 이 아니다)
- 빈 값·`null` 에도 안 터진다

**화면 (`enter.html`)**
- 칸이 둘이고, 「기록」 칸에서만 창이 넓어진다
- 항목 넷이 **모두** 열로 있다
- **0 / 「—」 뜻풀이가 표에 붙어 있다**
- 「기록은 켜는 날부터 쌓인다」를 빈 표에서 말한다
- **`once()` 로 읽고 구독하지 않는다**

뮤테이션으로 각 규칙을 하나씩 망가뜨려 검사가 실제로 잡는지 확인한다.
⚠ **뮤테이션 전에 기준선이 초록인지 먼저 본다.**
⚠ 검사에 **글자수 거리·함수 인자 목록·코드 모양·색**을 박지 않는다(`CLAUDE.md` 「검사를 쓰는 규칙」).
⚠ 글자를 볼 때는 **따옴표까지** 본다 — 주석에 속지 않게(오늘만 세 번 겪었다).

## 5. 이 설계가 막는 것

| 지금 | 뒤 |
|---|---|
| 「이 순간 얼마」만 안다 | 시간별로 얼마였고 얼마 늘었는지 안다 |
| 어느 항목이 늘었는지 모른다 | 창고·DB·서버·그 밖 각각 보인다 |
| 「시간당」을 알 길이 없다 | 항목마다 시간당 평균이 나온다 |
| 소식 없는 시간과 0원이 섞인다 | 「—」와 「0」을 갈라 적는다 |
