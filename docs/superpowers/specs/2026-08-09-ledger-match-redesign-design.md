# 거래내역 매칭 화면 재설계 — 설계서

- 날짜: 2026-08-09 (2026-08-15 대표 최종 확인 완료)
- 상태: **설계 확정** — 구현 계획 작성 단계로
- 대상: pu-erp.html 거래내역(FinanceLedger)과 매칭 엔진(erpMatchScore 등)
- 배경: 대표 지시 "어제 코딩한 거 모두 무시하고 계획 검토" — ①화면이 너무 크고 판단이 어렵다
  ②금액만 비슷한 후보가 나와 맞지 않는다 ③과입금·분할입금·합산입금 처리 방법이 없다
  ④입금+세금계산서+업무처리를 한 번에 비교해 확정하면 입금관리·성과관리까지 연쇄 처리

## 0. 대표가 정한(또는 대신 정해 둔) 방침
| 결정 | 내용 | 출처 |
|---|---|---|
| 과입금 | 자동으로 정하지 않는다 — 그 자리에서 「다음 달로 미리 받음 / 이 건에 그대로 / 나눠 담기」 중 고른다 | AI 권장, 대표 이의 없음 |
| 금액만 비슷한 후보 | 기본 숨김 — 「직접 찾기」에서만 보인다 | AI 권장, 대표 이의 없음 |
| 확정 단추 | 4갈래(자동확정·일괄확정·확인 후 확정·자문료 일괄확인) → **하나로** | AI 권장, 대표 이의 없음 |
| 밀린 자문료 충당 순서 | **오래된 달부터** 자동 충당, 펼침에서 달 직접 선택 가능 | AI 권장 |
| 월 정리 | 달 나누기 기준은 통장 입금일 하나. 짝 맞추기는 달로 자르지 않는다 | 대표 지시 반영 |

## 1. 원칙 네 가지
1. **한 줄 원칙** — 입금 한 건 = 한 줄. 신호등 + 「입금 → 항목 → 계산서 → 담당」이 한 줄에.
   판단이 필요한 줄(노랑)만 눌러서 펼친다.
2. **이름이 맞아야 후보** — 적요·학습(별칭)·세금계산서·금액지문(입금 이력) 중 하나라도
   업체를 가리켜야 후보. 금액만 비슷한 것은 숨긴다.
3. **달은 입금일 기준 자동, 짝은 기간 무제한** — 통장·카드·CMS 3개월치가 섞여 와도
   줄마다 날짜로 제 달에 자동 배치. 후보(사무관리·계산서)는 달로 자르지 않는다.
4. **확정은 한 번, 연쇄는 자동** — 확정하면 입금관리(finance_income) 기록 + 항목의
   입금표시(paidAmount·paidDate) + 성과급 분배(perfShares) + 적요 학습 + 처리지문까지 한 번에.
   되돌리기는 확정 이력(기존 기능).

## 2. 화면 설계 (목업 대표 확인함)
### 줄 상태 4가지 (신호등)
| 신호 | 뜻 | 줄 모양 |
|---|---|---|
| 🟢 확정 가능 | 이름+금액 근거 모두 확실 | 한 줄 요약, 체크박스 켜짐 |
| 🟡 확인 필요 | 후보는 있으나 애매(합계 후보·과입금·부족·이름만 맞음) | 한 줄 + 눌러서 펼침 |
| 🔴 후보 없음 | 이름 근거 있는 후보가 없음 | 「직접 찾기 / 직접 등록 / 보류함」 단추 |
| ⚪ 이미 처리 | 확정·등록·중복 지문에 걸림 | 흐린 한 줄, 기본은 목록 맨 아래 |

### 상단
- 달 탭(기존 월 넘기기)에 **달마다 미처리 n건**, 0이 되면 ✓.
- 요약 칩: 확정 가능 n · 확인 필요 n · 후보 없음 n · 이미 처리 n.
- 단추 하나: **「✅ 확정 가능 n건 모두 확정」**. (자동확정 6중 관문 통과분은 성과까지,
  나머지 🟢도 이름+금액 확실이므로 같은 경로 — 관문 미통과 항목은 🟡로 남는다)

### 펼침(🟡)에서 하는 일
- 합계 후보: 항목 여러 개 체크 → 합계·차액 표시 → 「이 n건으로 나눠 확정」
- 과입금: 차액 표시 + 3선택(다음 달 미리 받음 / 그대로 기록 / 나눠 담기)
- 부족(일부 입금): 「부분입금으로 확정」 — 남은 금액이 계속 후보로 산다(기존 paidAmount 활용)
- 달 선택: 밀린 자문료는 오래된 달부터 자동, 여기서 달을 바꿀 수 있다

### 여러 입금 → 한 항목 (나눠 들어옴)
줄 여러 개 체크 → 떠 있는 막대 「n건 묶어 한 항목에 확정」 → 항목 하나 고르면 합산 기록.

### 달 이동 (대표 확인: 새 달력을 만들지 않는다)
기존 월 넘기기(드롭다운 + ◀▶)를 그대로 두고 숫자만 붙인다 —
드롭다운 목록에 「4월 ✓ / 5월 ✓ / 6월 · 남은 12」, 현재 달 단추에 「남은 n」.
목업의 달 알약(pill) 줄은 그림용 과장이었음. 자리를 더 차지하지 않는 것이 조건.

### 중복 엑셀 재업로드 (대표 질문 반영)
걸러내기는 이미 두 겹(행 지문으로 초안 누적 차단 + 처리 완료 지문으로 재확정 차단)이며
같은 날·같은 금액의 진짜 이중 입금은 순번(#1·#2)으로 둘 다 살린다 — 이 동작은 유지.
**추가할 것은 「보이게 하기」**: 파일을 올리면 결과 요약을 바로 보여준다 —
「새로 들어온 122줄 · 이미 있어서 건너뜀 383줄」, 전부 겹치면
「이 파일은 전에 올린 것과 같습니다 — 새 줄 0건」. 조용한 걸러내기 금지.

### 없어지는 것 (어제까지의 화면)
초록 「이미 확정된 건일 수 있습니다」 상자 · 「-- 업체/항목 선택 --」 셀렉트 ·
추천 라디오 목록 · 「이름이 다른 것 n건」 접힘 · 후보 12건 목록 · 확인/VAT포함 아랫줄 ·
확정 단추 4갈래. (엔진·확정 이력·학습·직접 등록 창은 남긴다)

## 3. 매칭 엔진 변경
1. **이름 게이트**: 이름 근거 점수(적요 이름점수 ≥60 / 별칭 학습 / 계산서 일치 ≥85 /
   금액지문 ≥90) 없으면 후보로 내보내지 않는다. 점수식의 금액 55% 가중치보다 게이트가 우선.
2. **업체 단위 묶기**: 후보를 업체×달×항목 낱개가 아니라 **업체당 한 줄**로.
   "크레오에스지 · 자문료 (5·6·7월 세 달 밀림)"처럼 달을 안에 접는다.
3. **계산서 대조 창 60일 → 180일(6개월)**: 3월 발급·6월 입금을 잡는다.
   안전장치(이름 대조·이미 입금된 계산서 제외)는 그대로. INV_ARCH_MONTHS 보관 개월과 맞춘다.
4. **카드·CMS 수수료 감안 매칭**: 카드/나이스빌 줄은 「후보금액 −0~3.5%」 범위도
   금액 일치로 본다. 확정 시 차액을 exp-cardfee/exp-bankfee 지출로 자동 기록
   (기존 saveIncome opts.feeAmount 경로 재사용). 매출은 원금액, 수수료는 비용 — 세무 정석.

## 4. 기록이 어디에도 없는 입금 (상담료 · 현금 · 카드) — 3단 처리
①  **상담접수 대조**: 계약관리의 상담접수(status=consult) 이름·전화와 입금자명을 대조해
    "상담료일 수 있음 — ○○○ 상담접수(7/12)" 후보를 띄운다. 맞으면 원클릭 등록+상담건 연결.
②  **간편 등록**: 기존 「➕ 직접 등록」(상담료·현금영수증·카드입금)을 🔴 줄 단추로 승격.
    자주 쓰는 꼬리표(상담료·강의료·증명서발급 등)는 두 번째부터 자동 완성.
③  **보류함(가수금)**: 정체불명 입금은 「보류함에 넣기」 — 목록에서 빠지되 지워지지 않고,
    나중에 밝혀지면 보류함에서 꺼내 정식 확정. **월말 마감 때 보류함 잔량이 있으면 경고**
    (전문 회계프로그램의 가수금 계정과 같은 구실).
- **현금영수증 알림**: 상담료 등 개인 현금 입금을 등록할 때 「현금영수증 발행했나요?」
  체크 한 칸(의무발행업종 대비). 발행 여부만 기록, 발행 자체는 밖에서.

## 6. 확정 연쇄 (한 번에 벌어지는 일)
```
확정 →  finance_income 기록 (매출 달 = 입금일 달, advisoryYm = 몇 월분인지)
     →  항목 paidAmount·paidDate 갱신 (부분이면 남은 금액 유지)
     →  perfShares 성과급 분배 (주담당·부담당, 기존 검증된 계산 그대로)
     →  적요 별칭 학습 +1
     →  처리 지문 저장 (재업로드 중복 방지)
     →  세 날짜 보존: 입금일 · 계산서 발급일 · 해당 월
수수료 차감 확정 → 위 전부 + 차액을 지출(exp-cardfee 등)로 기록
되돌리기 → 확정 이력에서 (기존 기능, 연쇄 전부 원복)
```

## 7. 검증 계획
- 매칭: 이름 게이트(금액만 비슷한 후보 0건) · 업체 묶기(달 3개→1줄) · 계산서 180일 ·
  수수료 범위 매칭 · 오래된 달 우선 충당
- 확정: 부분입금 잔액 · 묶어 확정 합산 · 과입금 3갈래 각각의 기록 모양 ·
  성과 분배 값이 기존 입금관리 창과 동일한지(같은 입력 → 같은 결과)
- 화면: 82건 기준 그리는 줄 수(500+ → 100 이하) · 렌더 시간
- 회귀: 기존 스위트 + CRLF/LF + UTC(erp-ledger-suggest 등 이 구역 검사 다수)
- 변이: 게이트 제거·묶기 해제·충당 순서 뒤집기·수수료 무제한·보류함 우회 등
