# 입금확정 성과급 분배 정리 — 설계

- 날짜: 2026-08-16
- 요청: 대표님 — "어떻게 해야 실수 하지 않고 성과급을 반영하면서 담당자에게 성과반영하는게 쉽게 직관적으로 정리될 수 있을까. 혼자서 담당하는 것은 문제가 없으나 주담당 부담당이 항상 있을 경우 어떻게 처리하는게 가장좋을지 고민이 된다."
- 목업: `docs/mockups/perf-split-modal.html` (안 A 채택)
- 대상 파일: `pu-erp.html` (단일 파일, 빌드 없음, ES5)

---

## 1. 무엇이 문제였나

캡쳐하신 화면(대운토건주식회사 · 컨설팅 잔금 1,100,000원)은 **성과급이 0원인 상태**였다.

| | 직책 요율 | 분할 | 지급액 |
|---|---|---|---|
| 주 권형하 | 0% | 100% | **0원** |
| 부 박재원 | 15% | 0% | **0원** |

성과 기준 1,000,000원인데 아무도 받지 못한다.
대표님 직책 요율이 0%(성과급 대상 아님)인데 **분할 100%가 대표님께 가 있어서** 그 몫이 사라졌고,
박재원 노무사는 요율은 있으나 분할이 0%라 곱하면 역시 0이다.

**그런데 화면은 초록색 「분배 합계 100.0% ✓」를 띄우고 있었다.**

### 실수가 나는 자리 넷 (코드로 확인)

1. **숫자 칸 둘에 이름표가 없다.**
   나누기를 껐을 때 보이는 미리보기 표는 「분할 → 요율」 순인데,
   켜면 입력 칸이 **「요율 → 분할」로 순서가 뒤집힌다.** 구분은 `title` 툴팁뿐이다.
2. **초록 ✓ 가 「다 맞았다」로 읽힌다.**
   `valid = Math.abs(totalPct - 100) < 0.01` — 합계만 본다. 지급액이 전부 0원이어도 초록이다.
3. **요율을 실수로 만지면 확정이 막힌다.**
   요율 칸을 건드리면 override 가 켜지고 「요율 변경 사유」가 필수가 된다.
   무엇을 만졌는지 모른 채 막힌다.
4. **0원으로 확정해도 어디에도 안 걸린다.**
   `IncomeUnmatchedTab` 의 조건은 `perfShares.length === 0 || perfExclude === true` 다.
   0원 건은 `perfShares` 에 두 줄이 «있고» 금액만 0이라 **조용히 통과한다.**

### 돈이 오가는 길은 하나뿐이라는 확인

`calcPerfBonus(empSid, ym)` — 성과관리·급여가 쓰는 함수 — 는 `finance_income[].perfShares` 를 읽는다.
즉 **실제로 지급되는 성과급은 입금확정 때 저장한 값에서 나오므로, 이 창을 고치는 것이 맞는 자리다.**

⚠ 예외 하나(이번 범위 밖, 기록만): 법인 대시보드의 직원 카드(`CorpDashboard` 안, 대략 53799~53829줄)는
`perfShares` 를 안 보고 `입금 전액 × 본인 요율 ×(부담당이면 policy_perf.subRatio)` 로 **따로 어림잡는다.**
분할%를 반영하지 않으므로 이 설계가 적용되면 그 카드 숫자와 실제 지급액이 어긋난다.
돈이 오가는 길은 아니고 화면 숫자만 다른 것이라 이번에는 손대지 않는다. **나중에 볼 것.**

## 2. 대표님이 정하신 것

| 물음 | 정하신 것 |
|---|---|
| 주담당이 대표님(요율 0%)일 때 | **요율 0%인 사람은 분할에서 자동으로 빠진다** |
| 둘 다 대상자일 때 기본 분할 | **주 50 / 부 50** (환경설정에서 변경 가능) |
| 생김새 | **안 A — 표 정리** |
| 이미 0원으로 확정된 지난 건 | **몇 건인지 세어서 보여주기만** (자동으로 안 고친다) |
| 「⚖️ 부담당과 나누기」 체크박스 | **살려 둔다** |

## 3. 설계

### 3-1. 규칙 — 한 함수가 정한다

새 함수 **`erpDefaultSplit(mainSid, subSids, paidDate)`** 를 만든다.
반환: `{ mainPct, subPctMap, excluded }` (`excluded` = 요율 0%로 빠진 사번 배열)

규칙:

1. **대상자를 고른다** — 그 시점 요율(`getRateAt(sid, paidDate)`)이 **0보다 큰** 사람만.
   요율 0%인 사람에게 분할을 주면 그 몫은 **누구에게도 안 가고 사라진다.**
2. **대상자가 없으면** 모두 0 — 화면이 「아무도 못 받습니다」로 막는다.
3. **대상자가 한 명이면** 그 사람 100%.
4. **주담당이 대상자이고 부담당 대상자도 있으면**
   주담당 = `policy_perf.confirmMainPct`(기본 50), 나머지를 **부담당 대상자들이 균등**.
5. **주담당이 대상자가 아니면** 부담당 대상자들이 100을 균등.
6. 나누어떨어지지 않는 나머지는 **마지막 사람**이 받는다 — 합계가 정확히 100이어야 확정이 안 막힌다.

**쓰는 곳 둘 (규칙이 갈라지면 언젠가 어긋난다):**
- 입금확정 창이 열릴 때의 초기값
- 자동확정 경로(`opts.withPerf` — 창을 안 거치는 길)

⚠ **`calcPerfShares` 자체는 바꾸지 않는다.** 그 함수는 「받은 %대로 나눈다」는 순수한 셈이고,
거기서 몰래 재분배하면 **화면에 보이는 %와 저장되는 금액이 달라진다.**
기본값을 정하는 층과 셈하는 층을 섞지 않는다.

### 3-2. 환경설정 — 새 칸 하나

`policy_perf` 에 **`confirmMainPct`** (기본 50) 를 더한다.
「성과 반영 정책」 카드에 줄 하나: **「입금확정 기본 분할 — 주담당 %」**

⚠ 같은 카드에 이미 **「부담당 성과 비율」(`subRatio`, 기본 50)** 이 있는데 **뜻이 다르다.**
`subRatio` 는 법인 대시보드 카드가 쓰는 값이고, 새 칸은 입금확정 창의 초기값이다.
힌트 글에 서로 다르다는 것을 적는다. (이름이 비슷해 나중에 누가 하나로 합치려 들 수 있다.)

### 3-3. 화면 — 안 A

**체크박스는 살려 둔다.** 다만 **부담당이 있고 대상자가 둘 이상이면 창이 열릴 때 기본으로 켜진다** —
꺼진 채 열리면 「기본 50:50」이 실제로 적용되지 않아 정한 것이 무의미해진다.
- **끔** = 주담당 100% (지금과 같다). 이때 주담당이 요율 0%면 총 0원이 되고 아래 경고가 잡는다.
- **켬** = `erpDefaultSplit` 결과.

**입력표(켬)에서 바뀌는 것:**

1. **요율 칸을 잠근다.** 이름 아래에 「직책 요율 15%」를 회색 글씨로 «읽기»만 보이고,
   옆의 **「요율 조정」**을 눌러야 입력 칸이 열린다. override·사유 필수 동작은 그대로다.
   → 실수로 만져 확정이 막히는 일이 없어진다.
2. **남는 숫자 칸은 분할 하나.** 어느 쪽이 무엇인지 헷갈릴 수가 없다.
3. **열 이름표를 붙인다** — 「담당 / 분할 / 받을 금액」. 미리보기 표와 **같은 순서**로 맞춘다.
4. **빠른 단추 셋** — `반반 50:50` · `주담당 70:30` · `주담당이 다`.
   지금 상태와 같은 단추는 눌린 모양으로 보인다.
5. **요율 0%·수습·퇴사인 사람은 회색 줄**로, 분할 칸 없이 **까닭을 적는다**
   (「성과급 대상 아님 (직책 요율 0%)」 · 「수습 · 미지급」 · 「퇴사 · 미지급」).
   지금은 나누기를 «꺼야만» 보이던 정보다.
6. **대상자가 한 명뿐이면** 분할 칸을 안 보이고 「100%」로만 표시한다.
7. **초록 「분배 합계 100.0% ✓」를 없애고 「총 성과급 N원」으로 바꾼다.**
   0원이면 빨간 줄로 **「이대로 확정하면 아무도 성과급을 못 받습니다」.**

### 3-4. 0원이면 확정을 막는다

`총 성과급 === 0` 이고 **「⭐ 성과급 반영」이 켜져 있으면** 입금확정 단추를 막는다.

빠져나갈 길: **「⭐ 성과급 반영」을 끄면** 통과하고, 그 건은 「성과 미반영」에 **「⛔ 명시적 제외」**로 남는다.
→ **0원인지 아닌지가 아니라, 「일부러 그런 것인지」가 기록에 남는다.**

⚠ 자문료(`sourceKind === 'company'`)와 개인수익은 원래 성과 분배 대상이 아니므로 이 막음에서 제외한다.

### 3-5. 지난 건 세기 (고치지 않는다)

`IncomeUnmatchedTab` 의 필터에 조건을 더한다:
`perfShares.length > 0` 이면서 `합계 amount === 0` → 새 무리 **「💸 지급액 0원」**.

`classify()` 에 태그를 더하고, 무리별 개수에 함께 나온다.
**자동으로 고치지 않는다** — 이미 지급된 성과급과 어긋날 수 있어 대표님이 보시고 정하실 일이다.

---

## 4. 안 건드리는 것

- 저장 형식 `finance_income[].perfShares` — 성과관리·급여·명세서가 모두 이 모양을 읽는다
- `mgr_rates` (직책 요율 자체)와 `getRateAt` 의 시점별 요율 이력
- 이미 확정된 건의 금액
- 자문료(`company`) 성과 제외 규칙, 개인수익 갈래
- `calcPerfShares` 의 셈 (3-1 참고)
- `policy_perf.subRatio` 와 법인 대시보드 카드

## 5. 검사 (글자만 보지 말고 돌려 본다)

`tests/perf-split-rule.test.js` 새로 만든다. `erpDefaultSplit` 을 소스에서 뽑아 **실제로 돌린다.**

- 요율 0%인 주담당은 빠지고 부담당이 100%를 받는다
- 대상자 둘이면 설정값(기본 50)대로 나뉜다
- 부담당이 둘이면 부담당 몫을 균등하게 나눈다
- 나누어떨어지지 않아도 합계가 정확히 100이다
- 대상자가 하나면 100%, 하나도 없으면 전부 0
- 수습·퇴사자도 대상에서 빠진다
- 설정값을 바꾸면 결과가 따라 바뀐다 (숫자를 박지 않는다)

화면 쪽:
- 요율 입력 칸이 **기본으로 열려 있지 않다** (「요율 조정」을 눌러야 열린다)
- 열 이름표가 미리보기 표와 같은 순서다
- 총 성과급 0원이면 확정 단추가 막힌다 — 단, 「성과급 반영」을 끄면 안 막힌다
- 「성과 미반영」이 0원 건을 잡는다

뮤테이션으로 각 규칙을 하나씩 망가뜨려 **검사가 실제로 잡는지** 확인한다.

⚠ 검사에 **높이·색·내부 변수 이름·숫자 기본값(50)을 박지 않는다** — `CLAUDE.md` 「검사를 쓰는 규칙」과
`tests/test-pin-guard.test.js` 가 이를 막는다. 50은 설정값이므로 **설정을 바꿔 결과가 따라오는지**로 본다.

## 6. 이 설계가 막는 것

| 지금 일어나는 일 | 뒤 |
|---|---|
| 대표님이 주담당인 건에서 성과급이 통째로 사라진다 | 실무 노무사가 100% 받는다 |
| 부담당이 이름만 올라가고 0원 | 기본 50:50 으로 열린다 |
| 어느 칸이 요율이고 분할인지 모른다 | 숫자 칸이 분할 하나뿐이다 |
| 요율을 실수로 만져 확정이 막힌다 | 잠겨 있어 만질 수 없다 |
| 0원인데 초록 ✓ 로 보인다 | 빨갛게 막고, 일부러면 기록에 남는다 |
| 0원 확정이 어디에도 안 걸린다 | 「성과 미반영」에 모인다 |
