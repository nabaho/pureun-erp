# 자료함 — 한글 서식을 그 자리에서 고치고, 업체별로 채워 한번에 보내기

작성 2026-08-10 · 대상 `pu-cards.html`, `js/pu-hwp-edit.js`

## 왜 필요한가

대표의 말: *"셀이 너무 많고 중첩적이고 내용을 수정하거나 변경해야하는데 지금 서식
만으로 손보기가 너무 어렵다."*

### 실제 파일로 확인한 원인

`vendor/rhwp-core` 엔진에 대표의 한글 파일을 직접 넣어 봤다.

```
16년10월급여.hwp
  실제 문서 : 20행 × 3열 표 하나 (이름 │ 급여 │ …), 본문 문장 0개
  지금 화면 : 60개의 세로 줄
```

`js/pu-hwp-edit.js` 의 `readRows()` 는 표 칸을 하나씩 뽑아 **세로로 줄세운다.**
서식은 거의 전부 표이므로, 서식일수록 산산조각이 난다. 화면에 `65 신청정보`
`66 신청인` `67 예금주와 관계 : ( )` 처럼 조각만 남아 **어느 칸이 이름표이고
어디가 채울 자리인지 알 수 없다.**

표 안 위치(`표 1-1`)도 틀린 값이다. 지금은 `Math.floor(idx / colCount)` 로
짐작하는데, 이 계산은 **합쳐진 칸이 있으면 전부 어긋난다.** 공문 하나
(`'23년 안전보건관리체계…알림.hwp`)를 열어 보니 합쳐진 칸이 55개였다.

### 고칠 수 있다 — 엔진이 이미 답을 갖고 있다

| 엔진 함수 | 돌려주는 것 | 지금 |
|---|---|---|
| `getCellInfo(s,p,c,i)` | `{row, col, rowSpan, colSpan}` — **진짜 값** | 안 씀 |
| `getTableCellBboxes(s,p,c,page)` | 위 + `{pageIndex, x, y, w, h}` | 안 씀 |
| `HwpViewer.renderPageSvg(n)` | 인쇄 모습 그대로의 SVG | 안 씀 |
| `insertTableRow` / `deleteTableRow` | 표에 줄 넣고 빼기 | 안 씀 |
| `getFieldList()` | 누름틀 목록 | 안 씀 |

`getCellInfo` 로 격자를 되살려 보니 원본 그대로 나왔다.

```
 1 │ 이름   │ 급여    │
 2 │ 윤성인  │ 700만원 │
 3 │ 김연배  │ 600만원 │
```

**지금 코드가 이 정보를 버리고 있었을 뿐이다.**

### 서류 일은 5단계인데 2칸이 비어 있다

```
① 원본 서식 보관        ✅ 자료함
② 업체별로 값 채움       ❌ ← 매번 한글을 열어 손으로
③ 묶어서 발송           ✅ 묶음 + sendMaterialMail (살아 있음)
④ 상대가 채워 돌려줌     ❌ ← 이 설계 범위 밖
⑤ 업체별 보관           부분
```

이 설계는 **②를 채우고 ③에 잇는다.**

## 정한 것 (대표 결정)

| 물음 | 결정 |
|---|---|
| 고친 결과를 어디에 쓰나 | **둘 다** — `[원본 서식 고치기]` / `[이 업체용으로 채워 보내기]` 를 고르게 한다 |
| 채울 자리를 어떻게 정하나 | **팝업에서 칸을 눌러 지정.** 더해서 **명함첩에서 당겨오기** (대표 지시) |
| 보내는 형식 | **서류마다 골라 둔다** — 계약서·CMS·위임장은 한글, 제안서·홍보물은 PDF |
| 화면 방식 | **표를 표로 되살린다**(신구대조 방식) + `[원본 보기]` 단추 |

## 1. 쓰는 순서

대표가 실제로 하게 될 일. 설계의 모든 조각은 이 순서에 봉사한다.

```
── 준비 (서류마다 한 번) ──────────────────────
① 한글 원본(.hwp/.hwpx)을 자료함에 올린다
② 자료를 눌러 팝업을 열고, 빈칸을 눌러
   「여기는 회사명」「여기는 대표자」를 지정한다
③ 이 서류를 한글로 보낼지 PDF로 보낼지 정한다

── 매번 (보낼 때마다) ─────────────────────────
④ 메일 쓰기 → 받는사람에 명함을 고른다
⑤ 자료 서랍에서 묶음을 고른다 (예: 신규계약)
⑥ [명함첩에서 당겨오기] 한 번 → 모든 서류가 채워진다
⑦ 훑어보고 보낸다
```

지금은 ④⑤⑦만 있다. ②와 ⑥이 없어서 매번 한글을 열게 된다.

## 2. 문서 읽기 — `readGrid()`

`readRows()` 를 **버리지 않고 그대로 둔다.** 지금 화면이 그것을 쓰고 있고,
`tests/cards-hwp-integration.test.js` 가 그것을 검사한다. 새 함수를 옆에 놓는다.

```
readGrid(doc) →
  [ {kind:'body',  sec, para, text},
    {kind:'table', sec, para, ctrl, rows, cols,
     cells:[ {cell, row, col, rowSpan, colSpan, cpara, text} ] },
    … ]  ← 문서에 나오는 순서 그대로
```

### 규칙

- 표 칸의 `row`/`col`/`rowSpan`/`colSpan` 은 **반드시 `getCellInfo` 에서 받는다.**
  나눗셈으로 짐작하지 않는다. 이것이 이번 고침의 핵심이다.
- `getCellInfo` 가 실패한 칸은 **버리지 않고** `row:null` 로 담아 표 아래에
  「자리를 모르는 칸」으로 따로 보여 준다. 조용히 사라지면 그 칸은 영영 못 고친다.
- 한 칸에 여러 문단이면 문단마다 한 줄. 되돌려 넣을 때 자리가 어긋나지 않는다.
  **이것이 생각보다 훨씬 중요하다.** 실제 위임장(`7. 위임장.hwp`)을 열어 보니
  문서 전체가 **표 한 칸 안**에 들어 있었다 — 칸 2개에 문단이 각각 9개와 14개.
  한국 서식은 표로 테두리를 그리는 일이 흔하다. 칸을 한 줄로 그리면 위임장은
  **두 줄짜리 문서**가 되어 아무것도 못 고친다. 칸 안의 문단을 **각각 고칠 수 있는
  줄로** 그려야 한다.
- 본문의 빈 줄은 뺀다. 표의 빈 칸은 **남긴다** — 그게 채울 자리다.
- `CTRL_PROBE` 를 4에서 **8**로 올린다. 공문에서 표가 3개 나왔고, 그림이 앞에
  끼면 더 밀린다.
- `getStructure()` 는 **쓰지 않는다.** 실제로 돌려 보니 `memory access out of
  bounds` 로 터진다.

### 아직 안 하는 것 — 적어 두어야 나중에 헤매지 않는다

- **중첩표**(표 안의 표): 경로 API(`getTableDimensionsByPath`)가 있으나 이번엔
  안 읽는다. 대신 **읽지 못한 표가 있으면 화면에 알린다.** 조용히 빠지면
  「고쳤는데 안 바뀌었다」가 된다.
- **글상자**: `getTextBoxControlIndex` 가 있으나 이번엔 안 읽는다. 위와 같이 알린다.

## 3. 팝업 편집기

자료 이름을 누르면 **전체화면**으로 열린다. `rules.html` 의 신구대조 모달
(`.overlay` + `.modal` + `.body` + 도구줄 + 표 + `.foot`)과 같은 뼈대를 쓴다.

```
┌─ 📄 CMS신청서 ──────────────────────────── ✕ ─┐
│ [전체] [빈칸만] [원본 보기] [＋명함첩에서 당겨오기] [채울 자리 지정] │
│ ┌───────────────────────────────────────┐ │
│ │ 신청인       │ 천안미소신협              │ │
│ │ 대표자 │ 김완재 │ 연락처 │ 041-555-0000 │ │
│ │ 예금주와 관계 │ (      )                │ │
│ └───────────────────────────────────────┘ │
│ 고친 곳 2  ·  못 읽은 표 0                    │
├───────────────────────────────────────────┤
│ [닫기]        [원본 서식 고치기] [이 업체용으로 채워 보내기] │
└───────────────────────────────────────────┘
```

- 표는 HTML `<table>` 로 그린다. `rowSpan`/`colSpan` 을 그대로 `rowspan`/
  `colspan` 에 넣어 **합쳐진 칸이 원본과 같은 모양으로 나온다.**
- 문서 전체(본문·표 여럿)를 **세로로 이어** 한 화면에서 훑는다.
- 칸을 누르면 그 자리에서 고친다. 고친 칸은 색으로 표시한다.
- `[빈칸만]` — 채울 자리만 남겨 보여 준다. 서식은 대부분 이미 적힌 글이라,
  이게 없으면 빈칸을 찾느라 스크롤만 하게 된다.

### `[원본 보기]` 와 문서 두 벌 — 반드시 지킬 것

`new HwpViewer(doc)` 는 **문서의 소유권을 가져간다.** 실제로 겪었다.

```
const v = new HwpViewer(doc);
doc.getSectionCount();   // Error: null pointer passed to rust
```

**다행히 이미 막혀 있다.** `js/pu-hwp-engine.js` 의 `renderPreview(container,
bytes, name)` 는 **바이트를 받아 자기 문서를 새로 열고 끝나면 `free()` 한다**
(`pu-hwp-engine.js:112`, `:138`). 편집용 문서에는 손대지 않는다.

```
편집용 doc  = PureunHwp.openDoc(bytes)      ← 계속 살려 둔다
원본 보기   = PureunHwp.renderPreview(el, bytes, name)
              └ 안에서 제 문서를 열고 닫는다. 편집용은 무사하다
```

**지킬 것은 하나다 — `renderPreview` 에 `_he.doc` 를 넘기지 말고 `_he.bytes`
를 넘긴다.** 문서를 넘기면 그 문서가 죽는다. 지금 `heRenderPages()` 가 이미
바이트를 넘기고 있으니 그 방식을 그대로 따른다.

## 4. 채울 자리와 명함첩 당겨오기

### 자리 지정

칸을 누르고 `[채울 자리 지정]` 을 켜면 무엇을 넣을 자리인지 고른다.

```
회사명 · 대표자 · 사업자번호 · 주소 · 전화 · 담당자 · 이메일 · 금액 · 오늘날짜
```

저장 위치는 `pucards/materials/<id>/slots`.

```json
{ "s1": { "kind": "회사명", "mode": "append", "keep": "상 호 : ",
          "sec": 0, "para": 0, "ctrl": 2, "cell": 1, "cpara": 8 },
  "s2": { "kind": "대표자", "mode": "replace", "keep": "",
          "sec": 0, "para": 0, "ctrl": 2, "cell": 4, "cpara": 0 } }
```

열쇠(`s1`, `s2`)는 그냥 붙이는 번호다. **같은 `kind` 가 여러 자리에 있어도 된다** —
계약서는 회사명이 첫머리와 맨 끝 도장 자리에 두 번 나온다. `kind` 를 열쇠로 쓰면
한 곳밖에 못 채운다.

### `mode` — 채울 자리는 「빈 칸」이 아닐 때가 더 많다

실제 위임장을 열어 보고 알았다. 채울 자리가 **빈 칸이 아니라 이름표 뒤의 빈자리**다.

```
성 명 :                    ← 이 줄에 이름을 넣어야 한다
주민등록번호 :
상 호 : 이비공동근로복지기금   ← 이미 적힌 것을 갈아야 한다
```

이름표와 채울 곳이 **같은 줄에** 있다. 「빈 칸을 값으로 바꾼다」로만 만들면
`성 명 :` 이 통째로 `김완재` 로 덮여 **이름표가 사라진다.** 그래서 두 가지를 둔다.

| `mode` | 하는 일 | 쓰는 곳 |
|---|---|---|
| `append` | `keep` 을 그대로 두고 **뒤에 값을 붙인다** | `성 명 :` → `성 명 : 김완재` |
| `replace` | 줄 전체를 값으로 **갈아 끼운다** | 빈 칸, `상 호 : 이비공동근로복지기금` |

`keep` 은 자리를 지정하던 그 순간의 글자다. 이걸 저장해 두면 나중에 서식이
바뀌었는지 견줄 수 있다(§ 서식 교체).

**자리를 지정할 때 시스템이 먼저 골라 준다.** 사람이 매번 고르게 하면 안 쓴다.

```
줄이 비어 있음                → replace
줄이 : 또는 ： 로 끝남         → append   (성 명 :)
줄에 밑줄·괄호만 있음          → replace  ((      ))
그 밖 (이미 값이 적혀 있음)     → replace
```

고른 값은 화면에 보여 주고 **사람이 바꿀 수 있게 한다.** 짐작이 틀릴 때가 있다.

**칸 번호(`cell`)로 저장하고 행·열로 저장하지 않는다.** 되돌려 넣을 때 엔진이
받는 것이 칸 번호이기 때문이다. 행·열은 화면에 보여 줄 때만 쓴다.

### 당겨오기

`[명함첩에서 당겨오기]` → 명함이나 업체를 고르면 지정된 칸이 한꺼번에 채워진다.
값은 이미 명함첩·업체관리에 있다.

| 자리 | 어디서 | 없으면 |
|---|---|---|
| 회사명 | 명함 `company` | 빈칸으로 두고 노랑으로 표시 |
| 대표자·담당자 | 명함 `name` | 〃 |
| 전화 | `mobile` → 없으면 `phone` | 〃 |
| 사업자번호·주소 | 업체관리(사업자) | 〃 |
| 오늘날짜 | 시스템 | 항상 채워짐 |

**없는 값을 지어내지 않는다.** 빈칸으로 두고 눈에 띄게 표시한다. 계약서에
엉뚱한 회사명이 들어가는 것보다 빈칸이 낫다.

### 서식이 바뀌면 자리는 어떻게 되나

`🔄 교체` 로 새 한글 파일을 올리면 칸 번호가 달라질 수 있다. 그대로 쓰면
**엉뚱한 칸에 회사명이 들어간다.** 그래서 교체할 때:

1. 지정해 둔 각 자리의 **현재 글자**를 새 문서의 같은 칸 번호와 맞춰 본다.
2. 다르면 그 자리를 **풀고** 「자리를 다시 정해 주세요」라고 알린다.
3. 맞으면 그대로 둔다.

조용히 이어 쓰지 않는다.

## 5. 두 단추

### `[원본 서식 고치기]`

자료함의 파일 자체를 덮어쓴다. 서식의 오타·문구를 다듬을 때.

- 덮어쓰기 **전에** 이전 파일을 `materialFiles/<id>/prev` 로 옮겨 한 벌 남긴다.
  잘못 고쳐 저장하면 원본이 사라진다.
- 확인을 한 번 받는다. 「원본을 덮어씁니다. 이전 것은 한 벌 남습니다.」

### `[이 업체용으로 채워 보내기]`

**원본을 건드리지 않는다.** 사본을 만들어 메일에 붙인다.

- 이름: `CMS신청서_천안미소신협_2026-08-10.hwp`
- 보관하지 않는다. 매번 만든다 — 6,256개 업체의 사본을 쌓으면 저장소가 터진다.

## 6. 한번에 보내기 — 묶음

묶음은 이미 있다(`_sendMatPick`, `setLiveIds`). 여기에 **채우기를 잇는다.**

```
신규계약 묶음 = 자문계약서 + CMS신청서 + 위임장
입사   묶음 = 근로계약서 + 개인정보동의서      (근로자용)
견적   묶음 = 견적서 + 법인소개서
```

업체 하나와 묶음 하나를 고르면 **세 서류가 같은 값으로 한꺼번에 채워진다.**
보내기 전에 「무엇이 채워졌고 무엇이 비었는지」를 서류별로 보여 준다.

### 보내는 형식

자료마다 `sendAs` 를 둔다.

| 값 | 뜻 | 쓰는 서류 |
|---|---|---|
| `hwp` | 올린 한글 그대로 (기본값) | 계약서·CMS·위임장 — 상대가 채우고 도장 찍어야 함 |
| `pdf` | 짝으로 올린 PDF | 제안서·홍보물 — 상대가 고치면 안 됨 |

**PDF 는 짝으로 올린 파일을 쓴다.** 엔진에 PDF 내보내기가 없다(확인함).
그래서 **채운 문서는 항상 한글로 나간다.** `sendAs:'pdf'` 인 자료를 채우려
하면 화면에서 막고 까닭을 말한다.

## 7. 잘못될 수 있는 곳과 대비

| 위험 | 대비 |
|---|---|
| 원본을 덮어써 서식이 사라짐 | 덮기 전에 이전본을 한 벌 남기고 확인을 받는다 |
| 원본 보기 뒤 편집이 죽음 | 문서를 두 벌 연다. 보기용은 닫을 때 `free()` |
| 서식 교체 후 엉뚱한 칸에 값이 들어감 | 교체 시 글자를 맞춰 보고, 다르면 자리를 푼다 |
| 못 읽은 표·글상자를 모르고 보냄 | 읽지 못한 것의 수를 화면에 늘 보여 준다 |
| 없는 값이 지어내져 계약서에 들어감 | 빈칸으로 두고 노랑으로 표시. 절대 추측하지 않는다 |
| 채운 PDF 를 못 만듦 | `sendAs:'pdf'` 자료는 채우기를 막고 까닭을 말한다 |
| 큰 문서에서 화면이 멈춤 | 표가 200칸을 넘으면 표마다 접어서 그린다 |
| 되돌려 넣기가 조용히 실패 | `applyRows` 가 이미 실패한 줄을 센다. 그 수를 반드시 띄운다 |
| PDF 만 올린 자료를 고치려 함 | 「한글 원본을 올려 주세요」라고 분명히 알린다 |
| **이름표가 값에 덮여 사라짐** (`성 명 :` → `김완재`) | `mode:'append'` 로 `keep` 을 남기고 뒤에 붙인다 |
| 문서 전체가 표 한 칸이라 두 줄로만 보임 | 칸 안의 문단을 각각 고칠 수 있는 줄로 그린다 |

## 8. 확인 방법

`pu-cards.html` 은 빌드 없는 단일 파일이므로 이 파일이 이미 쓰는 방식을 따른다.

1. **문법 검사** — 인라인 `<script>` 를 뽑아 `new vm.Script`.
2. **순수 로직 검사** (`node --test`) — `js/pu-hwp-edit.js` 는 `module.exports`
   가 있어 그대로 불러온다. 가짜 `doc` 으로 7MB WASM 없이 검사한다.
   - 합쳐진 칸의 `rowSpan`/`colSpan` 이 `getCellInfo` 값 그대로 나오는지
   - `getCellInfo` 가 실패한 칸이 사라지지 않고 `row:null` 로 남는지
   - 표가 문서 순서대로 나오는지
   - 슬롯이 칸 번호로 저장되는지
   - `성 명 :` 에 값을 넣으면 `성 명 : 김완재` 가 되는지 (`append` 로 이름표가 남는지)
   - 빈 줄에 값을 넣으면 줄 전체가 값이 되는지 (`replace`)
   - `mode` 를 자동으로 고를 때 `:` 로 끝나는 줄이 `append` 로 잡히는지
   - **문단이 14개 든 칸**이 14줄로 그려지는지 (위임장처럼 문서 전체가 한 칸일 때)
   - 서식 교체 때 글자가 다르면 자리가 풀리는지
   - 없는 값이 빈칸으로 남고 지어내지지 않는지
3. **진짜 파일 검사** — 대표의 실제 한글 파일로 돌린다. 검사에 파일을 넣지
   않는다(개인정보). 손으로 돌리는 확인 절차로 적어 둔다.
   - `16년10월급여.hwp` → 20행 × 3열로 나오는가
   - 합쳐진 칸 55개인 공문 → 표 모양이 원본과 같은가
   - `7. 위임장.hwp` → 표 한 칸 안의 문단 9개·14개가 모두 고칠 수 있는 줄로 나오는가
   - 위임계약서(본문 28~30줄 + 표 14칸) → 본문과 표가 문서 순서대로 이어지는가
   - 한 칸을 고쳐 저장 → 그 칸만 바뀌고 나머지는 그대로인가
4. **화면 검사** (로컬 서버 + 브라우저)
   - `[원본 보기]` 를 켰다 끈 뒤에도 편집이 살아 있는가 ← 가장 중요
   - `[빈칸만]` 이 빈 칸만 남기는가

## 9. 안 하기로 한 것

- **채운 문서의 PDF 변환** — 엔진에 없다. 쪽을 그림으로 그려 PDF 를 짜는 길은
  있으나(`renderPageToCanvas` → JPEG → PDF) 별도 작업이라 이번에 넣지 않는다.
- **중첩표·글상자 읽기** — 이번엔 안 읽고, 있으면 알리기만 한다.
- **표 줄 추가·삭제** — 엔진에는 있다(`insertTableRow`). 다음 단계.
- **메일 수신(돌려받기)** — 별개의 큰 작업.
- **채운 사본 보관** — 매번 만든다.
