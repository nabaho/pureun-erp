# 업무관리 「내 업무」 화면 — 계획·실적 한 자리 + 열 접기

작성 2026-08-07 · 대상 `work.html` · 요청자 권형하 대표노무사

---

## 왜 고치나

엑셀 163건을 이관하고 푸른이알피와 짝지은 직후의 화면을 보면:

- 41건 전부 **「최근 기록」이 "기록 없음"** — 화면 폭의 10%를 쓰면서 아무것도 알려주지 않는다
- 「업무」 열은 `일터상생혁신컨설팅` 같은 긴 이름이 반복되며 두 줄로 접힌다
- 구분이 섞여 있어 사건을 보다가 컨설팅이 튀어나온다
- 상태를 바꾸려면 눌러서 한 칸씩 돌린다 — 보류로 가려면 네 번
- 요일 칸에 적을 수 있는 것은 **이미 한 일**뿐이다. 앞으로 할 일을 적을 자리가 표에 없다

한 문장으로: **앞을 보는 화면이어야 하는데 뒤만 보여 주고 있고, 그마저 비어 있다.**

## 무엇을 만드나

1. 구분(계약·사건·컨설팅·기금·기타사업)별로 소제목을 두고 묶어 보기 — 묶음 단위로 접기
2. 요일 칸에서 **앞으로 할 일**을 바로 걸고, 체크하면 그 자리에서 실적이 되기
3. 상태를 드롭다운으로 고르기
4. 열 접기 — 평소에는 「업무」·「최근 기록」이 접혀 있고, 필요할 때 그 자리에서 편다
5. 요일 칸에 여러 건을 연달아 넣기

## 만들지 않는 것

- 안 한 할 일의 **자동 이월**. 옮겨 놓으면 언제 하기로 했던 일인지 알 수 없게 된다
- 요일 칸 **드래그로 날짜 옮기기**. 표가 좁고 오조작이 잦다 — 드로어에서 날짜를 바꾼다
- 푸른이알피에 할 일·기록을 **쓰는 것**. 이 화면은 지금도 앞으로도 읽기만 한다

## 1. 구조 — 세 가지를 구분한다

| | 무엇 | 저장 위치 | 쓰는 쪽 |
|---|---|---|---|
| **기록** | 이미 한 일 | `work_erp/logs/{연}/{주}/{업무ID}/{기록ID}` + `work_erp/itemlogs/{업무ID}/{기록ID}` | 업무시트 |
| **할 일** | 앞으로 할 것 | `work_erp/steps/{업무ID}/{단계ID}` | 업무시트 |
| **원본** | 사건·계약 정보 | 푸른이알피 `data/*` | 푸른이알피만 씀 |

할 일은 **이미 있는 「진행 단계」를 그대로 쓴다.** 새 자료를 만들지 않는다.

```
work_erp/steps/{업무ID}/{단계ID} = {
  t:    제목
  g:    묶음 이름          — 요일 칸에서 만든 것은 '주간'
  o:    순서
  done: 0 | 1
  d:    기한(YYYY-MM-DD)   — 요일 칸에서 만들면 그 날
  by, at
}
```

이 그릇을 고른 이유:

- 드로어의 단계 목록·부당해고 템플릿·진행률(3/8)·캘린더가 **이미 이 자료를 본다**. 따로 만들면 할 일을 적는 곳이 세 군데(다음 할 일 · 진행 단계 · 주간 할 일)로 나뉘어 어디에 적을지 헷갈린다
- `items`와 분리되어 있어, 체크 한 번에 `items` 전체가 모든 화면으로 다시 밀려가지 않는다
- 푸른이알피와 무관한 자체 자료라, 연동된 건이든 아니든 똑같이 동작한다

**화면 설정은 서버에 올리지 않는다.** 접힌 열·접힌 구분은 `localStorage`에만 둔다 — 다른 사람 화면에 영향이 없고, 남의 업무를 열람할 때도 내 설정이 유지된다.

| 키 | 담는 것 |
|---|---|
| `work_my_cols` | 접힌 열 목록 (예: `pt,last`) |
| `work_my_grp` | 접힌 구분 목록 (예: `계약,기금`) |
| `work_my_group` | 구분별 묶어 보기 켬/끔 |

## 2. 화면

```
#  구분  기업          │업│ 상태▾  │최│ [ 월  화  수  목  금 ]  다음 할 일  종료
──────────────────────┼──┼────────┼──┼──────────────────────────────────────
▾ 사건 21건
1  사건  나래산업       │  │ 진행중▾ │  │  …넓어진 요일 칸…      D-3      종료
        사건-2026-012  │  │        │  │
        3/8            │  │        │  │
▸ 컨설팅 12건                                            ← 접힌 묶음
```

### 2.1 구분별 묶어 보기

- **처음 여는 사람은 묶어 보기가 켜진 상태**로 시작한다. 표 위 칩으로 끄면 지금처럼 한 덩어리로 보이고, 끈 상태는 기억된다
- 순서는 푸른이알피와 같은 고정 순: **계약 · 사건 · 컨설팅 · 기금 · 기타사업**, 그 밖의 값은 뒤에 이름순
- 같은 구분 안에서는 지금처럼 **기한이 급한 것부터**, 기한이 같으면 관리번호순
- 소제목 줄 `▾ 사건 21건` 을 누르면 그 묶음이 접힌다. 접힌 상태는 기억된다
- **묶어 보기를 켜면 「구분」 열은 자동으로 접힌다** — 소제목에 이미 쓰여 있다
- 걸러 보기가 걸려 있으면 소제목의 건수는 **걸러진 뒤 건수**다. 0건이 된 묶음은 소제목째 사라진다

### 2.2 열 접기

접을 수 있는 열: **구분 · 업무 · 상태 · 최근 기록 · 다음 할 일**
접을 수 없는 열: `#` · 기업 · 요일 칸 · 종료

- 접힌 열은 사라지지 않고 **폭 14px 세로 띠**로 남는다. 띠를 누르면 그 자리에서 펴진다. 마우스를 올리면 열 이름이 뜬다
- 펴진 열은 머리 이름 옆 `‹` 로 접는다
- 표 위 `빽빽하게 · 메뉴 접기` 옆에 **같은 스위치를 칩으로** 나란히 둔다 — 한 번에 여러 개를 켜고 끌 수 있다
- **처음 여는 사람은 「업무」·「최근 기록」이 접힌 상태**로 시작한다
- 접힌 열에 걸러 보기 조건이 걸려 있으면 띠에 **점(●)** 이 붙는다. 조건이 걸린 줄 모르고 "왜 안 나오지" 하는 일을 막는다
- 「업무」 열을 접으면 진행률 칩(3/8)이 함께 숨으므로, **진행률은 기업 칸 관리번호 아래로 옮긴다**

띠로 남기는 쪽을 고른 이유: 메뉴 안에 숨기면 접었다는 사실 자체를 잊는다. 접은 것이 어디 갔는지 보여야 한다.

### 2.3 상태 드롭다운

`진행중 · 대기응답 · 검토 · 대기 · 보류` 다섯 중에서 고른다. 지금의 순환 방식(`cycleStatus`)은 없앤다.

푸른이알피 원본 상태 칩(`peStChip`)은 지금처럼 아래에 그대로 붙는다 — 우리 상태와 원본 상태는 다른 축이다.

### 2.4 요일 칸

```
  월 4
┌──────────────────┐
│ 📅 기한           │  ← 그 날이 업무 기한
│ 📌 서면 제출      │  ← 그 날이 「다음 할 일」 날짜
│ ☐ 임금대장 요청   │  ← 할 일. 누르면 ✓
│ ✓ 조사관 통화     │  ← 체크해서 실적이 된 것
│ · 자료 정리       │  ← 계획 없이 바로 적은 기록
│ [적기…          ] │
└──────────────────┘
```

**적은 것이 할 일이 되느냐 기록이 되느냐는 그 칸의 날짜 하나로 정한다.**

| 그 칸의 날짜 | 무엇이 되나 |
|---|---|
| 오늘보다 뒤 (내일~) | **☐ 할 일** — `steps` 에 `{d:그 날, g:'주간', done:0}` |
| 오늘 · 오늘보다 앞 | **· 기록** — 지금과 같음 |

규칙은 이 한 줄뿐이고 예외를 두지 않는다. 지난 주를 열람하면 모든 칸이 과거이므로 전부 기록이 되고, 다음 주를 열람하면 전부 할 일이 된다 — 따로 정할 것이 없다.

미래 칸에 "이미 했다"를 적을 일도, 지난 칸에 "앞으로 하겠다"를 적을 일도 거의 없다. 잘못 들어갔으면 그 줄을 눌러 **서로 바꾼다**.

입력칸 placeholder가 무엇이 될지 미리 알려 준다 — `할 일…` / `기록…`.

### 2.5 체크 = 실적

☐ 를 누르면:

1. 그 단계가 `done:1` 이 된다
2. **그 날 기록이 하나 생긴다** — `{t:단계 제목, d:그 날, k:'step', sid:단계ID}`
3. 칸에는 `✓ 제목` **한 줄로만** 보인다. `sid` 가 붙은 기록은 칸에서 다시 그리지 않는다

3번이 필요한 이유: 기록을 만들지 않으면 팀 전체 화면의 「✍ 미기록」·「최근 기록」·전체 검색이 그 일을 못 본다. 그렇다고 두 줄로 그리면 같은 일이 두 번 적힌 것처럼 보인다.

체크를 **풀면** `done:0` 으로 돌아가고 그 기록도 지운다 — 체크가 만든 것이므로 체크가 거둔다.

### 2.6 여러 건 연달아 넣기

지금은 Enter를 치면 아랫줄로 내려가, 같은 날에 두 개를 넣으려면 되돌아와야 한다.

| 키 | 바뀌는 동작 |
|---|---|
| **Enter** (글자 있음) | 저장하고 **그 칸에 머문다** — 계속 쌓을 수 있다 |
| **Enter** (빈 칸) | 아랫줄로 (지금과 같음) |
| **↓ / ↑** | 아랫줄·윗줄 같은 요일 (지금과 같음) |
| **← / →** (빈 칸) | 옆 요일 (지금과 같음) |
| **Shift+Enter** | 저장하고 윗줄로 (지금과 같음) |

한글 조합 중 Enter는 지금처럼 글자를 확정할 뿐 저장하지 않는다(`_ime`).

## 3. 경계 조건

| 자리 | 어떻게 |
|---|---|
| **토·일 칸** | 지금은 그 주 *기록*이 있을 때만 나온다 → **할 일이 있어도** 나오게 한다 |
| **지난 주 / 다음 주 열람 중** | 2.4의 날짜 규칙이 그대로 적용된다 — 지난 주는 전부 기록, 다음 주는 전부 할 일 |
| **남의 업무 열람 중** | 할 일도 걸 수 있고, 기록과 똑같이 작성자 이름이 붙는다 |
| **☐ 를 지우면** | 그 할 일이 없어진다. 이미 체크해 기록이 된 것은 남는다 — 한 일을 지우지 않는다 |
| **안 한 계획이 지나면** | 그 자리에 **붉게** 남는다. 자동으로 밀지 않는다 |
| **날짜를 옮기려면** | 그 줄을 눌러 드로어에서 기한을 바꾼다 |
| **연동된 건** | 할 일·기록은 자체 자료라 똑같이 동작한다. 푸른이알피에 쓰지 않는다 |
| **다른 사람이 같은 칸에 적으면** | 기록ID·단계ID가 각각 달라 서로 덮지 않는다 (지금과 같음) |
| **접힌 열의 걸러 보기** | 조건은 살아 있다. 띠에 ● 로 알린다 |
| **묶음이 걸러져 0건** | 소제목째 그리지 않는다 |

## 4. 함께 고치는 결함

`wkMarks()` 가 진행 단계의 기한을 **`s.due`** 로 찾는데 실제 저장은 **`s.d`** 다 (`stepAdd`·`stepDate`·캘린더 모두 `d`). 그래서 🔖 단계 표시가 요일 칸에 **한 번도 뜬 적이 없다.** 이번 작업의 토대이므로 먼저 고친다.

```js
// work.html:2544  현재 (항상 빈 배열)
var st=stepsOf(it._id).filter(function(s){ return !s.done&&s.due===d; });
// 고침
var st=stepsOf(it._id).filter(function(s){ return !s.done&&s.d===d; });
```

## 5. 검사

`tests/work-my.test.js` 를 새로 만든다. 저장소 관례대로 `node tests/work-my.test.js`.

**묶어 보기** — 고정 순서, 그 밖의 구분은 뒤에 이름순, 묶음 안 기한순, 걸러진 뒤 건수, 0건 묶음은 안 그림, 접힘 기억

**열 접기** — 접을 수 없는 열은 접히지 않음, 묶어 보기를 켜면 구분 열이 접힘·끄면 돌아옴, 조건 걸린 접힌 열에 ● , 저장·복원

**할 일 / 기록 가르기** — 내일 이후 = 할 일, 오늘·지난 날 = 기록, 지난 주 열람 중에는 전부 기록, 경계일(오늘 자정)

**체크** — `done` 과 기록이 함께 생김, 칸에 한 줄만, 체크를 풀면 기록도 사라짐, `it.last` 가 갱신됨, 「미기록」에서 빠짐

**요일 칸** — 토·일이 할 일만 있어도 나옴, Enter가 머무름, 빈 칸 Enter는 아래로, 한글 조합 중 Enter는 저장 안 함

**결함 재발 방지** — `wkMarks` 가 `s.d` 를 본다 (`s.due` 로 되돌아가면 실패)

**쓰기 금지** — 이 화면이 `data/*`(푸른이알피)에 쓰지 않는다, `project_progress`·`my_todos` 등 통짜 저장 노드를 건드리지 않는다

## 6. 나눠서 넣기

각 단계가 그 자체로 쓸 만한 상태여야 한다.

1. **`wkMarks` 결함 수정** — 이것만으로 요일 칸에 단계 기한이 보이기 시작한다
2. **열 접기** — 화면이 즉시 넓어진다. 다른 것과 얽히지 않는다
3. **구분별 묶어 보기** — 열 접기의 "구분 열 자동 접기"가 여기서 이어진다
4. **상태 드롭다운** — 독립적, 작다
5. **요일 칸 할 일** — 결함 수정(1) 위에 올라간다. 가장 크다
6. **Enter 머무르기** — (5)와 함께 넣어야 여러 건 넣기가 완성된다
