# 폰에서 기업 상세(기업정보) 쓰기

작성 2026-08-15 · 대상 `pu-cards.html`

## 왜 필요한가

대표의 말: *"스마트폰에서는 명함과 사업자만 보이더라 기업정보도 확인할 수 있게 해달라."*
이어서 폰에서 어느 수준까지 볼지 물었을 때: *"PC와 동일한 기능"* — 폴더 만들기·
태그·이알피 가져오기까지 전부.

## 지금 구조 — 왜 폰에 안 보였나

`pu-cards.html`은 완전히 다른 두 화면을 한 파일에 갖고 있다.

```
IS_PC = matchMedia('(min-width:761px)').matches   // 처음 한 번만 잰다

폰(IS_PC=false)              PC(IS_PC=true)
#tabs (명함/사업자등록증)      #pcRoot (사이드바·표·기업 상세 팝업 전부 여기 안)
#list                         #pcCo, #pcDetail, #pcSide …
renderMobile()                renderPC()
```

`#pcRoot`는 `hidden` 속성으로 시작하고, `IS_PC`가 참일 때만 풀린다.

```css
#pcRoot[hidden]{display:none!important}  /* 폰에서 PC 레이아웃이 새어 나오던
                                             버그 수정 — 일부러 막아 둔 것이다 */
```

기업 상세(옆줄 「🏢 기업 상세」, 상세 팝업, 폴더/태그/이알피 가져오기)는 전부 이
`#pcRoot` 안, 즉 **PC에서만 존재**한다. 폰 쪽 `#tabs`는 명함·사업자등록증
두 개뿐이라 애초에 들어갈 길이 없었다 — 버그가 아니라 처음부터 안 만들어졌던 것.

### 좋은 소식 — 로직 대부분은 이미 화면과 분리돼 있다

살펴보니 폴더·태그·이알피 가져오기의 **실제 동작**은 이미 PC 화면 밖(공용 자리)에
있다.

| 함수 | 하는 일 | PC 전용 DOM에 묶여 있나 |
|---|---|---|
| `coList()` / `coVisible()` / `coFilteredList()` | 회사 목록 계산 | 아니오 — 순수 계산 |
| `_coFolders`, `_coInfo`, `_coTagHidden` | 저장된 자료 | 아니오 — 그냥 객체 |
| `openCoFolderDialog()` | 「새 폴더 / 이알피에서 가져오기」 창 | **아니오** — `#folderDlgBg`는 `#pcRoot` 밖의 공용 모달 |
| `coMoveToFolder()` / `coMoveSelTo()` | 폴더로 옮기기 | 아니오 — 같은 공용 모달 + Firebase 쓰기 |
| `coAssignTag()` / `coApplyTag()` | 탭에 담기 | 아니오 — 같은 공용 모달 |
| `coImportFolderFromType()` | 이알피 사업유형별 가져오기 | 아니오 — Firebase 쓰기만 |
| `openCoDetailPanel()` / `coDetailPanelHtml()` / `renderCoErpHistory()` | 회사 상세 내용 채우기 | `#pcDetail`은 `#pcRoot` **밖**에 있다(늘 DOM에 존재, 안 채워져 있을 뿐) |

PC 전용으로 진짜 갇혀 있는 건 **그리는 함수 둘**뿐이다 — `renderCoPage()`(넓은
8칸 표를 `#pcCo`에 그림)와 `renderPCSide()`(사이드바 폴더 목록). 이 둘만 폰에
맞게 새로 그리면 나머지는 그대로 재사용된다.

## 만들 것

### 1. 진입 — 상단 탭에 세 번째 버튼

```html
<div id="tabs">
  <button id="tabCard" onclick="setTab('card')">명함</button>
  <button id="tabBiz" onclick="setTab('biz')">사업자등록증</button>
  <button id="tabCo" onclick="setTab('co')">🏢 기업 상세</button>  <!-- 새로 추가 -->
</div>
```

`state.tab`이 `'card'|'biz'` 두 값뿐이던 것에 `'co'`를 더한다. `render()`(PC/폰을
가리는 진짜 갈림길)의 폰 쪽 분기(`renderMobile`)가 `state.tab==='co'`일 때 아래
2번 함수로 가지를 친다. 명함·사업자 쪽 동작은 손 안 댄다.

### 2. 목록 — 카드 한 줄에 한 회사

새 함수 `renderCoMobileList()`가 지금 명함 목록(`renderList()`)과 **같은
CSS 클래스**(`.row`, `.rowmain`, `.nm`, `.l1`, `.l2`)를 쓴다 — 새 스타일을
거의 안 만들어도 된다는 뜻이다.

```
┌─────────────────────────────────┐
│ 대명크라샤                [자문] │
│ 312-81-49225 · 담당 김보람       │
│ [일터상생혁신] [명함 3]          │
└─────────────────────────────────┘
```

- 데이터는 `coVisible()`(PC 표가 쓰는 것과 동일한 함수)를 그대로 받는다.
- 카드를 누르면 `openCoDetailPanel(key)` 호출 — PC와 **완전히 같은 함수**.
- 브라우저 목업(대표 승인, A안)과 같은 모양.

### 3. 상세 — 기존 패널에 폰용 CSS만 추가

새 화면을 안 만든다. `#pcDetail`은 이미 `#pcRoot` 밖에 있는 `<aside>`라 폰에서도
DOM에 존재한다 — 지금은 옆에 붙는 좁은 패널 모양의 CSS만 걸려 있을 뿐이다.

```css
@media(max-width:760px){
  #pcDetail.open{ position:fixed; inset:0; width:100%; z-index:50; }
  #pcDetailOverlay.show{ display:none; }  /* 전체화면이라 뒤 배경 가릴 필요 없음 */
}
```

안에 채우는 내용(`coDetailPanelHtml()`, `renderCoErpHistory()`, 폴더 표시,
이알피 이력 카드)은 **한 글자도 안 바꾼다** — PC와 폰이 같은 함수로 같은 내용을
그린다. 닫기는 기존 `closePcDetail()` 그대로.

### 4. 폴더 · 태그 · 이알피 가져오기 — 대부분 그대로 재사용

「새 폴더 만들기 / 이알피에서 가져오기」 창(`openCoFolderDialog`)은 위 표에서
확인했듯 이미 공용 모달이라 **손대지 않는다**. 폰에서 목록 위 「폴더 관리」
버튼을 누르면 지금 그대로 뜬다.

**새로 만들 것은 "어느 폴더를 볼지 고르는" 자리 하나뿐**이다 — 명함 탭이 이미
쓰는 그룹 선택 바텀시트(`openGroupSheet`)와 같은 모양으로 `openCoFolderSheet()`를
만든다.

```
┌─────────────────────────┐
│ 폴더 선택            ✕  │
│ ✅ 전체            4,141 │
│ 📁 거래처만          184 │
│ 📁 현장클리닉          0 │
│ 🏷 일터상생혁신        2 │
│ ＋ 새 폴더 / 이알피 가져오기│
└─────────────────────────┘
```

고르면 지금 있는 `pickCoFolder(k)`를 그대로 부른다(이미 PC/폰을 가리는
`render()`를 통해 다시 그리도록 되어 있어 손댈 필요가 없다).

### 5. 여러 곳 골라 한 번에 옮기기 · 태그 담기

명함 목록의 「✎ 편집」모드(`state.selMode`, 체크 표시)와 같은 방식을 기업
상세 카드에도 적용한다. 고른 뒤 「📁 폴더로 옮기기」/「🏷 탭에 담기」를 누르면
지금 있는 `coMoveToFolder()`/`coAssignTag()`가 그대로 동작한다.

### 6. 배선 정리 — render() 하나로 통일

지금 코드 곳곳(구독 콜백 3곳 포함— `coFolders`/`coInfo`/`coTagHidden`이
바뀔 때, `pickCoTag`/`deleteCoFolder`/`coMoveSelTo`/`coApplyTag`/
`coImportFolderFromType`/`coSortBy`/`coApplyColFilter`/`onPcSearchInput`/
`clearPcSearch` 등)가 `if(state.view==='co') renderPC();` 또는
`renderCoPage();`를 **직접** 부른다. PC에서만 있던 화면이라 그래도 됐지만,
폰에서 같은 조작을 하면 존재하지도 않는 `#pcCo`를 그리려다 아무 일도 안
일어나거나 조용히 어긋난다.

**원칙 하나로 통일한다**: "다시 그려야 한다"는 신호가 오면 `state.view==='co'`
**뿐 아니라** `state.tab==='co'`(폰)도 함께 보고, `renderPC()`/`renderCoPage()`를
직접 부르는 대신 **`render()`**(PC/폰을 알아서 가리는 진짜 진입점)를 부르도록
고친다. 데스크톱 동작은 그대로다 — `render()`가 `IS_PC`를 보고 결국
`renderPC()`로 가기 때문이다. 정확한 지점 목록은 계획서에서 줄 번호까지
못 박는다.

## 안 하기로 한 것

- **PC 관리자 화면 전체(사이드바·메일·설정·자료함)를 반응형으로 만들지 않는다.**
  이번 요청은 기업 상세 하나다 — 다른 PC 전용 화면까지 넓히면 손대는 범위가
  커지고, 폰에서 PC 레이아웃이 새는 걸 막아 둔 기존 안전장치와 부딪힌다.
- **표(열 정렬·열 깔때기)를 폰에 그대로 옮기지 않는다.** 카드 목록에는 "칸"이
  없다 — 정렬·유형별 거르기는 폴더 시트 안에 접어 넣거나, 필요하면 이후
  별도 요청으로 다룬다(이번 범위 밖).
- **명함 상세처럼 완전히 새로운 폰 전용 상세 화면을 만들지 않는다.** 기존
  `#pcDetail`에 CSS만 더해 재사용한다 — 내용 함수를 두 벌로 유지하면 나중에
  한쪽만 고쳐 어긋나는 사고(이 파일에 이미 여러 번 있었던 종류)로 이어진다.

## 에러 처리

- 클라우드 모드가 아니면(`Store.mode!=='firebase'`) 폴더 이동·태그·가져오기는
  지금과 똑같이 안내만 하고 아무 것도 쓰지 않는다 — 기존 PC 쪽 가드를 그대로
  탄다(같은 함수를 쓰므로 자동으로 적용된다).
- 이알피 조회(`loadErpCaseCons`)가 느리거나 실패해도 목록·상세 기본 정보는
  그대로 뜬다 — 기존 PC 동작과 동일.

## 테스트

- `renderCoMobileList()`, `openCoFolderSheet()`는 기존 관례대로 소스에서
  함수를 그대로 잘라 vm으로 실행하는 테스트를 새로 쓴다(예:
  `tests/cards-co-mobile-list.test.js`, `tests/cards-co-folder-sheet.test.js`).
- `render()` 통일 배선은 "폰 모드(`state.tab==='co'`)에서 폴더를 옮기면
  `renderCoMobileList()`가 다시 불리는지, PC 모드에서는 그대로 `renderPC()`가
  불리는지"를 함께 검사한다 — 한쪽만 고치고 다른 쪽을 깨뜨리는 사고를 막는다.
- 브라우저에서 폰 너비(375px)로 실제로 열어 카드 목록·상세 시트·폴더 시트·
  이알피 가져오기·선택 모드까지 눈으로 확인한다.
