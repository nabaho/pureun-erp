# 입금 매칭 검증 UI 설계

> 확정 목업: https://claude.ai/code/artifact/aef602c5-9c97-43e7-8c47-33f86b9adf10

- 상태: **구현 완료** (1-1·2-2·3-2·4-1·4-3 전부 반영됨) — 뒤늦게 설계서만 커밋

## 문제

총괄관리자가 입금을 확정할 때, 현재 화면은 **금액+적요만** 보여준다.
- 담당노무사(입력자) ≠ 총괄관리자(확인자) → 정보 격차
- 어떤 사건인지, 세금유형은 뭔지, 성과급이 맞는지 확인할 수 없다
- 비즈사업비N건은 각 사건별 대조가 불가능하다
- 잘못 확정한 건을 되돌리기 어렵다

## 선택한 조합

| 번호 | 기능 | 형태 | 사용 시점 |
|------|------|------|----------|
| **1-1** | 기본 매칭 목록 | 행에 요약 → 클릭하면 **팝업** | 일반 입금 1:1 매칭 |
| **2-2** | 비즈N건 나눠담기 | 좌우 대조 **팝업** | 합산 입금 분리 |
| **3-2** | 자문료 일괄확인 | 테이블 **팝업** | 업체관리 자문료 자동 처리 |
| **4-1** | 확정 이력 | 검색 + 되돌리기 목록 | 잘못 확정한 건 찾기·취소 |
| **4-3** | 비교 수정 | 변경 전/후 **팝업** | 담당자·성과비율 수정 |

---

## 1. 기본 목록 (1-1)

### 행 요약 정보
기존 행(금액+적요)에 다음을 추가:
- **업체명** + 후보 수 ("후보 1건" / "⚠ 후보 2건")
- **매칭률** 뱃지 (79% 이름+금액, 42% 이름유사 등)
- **세금유형** 필 (VAT별도 / VAT포함 / 3.3% / 8.8%)
- **계산서 상태** 필 (발행됨 / 미발행 / ?)
- **담당자** 이름
- **성과급** 금액
- 자문료 자동매칭 건은 별도 배경색(teal)으로 구분

### 상단 요약바
- 총 건수·금액
- 자동(자문료) / 수동검증 / 미매칭 분류 카운트
- "자문료 일괄확인" 버튼 → 3-2 팝업
- "자동 매칭" 버튼 → 전체 자동매칭 실행

### 팝업 (행 클릭 시)
모달로 열리며 3칸 그리드:

1. **사업 정보**: 업체명, 유형, 항목(착수/잔금/성공보수), 수수료, VAT/원천징수 계산, 예상입금액, 기존 입금 내역, 등록자·등록일
2. **세금계산서**: 상태(발행/미발행), 발행일, 공급가·세액·합계, 입금 대조 결과(일치/불일치)
3. **성과급**: 기준액(VAT제외), 성과급률, 총 성과급, 배분 상세(이름·역할·비율·금액)

하단: "확정" 버튼 + "확정 후 이력에서 되돌리기 가능" 안내

### 구현 위치
- `erpRenderPendingRow()` 또는 기존 행 렌더 함수 확장
- 새 함수 `erpDepositDetailPopup(txn, cand)` 추가
- 상단바는 `erpPendingSummaryBar()` 컴포넌트

## 2. 비즈N건 좌우 대조 (2-2)

### 트리거
목록에서 "비즈사업비N건" 행(또는 나눠담기 행) 클릭 시 전용 팝업

### 레이아웃
좌우 2패널 모달:

**왼쪽 (은행 원본)**:
- 입금 금액 (크게)
- 입금 일시, 적요, 은행명
- 금액 대조 박스: 사건 합계 vs 입금액, 차이, 차이 원인 추정(3.3% 차감, 수수료 등)
- 총괄관리자 확인 안내

**오른쪽 (ERP 사건들)**:
- 각 사건 카드:
  - 체크박스 + 업체명 + 세금유형 필 + 금액 일치 뱃지
  - 2칸: 좌=사업정보(수수료·차감·예상입금), 우=계산서+성과급 배분
- 하단: 성과급 합계 (사람별 소계)

### 하단 버튼
- "취소"
- "N건만 확정" (일부만 체크한 경우)
- "나눠담기 확정" (전체)

### 구현 위치
- 기존 `spOpen/spSel/spGap/spRow` 나눠담기 모달을 확장
- 새 함수 `erpSplitComparePopup(txn, candidates)` 추가

## 3. 자문료 일괄확인 (3-2)

### 트리거
목록 상단 "자문료 일괄확인" 버튼

### 내용
테이블 형태 모달:
- 열: 체크박스 / 입금(금액+업체+일자) / 매칭(업체→자문료·담당·세금유형·계산서) / 성과급 / 패턴(N회) / 대조(✓/✗)
- 이상 건(금액 불일치 등)은 빨간 배경 + 체크 해제
- "... 나머지 N건 (모두 정상)" 접기

### 하단
- 확정 건수·금액·성과급 합계
- "N건 확정" 버튼

### 자동매칭 판정 기준
- 업체관리에 등록된 자문료 금액과 입금액 일치
- 이전 입금 패턴 존재 (같은 금액으로 N회 반복)
- 선납·건별·분기별은 자동매칭 제외 (기존 `addAdvisoryPending` 로직 유지)

### 구현 위치
- 새 함수 `erpAdvisoryBatchPopup(autoMatched)` 추가
- 기존 `addAdvisoryPending()` 결과를 입력으로 받음

## 4. 확정 이력 + 비교 수정 (4-1, 4-3)

### 4-1: 이력 목록

#### 위치
입금 매칭 화면 하단 또는 별도 탭

#### 내용
- 검색: 업체명, 담당자, 금액으로 필터
- 행: 입금일·금액 / 매칭 요약(업체→사업·담당·세금·성과) / 확정일 / 상태(정상/되돌림) / 버튼
- 나눠담기 건은 하위 행으로 사건들 표시
- 되돌린 건은 흐리게 + 취소선 + 사유 표시

#### 버튼
- "되돌리기" → 확인 후 `finance_income` 삭제 + 사업 레코드 paid 플래그 복원 + 성과급 취소
- "수정" → 4-3 팝업

### 4-3: 비교 수정 팝업

#### 레이아웃
좌우 2패널:
- **왼쪽 (변경 전)**: 빨간 배경, 현재 담당자·성과비율·성과급액
- **오른쪽 (변경 후)**: 초록 배경, 드롭다운(담당자 변경) + 비율 입력 + 실시간 성과급 계산 + 변동분 표시(+/-금액)

#### 저장 시 처리
- `finance_income` 레코드의 `perfShares` 업데이트
- 변경 이력(`editHistory`) 배열에 `{date, before, after, by}` 추가
- 성과급 재계산: `calcPerfShares()` 재호출

### 구현 위치
- 새 함수 `erpConfirmHistoryList()` 컴포넌트
- 새 함수 `erpEditComparePopup(incomeRecord)` 팝업
- 되돌리기 함수 `erpUndoConfirm(incomeId)`

1. **1-1 기본 목록 행 확장** — 행에 요약 정보 추가 (가장 영향 작음)
