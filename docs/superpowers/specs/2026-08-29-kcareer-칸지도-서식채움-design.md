# kcareer 「칸 지도」 서식 채움 (2단계) — 설계서

2026-08-29. 대표 지시: 「다른 양식이 나오면 다른 양식대로 또 정보 넣을 수 있게」,
「본인 이름에 도장 넣는 것도 자동으로」, 「한글 화면을 최대한 크게」.

## 0. 한 줄
받은 한글 서식의 표를 훑어 **채울 자리를 전부 찾아 목록으로 보여 주고**,
못 알아본 자리는 사람이 한 번 골라 주면 **그 서식에 기억**한다.
이름은 짐작이지만 **자리는 사실**이다 — 그래서 처음 보는 서식도 100% 채운다.

## 1. 왜 지금 방식으로는 안 되는가 (실측 2026-08-29)

대표가 올린 「[지방공기업평가원] 위촉직이사 지원서류.hwpx」를 그대로 만들어 돌렸다.

| 칸 | 결과 | 까닭 |
|---|---|---|
| 성 명 → `(한글)` | ❌ 안 들어감 | 칸에 글자가 있어 「덮지 않는다」 규칙에 걸림 |
| 성 명 → `(한자)` | ❌ 안 들어감 | 같음 |
| 기관명 : 부서명 : **직위 :** | ⚠ 앞의 둘만 | 사이 공백이 4칸 미만이면 셋 다 실패 |
| 생년월일 · 현 주 소 · 자택/직장 · 휴대폰 · E-mail | ✅ | |

**이름이 아예 안 들어간다.** 지금 `kcareer-hwpxfill.js`는 라벨을 알아본 자리만 채우고
**모르는 자리는 조용히 지나간다.** 그래서 서식이 바뀔 때마다 몇 칸씩 빈다.

### 서식 여섯 개로 확인한 것

모양이 전혀 다른 서식 여섯 개(대표 지원서 · 세로 라벨형 · 한 행 두 쌍 ·
**사전에 없는 라벨**(위촉대상자/추천사유/비상연락망) · 목록 표 · 도장 자리)를 훑었다.

```
합계: 채울 자리 37군데를 «모두» 찾음 · 그중 이름까지 알아본 것 12군데
```

- **자리는 37/37 찾았다.** 표 구조를 읽으므로 서식 모양과 무관하다.
- **이름은 12/37.** 사전에 없는 말은 못 알아본다 — 이건 앞으로도 늘 그럴 것이다.

→ **결론: 짐작을 더 잘하게 만드는 것으로는 못 끝낸다.
모르는 자리를 「물어보는」 길을 내야 한다.**

## 2. 결정 사항 (대표 승인)

| 물음 | 결정 |
|---|---|
| 안 채워지는 칸을 어떻게 | **칸 지도** — 목록 보고 골라서 한 번에 |
| 화면 배치 | **전체화면 · 오른쪽 서랍** |
| 도장 | **기본은 꺼 두고 「🖋 도장 찍기」를 누를 때만** |

## 3. 구조 — 무엇을 어디에 둘 것인가

```
js/kcareer-hwpxfill.js   (있음, 안 건드림)  라벨 사전 · cellText · fillCell · 목록 표 채우기
        ↑ 부른다                            ⚠ 검사 154개가 지키고 있다. 다시 쓰지 않는다.
js/kcareer-formmap.js    (새로)             칸 지도 훑기 · 짝 맞추기 · 되돌려 넣기 (순수)
js/kcareer-hwpstamp.js   (새로)             hwpx 묶음에 도장 그림 넣기 (JSZip 필요)
kcareer.html             (고침)             전체화면 · 칸 지도 서랍 · 서식별 기억
```

**기존 모듈을 다시 쓰지 않는 것이 중요하다.** `kcareer-hwpxfill.js`는 검사 154개가
지키고 있고 「빠른 이력서」도 같이 쓴다. 칸 지도는 그 **위에 얹는다**.

### 3.1 `kcareer-formmap.js` — 세 가지 일만 한다

```js
scan(sectionXml)        → { slots:[…], lists:[…], warn:{ textBoxes, nested } }
guess(slots, lists, d)  → 각 slot·list 에 guess 를 채워 돌려준다
apply(sectionXml, plan) → { xml, changed, filled:[…], failed:[…] }
```

`plan`은 화면이 만들어 넘기는 **최종 답안**이다 —
`{ picks:{ 't0r1c2':'name', … }, lists:{ 'L0':'career' }, data:{…내 정보…} }`.
`''`(빈 값)을 고르면 **비워 둔다**. 화면은 `plan`만 만들고 XML은 모른다.

**자리(slot) 하나의 모양**

```js
{ id:'t0r1c2',            // 표0 · 2행 · 3열 (0부터). 기억의 열쇠
  tbl:0, row:1, col:2,
  kind:'빈칸'|'안내글뒤'|'칸안라벨',
  text:'(한글)',           // 지금 글자 ('' 면 빈 칸)
  left:'성  명',           // 왼쪽 칸 글자 — 짝 맞추기의 실마리
  guess:'name',            // 짐작한 열쇠 ('' 면 모름 → 🟨)
  pick:'name' }            // 사람이 고른 것 (없으면 guess 를 쓴다)
```

**자리를 가르는 규칙 (`slots` 세 갈래)**

| 갈래 | 알아보는 법 | 넣는 법 |
|---|---|---|
| `빈칸` | 글자가 하나도 없음 | 그 칸에 넣는다 |
| `안내글뒤` | 괄호만 있는 짧은 글 — `(한글)` `(한자)` `(인)` | **글자 뒤에 이어 쓴다** |
| `칸안라벨` | `자택:____` `기관명 : 부서명 :` | 라벨 뒤 빈자리에 넣는다 |

`글자있음`(그냥 본문)은 자리로 보지 않는다. **절대 덮지 않는다.**

**목록 표는 `slots` 가 아니라 `lists` 로 따로 나온다.** 머리행이 2열 이상 목록 열쇠와
맞으면 그 표의 빈 행은 낱개 칸으로 세지 않고 하나로 묶는다 —
`{ id:'L0', tbl:1, kind:'career'|'edu', cols:['period','org','role'], 빈행:3 }`.
칸 지도에는 **「경력 — 빈 3줄」 한 줄**로 보인다. 낱개로 두면 아홉 줄이 되어 못 쓴다.
채워 넣기는 기존 `kcareer-hwpxfill.js`의 `fillList`를 그대로 쓴다.

### 3.2 짐작을 고칠 다섯 가지 (실측에서 드러난 것)

1. **행 안에서 잇는다** — 왼쪽이 「성명」이면 그 행의 `(한글)`→name, `(한자)`→nameHanja.
   지금은 `(한글)`을 못 읽어 대표 서식의 이름이 통째로 빠졌다.
2. **사전에 흔한 말 추가** — 신청인 · 위촉대상자 · 추천인 · 대상자 · 성명(한글).
3. **목록 표는 묶는다** — 지금 훑기는 학력·경력 표를 낱개 9칸으로 본다.
   묶지 않으면 칸 지도가 지저분해져서 못 쓴다.
4. **순수 빈 칸은 접어 둔다** — 왼쪽 라벨도 없고 짐작도 없는 자리(병합 칸의 잔여 등)는
   기본으로 접고 「더 보기」로 편다. ①번 서식에서 13군데 중 4군데가 이런 자리였다.
5. **주민등록번호는 사전에 넣되 기본은 「비워 둠」** — 자동으로 나가면 안 되는 정보다.

### 3.3 서식별 기억 — 두 번째부터 진짜 한 번에

```js
LS[NS+'form_maps'] = { [지문]: { name, at, picks:{ 't0r1c2':'name', … } } }
```

**지문(fingerprint)**: 표 개수 + 각 표의 행×열 + 「글자있음」 칸의 글자를 이어 붙인 해시.
서식이 바뀌면 지문이 달라져 **옛 기억을 쓰지 않는다** — 엉뚱한 칸에 넣는 것이
안 넣는 것보다 나쁘다.

같은 지문이면 `picks`를 그대로 얹는다 → 🟨 없이 바로 「채우기」.

### 3.4 `kcareer-hwpstamp.js` — 도장

**오늘 실제로 찍어 확인했다.** 세 번 만에 맞췄고, 세 번째에 「(인)」 옆에 온전히 찍혔다.

넣는 것 세 가지:
1. `BinData/image1.png` — 도장 보관함의 PNG (흰 배경은 이미 투명 처리되어 있다)
2. `Contents/content.hpf` 의 목록에 `<opf:item id="image1" … isEmbeded="1"/>`
3. 문단 안에 `<hp:pic>` — `treatAsChar="0"`, `textWrap="IN_FRONT_OF_TEXT"`, `allowOverlap="1"`

**⚠ 실측으로 알아낸 두 가지 — 여기서 틀리면 그림이 잘리거나 종이 밖으로 나간다**

- `orgSz`는 **그림 본래 크기**(px ÷ 96 × 7200 HWPUNIT), `curSz`/`hp:sz`는 **찍을 크기**.
  둘을 같게 두면 그림이 잘려 조각만 보인다(1·2차 시도에서 실제로 그랬다).
- `imgRect`/`imgClip`/`imgDim`은 **본래 크기 기준**이지 찍을 크기 기준이 아니다.
- 찍을 크기 기본 **지름 12mm(≈3400 HWPUNIT)**. `treatAsChar="1"`로 글자처럼 붙이면
  뒤로 밀려 종이 밖으로 나간다 — 자리를 잡아 **겹쳐 놓아야** 한다.

**찍을 자리 찾기**: 서식에서 `(인)` `(서명)` `서명 또는 인` `印` 을 담은 칸·문단.
못 찾으면 칸 지도에 「🖋 도장 자리 — 골라 주세요」로 올린다.

**언제 찍나**: 「🖋 도장 찍기」를 누를 때만. 글자 채우기와 **따로** 둔다 —
도장을 안 찍는 서류가 있고, 내용을 다 확인한 뒤 마지막에 날인하는 것이 순서다.

## 4. 화면

**전체화면은 이미 있는 `#rcEditCard.rh-wide` 를 쓴다.** 새 창을 만들어 편집기를 옮기면
7MB 엔진을 다시 올려야 한다 — 옮기지 않는다.

- 「서식 작업」 단추 → `rh-wide` 켜기. 오른쪽 패널을 **서랍**으로 (접으면 문서가 화면을 다 씀).
- 서랍 세 칸: **채울 곳(칸 지도)** · **내 정보** · **경력·자격**
  - 「내 정보」가 새로 생긴다 — 지금 목록에는 위촉장·자격증만 있어서
    **성명·연락처를 클릭으로 넣을 수가 없었다.** 클릭하면 편집기 커서 자리에 들어간다
    (`insertToEditor`가 이미 있다).
- 칸 지도 한 줄: `칸 이름 | 배지(알아봄/골라 주세요) | 자리 | 지금 글자 | 넣을 값(고르기)`
- 발판: 「✅ 이대로 채우기」 · 머리: 「🖋 도장 찍기」
- 목업: `docs/mockups/kcareer-form-fill.html` (대표 승인 완료)

## 5. 못 하는 것 — 화면에 적는다

- **글상자(도형 안의 글)** — 엔진이 아직 못 읽는다. 세어서 「글상자 2개는 못 읽었습니다」로 알린다.
- **칸 안에 표가 또 있는 자리(중첩 표)** — 정규식이 경계를 잘못 짚어 건너뛴다.
- **PDF 서식** — 다른 길(PDF 편집 탭)이다.

조용히 빠지면 「채웠다는데 비어 있다」가 된다. **반드시 화면에 적는다.**

## 6. 안전장치

- 글자가 있는 칸은 **절대 덮지 않는다.** `안내글뒤`만 예외이고, 그때도 **뒤에 이어 쓴다**.
- **채우기 전에** 무엇이 어디로 가는지 목록으로 보여 준다.
- 주민등록번호는 기본 「비워 둠」.
- 서식 지문이 다르면 옛 기억을 쓰지 않는다.
- 도장은 따로, 누를 때만.

## 7. 검사

`js/kcareer-formmap.js`는 XML 문자열만 다루므로 **7MB 엔진 없이** 검사한다.

**tests/kcareer-formmap.test.js**
- 서식 여섯 개 픽스처(위 §1의 그것)로 **자리를 하나도 안 놓치는지** — 37/37
- 대표 서식에서 **이름이 실제로 들어가는지** (`(한글)` 뒤에 이어 쓰기) ← 오늘 빠졌던 그것
- 「기관명 : 부서명 : 직위 :」에서 **직위까지** 들어가는지, 공백이 좁아도 되는지
- 글자가 있는 칸을 덮지 않는지
- 목록 표가 낱개가 아니라 **묶여서** 한 줄로 오는지
- 지문이 다르면 옛 `picks`를 쓰지 않는지
- 글상자·중첩 표를 **세어서 알리는지**

**tests/kcareer-hwpstamp.test.js**
- BinData 파일 · hpf 목록 · `<hp:pic>` 셋이 다 들어가는지
- **`orgSz ≠ curSz`** 규칙 — 같으면 잘린다(오늘 실측). 같게 만들면 검사가 걸려야 한다
- `treatAsChar="0"` 인지 — 1이면 종이 밖으로 밀린다
- 도장 자리를 못 찾으면 조용히 넘어가지 않고 알리는지

**검사에 이빨을 넣는다** — 쓴 뒤 고친 자리를 도로 막아 실제로 걸리는지 확인한다.

## 8. 순서

1. `kcareer-formmap.js` 훑기 + 검사 (서식 여섯 픽스처)
2. 짝 맞추기 다섯 고침 + 검사
3. 되돌려 넣기(`apply`) + 검사
4. 화면: 서랍 · 칸 지도 · 「내 정보」 칸
5. 서식별 기억
6. `kcareer-hwpstamp.js` + 검사
7. 「🖋 도장 찍기」 붙이기
8. 실제 서식으로 끝까지 확인 (브라우저)
