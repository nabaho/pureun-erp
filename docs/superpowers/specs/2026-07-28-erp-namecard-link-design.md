# 계약관리 ↔ 명함첩 연결 설계문서

- 작성일: 2026-07-28
- 목표: 푸른이알피 계약 추가/수정 시, 명함첩(pucards)에서 회사 사업자정보와 직원(담당자)을
  찾아 계약 폼(회사정보 + 기업담당자)에 자동으로 채운다.

## 통합 방식 (기존 기능 재사용)
pu-erp.html에는 이미 **"📂 과거 회사 불러오기"**(PastCompanySearchModal + searchPastCompanies)가
있어 계약관리/업체관리/사건/컨설팅/기금/기타사업 6개 소스를 회사명·사업자번호로 검색하고,
`fillFromPast(picked)`가 `picked.company`(회사정보 + contacts)를 폼에 채운다.
→ 여기에 **명함첩을 7번째 소스로 추가**한다. 새 화면·새 채움 로직 불필요.

## Part A — 명함첩(pu-cards.html): 경량 검색 인덱스 `pucards/idx`
- 사진(썸네일) 없는 압축 레코드를 별도 노드에 유지 (전체 1MB 이하).
- 레코드: `pucards/idx/{id} = { k, n, c, m, t, e, ti, d, ct, ad, bz, ceo }`
  - k=kind(card|biz), n=이름, c=회사, m=휴대폰, t=직통, e=이메일, ti=직책, d=부서,
    ct=회사대표번호, ad=주소(card=companyAddr/biz=address), bz=사업자번호(biz), ceo=대표(biz)
  - 빈 값은 생략해 크기 최소화. 이름·회사·사업자번호가 모두 없으면 기록 안 함.
- 유지:
  - 저장 시(Store.put) 해당 id의 idx 동시 기록.
  - 삭제 시(Store.del/hardDel) idx 제거.
  - 최초 1회 백필: 이미 로드된 state.items로 idx 통째 생성(단일 write). 기존 idx가
    항목 수의 90% 이상이면 스킵(중복 방지).

## Part B — 푸른이알피(pu-erp.html)
- 인증 준비 후 `pucards/idx`를 `.on('value')`로 로드해 `window.pucardsIdx`에 보관(실시간 갱신).
- `searchPastCompanies(query)`에 명함첩 결과 추가:
  - **사람 단위(card)**: 회사명/이름/사업자번호 일치 시 1행. 선택하면 그 사람을 담당자로,
    회사 사업자정보(같은 회사 biz 레코드가 있으면 대표·사업자번호 보강)를 회사칸에 채움.
  - **회사 단위(biz)**: 사업자등록증 레코드 일치 시 1행. 선택하면 사업자정보 + 그 회사 전체
    명함을 담당자 목록으로 채움.
  - 담당자 매핑: `{ id, name:n, role:ti, phone:(m||t), bizPhone:ct, email:e, isPrimary }`.
  - 소스 배지: 파랑 "명함첩". 과다 방지 위해 명함첩 결과 최대 50건.

## 독립성(스냅샷) · 수동 갱신 (추가)
- 명함첩에서 고른 담당자는 선택 시점에 계약서로 **복사(스냅샷)** 되며, 이후 명함첩의
  퇴사·승진·연락처 변경은 **저장된 계약에 자동 반영되지 않는다**(라이브 링크 없음).
- 담당자에 원본 카드 id(`pcId`)와 가져온 날짜(`pcAt`)를 조용히 저장.
- 계약 폼 담당자에 출처·시점 표시(`📇 명함첩에서 YYYY-MM-DD 가져옴 · 자동연동 안 됨`)와
  **수동 [🔄 명함첩 최신정보로 새로고침]** 버튼 제공. 버튼을 누를 때만 `window.pucardsIdx[pcId]`로
  갱신(자동 아님). 명함첩에서 삭제됐으면 기존 정보 유지 + 안내.
