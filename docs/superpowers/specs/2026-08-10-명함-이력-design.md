# 명함첩 — 같은 사람이 진급·이직했을 때

작성 2026-08-10 · 대상 `pu-cards.html`

## 왜 필요한가

대표의 말: *"같은 핸드폰전화번호 같은 이름인데 진급하거나 회사가 바뀌는 경우
명함을 새롭게 업로드 할 경우 과거의 명함에 대해서 어떻게 해야할지 질문 하게 해달라."*

### 지금 상태 — 구멍이 정확하다

| 길 | 중복을 잡나 |
|---|---|
| 엑셀·연락처 **가져오기** (`previewImport`) | ✅ 잡는다. 「건너뛰기 / 빈칸만 채우기」를 묻는다 |
| 명함 **한 장 새로 등록** | ❌ **아무것도 묻지 않는다.** 그냥 한 장 더 쌓인다 |

`rowKeys()` 라는 좋은 열쇠 함수(휴대폰 → 이메일 → 이름+회사)가 이미 있는데
**가져오기에서만 쓰인다.** 명함을 한 장씩 올리는 길에는 연결돼 있지 않다.

그 결과 같은 사람이 진급할 때마다 명함이 한 장씩 늘어난다. 명함첩에는 이미
6,256장이 있어, 이런 겹침이 쌓이면 「어느 것이 지금 것인가」를 알 수 없게 된다.

## 정한 것 (대표 결정)

**갱신하고 이력을 남긴다.** 명함은 한 장으로 유지하되, 예전 회사·직책을 명함
안에 남긴다. 목록은 깔끔해지고 과거 이직 경로는 보존된다.

---

## 1. 언제 묻나

새 명함을 등록할 때(사진첩에서 확정하는 길과 손으로 등록하는 길 모두) 이미
있는 명함과 견준다.

```
이름 같음  +  휴대폰 같음
   ├─ 회사·직책도 같음 → 묻지 않는다. 지금처럼 처리한다
   └─ 회사나 직책이 다름 → ① 진급·이직 물음
휴대폰만 같음 (이름 다름) → ② 번호 물려받음 물음
그 밖 → 묻지 않는다. 새 명함으로 등록
```

**회사·직책이 똑같으면 묻지 않는 것이 중요하다.** 물음이 잦으면 읽지 않고
누르게 되고, 그러면 진짜 물어야 할 때도 지나친다.

### 비교 규칙

- 휴대폰은 숫자만 뽑아 견준다(`digits()`, 이미 있다). `010-1234-5678` 과
  `01012345678` 은 같다.
- 이름은 앞뒤 공백을 지우고 견준다. **가운뎃점·직함은 건드리지 않는다** —
  「김수한」과 「김수한 과장」을 같게 보면 다른 사람을 합칠 위험이 있다.
- 회사·직책 비교는 공백을 지우고 소문자로. 「(주)한서정공」과 「한서정공」은
  **다르게 본다.** 다르게 보면 물음이 한 번 더 뜰 뿐이지만, 같게 보면 조용히
  덮어쓴다. 물음이 뜨는 쪽이 안전하다.
- **잠긴 개인 폴더의 명함도 견준다.** 열려 있을 때만 견줄 수 있다. 잠겨 있으면
  견주지 못하므로 겹침이 생길 수 있다 — 이건 잠금의 대가이고, 화면에 적지 않는다
  (적으면 개인 폴더에 누가 있는지 새어 나간다).

## 2. ① 진급·이직 물음

```
┌─ 🔄 이미 있는 분 같습니다 ────────────────┐
│                                          │
│  김수한 · 010-3525-6150                   │
│                                          │
│  예전  한서정공 · 공장 과장      2019.08.18 │
│  새것  한서정공 · COO/경영운영책임          │
│         ↑ 직책이 바뀌었습니다               │
│                                          │
│  [갱신하고 이력 남기기]  [따로 두기]  [취소] │
└──────────────────────────────────────────┘
```

- 바뀐 칸에 표시를 해 준다. 회사가 바뀌었는지 직책만 바뀌었는지가 판단을 가른다.
- `[갱신하고 이력 남기기]` — 예전 값을 이력에 밀어 넣고 새 값으로 덮는다.
- `[따로 두기]` — 새 명함으로 등록한다. 동명이인이거나 실제로 두 자리를 겸하는 경우.
- `[취소]` — 아무것도 하지 않는다. 사진첩에서 온 경우 명함은 확정되지 않는다.

### 갱신할 때 무엇이 어떻게 되나

| 것 | 어떻게 |
|---|---|
| 회사·직책·부서 | 새 값으로 덮고 **예전 값을 이력에 남긴다** |
| 휴대폰·이름 | 그대로 (같으니까 여기 온 것이다) |
| 이메일·회사전화·주소 | **새 값이 있으면 덮고, 비어 있으면 예전 값을 지킨다** |
| 폴더·탭·담당자 | **손대지 않는다.** 이미 분류해 둔 것을 새 명함이 흩뜨리면 안 된다 |
| 명함 사진 | 새 사진으로 바꾼다. 예전 사진은 사진첩에 그대로 남아 있다 |
| 메모 | **지우지 않는다.** 새 메모가 있으면 줄을 바꿔 뒤에 붙인다 |
| 수신거부(`noMail`) | **그대로 지킨다.** 갱신으로 풀리면 거부한 사람에게 메일이 나간다 |

「비어 있으면 지킨다」가 핵심이다. 새 명함에 이메일이 안 적혀 있다고 예전에
받아 둔 이메일을 지우면 손해다.

## 3. ② 번호 물려받음 물음

휴대폰은 같은데 **이름이 다른** 경우. 회사폰을 후임에게 넘긴 흔한 경우다.

```
┌─ ⚠️ 같은 번호를 쓰는 다른 분이 있습니다 ──────┐
│                                              │
│  010-3525-6150                               │
│  기존  김수한 · 한서정공 · 공장 과장            │
│  새것  박정민 · 한서정공 · 대리                │
│                                              │
│  회사 전화를 물려받으셨을 수 있습니다.          │
│                                              │
│  [따로 두기] (권장)   [기존 명함에서 번호 지우기] │
└──────────────────────────────────────────────┘
```

**기본은 「따로 두기」다.** 여기서 갱신을 기본으로 두면 **다른 사람의 명함이
덮어써진다.** 되돌릴 수 없는 손해라 안전한 쪽을 기본으로 둔다.

`[기존 명함에서 번호 지우기]` 는 예전 사람의 명함에서 그 번호만 지운다.
명함 자체는 남는다.

## 4. 이력을 어디에 두나

```
items/<id>/hist = [
  { "company":"한서정공", "title":"공장 과장", "dept":"본사",
    "from":"2019-08-18", "to":"2026-08-10" },
  { "company":"대영전자", "title":"대리", "dept":"",
    "from":"2016-03-02", "to":"2019-08-18" }
]
```

- 새것이 앞. 명함을 열면 최근 이력부터 보인다.
- `from` 은 그 명함이 등록된 날, `to` 는 갱신된 날.
- **이력은 지우지 않는다.** 되돌릴 수 없는 삭제는 만들지 않는다.
- 명함 상세에 접힌 줄로 보여 준다. 이력이 없으면 아무것도 안 보인다.

```
이전  한서정공 · 공장 과장    2019.08 ~ 2026.08
이전  대영전자 · 대리         2016.03 ~ 2019.08
```

- **검색은 이력까지 뒤진다.** 「대영전자 김수한」으로 기억하고 있어도 찾아진다.
  이게 이력을 남기는 값어치의 절반이다.

## 5. 잘못될 수 있는 곳과 대비

| 위험 | 대비 |
|---|---|
| **다른 사람의 명함을 덮어씀** | 번호만 같으면 기본을 「따로 두기」로 둔다 |
| 동명이인을 한 사람으로 합침 | 이름 **과** 휴대폰이 둘 다 같아야 ① 물음이 뜬다 |
| 예전 이메일·주소가 사라짐 | 새 값이 비어 있으면 예전 값을 지킨다 |
| 분류해 둔 폴더·탭이 흩어짐 | 갱신은 폴더·탭·담당자를 손대지 않는다 |
| 수신거부가 풀려 메일이 나감 | `noMail` 은 갱신해도 그대로 지킨다 |
| 메모가 사라짐 | 지우지 않고 뒤에 붙인다 |
| 물음이 잦아 읽지 않고 누름 | 회사·직책이 같으면 묻지 않는다 |
| 갱신을 되돌리고 싶음 | 이력에 예전 값이 남아 있다. 이력 줄에서 되돌리기를 준다 |

## 6. 확인 방법

`rowKeys()` 옆에 순수 함수로 놓고 `node --test` 로 검사한다.

`findSamePerson(newCard, items)` → `{ kind:'promoted'|'phoneReused'|'same'|null, id }`

- 이름·휴대폰이 같고 직책이 다르면 `promoted`
- 이름·휴대폰·회사·직책이 모두 같으면 `same` (묻지 않음)
- 휴대폰만 같고 이름이 다르면 `phoneReused`
- 이름만 같고 휴대폰이 다르면 `null` (동명이인 — 묻지 않음)
- `010-1234-5678` 과 `01012345678` 을 같게 보는지
- 휴대폰이 아예 없는 명함끼리는 `null` (빈 값으로 엮이면 안 된다)

`mergeCard(old, next)` → 갱신된 명함

- 새 값이 비면 예전 값이 지켜지는지
- `gid`·`tabs`·`owner`·`noMail` 이 그대로인지
- `hist` 맨 앞에 예전 회사·직책이 들어가는지
- 메모가 지워지지 않고 뒤에 붙는지

화면 검사는 로컬 서버 + 브라우저로 한다.

- 회사·직책이 같은 명함을 다시 올리면 물음이 **안 뜨는지**
- 이력 줄이 명함 상세에 나오는지
- 이력의 예전 회사명으로 검색이 되는지

## 7. 안 하기로 한 것

- **이력 지우기** — 되돌릴 수 없다. 만들지 않는다.
- **이미 쌓인 겹침 자동 합치기** — 6,256장에 자동으로 손대지 않는다.
  기존 `🧹 중복 정리` 화면이 이미 있고, 거기서 사람이 보고 합친다.
- **이름 표기가 다른 경우 알아서 맞추기** — 「김수한」과 「金秀漢」을 잇지 않는다.
- **회사 이름 정규화** — 「(주)한서정공」과 「한서정공」을 같게 보지 않는다.
  같게 보면 조용히 덮어쓴다.
