>
> 대표님 지시(2026-08-01): "사진첩이 다 만들어지면 그때 진행할 예정이다."

## 0. 어떻게 여기까지 왔나 (판 이력)

| 판 | 내용 | 결과 |
|---|---|---|
| 1 | 사진 전용 저장소(Firebase Storage) 사용 | **철회** — 이 저장소의 어떤 앱도 Storage를 실제로 쓰고 있지 않음(명함첩은 SDK만 로드하고 사진은 실시간DB에 저장). 검증된 적 없는 길 |
| 2 | 컨설팅 앱을 열고 그 자리에서 촬영 | **철회** — 현장에서 앱을 만져야 함 |
| 3 | 찍어두고 몰아 올리기 + 날짜로 자동 배정 | 자동 배정만 **제외** — 하루 두 사업장이면 날짜로 안 갈림 |
| 4 | 컨설팅 앱 안에 보관함 | **철회** — 앱이 더 커지고 다른 앱이 못 씀 |
| **5** | **별도 사진첩 앱 + 각 앱에서 당겨오기** | **확정** |

## 1. 확정된 방침

| 항목 | 결정 |
|---|---|
| 사진 보관 | **별도 앱 「푸른 사진첩」** — 폰에서 가볍게 열림 |
| 각 앱 연결 | **당겨오기 창** — `js/` 공용 조각 하나로 만들어 앱마다 한 줄 |
| 사진 배정 | 자동 안 함. **담당자가 날짜를 골라** 직접 넣음 |
| 안 쓴 사진 | **안 지움.** 무조건 보관 |
| 공개 범위 | **올린 사람 + 관리자**만 |
| 도장 시각 | **실제 찍은 시각**을 기본값으로, 고칠 수 있게 |
| 연말 정리 | 해가 바뀌면 그 해 전체를 ZIP 백업 (**이번 범위 아님**, 12월 전) |

## 2. 왜 별도 앱인가 (확인한 사실)

| 근거 | 확인 내용 |
|---|---|
| 이미 그 구조 | 앱 15개 전부 `js/` 공용 파일 4개(`pu-resilience`·`pu-health`·`pu-version`·`pu-backup`)를 함께 씀. 당겨오기를 공용 조각으로 만들면 앱마다 한 줄 |
| 검증된 선례 | `pu-camera.html`(28KB)이 폰 전용으로 찍어 명함첩에 넣는 구조로 이미 운영 중. 사진은 실시간DB에 base64로 저장 |
| 앱 무게 | `gov-consulting.html` 은 500KB · PC용 화면. 폰으로 사진만 올리기엔 과함 |
| 포털 | `enter.html` 에 앱 목록(배열)이 있어 아이콘 추가가 한 줄 |
| 확장 | 급여·기금·취업규칙·명함첩에서도 같은 한 줄로 사진을 씀 |

## 3. 쓰는 흐름

### ① 현장 — 할 일 없음
평소대로 폰 기본 카메라로 찍는다. 앱 안 연다.

### ② 올리기 — 사진첩 앱, 터치 세 번
폰으로 푸른 사진첩 → `사진 올리기` → 앨범에서 여러 장 선택 → 끝.
- 사업장·일정 **안 고른다.** 그냥 사진첩에 쌓인다
- 올리는 중 자동: 크기 줄이기(긴 변 1600px) + 찍은 날짜·시각 읽기
- 신호 약하면 폰에 담아뒀다가 연결되면 자동 재시도

### ③ PC에서 당겨오기 — 컨설팅 앱
일정의 사진 칸 옆 `사진첩에서 가져오기` 버튼.
- 창이 뜨면 **날짜 고르기** → 그 날 사진만 격자로
- 사진마다 찍은 날짜 표시, **담당자가 고칠 수 있음**
- 쓸 것 체크 → 고른 순서대로 1번·2번·3번 칸에 배정 → `넣기` → 도장 자동
- 사진첩에는 **"사용됨" 표시만** 남고 사진은 그대로 보관

---

## 4. 사진은 누가 갖는가 (중요)

**컨설팅이 자기 것으로 복사해 갖는다.** 사진첩을 가리키기만 하지 않는다.
- 이유: 나중에 사진첩을 정리해도 **컨설팅 기록이 온전**해야 함
- 사진첩에는 "어디에 쓰였는지" 표시만
- 대신 같은 사진이 두 곳에 생김 → 용량 계산(6장)에 반영

---

## 5. 만들 것 (5덩이)

| 덩이 | 내용 | 예상 | 이것까지 하면 |
|---|---|---|---|
| A | 사진첩 앱 껍데기 + 포털 등록 | 반나절 | 앱이 열림 |
| B | 사진 클라우드 저장(실시간DB, 연도별 분리) | 반나절 | 폰↔PC 사진 공유됨 |
| C | 사진첩 화면(올리기·날짜별 보기·날짜 고치기) | 반나절 | 앨범에서 몰아 올리기 됨 |
| **D** | **당겨오기 창(공용 조각) + 컨설팅 연결** | 반나절 | **대표님 요구가 완성** |
| E | 연말 백업 | 반나절 | 해마다 안전하게 남음 (12월 전) |

**D가 이번 대기 항목.** A~C(사진첩)가 끝나야 시작한다.

### 설계 시 지킬 것
- 사진은 **볼 때만 한 장씩** 받아온다. 앱 열 때 통째로 받으면 느려진다
- **연도별로 나눠 보관.** 올해 것만 평소에 불러온다
- 통신 실패 시 기기에 먼저 저장 → 연결되면 자동 재시도
- 사진은 **한 장씩 추가만.** 배열 통째 덮어쓰기 금지 (2026-07 데이터 사고 재발 방지)

---

## 6. 용량 (무조건 보관 기준)

사진첩 원본분 약 300KB + 컨설팅 도장본 약 400KB = 쓰는 사진 한 장당 약 700KB.

| 시점 | 누적 | 무료 1GB 대비 |
|---|---|---|
| 1년 | 약 600장 | 약 25% |
| 2년 | 약 1,200장 | 약 50% |
| 3년 | 약 1,800장 | 약 75% |
| 4년 | 약 2,400장 | **꽉 참** |

4년쯤 뒤 선택: ①오래된 해를 클라우드에서만 비우기(ZIP 백업은 남음) ②유료 전환(월 몇 천 원).

## 7. 위험과 대비

| 항목 | 내용 | 대비 |
|---|---|---|
| 앱이 하나 늘어남 | 로그인·동기화·업데이트 대상 추가 | 공용 파일 그대로 사용, 30KB 수준 |
| 엉뚱한 일정에 붙음 | 사람이 고르므로 실수 가능 | 넣기 전 미리보기, 넣은 뒤 되돌리기 |
| 찍은 날짜를 못 읽음 | 카톡으로 받은 사진 등은 정보가 지워짐 | 파일 날짜로 대신 → 없으면 직접 지정 |
| 사진이 두 곳에 | 사진첩 + 컨설팅 복사본 | 의도된 설계(4장). 용량에 반영됨 |
| 앱 느려짐 | 사진을 안 지우니 계속 쌓임 | 연도별 분리 + 볼 때만 한 장씩 |
| 백업을 깜빡함 | 서버가 없어 강제 못 함 | 할 때까지 안내 표시(E) |
| 남의 사진 섞임 | 여러 직원이 같은 사진첩 | 올린 사람 것만 (관리자는 전체) |
| 개인정보 | 현장 사진이 클라우드에 | 이메일 로그인 계정만 읽도록 제한 |

---

## 8. 착수 전 확인할 것

1. 사진첩 앱을 **누가 만드는지** — 이 세션이 만들 것인지, 다른 세션·다른 경로인지
2. 사진첩이 사진을 **어디에 어떤 형태로** 저장하는지 (당겨오기가 읽어야 함)
3. 컨설팅 앱 수정 시 **다른 세션과 작업트리 충돌** 주의 — 임시 작업트리로 main에 cherry-pick
