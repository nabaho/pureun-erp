# 메일함을 직원 전원에게 열기 — 콘솔에 붙여넣을 한 칸

대표 지시 2026-08-27: **「전 직원에게 다 열기」**

---

## 왜 코드만 고쳐서는 안 되나

직원이 메일함에 들어가도 화면이 비어 있던 까닭은 **앱이 아니라 DB 규칙**이었다.

```
"mailbox": { ".read": "… isAdmin == true" }
```

`uid_roles` 를 세어 보니 `isAdmin: true` 는 **P-001(대표) 한 분뿐**, 나머지 아홉은 전부 `false`.
그래서 아홉 명은 메일 목록을 **한 줄도 못 읽었다**. 옆줄의 기본 칸(전체메일·받은메일함…)이
통째로 안 나온 것도 이 때문이다.

**★ 규칙은 코드 배포로 안 바뀐다.** Firebase 콘솔 [Realtime Database → 규칙]에
직접 붙여넣어야 한다. 저장소의 규칙 파일을 배포하면 사진첩·성과확인이 막힌다 — 하지 말 것.

---

## 붙여넣을 것

콘솔 규칙에서 `"mailbox"` 칸을 찾아 **아래 두 줄로 바꾼다**.

```json
"mailbox": {
  ".read": "auth != null && root.child('uid_roles').child(auth.uid).child('sid').exists() && root.child('uid_roles').child(auth.uid).child('status').val() === 'active'",
  ".write": false
},
```

### 바뀌는 것

| | 전 | 후 |
|---|---|---|
| 메일 목록·제목 | 대표님만 | **재직 중인 직원 전원** |
| 메일 본문·첨부 | 대표님만 | **재직 중인 직원 전원** |
| 읽음 표시·휴지통·폴더 옮기기 | 대표님만 | **재직 중인 직원 전원** |
| 다음메일 **폴더 자체**를 만들고 지우기 | 대표님만 | **대표님만** (그대로) |
| 아무나 쓰기 | 막힘 | **막힘** (그대로) |

---

## 조심한 것

**① 「로그인한 사람」이 아니라 「사번이 적힌 재직자」다.**
서버의 `requireStaff` 는 「비밀번호로 로그인했는가」만 본다 — 회사 계정이 아니어도 통과한다.
그래서 규칙과 서버 둘 다 `uid_roles` 에 **사번(`sid`)이 있고 `status`가 `active`** 인지 본다.
(2026-08-27 실측: `uid_roles` 10명 전원이 사번·status 를 갖고 있다)

**② 규칙과 서버를 «같은 뜻»으로 맞췄다.**
한쪽만 열면 목록은 보이는데 본문에서 403 이 나거나, 그 반대가 된다.
서버 쪽은 이미 배포했다(`functions/mail-sync.js` 의 `requireMailUser`).

**③ 폴더 만들기·지우기만 대표 몫으로 남겼다.**
한 사람이 폴더를 지우면 열 사람 화면이 함께 바뀌고 그 안의 메일이 휴지통으로 간다 —
되돌리기 어렵다. 메일을 보고·읽음 표시하고·옮기는 것과는 무게가 다르다.

**④ ⚠ 아직 남는 구멍 — 퇴사자 계정.**
`status` 는 그 사람이 **본인이 로그인할 때** 적힌다. 퇴사자가 다시 로그인하지 않으면
`active` 로 남는다. **퇴사 계정은 Firebase Auth 에서 «사용 중지»를 해야 진짜로 닫힌다.**
이 저장소의 다른 규칙(재무·인사)도 모두 같은 처지다 — 여기서만 생기는 구멍이 아니다.

**⑤ ⚠ 회사 메일함에는 고객사 임직원의 신상이 제목에까지 들어 있다.**
이제 직원 열 명이 모두 볼 수 있다. 대표님께서 그렇게 정하셨다는 것을 여기 적어 둔다.
