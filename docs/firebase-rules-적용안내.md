## 1순위 — 익명 접근 차단 (권장: 즉시)

**파일**: `docs/firebase-rules-1순위-익명차단.json`

이메일(비밀번호)로 로그인한 사람만 접근하도록 45곳을 바꿨습니다.
`data/$other` 등 기존 규칙에서 이미 쓰던 검증된 방식과 동일합니다.

### 익명을 그대로 둔 곳 (막으면 기능이 깨짐)

| 노드 | 이유 |
|---|---|
| `esign` | 외부 근로자가 링크로 접속해 서명 (`sign.html`) |
| `ieum_public` | 외부 공개 명단 보기 (`ieum-view.html`) — 쓰기는 이미 로그인 필요 |
| `appBuild` | 버전 확인용, 데이터 없음 |

### 적용 후 달라지는 점

- **컨설팅 일정**을 포털 로그인 없이 주소로 바로 열면 데이터가 안 보입니다.
  → 포털에서 로그인 후 들어가면 정상입니다. (원래 이래야 맞습니다)
- 그 외 직원이 정상 로그인해 쓰는 흐름은 변화 없습니다.

### 적용 방법

1. Firebase 콘솔 → Realtime Database → **규칙** 탭
2. **현재 내용을 전부 복사해 따로 저장** (되돌릴 때 필요)
3. `firebase-rules-1순위-익명차단.json` 내용을 전부 붙여넣기 → **게시**
4. 확인: 포털 로그인 → 컨설팅 일정·기금관리·업무관리가 정상인지
5. 이상하면 2에서 저장해둔 내용을 다시 붙여넣어 즉시 원복

## 2순위 — 권한 자가 부여 차단 (준비 후 진행)

**문제**: 지금은 `uid_roles/{본인}`을 본인이 쓸 수 있습니다.
직원이 자기 권한에 `fin: true`를 써넣으면 급여·재무 전체가 열립니다.

**왜 바로 못 막나**: 앱이 로그인할 때 이 값을 스스로 기록하는 구조라,
그냥 막으면 **아무도 권한을 못 받아 로그인 후 화면이 비게 됩니다.**

**안전한 순서**

1. 대표님이 직원 13명의 권한을 콘솔에서 한 번 등록
   (`uid_roles/{uid}` = `{isAdmin, isSubAdmin, fin, hr, ...}`)
   - 각자의 uid는 Firebase 콘솔 → Authentication 에서 확인
2. 전원이 정상 로그인되는지 확인
3. 그 뒤에 규칙을 `관리자만 쓰기`로 잠금
4. 앱의 자가 기록은 실패해도 무시되도록 이미 `catch` 처리돼 있어 화면에 영향 없음

> 1~2를 건너뛰고 3만 하면 전 직원이 잠깁니다. 반드시 순서를 지켜야 합니다.

## 3순위 — 급여 확정 잠금 정상화

**파일**: `app/firebase.rules.json` (급여 아웃소싱용 초안)

확정(잠금)된 급여월은 관리자만 고치도록 `payroll_monthly/$ym`에 규칙이 있으나,
**Firebase는 상위 규칙이 하위를 덮어씁니다.** 상위 `clients/$site/.write`에서 이미
담당자 쓰기를 허용해 **잠금이 전혀 작동하지 않습니다.**

**고치는 법**: 잠금 조건을 상위 `.write`에 함께 넣거나, 확정월을 별도 경로로 분리.
이 규칙은 아직 배포 전 초안이므로, 급여 아웃소싱을 실제로 운영하기 전에 손보면 됩니다.
