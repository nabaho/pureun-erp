## 지금 상태

| | 어디에 | 누가 보나 | 지금 되나 |
|---|---|---|---|
| **공동으로 맡은 회사** (부담당이 있는 곳) | `pucards/mailSeen` | 재직 직원(화면은 담당자에게만) | ✅ **바로 됩니다** |
| **혼자 맡은 회사 · 담당 모름** | `pu_mailseen` | **대표님만** | ⛔ **아래 규칙이 있어야 합니다** |

**아래 규칙을 넣기 전에는 「혼자 맡은 건」의 기록을 아예 안 적습니다.**
막히지도 않은 자리에 먼저 쌓아 두면 그게 제일 나쁩니다.

---

## 붙여넣을 것

Firebase 콘솔 → Realtime Database → **규칙** 에서 최상위에 이 한 칸을 더합니다.

```json
"pu_mailseen": {
  ".read": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
  "$mail": {
    "$sid": {
      ".write": "auth != null && root.child('uid_roles').child(auth.uid).child('sid').val() === $sid && root.child('uid_roles').child(auth.uid).child('status').val() === 'active'"
    }
  }
}
```

### 이 규칙이 하는 일

- **읽기 — 대표님만.** 직원은 «못 읽습니다». 화면에서 안 보이는 게 아니라 **DB가 막습니다**.
- **쓰기 — 자기 사번 칸에만.** 김보람은 `.../P-00X` 에만 씁니다. **남의 이름으로 못 적습니다.**
- 재직자만 씁니다.

---

## ⚠ 왜 `pucards` 밑에 못 두나

`pucards` 는 **위쪽에 `.read` 가 걸려 있습니다**.

```json
"pucards": { ".read": "auth != null && auth.token.email != null", … }
```

Firebase 규칙은 **위에서 한 번 허락하면 아래에서 다시 막을 수 없습니다.**
그래서 `pucards/mailSeen/solo` 같은 자리를 만들어도 **전 직원이 읽습니다.**
대표님만 보시게 하려면 **`pucards` 밖의 새 뿌리**여야 합니다.

---

## ⚠ 정직하게 말씀드릴 것 둘

**① 공동 자리(`pucards/mailSeen`)는 「자물쇠」가 아니라 「가림」입니다.**
`pucards` 는 전 직원이 읽으므로, 공동 건의 확인 기록은 **마음먹으면 볼 수 있습니다**.
화면에서는 그 회사 담당자와 대표님께만 보입니다.
여기까지도 진짜 자물쇠로 만들려면 **서버 함수를 거쳐야 하고**, 그건 따로 할 일입니다.

**② 「혼자 맡은 건」은 진짜 자물쇠입니다.** 위 규칙이 올라가면 직원은 **못 읽습니다.**
