# 파일 창고(Storage) 규칙에 한 덩이 넣기 — 증빙 사진용

2026-08-27 · 대상 버킷 **`pureun-erp-hrphotos`**

> 이것은 **실시간DB 규칙이 아니라 「파일 창고(Storage)」 규칙**입니다. 자리가 다릅니다.
> 콘솔 → **Storage → Rules** 입니다. (Realtime Database → 규칙 아닙니다)

---

## 왜 필요한가

현장 사진(입장·활동·추가)이 지금까지 **그 PC 브라우저 안에만** 있었습니다.

- 다른 PC 에서 열면 **안 보입니다**
- 브라우저 자료를 지우면 **사라집니다**
- 서버 백업으로 되살려도 **사진은 안 돌아옵니다**

정부 제출 증빙이 PC 한 대에 묶여 있는 상태였습니다.
이제 사진을 넣으면 **창고에도 올라가** 어느 PC 에서 열어도 보입니다.
**규칙이 없으면 올라가지 않습니다** — 화면에 「창고 규칙이 아직 없습니다」라고 뜹니다.

---

## 넣을 것

콘솔 → **Storage** → 버킷 **`pureun-erp-hrphotos`** 선택 → **Rules** 탭.
이미 있는 `match /...` 줄들 **옆에** 아래 한 덩이를 넣고 **게시**합니다.

```
    // 정부사업일정 — 현장 사진(증빙). 법인 기록이라 직원이면 누구나 본다.
    match /gov_evidence/{sid}/{file} {
      allow read:  if request.auth != null;
      allow write: if request.auth != null;
    }
```

넣는 자리 예시 (앞뒤는 이미 있는 것):

```
service firebase.storage {
  match /b/{bucket}/o {

    ... 이미 있는 규칙들 ...

    // ↓ 여기에 넣습니다
    match /gov_evidence/{sid}/{file} {
      allow read:  if request.auth != null;
      allow write: if request.auth != null;
    }

  }
}
```

---

## 왜 「직원이면 누구나」인가

- 증빙 사진은 **법인 기록**입니다. 개인 사진첩과 다릅니다.
  담당자가 바뀌거나 대표님이 확인하실 때 **못 보면 안 됩니다.**
- 사진첩(`pu_photos`)에 넣지 않은 것도 같은 이유입니다 — 사진첩은
  **사람별로 갈려** 있어 규칙상 주인과 총괄관리자만 읽습니다. 동료가 못 봅니다.
- 익명 로그인은 2026-07-30 부터 막혀 있으므로, `request.auth != null` 은
  **사실상 「로그인한 직원」** 과 같습니다. 새로 여는 권한이 아닙니다.

---

## 넣은 뒤 확인

1. 정부사업일정 새로고침
2. **환경설정 → 백업/복원** → 맨 위 「☁ 증빙 사진을 창고에도 두기」
3. **[☁ 이 PC 사진 창고에 올리기]** 를 누릅니다
4. 「몇 장을 창고에 올렸습니다」가 뜨면 성공입니다

> ⚠ **직원마다 자기 PC 에서 한 번씩** 눌러야 합니다.
> 지금까지 찍은 사진은 각자 PC 안에 있어서, 남의 PC 안은 들여다볼 수 없습니다.
> 새로 찍는 사진은 그 뒤로 **저절로** 올라갑니다.

---

## 요금

증빙 1장 = 약 0.44MB. 창고는 **5GB 까지 무료**입니다.

| 증빙 사진 | 창고 저장량 | 월 요금 |
|---|---|---|
| 300장 | 130 MB | **0원** |
| 1,000장 | 440 MB | **0원** |
| 3,000장 | 1.3 GB | **0원** |

같은 사진을 실시간DB 에 뒀다면 GB당 **$5**, 창고는 **$0.025** — **200배** 차이입니다.
자세한 계산은 `docs/파이어베이스-비용계산-2026-08-27.md`.
