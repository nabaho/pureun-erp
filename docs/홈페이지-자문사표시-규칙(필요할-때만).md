# 자문사 표시 — 파이어베이스 규칙 (필요할 때만)

홈페이지 관리 화면의 **자문사현황**은 두 자리를 씁니다.

| 무엇 | 자리 | 하는 일 |
|---|---|---|
| 업체 목록 | `data/companies` | **읽기만** 합니다 (푸른ERP 업체관리 자료) |
| 올림/안 올림 표시 | `homepage/partners/{업체id}` | 이 화면이 **씁니다** |

## 아마 아무것도 안 하셔도 됩니다

지금 규칙(저장소의 `docs/firebase-rules-일정관리-직원저장(붙여넣기용).json` 기준)으로는

- `homepage` 아래가 **총괄관리자에게 읽기·쓰기 모두** 열려 있습니다 → `homepage/partners` 도 그대로 열립니다.
- `data/$other` 가 로그인한 직원에게 열려 있습니다 → `data/companies` 읽기가 됩니다.

**규칙은 콘솔이 진짜입니다.** 저장소 파일이 콘솔과 다를 수 있으니, 실제로 되는지는 화면에서 확인하십시오.

## 안 되면 화면이 말해 줍니다

자문사에서 「올림」을 눌렀을 때 저장이 거부되면, 화면 왼쪽 「할 일」 칸에 이런 띠가 뜹니다.

> 자문사 표시를 저장하지 못했습니다(PERMISSION_DENIED) — 파이어베이스 규칙에 «homepage/partners» 자리가 아직 없을 수 있습니다.

조용히 삼키지 않습니다. 표시가 남지 않았는데 남은 것처럼 보이면, 올렸다고 착각해 홈페이지를 안 고치게 됩니다.

## 그때만 붙여넣을 조각

파이어베이스 콘솔 → Realtime Database → 규칙에서, **`"homepage"` 안쪽에** 아래를 넣으십시오.

```json
"partners": {
  ".read": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
  ".write": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true"
}
```

넣은 뒤 모양은 이렇습니다.

```json
"homepage": {
  ".read": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
  ".write": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
  "partners": {
    ".read": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true",
    ".write": "auth != null && root.child('uid_roles').child(auth.uid).child('isAdmin').val() == true"
  }
}
```

## 하지 마실 것

- **저장소의 규칙 파일을 그대로 배포하지 마십시오.** 콘솔 규칙이 앞서 있을 수 있어, 파일로 덮으면 사진첩·성과확인 같은 다른 앱이 막힙니다. 콘솔에서 **필요한 조각만** 손으로 넣으십시오.
- `data/companies` 에 **쓰기 권한을 더 열지 마십시오.** 이 화면은 업체관리를 읽기만 합니다. 회사 이름·업종·거래 여부는 푸른ERP 업체관리에서 고칩니다.
