# 사진 편집 라이브러리 — 깃허브에서 찾아 붙일 수 있는가 (2026-08-29)

대표 지시: "깃허브에 사진편집기능 있는것 찾아달라 그리고 첨부가능한지 검토해라"

---

## 결론 먼저

1. **지금 하는 일에는 필요 없습니다.** 「붓으로 칠해 AI로 고치기」는 우리 층 **22KB**가
   이미 하고 있고, 어떤 라이브러리도 이 일을 대신해 주지 않습니다(AI 부르기는 우리 서버 몫).
2. **없는 것은 자르기 · 밝기/대비 · 글자 넣기 · 도형**입니다. 이건 **요금 0원**으로 되는
   일이라 라이브러리가 값어치를 합니다.
3. **권합니다**: 자르기부터, `cropperjs` **36KB**를 «쓸 때만 늦게» 불러오기.
   이 저장소에 이미 그 길이 나 있습니다(JSZip 을 그렇게 부릅니다 — `loadZipLib`).
4. **지금은 안 권합니다**: `tui.image-editor`(통짜 편집기). 붙기는 붙는데 **1MB**이고
   **4년 묵었습니다**.

브라우저에서 «늦게 불러오기»로 실제 붙여 봤습니다.

```
■ ① 자르기만 — cropperjs
  받음 45ms · window.Cropper = function
  ✅ 만들어짐 — 잘라낸 그림 640×480

■ ② 통짜 편집기 — tui.image-editor
  fabric 4 받음 · window.fabric = object
  다 받음 (합 298ms) · window.tui = object · ImageEditor = function
  ✅ 편집기가 만들어졌다 · 한글 이름표도 들어간다
  화면에 뜬 단추: crop, rotate, filter, text
```

**둘 다 빌드 없이 `<script>` 한 줄로 붙습니다.** 이 저장소는 빌드가 없으므로 이것이
첫 번째 관문이었고, 통과했습니다.

## 이 저장소에 붙일 때 걸리는 것 다섯

### ① 빌드가 없다 → 「전역 배포본(UMD)」만 쓸 수 있다
cropperjs·tui 는 있습니다. 요즘 나오는 것 중에는 **ESM 전용**이라 빌드 없이는 못 쓰는 것이
많으니 고를 때 이것부터 봐야 합니다.

### ② 남의 서버(CDN)에 기대게 된다
이미 전례가 있습니다 — 파이어베이스(gstatic)와 JSZip(cdnjs). 다만 **평소에 안 받고
쓸 때만 받는 방식**이라야 합니다. 사진첩은 처음 열 때 이미 무겁습니다.

### ③ ★ 증빙 사진 규칙을 라이브러리는 모른다
지금 우리는 **원본을 안 덮고 새 사진으로 담고**(`editedFrom`), **무엇을 시켰는지
기록**합니다(`meta.edited.what`). 라이브러리에 딸린 「저장」·「Download」 단추를 그대로
쓰면 이 규칙이 통째로 빠집니다.
→ **라이브러리는 «그림을 만드는 데»까지만 쓰고, 담는 것은 반드시 우리 저장 층으로.**

### ④ 검사를 어디까지 할 것인가
라이브러리 «안»은 우리가 못 잡습니다. 대신 **경계**를 검사합니다 —
무엇을 넣었고 무엇을 받았고, 받은 것을 우리 규칙대로 담았는가.

### ⑤ 크기
기업정보함에서 2.5MB 로 데인 적이 있습니다. **1MB 통짜는 신중히.**
