## 1. 오늘 붙인 것

### ① 한글 서식 스킬 (`.claude/skills/hwpx/`)
- 저장소에 통째로 넣었다. 계정·PC 가 바뀌어도 설치 단계가 없다.
- 배포본(GitHub Pages)에는 안 올라간다 — 워크플로가 `.claude/` 를 지운다.
- 확인한 것(2026-08-30): 실제 **외국인근로자 표준근로계약서(.hwp)** 를
  한글 프로그램 없이 리눅스에서 **1.2초** 만에 .hwpx 로 바꿨다.
- 개인정보 비경유 채우기(`secure_fill.py`)가 딸려 있다 —
  주민번호를 **화면·로그에 찍지 않고** 채우고, 쓰고 난 프로필을 지운다(`shred`).

### ② MCP 연결 (`.mcp.json`)
```json
{ "mcpServers": {
    "hrmcp":      { "type":"http", "url":"https://ncs-mcp-bridge-mini2.vercel.app/api/mcp" },
    "korean-law": { "type":"stdio", "command":"npx", "args":["-y","korean-law-mcp"] } } }
```
- 인사(HRMCP)와 법령(korean-law)을 저장소 차원에서 붙였다 —
  이제 이 저장소를 여는 사람은 누구나 같은 도구를 갖는다.
- **주의**: 이 환경(원격 상자)은 vercel.app 으로 나가는 길이 막혀 있어
  **여기서는 응답을 확인하지 못했다**. 대표 PC 에서 `/mcp` 로 붙는지 한 번 봐 주셔야 한다.
- 법령 도구는 `LAW_OC`(법제처 열쇠)가 있어야 산다. 없으면 그 도구만 조용히 죽는다.
- 곁들여 확인한 것: 한국산업인력공단이 2026-08-18 **HRDKorea MCP** 를 열었다
  (국가자격·해외취업·NCS·과정평가형·숙련기술·**외국인고용지원** 6개 분야 41개 기능, 인증키 없음).
  마지막 것은 푸른 업무와 정면으로 맞닿는다. 공식 주소를 받으면 위 파일에 한 줄 더 넣으면 된다.

### ③ 푸른통합시스템 연결 — 「📎 원본 서식 채우기」
계약 → 서식 창 아래에 단추를 하나 더 뒀다.

- **왜 필요했나**: 지금까지 푸른의 한글 저장은 문서를 **처음부터 새로 그렸다**(`hwpx_gen.js`).
  그래서 고용노동부·공단 서식처럼 «칸과 줄이 정해진» 서식은 만들 수 없었다 —
  표 하나만 어긋나도 접수처에서 되돌아온다.
- **어떻게 하나**: 원본 .hwpx 를 열어 `{{회사명}}` 같은 자리의 **글자만** 바꾸고 그대로 다시 묶는다.
  표·글꼴·도장 자리·그림은 원본 그대로 남는다.
- **주민번호**: 이 일은 **브라우저 안에서 끝난다**. 서버로 아무것도 안 보낸다
  (검사가 `fetch`·`fbDb.` 가 그 함수에 못 들어오게 막는다).
- 한글이 한 문단을 글꼴별로 쪼개 두어 `{{회` + `사명}}` 처럼 갈라져 있어도 채운다.
- 못 채운 자리는 이름까지 말해 준다 — 「채웠습니다. 다만 못 채운 자리: {{대표자}}」.

새 파일 `js/pu-form-fill.js` · 검사 `tests/form-fill-hwpx.test.js`(16가지).

> 실제로 겪은 것 하나: 처음엔 그냥 다시 묶었더니 스킬의 검사기가
> 「mimetype should use ZIP_STORED」로 걸렀다. 한글도 같은 자리를 본다.
> 붙여 둔 도구가 **그날 바로** 버그를 잡아 준 셈이다.

## 2. 앞으로 — 서식함 3층

지금은 대표가 서식 파일을 **직접 골라** 올린다. 그것만으로도 오늘 일은 된다.
다음 단계는 「매번 찾지 않게」다.

| 층 | 하는 일 | 어떻게 | 필요한 것 |
|---|---|---|---|
| 1층 **등록** | 사업장·공단 서식(.hwp)을 푸른 서식으로 들인다 | 스킬로 .hwpx 변환 → 채울 자리를 `{{토큰}}` 으로 바꿔 저장 | 사람 손(한 서식당 한 번) |
| 2층 **보관** | 서식 원본을 어디에 두나 | **Firebase Storage** (RTDB 아님 — 내려받기 값이 8배 싸다) | 규칙 한 줄 |
| 3층 **발급** | 계약·근로자를 고르면 채워서 내려준다 | 지금 만든 `pu-form-fill.js` 를 그대로 씀 | 서식 고르는 창 |

- **도장**: 원본 서식의 도장 자리에 그림을 넣는 일은 아직 안 했다.
  `BinData/` 를 손대지 않고 그대로 옮기는 것은 이미 되므로(검사로 지킨다),
  도장은 «미리 도장이 찍힌 서식 원본을 등록하는» 방식이 가장 싸고 안전하다.
- **주민번호**: 3층은 브라우저 안이므로 그대로 채운다.
  서버로 올라가는 백업만 `js/pu-rrn-seal.js` 가 잠근다 — 이미 붙어 있다.

## 3. HRMCP 를 «앱에서» 쓰려면

지금 붙인 것은 **개발 도구** 쪽이다(내가 쓰는 길). 앱 화면에서 직접 부르려면 한 걸음 더 있다.

- 브라우저가 남의 서버를 바로 부르면 CORS 에 막히고, 막히지 않더라도
  **푸른 화면이 제3자 서버와 직접 말하게 된다** — 그건 안 하는 편이 낫다.
- 그래서 Cloud Function 하나(`hrLookup`)를 두고 그쪽만 나가게 한다.
- **다만 지금은 못 한다**: 함수 배포(`firebase deploy --only functions`)가 아직 한 번도 안 됐다.
  하나은행 문자 읽기 고친 것도 같이 밀려 있다. 배포하는 김에 함께 올리는 것이 맞다.

## 6. ★ 준비 단계를 없앴다 (2026-08-30 저녁)

대표 지시: 「이렇게 만드는것 너무 불편하다 아주 쉽게 방법을 찾을것 아니면 의미가 없다」.

맞는 말이었다. 위 ③번은 서식마다 사람이 `{{토큰}}`을 심어야 했다 —
서식이 수천 종인데 그 준비를 누가 하나. 그러면 결국 안 쓰인다.

**깨달은 것**: 정부·공단 서식은 «칸 이름이 표준»이다.
「업체명」 「사업자등록번호」 「소재지」 「전화번호」 — 서식이 달라도 같은 말을 쓴다.
그래서 앱이 이름표를 읽고 스스로 넣게 했다(`js/pu-form-auto.js`).

| | 전 | 후 |
|---|---|---|
| 서식 한 종을 쓰려면 | 나에게 보내 → 토큰 심기 → 받기 | **없음** |
| 대표가 하는 일 | 파일 올리기 | 파일 올리기 |
| 새 이름표가 나오면 | 서식을 다시 만든다 | 사전에 **한 줄** 더한다(모든 서식에 듣는다) |

**확인**: 손대지 않은 원본 표준근로계약서(.hwp → .hwpx)를 그대로 올려
업체명·전화번호·소재지·대표자성명·사업자등록번호 **다섯 칸이 저절로** 채워졌고,
스킬 검사기로 「한글이 여는 모양」임을 확인했다.

**지어내지 않는다**: 「성명」 하나만 있는 칸은 사용자인지 근로자인지 알 수 없다.
그런 자리는 비워 두고 이름을 대며 말한다. `근로자·본국·피보험자·외국인` 이 함께 있는
칸은 아예 건드리지 않는다 — 잘못 채운 서류가 접수되는 것이 빈칸보다 나쁘다.
`tests/form-auto-fill.test.js` 가 이 규칙을 기계로 지킨다(이빨 확인 완료).

### 아직 남은 불편 — 다음에 없앨 것
1. **파일을 매번 고른다** → 서식함(Storage)에 한 번 올려 두고 목록에서 고르기
2. **.hwp 는 아직 못 받는다** → 한글에서 «.hwpx 로 저장» 한 번 필요.
   브라우저 rhwp(vendor/rhwp-core)가 .hwp 를 읽으므로 앱 안에서 바꿀 수 있다 — 다음 단계.
3. **근로자 칸은 안 채운다** → 계약이 아니라 «근로자»를 골라야 채울 수 있다
