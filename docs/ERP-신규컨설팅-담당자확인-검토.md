# 푸른이알피에 새 컨설팅이 생기면 담당자에게 물어보기 — 검토

2026-08-21 · 대상: 정부사업일정(`gov-consulting.html`) ↔ 푸른이알피 컨설팅관리

---

## 1. 결론 — 됩니다

담당자가 정부사업일정에 로그인하면 **푸른이알피에 새로 생긴 내 컨설팅**을 찾아
「일정관리로 가져올까요?」 하고 묻고, 동의하면 사업장을 만듭니다.

**가능한 이유 (확인한 것)**

| 확인한 것 | 결과 |
|---|---|
| 담당자 브라우저에서 ERP 자료를 읽을 수 있나 | **읽힙니다.** 보안 규칙상 `data/consultings`는 이메일 로그인한 직원이면 누구나 읽습니다. 그 PC에서 푸른이알피를 연 적 없어도 됩니다 |
| 새 건을 가려낼 수 있나 | **됩니다.** 이미 `erpBuildPlan()`이 ERP 컨설팅 한 건 한 건을 새로 추가·종류 추가·이미 있음·못 가져옴으로 분류하고 있습니다 |
| 내 것만 골라낼 수 있나 | **됩니다.** ERP에 주담당·부담당 사번이 들어 있고, 8/7에 직원마다 사번을 이어 두었습니다 |
| 만드는 일 | 이미 있는 「사업장 가져오기」를 **담당자용 확인 창**으로 다시 포장하는 수준 |

**푸른이알피는 읽기만 합니다.** 동의·거절 기록은 전부 일정관리 쪽에만 남습니다.

---

## 2. 동의할 때

1. 로그인 → 「푸른이알피에 새 컨설팅 2건이 있습니다」
2. 목록에서 확인 (업체명 · 컨설팅 종류 · 수행기관 · 부담당)
3. `가져오기` → 사업장이 생기고 주담당·부담당이 붙습니다
4. **일정은 만들지 않습니다.** 언제 갈지는 사람이 정합니다(지금 원칙 그대로)

---

## 3. 동의하지 않을 때 — 세 갈래로 나눕니다

여기가 이 검토의 핵심입니다. 「아니오」 하나로 두면 안 됩니다.

| 고름 | 무슨 일이 | 언제 쓰나 |
|---|---|---|
| **나중에** | 다음 로그인 때 다시 묻습니다 | 지금 바쁘다 |
| **안 가져옴** | 목록에서 빠집니다. 다만 **지워지지 않고** 「보류」로 남습니다 | 일정관리로 관리할 사업이 아니다 |
| 그냥 창 닫기 | **「나중에」와 같게** 봅니다 | 실수로 닫아도 잃지 않게 |

### 왜 「안 가져옴」을 완전히 지우지 않나

ERP에 있는 건 **회사가 실제로 수주한 사업**입니다. 일정관리에 안 넣기로 한 것과
아예 없는 것은 다릅니다. 나중에 「이 사업이 왜 일정에 없지?」라고 물을 때
**누가 언제 왜 뺐는지** 답할 수 있어야 합니다.

→ 환경설정 「푸른ERP 연결」에 **「보류한 건 N건」** 을 두고, 거기서 언제든 되살립니다.

### 보류를 자동으로 푸는 경우

- **ERP에서 주담당이 바뀌면** 다시 묻습니다. 담당이 바뀐 건 새로운 상황이고,
  앞사람의 판단을 새 담당에게 물려줄 이유가 없습니다.
- ERP에서 그 컨설팅이 **종료·취소되면** 보류 기록도 조용히 정리합니다.

---

## 4. 반드시 정하고 가야 하는 것 (설계 판단)

### ① 누구에게 묻나 — **주담당에게만** (권장)

부담당에게도 물으면 **둘이 각각 동의해 사업장이 두 개** 생깁니다.
주담당 한 사람만 묻고, 부담당은 사업장이 생긴 뒤 자기 목록에서 보게 됩니다.

### ② 거절 기록은 사람별인가 건별인가 — **건별** (권장)

사람별로 두면 주담당이 뺐는데 나중에 담당이 바뀌면 또 뜹니다.
건별로 두되 **누가 언제 뺐는지 함께** 적고, 관리자는 환경설정에서 전부 봅니다.

### ③ 언제 확인하나 — **로그인 직후 하루 한 번**

ERP 컨설팅은 40건 남짓이라 읽는 부담이 거의 없습니다. 다만 화면을 새로고침할
때마다 창이 뜨면 성가시므로, **하루 첫 로그인에만** 띄웁니다.
그 뒤에는 🔔 알림 센터에 한 줄로 남습니다(놓쳐도 사라지지 않게).

---

## 5. 가져올 수 없는 건 — 담당자가 아니라 관리자 일입니다

담당자에게 「가져올 수 없습니다」만 띄우면 할 수 있는 일이 없습니다.

| 막히는 이유 | 누가 풀 수 있나 | 어떻게 |
|---|---|---|
| ERP 컨설팅 유형이 일정관리 종류와 **연결 안 됨** | 관리자 | 환경설정 → 종류 표의 「ERP 연결」 칸 |
| 주담당이 일정관리에 **직원으로 없음** | 관리자 | 직원 관리 → 「+ 직원 추가」로 ERP에서 고르기 |

→ 담당자 화면에는 **「관리자 확인이 필요합니다」** 한 줄로만 알리고,
   관리자에게는 별도로 「막힌 건 N건」을 보여 줍니다.

---

## 6. 지금 있는 허점 하나 (같이 고치는 편이 낫습니다)

`erpBuildPlan()`이 **사업장 이름으로** 짝을 짓습니다. 그래서 ERP에서 업체명을
조금만 고쳐도(예: `(주)수성` → `주식회사 수성`) **새 컨설팅으로 잡힙니다.**

사업장에는 이미 `erpId`가 저장되고 있으므로, **이름보다 `erpId`를 먼저 보게**
바꾸면 됩니다. 몇 줄이면 되고, 이 기능의 오작동을 크게 줄입니다.

---

## 7. 위험과 대비

| 항목 | 내용 | 대비 |
|---|---|---|
| 중복 생성 | 주담당·부담당이 각각 동의 | 주담당에게만 묻는다(4-①) |
| 로그인마다 창 | 성가셔서 습관적으로 닫게 됨 | 하루 한 번 + 알림 센터에 남김(4-③) |
| 실수로 「안 가져옴」 | 사업이 조용히 묻힘 | 지우지 않고 보류로 남겨 되살리기(3장) |
| 이름 바뀌어 새 건으로 | 사업장이 두 개 | `erpId` 우선 매칭(6장) |
| ERP를 못 읽음 | 창이 안 뜸 | 조용히 넘어간다 — 기존 수동 가져오기가 그대로 있다 |
| 남의 건이 보임 | 다른 담당자 사업이 노출 | 내가 주담당인 건만 목록에 올린다 |

---

## 8. 만들 것과 크기

| 할 일 | 크기 |
|---|---|
| ① 로그인 후 내 새 컨설팅 찾기 (ERP 읽기 + 내 것만 + 이미 있는 것 제외) | 두어 시간 |
| ② 확인 창 (가져오기 / 나중에 / 안 가져옴) | 두어 시간 |
| ③ 보류 보관·되살리기 (환경설정) | 두어 시간 |
| ④ 막힌 건을 관리자에게 알리기 | 한 시간 |
| ⑤ `erpId` 우선 매칭으로 바꾸기 (6장) | 한 시간 |
| | **합계 하루 안쪽** |

---

## 9. 결정해 주실 것

1. **주담당에게만 물을지** — 권장은 주담당만. 부담당에게도 알리려면 「알림만,
   가져오기 단추 없음」으로 두는 방법이 있습니다
2. **하루 한 번 창을 띄울지** — 아니면 창 없이 🔔 알림에만 남길지
3. **「안 가져옴」한 건을 관리자도 볼지** — 권장은 봅니다(누락 점검용)
