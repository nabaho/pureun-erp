# OCR 단계 계획 (전수 재검토 결과 반영)

## 현황 — 급여대장 매체별
| 매체 | 개수 | 처리 방법 |
|---|---|---|
| xlsx | 678 (파싱 578, 85%) | ✅ 완료(로컬 파서) |
| **PDF 텍스트형** | 388 중 **실제 급여 ~51** | 로컬 추출 가능(좌표복원). 나머지는 세금·행정서류 |
| PDF 스캔형 | 135 | 🔒 LLM 비전 |
| **이미지(사진)** | 467 | 🔒 LLM 비전 ← **OCR 진짜 대상** |
| hwp | 106 | 변환 또는 비전 |

## 핵심 판단
- 텍스트 PDF 388개 중 급여 실물은 ~51개(급여명세서 47+급여대장 4). 대부분 이미 엑셀로
  파싱된 사업장이라 **추가 가치 낮음**. 나머지 337개는 사업자등록증·원천징수·위탁서.
- **OCR의 진짜 가치 = 이미지 467 + 스캔PDF 135** (여러 직원 든 스캔 급여대장).
  이것이 커버리지를 크게 늘리는 부분.

## 이미지 OCR = 대표님 결정·준비 필요 (제가 못 하는 것)
1. **LLM 비전 API 키**: Gemini Flash(장당 1~5원) + Claude 재판독 → 대표님 발급
2. **외부 전송 동의**: 이름+급여가 외부 API로 나감 → 개인정보. 대표님 명시적 동의 필요
3. **이미지 주민번호 마스킹 구현**: 전송 전 필수(설계 보안 ②). 현재 미구현
   - 방법 A: 1차 로컬 OCR로 위치 탐지 후 덧칠
   - 방법 B: 양식별 주민번호 컬럼 좌표 템플릿

## 준비되면 제가 하는 것
- `ocr_pipeline.py`의 `call_vision`·`mask_rrn_image` 구현
- 3중 방어: ①행합계 검산 ②Gemini/Claude 2모델 비교 ③저확신 사람큐 (골격 완성)
- 결과를 엔진 골든 대조에 편입 → 커버리지 확대
